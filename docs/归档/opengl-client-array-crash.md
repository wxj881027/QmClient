# 旧 OpenGL 后端客户端数组越界读取

## 问题与证据

用户提供的 `2026-09-20_15-29-08_11484` 崩溃记录对应 QmClient
`2.79.33`、提交 `86dc574bc`，实际异常时间为 15:30:58。
转储中的程序映像大小、时间戳与 PDB 标识均与该版本发布程序一致。
异常为 Intel `ig11icd64.dll`（`30.0.100.9955`）中的非法内存读取。

- 发布程序的返回地址 `DDNet.exe+0x14d41c` 位于旧后端地图边界绘制的
  `glDrawArrays` 调用之后。
- 先前普通绘制命令包含 1260 条线段、2520 个顶点，其颜色指针为
  `0x2b9be495140`，步长为 20 字节。
- 崩溃中的地图边界命令只画一个四边形，但顶点起点为 293012；驱动仍沿用
  先前的颜色指针，并在 `0x2b9be69600c` 读入未提交内存。
- 当前工作区 `3.9.46` 的普通图元绘制与地图边界绘制相关函数仍与旧版一致。
  `Cmd_Render` 开启客户端数组后没有关闭；`Cmd_RenderTarget_Draw` 有相同遗漏。

## 修复范围

用户确认修复这条崩溃路径。普通图元绘制和离屏纹理回绘在完成绘制后，
关闭顶点、纹理坐标及颜色客户端数组，沿用现有 `Cmd_RenderTex3D` 和
`DoAnalyzeStep` 的清理模式，避免 OpenGL 2.x / 3.0 的后续缓冲地图绘制
继承客户端内存指针。

改动保留在既有 `BACKEND_GL_MODERN_API` 条件保护内，不改变图元数量、
地图数据或绘制顺序。安全修复始终生效，无需配置开关或设置卡片。
版本从 `3.9.46` 更新至 `3.9.47`。
