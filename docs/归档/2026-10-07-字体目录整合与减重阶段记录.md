## 背景与目标

当前沿用 TClient 的自定义字体框架，字体资产分裂在两个随包目录：

| 目录 | 现状角色 | 体积 |
| --- | --- | --- |
| `data/fonts` | 上游 DDNet「字体索引链」域：`index.json` + DejaVu/GlowSansJ/思源黑体 + 16 个 Noto 素材 | 51.3 MB（仓库内 20 项，无 Phosphor） |
| `data/qmclient/fonts` | TClient「自定义字体」域：精选预装字体 + Phosphor 图标字体 | 约 195 MB |

用户目标：

1. **单一随包域**：内部域合并，只保留一个 `data/fonts`；`data/qmclient/fonts` 取消。
2. **字体卡片识别两个来源**：随包 `data/fonts` + 用户存档目录（`%APPDATA%/DDNet/qmclient/fonts`，字体商店下载安装处）。
3. **字体卡片 = 全局字体增强**：选中字体增强全局正文与中文，**不影响客户端图标（FONT_ICON_* / Phosphor）**。
4. **消除 C 盘复制**：随包字体不再复制进用户存档目录。
5. 顺带完成打包减重：基础字体和基础音频随客户端本体发布，额外字体、音频包和工具通过少量可选组件分发；已保留的版权字体不在本轮删除，但不再默认等同于必选 core 内容。

## 现状核实（2026-10-05，阶段一改动前基线）

### 已验证的事实

- **C 盘复制范围**：`%APPDATA%/DDNet/qmclient/fonts/` 实测只有两类内容——
  - `Phosphor/` 5 个字重（`text.cpp` `InstallBundledIconFonts()` 首启硬编码复制，本机 09-28 产生）；
  - 字体商店下载的字体（Aclonica / Coming Soon / Playball，09-29 用户安装）。
  随包的霞鹜文楷、Maple Mono、Ping Fang SC 等**没有**被复制（设计上直接经 `IStorage::TYPE_ALL` 命中随包原件）。运行时同名相对路径按存储层优先只加载一份，无内存双份；但磁盘上 Phosphor 确实双份（约 2.4 MB）。
- **图标与全局字体已解耦**：`FONT_ICON_*` 走独立的 icon face（`m_IconFace`，硬编码 Phosphor），`SetCustomFace`（全局字体）只替换 `m_DefaultFace`，二者互不影响。正文流内联图标码位经 fallback 链命中 Phosphor，同样不受全局字体影响。「全局增强不动图标」在现有架构上已成立，方案只需固化并加回归测试。
- **字体卡片识别域割裂**：`UpdateCustomFontList()` 只列 `qmclient/fonts` 加载出的 face（外加固定的 DejaVu Sans 头项），并显式排除「`index.json` font files 加载的默认面集合」——即 `data/fonts` 域的字体对卡片不可见。这是两域割裂的直接表现。
- **`index.json` 的 `icon` / `icon bold` 键是死配置**：解析代码不读这两个键，icon face 完全靠 `text.cpp` 硬编码 `TrySetIconFaceByName("Phosphor")`。配置与代码双轨。
- **NotoSansSC-VF（16.9 MB）近乎闲置**：默认字体已于 b4be903（10-03）改为「霞鹜文楷 Regular」，简繁中语言变体与 fallbacks[0] 的 Noto Sans SC 实际只在霞鹜文楷缺字时才被命中，其后还有思源黑体兜底。
- **打包全量随包**：根 `CMakeLists.txt` `EXPECTED_DATA` 显式 glob `data/qmclient/fonts/*`，`copy_directory` 同步 → `zip_pack.py` 打包，195 MB 全部进发布包。
- **旧包覆盖升级不删旧文件**：用户安装目录中 09-20 的 `data/fonts/Phosphor-*.ttf` 即残留实证（源码已删，包里还在）。

### 版权字体（用户决定：保留资产）

Ping Fang SC（Apple 专有）、方正屏显雅宋（方正授权）、Times New Roman（Microsoft）、Minecraft.ttf（Mojang）存在再分发授权约束。**用户 2026-10-05 明确决定保留这些资产、不做删除**，阶段二仍需把它们登记到 core 或 `fonts.7z` 的许可证清单中，不得因组件拆分而静默丢失。

## 目标架构

```
data/fonts/                          ← 唯一随包字体域（git 跟踪、随包发行）
    index.json                       ← 单一事实源：角色声明 + fallbacks + 图标字体配置
    Phosphor/                        ← 图标字体 5 字重（图标域唯一来源）
    霞鹜文楷/                         ← 默认正文字体（已由其他会话子集化，本方案不动本体）
    <基础 CJK/Emoji/Symbols 资源>/     ← 客户端启动和基本显示所需资源，随 core 发布
    DejaVuSans.ttf / SourceHanSans.ttc / GlowSansJ-*.otf / 精简后 Noto 素材

%APPDATA%/DDNet/qmclient/fonts/      ← 用户域：fonts.7z 与字体商店下载安装的额外字体
%APPDATA%/DDNet/qmclient/audio/<id>/ ← audio.7z 解压后的独立音频包目录
%APPDATA%/DDNet/qmclient/tools/<ver>/← tools.7z 解压后的工具目录
```

阶段一把现有官方字体资产合并到 `data/fonts`；阶段二出包时，当前仓库 `data/fonts` 全部随完整安装包发布，外部额外字体通过 `fonts.7z` 本地导入。这样保留“单一随包字体域”的运行时语义，同时减少必选包体积；用户域只承载显式安装的可选资源。

`index.json` 目标形态（`font files` 废弃，文件发现统一走目录扫描）：

```json
{
    "default": "Source Han Sans SC",
    "language variants": { "japanese": "...", "korean": "...", "simplified_chinese": "...", "traditional_chinese": "..." },
    "fallbacks": [ "..." ],
    "icon": "Phosphor",
    "icon bold": "Phosphor-Bold",
    "icon styles": { "light": "Phosphor-Light", "fill": "Phosphor-Fill" }
}
```

## 改动清单

### 引擎（`src/engine/client/text.cpp`）

1. **加载顺序重构**：先递归扫描 `fonts`（TYPE_ALL，命中随包 `data/fonts`）建 face 池，再扫 `qmclient/fonts`（TYPE_ALL，现用户域商店字体）补充；两个路径都进 `m_vLoadedCustomFontPaths` 去重。
2. **`index.json` 解析调整**：`font files` 键废弃（保留向后兼容：存在则仍按旧逻辑加载）；新增读取 `icon` / `icon bold` / `icon styles` 键设置 icon face，缺键时回退现硬编码 Phosphor 默认值。加载顺序统一为「目录扫描 → 按 index.json 绑定角色（default/variants/fallbacks/icon）」。
3. **删除 `InstallBundledIconFonts()`**：Phosphor 随包在 `data/fonts/Phosphor`，TYPE_ALL 直接命中，无需复制。用户域扫描必须排除 `qmclient/fonts/Phosphor/**`，老用户 C 盘残留不得再次进入 face 池；当前工作区已加入该过滤，发布前仍需保留旧安装包清理说明。
4. **`UpdateCustomFontList()` 调整**：删除「默认面集合排除」逻辑（合并后无意义），只排除图标字体（Phosphor）与预览面；卡片列表 = 随包 `data/fonts` 全部字体族 + 用户域商店字体。DejaVu Sans 固定头项移除（默认字体本身已是霞鹜文楷）。

### 资产（`data/`）

5. `data/qmclient/fonts/` 内容整体并入 `data/fonts`（目录结构原样保留子目录组织）；`data/qmclient/fonts/` 删除。
6. 减重（本方案内一并决策，单独提交）：
   - 移除 `NotoSansSC-VF.ttf`（16.9 MB），简繁中 variants 改回 `Source Han Sans SC/TC`，fallbacks 删「Noto Sans SC」；
   - 裁剪小语种 Noto（Vai/Bamum/Batak/TaiLe/EgyptianHieroglyphs/Oriya/Balinese/Javanese/Yi/Tibetan/Thai，约 2 MB），保留 Emoji/Symbols/Symbols2/Math；
   - **霞鹜文楷不动**：GB2312 子集化（79.2 → 40.2 MB）已由另一会话于 2026-10-05 完成，本方案不碰字体文件本体；资产迁移仅做目录搬移（保留该会话的工作区改动，不纳入本方案提交）。
   - **阶段一保留在官方字体资产中（用户决定，不删除）**：版权字体（Ping Fang SC、方正屏显雅宋、Times New Roman、Minecraft.ttf）、Maple Mono（54 MB）、霞鹜新晰黑/新致宋（22 MB）及其余现役预装字体。阶段二仍保留这些资产，但按“基础字体随 core、额外字体进 `fonts.7z`”分配；可选化只能通过已登记、已校验的包完成，不能静默删除或替换。

## 审查结论与阶段二的修订要求（2026-10-05）

以下结论来自对当前 `text.cpp`、字体商店、打包脚本、测试夹具和本方案的交叉审查。它们是阶段二开始前的必要修订项，不代表阶段一已经完成了这些能力。

### 已确认的问题

1. **远程组件清单方案已取消**。此前设计的 `packages.json`、蓝奏云 URL 和远程可选包下载链路不再作为实施目标；当前只保留现有客户端自动更新，以及字体/音频/工具的本地导入校验。
2. **当前字体池不支持同路径热更新或删除**。`m_vLoadedCustomFontPaths` 按路径跳过已加载文件，`ReloadCustomFonts()` 不会释放旧 `FT_Face`、字体数据和字形缓存。因此覆盖同一路径后当前进程继续使用旧字体，删除文件也不会让已加载字体立即消失。阶段二在引擎完成字体池重建前，只能承诺“下次启动生效”，不能在 UI 中承诺立即更新或删除。
3. **旧 Phosphor 残留曾会被扫描**。审查时 `LoadCustomFonts()` 会扫描 `fonts` 和 `qmclient/fonts`，没有排除 `qmclient/fonts/Phosphor/**`，会额外建立重复 face。本轮工作区已补路径过滤和真实进程场景；随包字体优先于用户同族字体的规则仍需在组件化设计中固定。
4. **图标样式缺失时的回退实现曾不完整**。审查时 `TrySetIconStyleFaceByName()` 在查找失败时会把目标样式写成空 face。本轮已改为按“指定样式 → 当前样式 → regular icon”回退，并新增策略单测；仍需补 index.json 缺键和未知族名的真实加载场景。
5. **组件包内容没有覆盖全部字体资产**。当前 `data/fonts` 中的 Cabin、FreeSans、GoogleSans、Minecraft、Inter、Poppins、Rubik、Times New Roman 等文件没有在阶段二表格中归属；推荐包列出的字体文件数量也与“12 文件”不一致。调整为“基础字体随客户端本体、额外字体统一进入 `fonts.7z`”后，所有字体、许可证、`index.json` 和附属配置仍必须恰好归属一个组件，未归属或重复归属应使打包失败。
6. **阶段二的包根目录和必选性尚未定义**。此前把字体 bootstrap 单独拆成必选包，既增加了组件选择复杂度，也与“基础资源随客户端本体发布”的目标冲突。新的必选项只有客户端本体；本体必须自带 `index.json`、Phosphor、默认正文字体和最低限度 CJK/Emoji/Symbols 资源，缺少这些资源时 Setup 应在安装前失败并保留旧版本。额外字体、音频包和工具包均为可选项，解压目标必须区分安装目录和用户存档目录。
7. **行为测试仍未形成完整证据**。本轮已增加路径过滤和回退策略单测，以及旧 Phosphor 残留的真实进程场景；仍缺少覆盖全局字体与图标隔离、缺失 index 字段和字体重载生命周期的真实场景。`qmclient_scripts/tests/test_zip_pack.py` 仍使用旧的 `data/qmclient/fonts` 夹具，需在打包组件化实施时同步迁移。

### 当前采纳的发布方案

用户最终确认：Windows CI 在现有 ZIP / 7z 便携包之外，增加 `QmClient-Setup.exe`。这是完整离线安装包，载荷只包含当前仓库 `data`、`DDNet.exe`、`DDNet-Server.exe` 和构建目录根下的 DLL。不额外内置 `fonts.7z`、`audio.7z`；仓库已有的默认字体及基础声音全部保留。

取消蓝奏云对接、分享密码解析、远程可选组件清单和联网 bootstrap 安装器。本轮添加的远程组件清单解析代码及对应测试已移除；现有 HTTP 下载器和客户端自动更新功能保留。

### Setup 实现

- CI 在便携目录生成后调用 Inno Setup，产出 `QmClient-Setup.exe`，与 ZIP / 7z 一起上传和发布。
- Setup 使用 LZMA2 `ultra64` 与 solid 压缩，这是 7z 使用的压缩算法；Inno Setup 内部载荷格式并非独立 `.7z` 文件。独立 7z 便携包使用 `-mx=9 -m0=lzma2 -ms=on`。
- 默认安装到当前用户 `%LOCALAPPDATA%/Programs/QmClient`，无需管理员权限；提供开始菜单快捷方式、可选桌面快捷方式和卸载入口。
- 升级复用固定 AppId 与安装位置，安装器不删除 `%APPDATA%/DDNet` 中的用户配置和资源。
- 安装清单只记录此次发布文件，卸载不递归清空整个应用或用户存档目录。
- Setup 和便携包保持同一版本，普通构建不升级版本。

### 后续本地导入功能

`fonts.7z` 和 `audio.7z` 使用文件选择器一键导入，避免让用户手动查找存档目录。本轮 CI 安装器不包含此功能；客户端导入作为后续独立实现。

导入实现需检查归档路径、符号链接、大小写冲突和解压大小预算，先在 staging 目录解压，再安装到对应用户资源目录。音频包按目录管理；字体更新与删除在 face 池支持重建前标记为下次启动生效。导入失败保留旧资源；不导入或执行包内 EXE。

### DLL 缺失处理建议

Setup 已把所有构建目录根下的 DLL 纳入完整安装包，重新运行 Setup 即可修复安装不完整或 DLL 被删除的问题。客户端无法启动时不能依靠客户端内 UI 下载 DLL，因为缺失 DLL 可能发生在进程初始化之前。

如果要提供“选择下载 DLL”，可在 Setup 中增加“修复运行库”模式，下载一个单独的 DLL 依赖包并使用与完整更新相同的签名清单、SHA-256 和路径白名单。国内镜像可以作为清单中的备用 HTTPS 地址，但必须由 CI 生成并签名，不能让客户端直接信任未经校验的镜像文件。本轮不硬编码 GitHub 以外的下载源，待有稳定镜像地址后再接入。
