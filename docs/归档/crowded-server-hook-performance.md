# 多人服务器与大地图渲染开销优化

## 目标与边界

- 用户反馈 R5 5600 在人少时约 1000 FPS，128 人服务器约 100 FPS；复现地图没有移动方块。
- 用户确认保持显示效果和操作手感，不通过隐藏玩家、降低特效换帧率。
- 第一批优化钩线提示的玩家相交查询；后续扩展到名牌文字缓存与 Gores 路线显示的临时访问表。不改变真实钩子、物理、预测、地图、协议或既有开关。
- 内部等价计算无需新增 UI 配置项，算法放入独立 QmClient 头文件。

## 源码证据与实现

`CPlayers::RenderHookCollLine` 逐段模拟提示线，调用 `CGameClient::IntersectCharacter`。
候选玩家已按本帧的队伍、solo、super 和禁钩规则缓存，但每段仍对所有候选计算最近点和距离。
多人时成本随提示线数量、模拟段数和候选人数一起增长；未开启相应提示线时，这项优化没有收益。
仅凭源码不能认定它就是本次从 1000 FPS 降到 100 FPS 的主因。

新增 `qm_hook_coll_intersection.h`：

- 每段仅计算一次方向差、长度平方和保守包围框。
- 先排除包围框外的玩家，再执行原浮点顺序的最近点、距离和严格半径判定。
- 保留候选顺序与等距离选取规则；未命中不修改输出参数。
- 包围框使用最近点公式的重建终点，半径外额外保留一单位；它只影响粗筛，不改变精确判定半径。
- 逐段采用实际端点，不依据角色是否在屏幕内跳过模拟，因此保留传送钩和屏幕外伸入画面的提示线。
- 算法仍线性扫描候选，但远处玩家只需坐标比较，避免投影除法和距离开方。

## 深入主渲染链：远端模拟与空间候选（2026-09-19）

用户澄清“继续往后退”指继续深入排查优化，不是撤销补丁。沿用保持显示效果、
操作手感、不动拖尾和预测语义的边界。

### 源码证据

- `CPlayers::OnRender` 在角色可视范围判断之前调用每位玩家的 `RenderHookCollLine`。
  `CCollision::IntersectLineTeleHook` 沿每段逐像素采样；整条线不可能进入当前画面时，
  原代码仍完成地图查询与角色相交查询。这项成本与地图上的玩家分布和提示线设置有关。
- 前一批的几何粗筛只减少精确计算，依然逐段扫描全部合资格玩家名单。
  多条提示线和多段模拟会重复进行同一批远端玩家的包围框比较。
- 核对名牌参照对象后确认：游戏内已有按玩家复用；逐帧临时销毁发生在设置预览，
  不作为当前在线多人场景的补丁。

### 实现与范围

1. `qm_hook_coll_visibility.h` 在加载地图时记录当前与旧模式的钩子传送入口。
   无相应传送入口时，以钩长、最后一次发射步长、方向量化误差、100 世界单位保守余量、
   线宽与像素边缘扩展可能可见范围。只有整个范围与当前视口分离才跳过提示线模拟。
   有钩子传送入口则保留原模拟，兼容传送后进入画面的线；旧传送设置按当前值判断。
   判断发生在图形状态写入前，不改变实际钩子、预测或地图碰撞实现。
2. `qm_hook_coll_spatial_index.h` 每轮绘制按需建立一次有效玩家的 X/Y 有序位置表。
   每段在更窄的一轴取范围，再沿另一轴及原资格名单过滤；最终按客户端编号恢复顺序，
   交给原精确判定，保持等距离时的目标选择。
   少于 16 个合资格目标直接扫描；当范围包含整群或不能至少排除一半候选时也保留原名单。
   这些分支避免小集合及密集场景反复整理名单，但尚未做运行时间基准，不能保证所有分布都更快。
3. `UpdateHookCollTargets` 每次绘制刷新位置时同步让索引失效。关闭提示线或没有有效查询时
   不建立有序位置表。不同视口不复用可见性结果，传送后的段使用其实际端点重新查询。
