## 性能入口与保留决定

现有 CMake 提供 `qm-benchmarks` 和 `run_cxx_benchmarks`，目标要求 Google Benchmark 依赖、SERVER 和 FreeType；当前工作区 Release cache 已启用依赖下载。现有 gate 检查注册表没有 benchmark 运行项。

[性能验证参考](../../.agents/skills/qmclient-verification-gate/references/performance.md) 维护配置、构建、注册项枚举、过滤运行、重复统计、JSON 留存、计时范围、可比基线、错误/跳过与实际未覆盖项。CPU 微基准、功能测试、帧/设备场景分别报告；不将 gate 通过解释为性能通过。

本次保留 `qmclient_scripts/perf/` 的 HTML/JSON 分析脚本。其 CLI 实际读取客户端 `qm_perf_debug` 日志，解析帧、卡顿、采样和配置变化；这些数据仍有真实场景诊断用途，CPU benchmark 不提供对应玩家操作数据。已移除旧规则对常规代码验收生成 HTML 的要求，旧 perf 配置开关不再作为运行步骤。

保留依据来自日志采集与离线消费职责，不来自现有 C++ 源码字符串测试。`src/test/qmclient_monitoring_test.cpp` 仍有读取分析器源码并查找字符串的旧测试，例如 `PerfAnalyzerReportsUiBudgetFields` 和 `PerfTelemetryOverheadIsAttributedByFrameWindow`；它们不能证明运行时统计或报表行为。本轮未改测试实现或扩大为监控系统整改。

将来删除旧分析器需先确认真实场景日志的替代消费方式，再同步清理 CLI、报表/解析模块、测试、package/lock、忽略项及文档，避免留下失效消费者。
