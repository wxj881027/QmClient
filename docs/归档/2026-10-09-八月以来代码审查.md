### R1 P1 配置迁移的递归清理会跟随目录链接

位置：`src/engine/shared/config.cpp:86–95`、`:223–227`。入口：`src/engine/client/client.cpp:4752–4762`。

- 触发：配置迁移待完成，合并保存成功，`qmclient/migration_backup_v1` 或 `migration_backup_v2` 本身或子目录是指向外部目录的 Windows junction / 符号链接。
- 原因：清理只跳过 `.` 和 `..`，随后按 `IsDir` 递归。底层目录枚举和 `fs_is_dir` 会把目录链接作为目录，`RemoveFile` 对经过链接的路径直接删除文件，没有链接检测或实际路径边界。
- 风险：自动迁移可以删除备份目录以外的目标文件。链接环和路径截断还可能使递归无法正常结束。已有“保存失败不清理”保护不能阻止这个路径。
- 修复：优先仅清理迁移程序创建的已知文件，或保留备份。确需递归时，对根目录和子项拒绝 symlink / reparse point，并处理路径长度、深度及实际目标边界；不应仅用字符串前缀判断安全。
- 影响面：历史配置迁移的文件清理，不涉及配置格式或玩家设置语义。
- 建议回归：在隔离临时目录中建立指向外部哨兵目录的链接；完成迁移后外部文件不变。补链接环、长路径和保存失败场景。现有 `storage_replace_test.cpp` 有普通迁移与缺少合并文件的测试，未证明链接边界。

### R2 P1 幽灵时间线缓存的数量与事件字段未经校验

位置：`src/game/client/components/qmclient/rank_ghost.cpp:2461–2500`、`:2633–2634`。消费端：`src/game/client/components/effects.cpp:252–279`。

- 触发：加载损坏或被修改的 `.qmevt` 缓存；文件保留合法 magic，但记录数量异常，或死亡事件的 ClientId 超出 `MAX_CLIENTS`。
- 原因：读取计数后立即 `reserve(Count)`，没有先核对文件剩余长度和数量预算。事件负载也直接传给特效；`PlayerDeath` 只检查 ID 非负，随后索引客户端数组。
- 风险：仅有合法头和极大计数的短文件就能请求巨额内存，分配异常绕过“缓存损坏后重建”的回退。合法计数配合越界死亡 ID 会造成数组越界读取，可能崩溃。
- 修复：按剩余文件字节、记录大小和合理数量预算验证各段；检查事件类型、ClientId、tick 顺序等语义字段；解析到有界临时容器，验证成功再替换当前状态。失败统一回退到重建。特效消费端也应防御越界 ID。
- 影响面：排行榜幽灵加载和在线回放的时间线缓存；未确认可通过远程服务直接投递恶意缓存。
- 建议回归：巨大计数的短文件、截断记录、非法事件 ID、未知类型以及损坏后重建。通过生产加载接口验证，不用源码字符串断言。

### R3 P2 WebSocket 建连阶段不能及时取消

位置：`src/engine/shared/qm_websocket.rs:73–113`、`src/engine/shared/websocket_client_rust.cpp:78`、`:222–227`。主线程调用点：`src/game/client/components/qmclient/qmclient.cpp:1984–1988`。

- 触发：DNS 解析迟迟不返回，或 TLS / WebSocket 握手缓慢，此时切换服务地址、断开连接或关闭组件。
- 原因：总 deadline 只约束 TCP connect；同步 DNS 和 `client_tls_with_config` 没有取消入口。握手设置的是每次 socket I/O 的超时，不能替代整次握手 deadline。`Disconnect` 设置停止标志后直接 join，标志要等建连返回才会被观察。
- 风险：调用 `Disconnect` 的主线程会等待连接线程，造成界面冻结、地址切换迟滞或退出等待。对端持续缓慢发送握手数据时，总等待可能明显超过配置超时。最终退出 watchdog 不解决主循环中的卡顿。
- 修复：将解析和握手纳入同一个可取消的 deadline；采用可中断解析、分步非阻塞握手或明确拥有并可关闭的连接 socket。停止标志应在各阶段有界观察。
- 影响面：共享 WebSocket 的实时服务、匿名通道和语音；已建连后的非阻塞读写及有界 close 已有保护，应保留。
- 建议回归：本地 fake peer 分别不回复、缓慢回复握手；取消和地址切换必须在明确时间内完成。DNS 使用可控 resolver，不依赖互联网。

当前 Rust 建连实现由 `3413f137632` 于 2026-09-15 引入。

### R4 P2 截图缩略图没有解码后像素预算

位置：`src/game/client/components/qmclient/screenshot_image_job.cpp:41–71`、`screenshot_image_job.h:17–21`。分配点：`src/engine/gfx/image_loader.cpp:276–286`。

- 触发：截图库出现压缩体积小、像素尺寸大的 PNG / WebP，尤其同时调度多个缩略图任务。
- 原因：64 MiB 限制只针对压缩文件；解码先分配完整像素，之后才缩至最大边 512。底层 PNG 检查防整数溢出，没有提供资源预算。最多 4 个并发任务仍能同时保留大图。
- 风险：高压缩率 PNG 可以在文件限制内要求数 GB 像素内存；例如 32768×32768 RGBA 仅像素即 4 GiB。可能引起内存耗尽、换页卡顿或进程失败。分配失败有部分回退，不表示资源压力已经受控。
- 修复：在完整分配前验证图片头中的尺寸及乘法结果，为该用途规定解码字节预算，并约束并发任务的总字节数；必要时使用解码阶段降采样。预算需兼容正常高分辨率截图。
- 影响面：截图缩略图与预览任务。通用 loader 的接口可以接受调用方预算，避免把截图限制无条件施加给其他资源用途。
- 建议回归：高压缩率大尺寸图片应在完整分配前被拒绝；普通 4K / 8K 按选定预算正常处理；多个任务不突破总预算。现有图片 job 测试主要覆盖缩放、格式识别和无效文件。

图片任务在本次范围内新增。

### R5 P2 水印重新导出失败会破坏已有导出文件

位置：`src/game/client/components/menus_demo_screenshots.cpp:229–237`、`src/game/client/components/qmclient/screenshot_manager.cpp:629`。写入顺序：`src/engine/gfx/image_loader.cpp:503–525`。

- 触发：同一截图已经成功导出 `_watermarked.png`，再次导出时发生编码失败、磁盘空间不足或短写。

- 建议回归：预先保存有效目标，注入编码、写入和替换失败，原目标字节保持不变；正常重复导出替换成功。现有水印渲染测试没有证明这个失败边界。

### D1 只读共享内存工具使用具有写入语义的原子操作

位置：`src/game/client/components/qmclient/netease/netease_shared_memory.cpp:18–26`、`:102–105`。

`CV5SharedMemoryReader` 使用 `FILE_MAP_READ` 打开映射，但 `LoadSequence` 调用 `InterlockedCompareExchange64`。CMPXCHG 即使比较不成立也具有写访问语义；在只读页上执行可能访问违规。[Intel 指令手册](https://cdrdv2-public.intel.com/774492/325383-sdm-vol-2abcd.pdf)说明 CMPXCHG 的写周期，[Microsoft Interlocked.Read 文档](https://learn.microsoft.com/en-us/dotnet/api/system.threading.interlocked.read?view=net-10.0)也说明依赖 CompareExchange 的只读地址访问风险。

当前生产网易云 provider 在 `netease_hook/qm_netease_hook_provider.cpp:25` 已明确避开此操作。检索未找到 `CV5SharedMemoryReader` 的生产实例，因此这里属于工具接口的潜在接入风险，不能写成当前网易云功能必然崩溃。

可复用实际 provider 的只读安全读取策略，或移除未使用的重复工具。若保留，使用真正的只读映射测试，不仅以可写内存里的结构体测试快照算法。该工具在本次范围内新增。
