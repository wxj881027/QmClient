# 固定 Worktree 开发与集成

状态：有效。创建日期：2026-10-07。

共享规则不绑定某个开发者的目录或分支。机器配置从 [.agents/machine.example.json](../../.agents/machine.example.json) 复制到同目录的 machine.local.json 后填写；本地文件由 Git 忽略。Agent 按根 AGENTS.md 发现和核对配置，匹配后默认采用对应 profile。当前目录没有配置时，可从同一仓库主工作树继承；无配置时沿用当前目录和分支，不自动初始化槽位。

本文展示单集成分支、detached HEAD 槽位的流程。需要独立任务分支的协作者可以采用自己的已授权分支策略。命令中的 <primary-worktree>、<slot-1>、<slot-2>、<integration-branch> 和 SHA 都是占位符，执行前从匹配的机器配置与实际 Git 状态替换；带空格路径需加引号，不能直接执行占位符。构建目录也以配置为准，示例使用默认 cmake-build-release。

| 配置字段 | 含义 |
| --- | --- |
| schema_version / profile | 当前版本为 1；profile 是本机描述标签，不自动识别主机名 |
| primary_worktree / integration_branch | 本仓库主工作树绝对路径与实际集成分支 |
| slot_mode / worktree_slots | 当前支持 detached；固定槽位绝对路径数组，必须属于同一仓库 |
| build_directory | 各工作树内部的相对构建目录，不能是绝对路径或包含 ..，不能共享目录 |
| build_jobs_single | 单个重构建的 job 数 |
| build_jobs_per_slot_parallel / max_concurrent_heavy_builds / total_build_job_budget | 并行时每槽 job 数、全机重构建数量上限、总 job 预算；两种 job 配置都不得超过预算 |
| client_smoke_window_mode / client_smoke_start_minimized | 普通烟测使用 windowed，是否尽量最小化启动；专项验证按目标选择 |

本机配置只保存工作偏好，不保存秘密，也不产生 Git 操作授权。JSON 不使用环境变量展开或命令求值。目录换位置、分支改名或更换机器后更新本地文件；不要把旧机器配置复制后直接用于其他仓库。模板可提交，本地配置不得通过 git add -f 强制纳入提交。Git ignore 不会自动取消已跟踪文件，发现被跟踪时先核对并报告。

每个目录在 Codex 中作为独立 Local 项目使用。一个活跃写入任务独占一个目录；协调者记录槽位、任务、基线 SHA、交付 SHA、占用会话和构建占用，长任务在已有计划中维护，短任务在会话中记录。固定槽位不使用自动 Worktree 创建或归档功能。现存 tmp 下历史 Worktree 不自动改名、清理或转换为槽位。

## 首次准备

以下是一次性操作示例，不代表阅读本规则时自动执行。先检查 git worktree list、目标目录是否已存在，以及主目录的 git status。槽位基线只能包含已提交成果，主目录未提交修改不会复制过去。目录已经初始化时直接复用。

```powershell
cd <primary-worktree>
git worktree add --detach <slot-1> <integration-branch>
git worktree add --detach <slot-2> <integration-branch>
git worktree lock <slot-1> --reason "固定 Agent 槽位，长期保留"
git worktree lock <slot-2> --reason "固定 Agent 槽位，长期保留"
```

lock 用于防止误移除或修剪，不能代替会话占用管理。每个槽位依次初始化，不同时做首次全量构建：

```powershell
cd <slot-1>
git submodule update --init --recursive
.\qmclient_scripts\cmake-windows.cmd -G Ninja -S . -B cmake-build-release -DCMAKE_BUILD_TYPE=Release
.\qmclient_scripts\cmake-windows.cmd --build cmake-build-release --target game-client -j 6
```

wt-2 同理。Submodule 指针变化时检查其未提交改动，再执行 git submodule sync --recursive 和 git submodule update --init --recursive；不用 --remote。Git 对含 Submodule 的多工作树支持仍有局限，更新只在目标槽位执行，失败时检查该槽位路径与实际 checkout，不以强制重置处理。

## 新任务与交付

接任务前确认槽位无人写入、没有构建或测试占用；核对 git status --short、git log 和上次交付记录。槽位必须没有未保存改动，上次成果已集成或已有保存引用。按任务需要从主目录取得已提交基线：

```powershell
cd <primary-worktree>
git rev-parse <integration-branch>
cd <slot-1>
git switch --detach <已核对的基线SHA>
```

尖括号内容为占位符，执行前替换为真实 SHA。如需远端同步，只由主目录负责 fetch 和审查集成；不默认 reset 到 origin/main 或 origin/<integration-branch>。槽位工作期间主分支前进不会自动同步到槽位。

交付前检查 git status、git diff 和暂存区，只提交本任务文件。按项目 Git skill 生成完整小提交，并在切离之前建立唯一的保存标签，例如 agent-save/wt-1/2026-10-07-ui-settings；后续任务使用新的名称，不覆盖旧标签，不自动删除。标签是提交保留引用，不是新的开发分支，不默认推送。

```powershell
git tag agent-save/wt-1/2026-10-07-ui-settings HEAD
git rev-parse HEAD
```

多提交任务同时记录基线和按顺序排列的提交 SHA，标签指向任务末端。主目录确认当前分支为 <integration-branch>，并确保没有其他会话写入；有未提交成果时先由其所有者完成保存，不自动 stash、暂存或提交其他任务。然后审查提交并依次集成：

```powershell
cd <primary-worktree>
git show --stat <交付SHA>
git cherry-pick -x <交付SHA>
```

cherry-pick 后 SHA 通常改变，交付记录保存来源 SHA 与集成 SHA。发生冲突时结合两侧意图处理并验证，不能统一选 ours/theirs；不能完成时保留保存标签并报告原因。重试前检查来源尾注和集成记录，避免重复摘取同一成果。原槽位通过的测试不能替代主目录在组合代码上的相关验证。

主目录完成集成验证后，槽位核对干净状态、保存标签与集成结果，再 git switch --detach <integration-branch> 回到最新已提交基线；保留目录和构建产物。合并成本集中于一次 diff 审查、串行 cherry-pick 和受影响验证。SQLite schema、统计、排行和迁移等同一功能链连续放在一个槽位；多个任务需要修改 CMakeLists.txt、配置头、gameclient 或公共接口时优先串行。

## 构建与客户端验证

每个目录独占自己的 cmake-build-release，不能复制其他槽位 Cache、共享中间产物或使用目录链接共用 build。已有 Cache 默认复用；配置或依赖变化、CMake 要求重新生成、源码路径不匹配时重新配置，不将删除 build 作为常规步骤。同目录构建、测试、benchmark、打包和 gate 串行。

无配置时单个重构建默认 -j 6 并串行执行。有匹配配置时按 build_jobs_single、build_jobs_per_slot_parallel、max_concurrent_heavy_builds 和 total_build_job_budget 协调。两个槽位各 -j 3、总预算 6 是示例配置，不是所有协作者的固定要求。这是保守初始值，不是根据本机测量确定的最优值；内存紧张、链接峰值或前台卡顿时降低到 -j 2 或串行。会另行启动构建的脚本要核对实际并行参数，不能只改外层命令；CMake job 预算也不能硬限制 Rust、测试或所有子进程。

需要用户人工验证时，最终回复提供实际产物目录的 PowerShell 命令，例如主目录：

```powershell
cd <primary-worktree>/cmake-build-release
.\ddnet.exe "gfx_fullscreen 0" "gfx_borderless 0" "gfx_screen_width 1280" "gfx_screen_height 720" "cl_save_settings 0"
```

槽位 1 的命令必须改为 <slot-1>/cmake-build-release，槽位 2 同理。不要让用户误测其他目录的旧二进制。参数显式窗口化，并关闭本次退出保存；自动烟测仍优先使用现有 harness 的隔离配置和日志路径，不用真实用户配置验证持久化行为。

普通非视觉启动尽量后台最小化：

```powershell
cd <slot-1>/cmake-build-release
Start-Process -FilePath .\ddnet.exe -WorkingDirectory (Get-Location).Path -WindowStyle Minimized -ArgumentList '"gfx_fullscreen 0" "gfx_borderless 0" "gfx_screen_width 960" "gfx_screen_height 540" "cl_save_settings 0" "minimize"'
```

客户端提供 minimize 控制台命令；窗口化参数防止默认配置触发独占全屏，最小化标志与命令尽量减少前台干扰，但图形窗口是否瞬时激活取决于启动过程，不能承诺完全无焦点变化。只在验证目标涉及全屏、焦点或显示切换时使用相应模式并提前说明。渲染、截图和交互验收必须使用可见普通窗口，最小化时可能暂停渲染，不能替代这些验证。

当前文档只规定后续执行方式，不宣称所有旧 smoke runner 已满足窗口与焦点要求。运行前检查 runner 实际参数；不相关的全屏场景不要启动，本次未修改现有 runner。
