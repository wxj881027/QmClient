## 本次行为

发送者昵称原本就与正文分离。新增独立生产模块 `src/game/client/components/qmclient/translate/translate_detect.*`，收发自动翻译复用其统计和目标语言判断。

正文开头的「当前在线玩家完整名字 + 半角或全角冒号」、有前后边界的 `@完整玩家名`、对应在线玩家的 `@数字ID` 不计入语言统计。名字匹配区分大小写，重叠名字取最长有效匹配，普通单词和未确认的名字继续统计。玩家名单每次从当前状态读取，无跨消息昵称缓存。

目标为普通中文 `zh` 时，排除引用后纯汉字消息不受混合文本的最少字符门槛限制。因此在线玩家 DYL 对应的 `DYL：泥蛙！！！` 在截图的 3 字符、50% 配置下跳过自动翻译。`DYL：help me` 仍触发翻译。纯数字、空白、符号及只含明确玩家引用的消息不发起自动请求。显式中文变体 `zh-CN`、`zh-TW` 保留后端转换路径；入站「始终翻译」对有文字的消息继续生效。

原始正文和玩家名字没有被改写。排除只影响本地判断；确需翻译时后端仍接收完整正文，所以本次不保证第三方返回结果中名字一定原样保留。普通未知名字、无分隔符的提及及扩展汉字未做猜测识别；混合文本沿用原比例和数字占优策略。

增加 20 项生产行为单元测试，覆盖短中文、明确引用、未知名字、大小写、名字前缀、空格和标点、重叠名字、在线 ID、超长 ID、名单变化、重复调用、语言变体、始终模式、不同文字系统、无意义文本和非法 UTF-8。先运行旧行为下的短中文测试并确认失败，再完成修复。

根 CMake 仅改本任务所需的客户端、单测和 benchmark 注册。验证时工作区并行任务新增滚动 benchmark 但缺少 QmScroll 实现，另补 benchmark 目标的 `QmScroll.cpp` 注册，未改滚动实现。其他任务已有改动均保留。

## 确定问题与建议

### 严重：LLM 初始化失败可能空指针崩溃

位置：`src/game/client/components/qmclient/translate/translate.cpp:1491`、`:1523`、`:1565`。

缺少选中 Provider 的 Key、缺少端点或端点归一失败时，构造函数 SetInitError 后返回，HTTP 请求保持空。基类 Update 返回 false；派生 Update 仍进入 ShouldRetryWithResponses。此时默认 AUTO/CHAT 通过检查，接着访问空请求的 StatusCode。入站、手动与自动出站共享此路径。

建议：初始化失败作为终态，不允许进入 HTTP 重试；对真实后端使用 fake IHttp 验证缺 Key、缺端点、非法端点和正常失败重试。未在真实客户端中触发崩溃。

### 严重：LibreTranslate 在请求提交后改写请求体

位置：`src/game/client/components/qmclient/translate/translate.cpp:573`、`:735`。

CreateHttpRequest 调用 Http.Run 后才调用 PostJson。HTTP 工作线程出队即读取请求类型和正文，PostJson 对这些字段的修改没有同队列锁同步，存在读写竞争，可能发出 GET 或错误正文。其他后端多数已遵循配置完成后再 Run 的顺序。

建议：公共 HTTP helper 分开「创建配置」与「提交」，LibreTranslate 完成 POST 后再提交。用 fake IHttp 在 Run 时捕获生产请求的 method/body，并验证真实解析成功、HTTP 错误和取消。

### 重要：手动翻译在聊天环形索引为零时失效

位置：`src/game/client/components/qmclient/translate/translate.cpp:1830`；聊天索引更新在 `src/game/client/components/chat.cpp:2090`。

m_CurrentLine 是环形索引，每次回绕到 0 都是有效聊天状态；当前大于零判断直接跳过整个搜索，报告无消息。建议根据初始化状态判断可用行，而不是把索引零当作空历史；行为测试覆盖回绕前、回绕时和之后的选择。

### 重要：手动翻译自身消息的过滤不生效

位置：`src/game/client/components/qmclient/translate/translate.cpp:1840`。

continue 只继续 m_aLocalIds 内层循环，随后仍给当前聊天行打分，所以本人或分身消息可能被手动 translate 命令选中。可见行按钮和自动入站另有正确过滤，行为不一致。

建议：复用聊天候选策略或先计算是否本地作者再跳过外层。覆盖本人、分身、普通玩家以及非法本地 ID。

### 重要：入站翻译没有计入出站占用的并发

位置：`src/game/client/components/qmclient/translate/translate.cpp:1883`、`:1933`、`:2151`。

出站路径检查两类任务总数，入站只检查 m_vJobs。因此先启动出站任务再收到入站消息，可以超过后端并发限制。默认限额为一的后端也可能同时运行两个请求。

建议：所有入口统一使用总占用计数；通过生产调度接口覆盖入站先到、出站先到、完成释放和用户手动配置。不要用测试内复制计数条件证明调度。

### 重要：自动出站请求失败后丢失原消息

位置：`src/game/client/components/qmclient/translate/translate.h:42`、`src/game/client/components/qmclient/translate/translate.cpp:2027`、`:2162`。

队列已满或未知后端时会发送原文，但有效后端发生 HTTP 错误、缺凭证或空译文时仅 Echo，任务删除。出站任务没有保存原文，也不区分自动翻译和显式翻译后发送，因此无法恢复。玩家按下发送后消息未发出，历史也没有经过正常发送路径记录原文。

建议：保存原文及触发方式，为自动出站失败建立明确恢复策略；显式翻译操作保留其单独语义。覆盖失败、空响应、重试成功、断线取消和防止重复发送。

### 重要：HTTP 没有总时限，慢速持续响应可占满翻译任务

位置：`src/game/client/components/qmclient/translate/translate.cpp:570`、`:899`、`:1483`；超时字段定义在 `src/engine/http.h:49`。

CTimeout 第二字段为总超时，当前均为零。30000 位于连接超时字段，并非注释所称的完整 LLM 响应 30 秒上限。持续高于最低速度的响应不会因低速检查退出，单并发后端会长期拒绝后续任务。

建议：各后端设置明确且符合用途的总时限，并给慢响应、连接失败、取消和任务释放补行为验证。

### 重要：现有翻译测试存在生产脱节，且已出现错误预期仍通过

位置：`src/test/translate_integration_test.cpp:25`、`:68`、`src/test/translate_llm_provider_test.cpp:11`、`src/test/translate_boundary_test.cpp:20`、`src/test/translate_safety_test.cpp:20`。

integration 文件重新实现并发策略，仍断言 Zhipu 默认 3，而生产代码已为 1；MyMemory 也没有被其后端默认矩阵覆盖。Provider 枚举测试是 EXPECT_EQ(0,0) 等自等断言；边界和安全测试多处只操作模拟行或本地常量。另有生产 ParseLlmResponseJson 被测试，但真实 LLM 后端又保留自己的 Chat/Responses 解析，解析测试并未约束运行中的所有解析路径。

建议：提取生产调度和解析接口，先补可失败的真实行为测试，随后删除实现镜像及其专属 helper。本次新增检测测试不复制生产算法，但不能弥补现有 HTTP 和组件协作测试缺口。

### 重要：Responses 多段译文只保留第一段

位置：`src/game/client/components/qmclient/translate/translate.cpp:1197`、`:1222`。

数组响应路径遇到第一个 output_text 就复制并返回，后续同一消息的文本片段不会保留；第一段为空时也不会继续寻找后续文本。建议由共享生产解析器合并完整文本并检查输出容量，以多段、空首段、非文本项和错误响应验证。

### 轻微：LLM 凭证提示检查全部 Provider，未检查当前选择

位置：`src/game/client/components/chat.cpp:361`。

只要任意其他 Provider 已配置 Key，当前 Provider 缺 Key 时菜单也不显示缺凭证警告。建议从统一 Provider 配置解析接口读取当前凭证；LibreTranslate 无 Key 警告也应区分允许匿名的自建服务。

## 审查问题后续修复

用户在同日要求立即修复全部 review 问题，已完成以下生产改动：

- 从客户端组件拆出 `translate_backend.*`，真实后端支持注入请求工厂；测试中的 fake 只提供 HTTP 传输状态和响应，不复制生产构造或解析逻辑。
- LLM 初始化失败、网络 ERROR/ABORTED 均不进入格式重试；只有已完成请求的 404/405 或 HTTP 200 HTML 响应允许 AUTO Chat→Responses 回退一次。
- 公共 HTTP helper 仅准备请求，所有后端在配置 method、body、headers 后提交。LibreTranslate 修复 POST 竞争，并使用具名 std::string 保持 JSON 正文生命周期。
- 普通翻译请求连接上限 10 秒、总上限 30 秒；LLM 连接上限 10 秒、总上限 60 秒。fake 请求测试直接观察生产填写的总时限；没有在真实网络上等待超时。
- `translate_jobs.*` 统一管理收发任务容量与释放。自动出站失败或空译文生成原文恢复内容；显式翻译发送失败不发送原文。重试占用同一槽位，成功只发送译文；reset/shutdown 清空并 Abort，不恢复旧连接消息。
- 历史选择独立为生产接口，合法处理环形索引零、最新消息优先及精确名字匹配优先，统一排除本人、分身、服务器、未初始化和已翻译的消息。
- 入站任务发布使用初始化状态、翻译 ID、shared response owner 三项匹配；任务完成后的出站 Echo 可能重用聊天缓冲，组件发布前再次核对 owner。
- 运行后端直接使用共享 Chat/Responses 解析。Responses 合并所有消息文本段、跳过空首段和非文本项；超过解析或聊天容量报告失败，不发布残缺译文。
- 当前 Provider 的 Key 解析由菜单和请求共用，包含已有环境变量回退。移除 LibreTranslate 必须有 Key 的菜单警告，允许匿名自建服务。
