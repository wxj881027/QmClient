# 撤回自动限帧与主循环等待

## 目标与边界

用户反馈近期优化后疑似锁到显示器刷新率，并伴随操作延迟、拖影、卡顿或撕裂。
只读调查后，用户确认撤掉 `402a4b89e` 新增的自动限帧与渲染限速等待，恢复此前行为。
本次不调整图形后端、协议、物理、预测或其他性能优化。

## 原因与修改

- `gfx_vsync` 默认仍是 0。问题之一是默认开启的 `qm_present_align`：关闭垂直同步且未设置渲染上限时，也会按显示器刷新率限帧，游戏中同样生效。
- 新增的 `RenderGateRate` 分支让整个主循环等待，下一轮输入和客户端更新被一起推迟；用户手动设置渲染上限时也受影响。
- 删除这两段逻辑和 `qm_present_align` 配置定义。恢复原有手动渲染限帧，保留显式更新频率、后台与菜单空闲节流，以及录制例外。
- 不新增功能或配置卡片；原有图形设置继续提供垂直同步与手动帧率上限。
- 版本从工作区现有的 `3.9.9` 更新为 `3.9.10`。
