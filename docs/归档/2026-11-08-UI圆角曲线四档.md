# UI 圆角曲线四档

## 目标

把 UI 圆角从"圆弧 / 连续曲率"两档，改成可选的四种曲线，并让连续曲率在数学上真的成立：
一共有 `原圆弧`、`超椭圆`、`五次贝塞尔`、`圆锥贝塞尔`、`苹果三段式` 五档，桌面端、移动端和几何兜底走同一套形状。

## 五档曲线

| 档位 | 曲线 | 端点曲率 | 定位 |
| --- | --- | --- | --- |
| 0 原圆弧 | 精确圆弧 | `1/R` | 旧外观。不沿边生长、不换曲线，等于改动前的渲染。 |
| 1 超椭圆 | p 范数，指数 2 → 4 | `0` | 真连续曲率。两端很平、中间急，圆角看起来最"紧"。 |
| 2 五次贝塞尔 | 6 控制点 | `0` | 真连续曲率。拟合了圆锥 W=1.2 的手感（外形偏差 0.6%），是默认档。 |
| 3 圆锥贝塞尔 | 有理二次，权重 0.7071 → 1.2 | `1/(2W²E)` | 保留既有手感。端点曲率压不到 0，只能算"更柔和"。 |
| 4 苹果连续曲率 | 三段三次贝塞尔（`UIBezierPath` 实测） | `0` | 档位 100% 就是 `UIBezierPath(roundedRect:cornerRadius:)` 的原路径：单侧足迹 `1.528665 r`、最贴角点 `0.41225 r`，控制点见下节。曲线沿两条直边外扩 `0.528665×强度`，角区判定跟着外扩。往下是按控制点线性插值到「三段 30° 圆弧」，**两个轴共用同一个标量**。 |

三次贝塞尔凑不出两端曲率同时为 0，五次才有足够自由度。

### 苹果连续曲率的控制点

归一化到 `r = 1`，角点在原点、两条直边沿 +x / +y，曲线从 `(1.528665, 0)` 走到 `(0, 1.528665)`。
`P0` 是起点，之后每段两个手柄加一个段末点；`P5..P9` 是 `P4..P0` 关于对角线的镜像。

| 段 | 控制点 | 满强度（`UIBezierPath` 实测） | 圆弧退化（三段 30°） |
| --- | --- | --- | --- |
| — | P0 | `(1.528665, 0.000000)` | `(1.000000, 0.000000)` |
| 1 | P1 / P2 / P3 | `(1.088493, 0)` / `(0.868407, 0)` / `(0.631494, 0.074911)` | `(0.824462, 0)` / `(0.652020, 0.046206)` / `(0.500000, 0.133975)` |
| 2 | P4 / P5 / P6 | `(0.372824, 0.169060)` / `(0.169060, 0.372824)` / `(0.074911, 0.631494)` | `(0.347980, 0.221744)` / `(0.221744, 0.347980)` / `(0.133975, 0.500000)` |
| 3 | P7 / P8 / P9 | `(0, 0.868407)` / `(0, 1.088493)` / `(0, 1.528665)` | `(0.046206, 0.652020)` / `(0, 0.824462)` / `(0, 1.000000)` |

来源：对 `UIBezierPath(roundedRect:cornerRadius:)` 的零像素误差反解（Liam Rosenfeld），与
CoreAnimation 的 `cornerCurveExpansionFactor = 1.528665` 一致。实测指标：最贴角点 `0.41225 r`，
转角分配 `17.4° / 52.3° / 20.3°`。

**足迹必须塞进短边半高**：`1 + 0.528665·s ≤ 短边半高 / r`。塞不下时只削强度这一个标量，
半径不缩、曲线不拉伸；分轴各钳一次就会把端帽拉成 `1.53:1` 的橄榄头，端头外凸就是这么来的。

## 连续曲率为什么会"变方"

90° 转弯、端点曲率归零、圆角沿边长度不变三者同时成立时，曲率峰值必然高于圆弧：

| 曲线（强度 1，未生长） | 接缝曲率 | 峰值曲率 | 45° 处外鼓 |
| --- | --- | --- | --- |
| 圆弧 | 1.00 | 1.00 | 0.707 |
| 圆锥 W=1.2 | 0.37 | 1.79 | 0.773 |
| 超椭圆 p=4 | 0.00 | 2.52 | 0.841 |
| 五次贝塞尔 | 0.00 | 1.67 | 0.772 |

（都除以原半径 R。峰值 2.5 倍时，圆角中间会出现肉眼可见的硬拐。）

所以补偿方式是**把圆角沿边拉长**：有效半径最多到原半径的 2.3 倍，峰值就能压回 1.1 左右。
拉长有上限，而"强度"只有在真拿到生长时才有意义——曲线的档位参数由**实际生长比例反解**：
目标半径 = `R × (1 + 1.3 × 强度)`，上限半径取"短边 × 上限比例"与原半径的较大者，
有效半径夹在两者之间，曲线强度 = `(有效半径 / R - 1) / 1.3`。

于是"扩不动"自动等于"退回圆弧"：胶囊（半径已经贴到短边一半）永远是胶囊，
短边很近的小控件也不会被强行压弯。

## 生长上限

| 元素 | 上限 |
| --- | --- |
| 普通控件 | 短边的 25% |
| 已经是胶囊的元素（半径 ≥ 短边 9/10） | 短边的 40%（实际用不到，它们没有生长空间） |

由此得到的实际效果是：**只有卡片、面板、聊天框这类大表面会变**；列表行、按钮、页签
（半径普遍 ≥ 短边 25%）保持经典圆弧。这是有意的层次设计，不是漏改。

## 胶囊端头三档

胶囊半径已经贴到短边一半，没有生长空间，连续曲率的"沿边生长"在胶囊上完全不生效，
所以端头单独给一个三档开关 `qm_ui_capsule_style`：

| 档位 | 效果 |
| --- | --- |
| 0 普通胶囊 | 正圆弧端头，等于改动前的胶囊 |
| 1 丝滑胶囊 | 端帽仍是精确正圆，直边靠近端帽的一段按回旋线把曲率从 0 升到 1/R |
| 2 苹果胶囊 | 端帽仍是精确正圆，直边按原生 iOS 胶囊实测的肩部提前 `0.4154 R` 起弯 |

丝滑档由着色器的 `SilkyCapsuleSdf` 实现，整块形状单独求距离，不再走通用圆角分支：

- **端帽**：仍是精确正圆（半径 = 短边一半），取它在 φ=18° 处到顶点的圆弧。
- **肩部**：直边最后 0.33R 的范围内，高度按 `R·(1 - Drop·u^Power)` 单调内收，端部比中段矮
  `R(1-cos18°) ≈ 4.9%R`；幂次 `Power = 2.169` 由「末端曲率恰好等于 1/R」解出。
- 曲率从 0 单调升到 1/R，没有曲率突变，也没有「鼓一下再退回来」的起伏——后者正是一切
  「先往外填再接回直边」做法的通病。

### 苹果胶囊（2026-11-15 修订）

端头**不是**把圆角曲线塞进端帽。对原生 iOS 胶囊做亚像素拟合（残差 < 0.5 px）得到的形状是：

| 量 | 值 | 含义 |
| --- | --- | --- |
| λ | `0.4154 R` | 直边在距切点多远开始起弯 |
| φ | `0.5976 rad`（34.24°） | 肩部与端帽的接点，从端帽顶点起算 |
| h₀ | `0.2591 R` | 直边侧贝塞尔手柄 |
| h₁ | `0.3102 R` | 端帽侧贝塞尔手柄 |

- 端帽是半径 = 短边一半的**真圆**，半径不缩、端帽不拉长；相对正圆胶囊的最大内收 `0.020 R`，
  向外越界 ≈ 0。
- 肩部端点与端帽切线 G1 相接，直边侧曲率从 0 起。直边不够长时 λ 与 φ 一起等比收窄，
  方盒退化成正圆。
- 反例（本次修掉的）：把「三段式圆角」整条曲线套在端帽上。端帽在短轴上没有空间容纳
  `0.528665 R` 的外扩，两个角的肩部会互相穿过中线，`|y| = R` 处挤出一条 `+0.078…+0.095 R`
  的唇边——也就是肉眼看到的「端头外凸」。实测该做法在 `|y| ≤ 0.93 R` 内与正圆胶囊差
  `≤ 0.002 R`，等于既没做出苹果的肩部，又多了外凸。

试过但没有采用的形态：

- **端帽整段换曲线**：端头不再是半圆，视觉变方，且必然外凸（见上）。
- **直边外鼓**（往外填 3%R 再退回）：边界先鼓后退，肉眼看就是起伏/凹坑。
- **端帽收窄 / 小帽**：端头外侧留台阶。
- **纯圆弧内收**：形变 ≤ 0.001%R，1 倍尺寸下和正圆弧完全重合，等于没做。
- **分轴独立钳制**（X/Y 各算一个混合系数）：端帽被拉成 `1.53:1` 的橄榄头，长短轴比例越
  极端越明显。

参考：iOS 灵动岛的胶囊同样是「曲率处处连续」的连续曲线（SwiftUI `Capsule(style: .continuous)`），
不是「直线 + 半圆」拼接。

模糊掩码的状态：五档曲线（含苹果连续曲率）都由 `RoundedCornerCurveDirection` 采样同一条曲线，
苹果档沿直边的外扩也一并参与，掩码和面板轮廓不会再错位。胶囊两档（丝滑 / 苹果）是例外——
它们只在着色器里改端头，掩码仍按正圆胶囊生成，那 ≤ 0.021 R 的差异不参与投影。

限制：只有**长边比短边超过 1.2 倍**的形状才吃这个参数——正圆（滑块圆点、单选按钮）
四个角本来就连续，不能被压成方圆。

## SDF 使用率（实测）

数据来源：真实客户端开启 `qm_perf_debug 1`，从客户端自带的结构化性能日志
（`dumps/QmClient_Perf/qm_perf_*.log`）里取 `perf/qm` 每秒记录。Vulkan 后端 / RTX 4060 Ti /
3840x2160 窗口化 / 设置页与服务器列表来回切换，每段采样 9–10 秒。

| 场景 | 采样秒 | SDF 绘制/秒 | 峰值/秒 | SDF 绘制/帧 | 批处理中断/秒 | 中断占比 |
| --- | --- | --- | --- | --- | --- | --- |
| 开始菜单 | 10 | 3086 | 10241 | 25.7 | 0.0 | 0.0% |
| 设置 · 图形页 | 10 | 2297 | 2299 | 19.1 | 0.0 | 0.0% |
| 服务器列表 · 互联网 | 10 | 2290 | 2299 | 19.1 | 0.0 | 0.0% |
| 设置 · 图形页（回访） | 9 | 2291 | 2299 | 19.1 | 0.0 | 0.0% |

合计 45 个采样秒、143408 次 SDF 圆角绘制、0 次批处理中断。参考帧率取设置页实测的 120 fps。

结论：

- **使用率是 100%**。只要后端支持 SDF，所有带圆角的表面都走 SDF；几何兜底只在没有 SDF
  管线的后端（老设备）才生效，本机 Vulkan 全程未触发。
- 稳定的 19 次/帧说明圆角绘制量由界面元素数决定，不随页面切换变化；开始菜单那一秒的
  10241 次峰值是入场动画把大量元素同时绘制出来的瞬时值。
- **批处理中断为 0**：SDF 绘制都发生在几何批次边界上，不会打断正在排队的顶点，
  所以"每个圆角单独一次绘制"在性能上没有想象中那么贵。

## 配置与界面

| 配置项 | 范围 | 默认 | 界面入口 |
| --- | --- | --- | --- |
| `qm_ui_corner_curve` | 0..4 | 2（五次贝塞尔） | 设置 → 图形 → 视觉 → 圆角曲线 |
| `qm_ui_corner_smoothing` | 0..100 | 40 | 同上，圆角强度 |
| `qm_ui_corner_smoothing_apple` | 0..100 | 100（= 苹果原版） | 同上，仅「苹果连续曲率」档出现 |
| `qm_ui_capsule_style` | 0..2 | 0（普通） | 同上，胶囊端头（普通 / 丝滑 / 苹果） |
| `qm_ui_capsule_apple_strength` | 0..100 | 100（= 苹果原版） | 同上，仅「苹果胶囊」档出现 |

苹果两档的 100% 就是实测原版曲线本身（0% 是正圆弧），所以默认给满。2026-11-15 之前
苹果档的默认是 60%，语义是「60% 的 0.881×扩边」；已存的旧值不会迁移，旧 `60` 现在只表示
60% 强度（比原版柔和），要看原版把滑杆拉到 100 或删掉配置项。

选「原圆弧」时强度与胶囊两行都不占位，数值保留不清空。未发布，不做旧值迁移；
本机已存的旧 `qm_ui_corner_curve 1`（旧语义 = 圆锥）会被解释成超椭圆。

## 顺带修掉的五个既有问题

| 问题 | 表现 | 修法 |
| --- | --- | --- |
| 曲线档位与「边框取渐变」共用同一参数分量 | 切换曲线会顺带打开/关闭边框渐变，彩虹光环那类描边会变色 | 档位独立占用形状参数的一个分量 |
| 超椭圆采样端点会算出 NaN | 几何兜底的最后一个采样点落在 `cos(π/2)` 的负极小值上 | 底数夹到 0 |
| 模糊层与面板的像素对齐不一致 | 面板对齐到物理像素、模糊掩码用原始亚像素矩形，差半个像素会漏出一条细白线，并随位置上下跳 | 掩码也用同一份对齐后的矩形 |
| 模糊遮罩在垂直中线合成两次 | 半透明面板的模糊底在中线叠了一遍，胶囊和分段控件上是一条贯穿的窄带；合成 alpha 为 1 时看不见，所以只在部分背景下暴露 | 遮罩从「两条各覆盖整高/整宽、重叠 1 像素」改回「中心 + 上下左右五块互不重叠」，边界仍用曲线感知半径 |
| 好友跟随彩虹光环的四角与卡片错位 | 光晕层用「矩形放大 + 半径加宽」做外扩；连续曲率下外扩曲线不是同一条曲线，换档位或强度时四角明显错位 | 改用形状外扩（距离场整体偏移），半径与卡片一致，任何档位都同心 |

## 验收与缺口

- 单元测试覆盖：胶囊与小控件退回圆弧、大表面按强度生长、生长被夹住时强度同步下降、
  四档端点重合、强度 0 精确等于圆弧、胶囊端头软化与正圆排除。
- 2026-11-15 追加的单元测试：苹果曲线满强度的足迹 `1.528665`、最贴角点 `0.41225`、
  沿两个轴单调；短边夹取只削强度（`8 px` 半径 / `20 px` 高时强度被夹到 `0.4729`，足迹正好
  等于 `10 px`）、半径不缩；胶囊半径贴到短边一半时强度归零。
- 静态合同测试覆盖：三份着色器携带同一条五次贝塞尔、同一套上限与反解公式，
  OpenGL 与 Vulkan 的圆角核心逐字符一致。
- 着色器校验：`glslangValidator` 对 OpenGL 与 Vulkan 两份都通过（Vulkan `-V --target-env
  vulkan1.2`，OpenGL `-G --aml`）。Metal 仍只做源码同步，需 macOS 实机。
- 真实 GPU 像素回归通过；实机窗口化截图确认四档差异可见、默认三项正确。
- 缺口（2026-11-15）：苹果胶囊与苹果圆角这一轮只做到源码 + 单元测试 + 着色器编译，
  没有实机截图。肩部相对正圆胶囊的内收只有 `0.020 R`（`56 px` 高的按钮约 `0.6 px`），
  要确认「与 iOS 原生一致」需要拿 4K 截图和原生截图逐像素比对。
- 翻译链已跑通：7 个界面文案与 4 条配置说明补齐 12 种语言，`validate` 零阻断。
- 顺带统一了 tooltip 尺寸：新增 `ui_token::tooltip`（字号 10 / 内边距 3 / 外边距 4 / 圆角 3 / 宽度 300），
  设置页与服务器列表的气泡改成同一套；`Corner curve` 那行原来是自绘控件没注册悬浮提示，已补。
- 缺口：Metal 只在源码层同步，需要 macOS 机器实测；tooltip 白线的修复依赖一次实机悬停确认。
- 缺口：胶囊两档新增的 `Capsule ends` / `Plain capsule` / `Silky capsule` 三条文案尚未进翻译链，
  当前显示英文源文。
