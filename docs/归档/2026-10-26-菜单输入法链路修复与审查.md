# 菜单输入法链路修复与审查

状态：修复与静态审查完成；已补充测试，未执行。未编译、未运行 gate、未启动客户端。

反馈场景：QmClient 3.4pre56、搜狗 15.12.0.2855，游戏聊天可正常输入，服务器浏览页筛选框等菜单输入框偶尔无法唤出输入法。审查基线为 `afbdd7858e31e8c30f22fd156ad07c26e98f888c`。下面的缺陷由源码和状态转换确认，尚未证明每项都在反馈者机器上触发。

审查沿服务器搜索/排除框的 `InputField → DoEditBox → CLineInput` 路径，向下检查 `CInput` 的 SDL/Windows IMM 事件与候选状态，向上检查 IME 管理器、聊天/控制台/编辑器交接及两种候选栏。共享输入控件中的同类提交和取消路径也纳入范围。

## 已修复问题

| 严重度 | 触发与影响 | 修复及共享影响面 |
| --- | --- | --- |
| 重要 | `UiForms.cpp` 的输入框包装层在渲染时重新读取原始 Enter；即使路由层已经消费该键，只要组合状态在绘制前结束，仍可能误失焦。数值选择器也有直接读取原始 Enter 的分支。 | 提交、提交结果和焦点边框统一使用已路由热键；删除包装层重复失焦逻辑。覆盖菜单搜索框、表单、数值框及共享数值选择器。 |
| 重要 | `input.h` 只用非空组合串判断组合状态；短暂空编辑事件会保留候选，却被当作不在组词，键盘可能进入页面逻辑。 | 有组合串或有效候选时均保持组合状态；候选确认仍由 IME 消费。保留空编辑事件不清候选的现有兼容处理。 |
| 重要 | `input.cpp` 的组合输入过滤同时拦截鼠标按键和滚轮，UI 无法收到切换焦点、取消组合或操作页面所需的输入。 | 组合输入期间继续过滤键盘按下，保留鼠标按下和滚轮；释放事件与窗口焦点切换过滤维持原行为。 |
| 重要 | `qm_ime_manager.h` 只记录是否需要文本输入，同帧从一个输入框切换到另一个时无法识别所属对象变化，旧组合会话可继续沿用。 | 记录活动输入框身份；切换对象时先停止旧会话，再启动新会话。每帧先验证输入框可见性、同步会话，再绘制候选；交接时清空候选弹窗缓存。 |
| 重要 | `ui.cpp` 仅在鼠标已是 active item 且仍按住时取消组合，点击当帧尚未进入该分支，短点击可能漏掉取消。 | 单行和多行输入框均在点击当帧取消组合；持续按住鼠标不重复重启会话。 |

定位入口：`src/game/client/QmUi/UiForms.cpp:53` 的提交结果；`src/engine/shared/qm_ime_policy.h:74` 的组合状态；`src/engine/client/input.cpp:824` 的按键过滤；`src/game/client/qm_ime_manager.h:71` 的会话交接；`src/game/client/ui.cpp:1978`、`:2112` 的单行/多行点击取消。行号对应本次修复。

## 链路审查结果

| 环节 | 静态审查结论与边界 |
| --- | --- |
| Windows/SDL 候选来源 | 保留 SDL 候选事件与 IMM 补读。原生候选缓冲区长度、偏移和 UTF-16 终止边界已有检查；本次未改解析、分页与选中项规则。 |
| 连续选词与迟到通知 | 保留提交后抑制迟到候选、下一轮组合恢复接收的处理。停止会话会清空组合/候选和本地原生通知队列；本次在输入框交接时复用这一入口。 |
| 键盘路由 | `CUi::OnInput` 先交给活动 `CLineInput`，未消费的 Enter 才成为提交热键。表单和数值选择器统一遵循这一结果；多行 Enter 仍由行输入插入换行。 |
| 鼠标路由 | 修复组合状态下鼠标事件丢失及短点击取消遗漏。菜单、聊天和控制台的活动输入处理位于通常游戏控制处理之前；未增加游戏按键直通。 |
| 输入框生命周期 | 所属对象比较只保存身份，不拥有或解引用旧指针；无焦点、离页、重新打开及输入框互换分别同步会话。相同输入框重复绘制不重复启动。 |
| 新旧候选栏 | `qm_new_ime` 仍只决定候选栏绘制方式；两种模式共用会话管理。可见性验证收敛到管理器，避免同一帧重复验证导致活动输入失效。 |
| 聊天/控制台/弹窗 | 保留所属组件存活和输入优先级判定。关闭界面或玩法覆盖层阻断输入时仍停止会话；没有把残留的活动输入标记视为有效界面。 |
| 编辑器与窗口焦点 | 编辑器持有输入管理权时管理器不干预；返回客户端时重建所属关系。SDL 窗口焦点恢复路径保留，不新增另一套窗口焦点重启机制。 |
| 性能与所有权 | 每帧增加常数次状态/指针比较；仅实际交接时停止、启动输入。未新增线程、后台轮询或逐帧堆分配；未做性能测量。 |

修复后，在上述范围内未发现其他已确认的阻断缺陷。此结论仅来自静态审查，不能替代搜狗实机兼容性验证。
