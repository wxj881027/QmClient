# 更新镜像回退与完整包发布

状态：历史实施与验证记录。2026-10-08 的恢复边界和低速下载修正见文末，旧记录中“官方可达即优先”已由该节替代。适用 Windows x64；其他平台保留 GitHub 手动下载，不安装 Windows 附件。

## 当前更新链路

更新主入口是独立 update_client.cpp 中的 CTClient 适配层，tclient.cpp 只保留生命周期调用；不使用旧 engine/client/updater.cpp 的逐文件下载。稳定通道读取 GitHub releases/latest，开发预览通道读取 releases?per_page=100；沿用现有版本比较、portable 标识与 Setup 安装标记。

发布信息优先于附件能力：ParseQmClientReleaseInfo 返回有效 Release 的版本、body 更新说明、是否比本地新和是否有当前构建类型可用的完整签名附件；缺 portable、Setup 或签名附件不会让元数据检查失败。有效同版本/旧版本显示已是最新版本，仍保留发布说明与包可用情况；有效新版本缺包时显示明确的不可下载提示、禁用自动下载，保留 GitHub 手动入口。已有严格 ParseQmClientUpdateRelease 安装入口继续要求匹配平台和完整签名附件，后续验签流程不放宽。预览信息入口选择最新有效发布，即使其包暂未上传；不会为了寻找可下载包而隐藏更新版本。HTML、缺必需发布字段、非法附件 URL 和类型错误仍会拒绝并换源。

元数据和安装包共用 update_sources.h 中的批准源配置，禁止客户端接受任意第三方域名或嵌套代理 URL。普通完整包优先 QmClient-windows.7z；portable 优先 QmClient-windows-portable.7z；安装版有完整 Setup 附件时使用 QmClient-Setup.exe。没有签名 7z 的旧 Release 继续使用签名 ZIP。不能删除旧发布中的 ZIP，也不能只改后缀伪装格式。

元数据顺序：先通过系统代理或直连请求 GitHub 官方 API；官方不可达或返回无效内容时，切换批准的镜像。镜像内部仍按最近成功节点、配置优先级和服务组去重排序，近期镜像成功不能抢占可用官方源。安装包在元数据通过后，并行探测官方与各批准镜像的 64 字节签名附件；官方可达时优先官方，即使镜像响应更快；官方不可达时按实际延迟选择可达镜像。代理解析和十秒探测传输分别计时，官方显式系统代理失败允许一次直连探测，但不能绕过 429/Retry-After 限流。未成功探测的官方源不作为盲目下载兜底。相同延迟保持最近成功/配置优先级顺序。小附件响应最快不等于大包吞吐最快，也不证明附件真实；每次完整下载仍需验签。gh-proxy.com、gh-proxy.org、cdn.gh-proxy.org 保守放入 gh-proxy 组；ghfast.top、ghproxy.net 在独立运营关系未确认前保守放入 ghproxy 组。同组域名不构成独立备用源。当前 gh-proxy.org 首页会重定向到 gh-proxy.com，进一步支持归入同组；ghfast.top/ghproxy.net 的独立运营关系仍未确认，不能承诺它们是两个独立服务。cdn 节点默认停用，能力位为零；重新验证 TLS 和相应资源后才可批准启用。

API 仅允许已验证的 gh-proxy 组；ghfast.top 和 ghproxy.net 只批准 Release/Raw。镜像 API 支持失效且官方也不可达时明确失败，不把 HTML 或缺字段响应显示成最新。无需 Token、第三方后端或远程镜像列表；不修改 GitHub 元数据格式，不接受元数据中的任意 mirror_download_url。

元数据每服务组一次，官方实际使用显式系统代理失败时额外尝试一次直连，最多三个请求；下载每服务组一次，官方同样允许一次显式代理到直连的回退，最多四批，每批四个附件请求。429 或带 Retry-After 的失败不换官方传输路由。失败后无固定延时密集重试；每组默认降级五分钟。429 支持秒数及 HTTP 日期 Retry-After，同组及官方在等待窗口内不重新请求，其他服务仍可尝试。不在玩家前台等待 Retry-After；全部候选不可用时提供重试及手动下载。

连接五秒；首字节十秒；连续无进展二十秒。小型元数据请求另有三十秒总上限，大包没有固定总时长。下载没有 Range 续传，每次换源重下，避免跨源拼接与 200 追加残片。每次换源使用独立临时目录；取消后旧请求不会覆盖新请求。重试次数受固定候选队列约束，正常仍有进展的大包不因总等待预算被中断。

GitHub 官方 API/Release 请求在 Windows 上自动读取当前用户的系统 HTTPS 代理、代理绕过列表和 PAC/DNS 自动发现；已有 HTTPS/ALL_PROXY 环境变量优先，保留 curl 的 NO_PROXY 行为。代理解析在后台作业完成，主线程最多等待八秒，超时继续请求；移交 HTTP 时重新起算首字节预算，避免代理解析耗尽十秒传输预算；取消后不再发布请求，作业不持有 HTTP/客户端指针。镜像不套用这个官方专用系统代理决策，仍遵循已有 curl 环境代理。未自动提供代理认证凭据。WinHTTP 的 PAC 执行不承诺八秒内结束，八秒是客户端不继续等待结果的预算；实际 PAC、企业认证代理和 WPAD 环境仍须人工验收。

HTTP 沿用 curl 的 HTTPS、最多四次重定向及状态错误处理。不向镜像发送认证 Header。正文要通过生产 JSON 解析、签名和哈希验证；200 HTML 不会安装。包、清单或签名任一网络失败会取消同批其他请求，然后换源；校验失败同样换源。磁盘准备失败直接报告错误。

## 弹窗与安装

专用 POPUP_QM_UPDATE 使用 Qm 新功能弹窗同类遮罩、卡片、共享按钮和滚动区；更新不再使用 AddWarning 的通用红框提示。启动页右侧客户端版本是入口，失败状态亦可点开。所有候选传输失败显示“网络错误”，无效 JSON/HTML、签名或哈希错误显示更新失败；均提供重试及 GitHub 手动下载。控制台 qm_update check 打开并检查，qm_update cancel 停止，qm_update status 输出可观察状态。

关闭或 ESC 只收起弹窗，下载继续；取消按钮终止检查、下载与后续换源。在线时不会强制打开菜单，待玩家打开菜单后呈现。安装就绪仍按退出安装，保留现有事务备份、回滚及用户 profile/storage.cfg 保护。Setup 沿用现有退出后的安装及卸载记录更新行为；不引入新的强制重启流程。

签名清单和包摘要签名使用已嵌入公钥的 Ed25519 验证。SHA-256/大小来自签名清单，不把代理提供的 hash 当真实性保证。缺失 GitHub asset digest 不阻塞；发布流程已有独立 sha256。7z 使用 sevenz-rust，逐文件检查路径、属性、重复大小写、大小、SHA-256、清单完整性，禁止链接、重解析点、未签名条目和 profile 数据。客户端只提取 updater 所在压缩块，完整解压在独立安装器执行。

已有签名机制继续复用，无需新增签名依赖。签名不防止代理延迟/冻结元数据，亦没有独立时间戳防回放机制；版本比较防止安装低于当前版本，但无法证明镜像列出了所有最新 Release。

## 维护镜像

修改 update_sources.h 的 BuiltinSources：prefix 必须是 HTTPS 下载前缀，group 表示同一或尚未证实独立的运营组，priority 数字越小越靠前，resources 标注 RELEASE/RAW/API，enabled=false 停用。停用或删除后 qm_update_recent_source 即便保存旧地址也不会授权它。最近成功记录保存在既有配置保存链中；降级状态仅当前进程保存。

维护者先用真实项目附件的小文件及 API 做有限验证，再批准能力；下载能力不能推导 API 能力。不得为了“修复网络”关闭 TLS 验证。若未来仅剩下载镜像，需另行生成稳定/预览静态 Release 索引并验证发布一致性；本次没有引入无人维护的远程列表或新后端。

## 独立模块与真实下载验收（2026-10-07 追加）

更新生命周期、控制台注册、检查、探测、下载、完整性验证和退出安装集中到 src/game/client/components/qmclient/update_client.cpp（约 800 行）；原 tclient.cpp 移出约 700 行，只保留 InitUpdateLifecycle、TickUpdateLifecycle、ShutdownUpdateLifecycle、RegisterUpdateCommands 调用。状态仍由原 CTClient 持有，公开入口和 UI 调用保持兼容，镜像/请求/探测/代理/解析策略继续由已有独立模块负责。docs/规格/大文件拆分方案.md 标为待评审且主要讨论卡片，本次采用功能边界和保持行为的原则，不把旧行数估算或目录粒度当强制架构。

HTTP 增加显式直连语义：Proxy("") 会设置空 CURLOPT_PROXY，未调用 Proxy 才继承环境代理；这也修复 PAC 返回 DIRECT 后仍可能继承环境代理的问题。CompletedStatusCode 允许已完成的失败请求输出 403/429 等状态；已取消的排队请求在初始化连接前结束，不占用网络连接。没有增加活跃 HTTP 每秒十次轮询：首次观察到的官方直连是持续低速，完整日志不支持“取消无响应”的推断，该试验性修改已撤回。

显式联网工具 qm-update-download-probe 链接生产 curl、系统代理作业、Release 解析器与 Rust 公钥验证接口。Python 入口只负责编排、保存证据和独立重读文件；批准镜像配置由原生工具输出，不在 Python 重复维护域名。所有产物在工作区 tmp/，不运行安装包或更改正式安装，不修改用户的系统代理设置。

运行入口（须已有 cryptography，仓库签名环境已安装）：

~~~powershell
cmd /c qmclient_scripts\cmake-windows.cmd --build cmake-build-update-reliability --target qm-update-download-probe -j 14
python -m qmclient_scripts.integration.update_download_local --probe cmake-build-update-reliability/qm-update-download-probe.exe
~~~

## 2026-10-08 更新恢复与低速下载修复

本节记录本轮初版恢复修复；最终分段下载、官方 100 KiB/s 慢源阈值、五秒窗口和镜像强制直连策略由 [GitHub 更新分段下载与慢源切换](../规格/2026-10-08-GitHub更新分段下载与慢源切换.md) 替代。保留下述初版验证及失败记录，最终交付结果见本节末尾追加说明。

本节替代上文关于“官方只要小签名可达便始终优先”的描述。检查实际 HTTPS 附件路径，不使用 ICMP ping 决定 GitHub 是否可下载：ping 不能证明 TLS、代理、重定向及 Release 附件正文可用。

下载探测先请求 64 字节签名，再对真实包做最多 256 KiB、八秒传输预算的内存前缀采样。每组最多一个探测候选；采样收到足够字节主动停止，不落盘、不续传或拼接到完整包。检查 ZIP/7z/EXE 魔数，拒绝 HTML。超时但已收到有效前缀的慢源可保留为备用；采样本身不证明真实性，完整包仍须原有签名、大小、哈希和清单校验。
