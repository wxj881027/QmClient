## 问题与处理

- 皮肤源包含 24 张纹理，旧路径每个渲染帧只允许推进一张，下一份已解码数据还会等待容器的周期扫描。现在在共享 1 ms 时间预算和现有 GPU 上传限额内连续推进；已完成解码的任务每次逻辑更新都能收尾。无加载任务时直接返回，正常队列已经包含全部加载项时跳过全表兜底扫描。
- 旧下载任务即使解码了有效缓存，也要等 HTTP 完成才发布。现在缓存读取与 PNG 预处理成功后先返回并发布；预览可用后再发起后台 HTTP 更新，网络完成后才进入解码队列，并限制后台解码数量。缓存缺失或损坏仍走原有下载回退，304 缺少可用缓存时无条件重试。
- F5 扫描原来只更新修改时间，同名文件的纹理不会重新加载。现在比较来源类型、存储路径和修改时间；变更使已请求的皮肤回到待加载状态。同名文件按存储优先级取第一份，本地皮肤优先于下载缓存。
- 重载和后台更新期间继续使用已发布的纹理，成功后完整替换并通知受管理预览；失败保留旧预览，下次刷新可按已发布的来源版本重新请求。取消、刷新和回收释放未完成的上传数据与后台请求；回收也计入重载期间保留的旧纹理。
- 文件修改时间随解码结果传递到发布阶段，避免跨帧上传时重新采样文件时间，掩盖期间发生的新修改。

下载任务及其像素所有权移入 `src/game/client/components/qmclient/skin_source_job.*`，生产实现可通过隔离存储和假 HTTP 传输直接测试。未改变皮肤 PNG 格式、配置项、网络协议或版本号。
