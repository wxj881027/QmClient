# 设置页签译文悬空引用与崩溃后卡死修复

## 现场证据

两份 2026-10-24 的 hang 文本报告均记录离线、无地图，以及约 10.4 秒没有心跳。只提供了 20:53:39 的 dump，以下原始异常结论仅适用于该 dump。

- 主线程停在 `exchndl → StackWalk64 → DbgHelp → symsrv → wininet!InternetReadFile`，正在等待符号下载。
- 从异常处理栈中的 `EXCEPTION_POINTERS` 恢复出原始访问违例：`0xC0000005`，指令位置 `DDNet+0x1DB6B0`，读取地址 `0x138D70ADFC0`。
- 找到了与 dump 匹配的原版 EXE。时间戳为 `0x6AD365CF`，PDB GUID 为 `011D5E0B-3E4A-4A69-887F-5C983FAE6961`，age 为 `278`。当前本地 PDB 的 age 为 `334`，不能用于直接给原始偏移分配源码行号。
- 使用匹配 EXE 恢复的调用栈、原版指令和当前实现对照，定位到 TClient 页签绘制中的字符串读取。原版页签数组 `DDNet+0x1179880` 的第一项正是 `0x138D70ADFC0`；相邻缓存语言名为 `languages/simplified_chinese.txt`。

## 原因与修改

TClient 页签长期缓存 `Localize()` 返回的指针，以语言文件名判断是否需要更新。语言库重载会释放字符串堆。同路径重新加载，或在未访问该页时切换语言后又切回原语言，都会使缓存检查遗漏已经失效的指针。外观、素材页签使用了同样的缓存方式。

三组页签改为在每次绘制时从当前语言库取值，不跨帧保存译文指针。TClient 原先附带的局部语言缓存失效调用随旧缓存移除，语言变更仍走现有 `HandleLanguageChanged()` 与 `InvalidateSettingsRuntimeCaches()`。

原始崩溃后，自有异常过滤器先写报告，再调用此前保存的外部过滤器。该外部过滤器进入在线符号解析，主线程再次阻塞，随后产生 hang 报告。修改后，自有过滤器完成报告与确认标记后返回 `EXCEPTION_EXECUTE_HANDLER`，结束异常处理。
