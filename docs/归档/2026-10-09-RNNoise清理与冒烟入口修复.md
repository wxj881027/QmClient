# RNNoise 构建清理、全局数据优化与冒烟入口修复

状态：实现及本地验证完成。创建日期：2026-10-09。源码基线：`9a51b6bae75a6a073d14cf46319d9973de1e164f` 加本次未提交修改。

## 行为与实现

实时采集原本已仅执行麦克风增益，RNNoise 不再进入音频链路，但构建仍保留模型数据。本次移除 RNNoise 源码注册、头文件目录、编译宏、废弃状态指针和仅服务旧降噪入口的测试。第三方 vendored 源码仍保留，目录删除被工具审批拒绝；它已不参与构建，最终 PDB 无 RNNoise 模型符号。

旧配置字段与取值范围保留兼容性；UI 移除 RNNoise 选项、失实的回退提示及对应高度分支，历史模式值 2 按关闭展示。二维码未修改。新增采集行为测试覆盖历史模式值、重复调用、空输入及饱和输出；布局回归覆盖窄、中、宽视口。

MSVC 优化配置通过默认开启的 `QM_MSVC_OPTIMIZE_GLOBAL_DATA` 使用 `/Gw`。同一源码先关闭后开启此选项，使用主目录已有缓存串行构建。

| 版本 | EXE 字节数 | 相对上一阶段减少 |
| --- | ---: | ---: |
| 原始构建 | 18,807,808 | — |
| 移除 RNNoise，/Gw 关闭 | 15,246,848 | 3,560,960 |

最终减少 3,581,440 字节（19.04%），约 15.23 MB / 14.52 MiB。重排 include 后再次构建，大小保持一致。体积数据与区段对照见 `tmp/exe-size-rnnoise-gw/size-comparison.json`。

## 进程测试入口

此前普通 Windows 构建传入隔离 runner 后，直到客户端存储初始化才因不支持 `QMCLIENT_TEST_STORAGE_ROOT` 失败。本次新增共享 `process_build.py`，通用进程环境、启动呈现和实时名单冒烟在启动前选择同源码、配置、生成器与编译器的隔离缓存。已有合适缓存优先复用；否则采用输入目录旁的 `<build-dir>-process-tests`，保持原缓存存储模式。隔离构建启用 DEV 和测试存储，功能开关沿用输入缓存，通过 Windows 封装入口增量构建后再启动。构建失败、来源或存储模式不匹配不会退回旧 exe。便携版资源与存储专用测试保留专用便携模式。
