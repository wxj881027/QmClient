## 发现与实现

| 问题 | 改进及可观察证据 |
| --- | --- |
| 原生过滤未命中或 case SkipWithError 不能靠退出码证明成功 | 先枚举，再校验命中集合、原始重复、skip/error、迭代和字段；有子进程失败测试 |
| 字体面/Library 未释放，准备失败可能留下旧 Ready，缺字被跳过仍按 256 字形报吞吐 | 每次重复初始化并按依赖顺序释放，验证字体和字符覆盖；任一渲染失败报告原生错误 |
| GlyphColdPaint 名字把重复光栅化当完整冷启动，数据位置依赖 cwd | 改为 GlyphRasterizeBatch，源码路径加载字体，明确计时不含文件加载、应用缓存和 GPU |
| presence 预热只触达第一帧，后续可能退出；idle 实际混入活跃轨道 | 逐帧 BeginFrame/ResolvePresence/EndFrame，idle/presence 检查零活跃轨道，并预填布局 |
| 固定目标弹簧用例不能表达持续目标改变；全局 motion 配置未恢复 | 目标每帧交替且与布局目标一致；fixture 保存/恢复 motion，避免交错重复相互污染 |
| LayoutCacheChurn 固定一组键，4096 键大部分测成命中；夹具初始化无关 presence | 分成预填固定键命中和两组键交替 churn，只准备对应生产模块，运行时键集有界 |
| 内联字体分类的常量输入可能被折叠；格式化仅在循环后观察首字节 | 输入逃逸/内存屏障、每次输出观察；保持直接调用生产实现 |
| Huffman/快照只计时，不检查完整工作，错误也可能形成漂亮数字 | 准备时真实往返校验，计时检查返回值，末尾核对还原输出；网络 items 与 bytes 分开 |
| 无统一来源/数据留存，易覆盖基线或把 CV aggregate 当 ns | 运行入口保存 command/raw/summary/run；检查重复索引，原始耗时统一 ns，CV 为无量纲 |
| 本机 Windows JSON 中文主机名是 CP936；dry-run 零 CPU 时间会生成 Infinity 吞吐 | UTF-8 优先、本机 ANSI 回退并记录；保留原始字节；smoke 摘要不输出性能指标 |

[统一入口与说明](../../qmclient_scripts/benchmark/README.md)；[运行实现](../../qmclient_scripts/benchmark/run.py) 与 [结果校验](../../qmclient_scripts/benchmark/results.py)。

已有 `qm_anim_benchmark.cpp` 中其他任务的卡片测量用例全部保留；编辑前副本位于 `tmp/benchmark-research/before/`。其他生产/UI/翻译改动未回退或并入本次修改。

## 实际验证

- Windows Release `qm-benchmarks` 构建成功，均经 `qmclient_scripts/cmake-windows.cmd`，同一 build 的构建、运行与其他已观察任务串行安排。
- 18 项 Python 单元测试 + 12 项真实 fake 子进程集成测试，共 30 项通过。测试生产摘要接口和进程边界，不读源码证明行为。覆盖空过滤、原生错误/跳过、非零退出、超时、JSON 缺失/畸形、重复缺失/冲突、单位归一、数值溢出、标签漂移、Windows 编码、smoke 含义及已存在目录保护。
- 真实 benchmark 全量 smoke：37 个 case 通过。日志及摘要在 `tmp/benchmark-research/smoke-final/`。
- 全量测量：37 个 case × 5 次重复 = 185 个原始测量样本；min time 0.2 秒、warmup 0.05 秒、原生随机交错。来源在运行期间稳定，结果在 `tmp/benchmark-research/measured/`。
- 高波动过滤测量：3 个 case × 7 次 = 21 个样本；min time 1 秒、warmup 0.2 秒，结果在 `tmp/benchmark-research/stability/`。
- 4096 键局部固定 CPU 对照：1 个 case × 7 次；与长测量相同计时参数，仅本次调用 shell/继承子进程 affinity mask 0x1，结束恢复；结果与 mask 在 `tmp/benchmark-research/affinity/`。
- ruff check/format、本轮 6 个 C++ 文件 clang-format 与差异空白检查通过。
- quick gate 实际执行，但失败于其他工作区改动 `src/engine/client/text.cpp:1220` 和 `src/game/client/components/qmclient/menus_qmclient.cpp:5151` 的格式；10 项通过、1 项失败、无 skip。不修改它们或降低门禁；结果为 `tmp/benchmark-research/quick-gate-utf8.json`。首次 gate 的本机 GBK 输出异常通过本次调用设置 Python UTF-8 解决，未改 gate。

## 样本可信度

以下为本机测量波动，不是生产性能收益。CV = 重复耗时的样本标准差/均值；不同过滤集合、采集时序和亲和性使这几组不能用来推导严格 A/B 改善。

| Case | 全量短测 CPU CV | 延长测量 CPU CV | 固定单 CPU 单 case 的 CPU CV |
| --- | --- | --- | --- |
| FontCategoryClassify | 25.8% | 3.28% | 未测 |
| LayoutCacheHits/256 | 40.0% | 3.12% | 未测 |
| LayoutCacheHits/4096 | 35.7% | 28.58% | 2.71% |

因此 `MEASURED` 只表示有效采样完成。当前环境的大规模缓存 case 对调度/采集条件敏感，不能默认设 5% 等全仓统一阻断阈值；先固定实际 case 和测量条件，再用匹配基线评估回退。修改前结果在 `tmp/benchmark-research/before.json`，但场景语义修正的用例不能直接与其计算速度提升；生产实现未改，本轮不宣称客户端性能提高。

## 未覆盖与后续

未运行 Linux/macOS、GPU 或玩家交互端到端；未新增 line/function/branch coverage 报告。当前 37 个注册 case 不能代表全部热路径覆盖：Huffman 只有固定 16 KiB 分布，snapshot 只有全部字段 +1，未覆盖未变化/部分变化/新增删除的性能矩阵；文本和字形也仅代表所列输入。后续按真实优化任务扩展对应输入和行为检查，再建立同环境基线；现有 HTML 场景诊断工具继续保留。

后续 gate 的显式性能入口或回退比较应消费当前原始结果和来源，不将 MEASURED、测试数量、case 数量或单次耗时当完整性能通过。
