# 启动窗口呈现与加载页字体修复

状态：字体回归已由真实渲染验证；窗口生命周期修正已构建并通过启动冒烟，用户所用截图软件的最终验收待完成。
日期：2026-09-30

## 原因与改动

加载页在 CTClient::OnInit 之前绘制，而自定义中文字体原先在该组件初始化时才应用。修复前隔离客户端中，配置 Noto Sans SC / 中文字重 400，第一枚实际光栅化中文字形却使用 900；配置 Source Han Sans SC，第一枚字形仍使用 Noto Sans SC。

字体文件加载、语言字体、自定义拉丁/中文/符号面与字重现在在 LoadFonts 返回前统一应用，字体重载复用同一入口。删除 CTClient 的晚期重复应用。中文字体角色或语言回退面变化会重新计算可变轴；独立中文面与语言中文回退面使用中文字重，共用物理字体面时保留拉丁字重优先规则。诊断仅在 qm_graphics_trace 开启时记录实际首次光栅化字形的字体面与 FreeType 轴坐标。

窗口历史中的相关改动是 dd704b3050（2026-09-17，隐藏创建、加载帧后显示）与 c34e1dd90c（2026-09-23，显示入口追加 Restore/Raise）。本轮将 Windows OpenGL 恢复可见创建流程；其他后端保留隐藏创建，首个有效后缓冲准备好后显示再交换帧。加载路径和主循环兜底共用首次显示入口；后台渲染关闭也能进入可见主循环。显示函数不再无条件恢复最小化窗口或请求焦点。

Windows OpenGL 恢复可见创建意味着初始化期间可能出现原来的初始清屏；不能同时宣称已经保持隐藏启动的防空帧效果。窗口改动针对已定位的生命周期变化，尚未证实它就是用户截图问题的全部根因。
