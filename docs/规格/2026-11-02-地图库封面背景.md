# 地图库封面背景

## 目标

地图库（ESC 菜单 → Call vote → Map）的每个地图条目、以及选中后展开的详情条，都改用该地图自己的封面作为背景。封面尾部向右参差渐隐到没有，形成有层次的尾巴，而不是一条平直的渐变或硬边。

封面来自 DDNet 官方地图缩略图，由客户端按需下载并在本地缓存，同一张图只需下载一次。

## 数据来源

`https://ddnet.org/releases/maps.json` 的每一项已经带有官方缩略图地址：

```json
{
  "name": "Kidou",
  "thumbnail": "https://ddnet.org/ranks/maps/Kidou.png",
  "...": "..."
}
```

- 目录解析时把 `thumbnail` 存进 `QmVoteMaps::SMap::m_Thumbnail`；服务器投票选项合并出来的条目可能没有该字段，此时不显示封面。
- 只有 `https://ddnet.org/ranks/maps/<文件名>.png` 形式的地址会被接受，避免把目录数据里的任意 URL 变成下载行为。

## 本地缓存

- 目录：`qmclient/mapcovers/`（`IStorage::TYPE_SAVE`），创建于首次使用。
- 文件名：`cover_<官方文件>.png`，与官方地址末段一致，便于人工核对；加 `cover_` 前缀避免与 Windows 设备名冲突。
- 下载通过 `IHttpRequest::WriteToFileAndMemory` + `ValidateBeforeOverwrite(true)`：先写临时文件，确认响应是合法 PNG 后才由 `OnValidation(true)` 落到缓存路径；非法响应的临时文件会被删除。
- 缓存文件是解码的输入，不做过期时间：地图缩略图由官方按地图更新，客户端在缓存被判定损坏时删除并重新下载即可。

## 合成与绘制

缓存命中或下载完成后，在工作线程里完成解码、缩放与遮罩，主线程只做纹理上传，避免菜单帧里出现解码卡顿。

1. **裁切**：按「填满目标矩形、居中裁切」缩放，保留缩略图中段。
2. **压暗**：RGB 乘以固定系数（默认 `0.40`），保证列表文字压在封面上仍然可读。
3. **尾部渐隐**：遮罩在归一化 x 的 `[0.36, 0.80]` 区间渐隐到 0；三档频率的 value noise 错切渐隐边界，第二层以更靠后的起点、70% 峰值叠加，得到「参差 + 分层」的尾巴。噪声种子取自封面 URL，同一张地图的行条目与详情条走向一致。
4. **圆角**：左侧圆角 4px（输出像素），与列表行的选中底色圆角贴合。
5. 输出固定为 RGBA 纹理；绘制时用纹理 alpha 完成渐隐，不再额外做混合遮罩，因此全部渲染后端行为一致。

纹理按 `(URL, 目标像素尺寸)` 缓存：

- 目标尺寸按 UI 矩形的物理像素计算（`1 / Ui()->PixelSize()`），但最多放大到逻辑尺寸的 2 倍、宽度上限 1280、高度上限 256，控制纹理内存。
- 纹理总数上限 40，按最近使用时间淘汰并释放 GPU 纹理。
- 新纹理 0.18 秒淡入，避免滚动时突然出现。

## 渲染接线

- 行条目：列表条的选中/悬停底色改由地图库自己绘制（和原来同样的颜色与 alpha），顺序是封面 → 选中/悬停底色 → 左侧选中竖条 → 图标与文字；列表控件只保留命中测试与滚动。
- 详情条：先画封面，再画原有的半透明底色与描边，文字照原样叠在上面。
- 打开页面时每帧最多启动 2 个下载、4 个合成任务、上传 2 张纹理，其余任务排队；可见行以外不请求。

## 生命周期

- 离开地图库页面、关闭 ESC 菜单、连接状态变化时 `Release()`：取消排队与进行中的下载/任务，保留磁盘缓存与已生成的纹理。
- `CMenus::OnShutdown` 里 `Shutdown(Graphics())` 释放全部纹理（此时图形接口仍存活）。
- 窗口尺寸变化后目标尺寸变化会生成新的纹理，旧纹理按 LRU 自然淘汰；不做额外重建。

## 测试

- `src/test/unit/qmclient/ui/qm_map_cover_art_test.cpp`：URL 白名单、缓存文件名、尾部渐隐的端点/确定性/参差程度、合成尺寸与压暗、居中裁切、异常输入、PNG 解码到合成的闭环。
- `src/test/unit/qmclient/ui/vote_map_library_test.cpp`：目录解析保留 `thumbnail`，缺失时为空。

视觉验收仍按项目规则用真实窗口截图进行；本方案不引入新的配置项，也不改变地图投票、目录刷新与详情请求的既有行为。
