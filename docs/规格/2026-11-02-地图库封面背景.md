# 地图库封面图

## 目标

地图库（ESC 菜单 → Call vote → Map）的每个地图条目、以及选中后展开的详情条，都显示该地图自己的封面：左侧是可辨认的地图缩略图，右侧接一段参差、分层的拖尾渐隐到没有。

封面来自 DDNet 官方地图缩略图，由客户端按需下载并在本地缓存，同一张图只需下载一次。

## 为什么不是整行背景

第一版把封面拉伸铺满整行作为背景。列表行只有二三十像素高、一屏一千多像素宽，等比铺满等于把 16:10 的缩略图横着裁成一条极窄横条：每行最后只剩缩略图里的一条色带，既认不出是哪张地图，又因为压暗和整体偏色看起来像一团糊。

现在改为「左侧缩略图 + 右侧拖尾」：缩略图按正常比例缩放，玩家能直接看出地图内容；拖尾沿用封面右边缘的像素向外拖出并渐隐，保留原来的参差尾巴效果，同时不遮挡条目文字。

## 数据来源

`https://ddnet.org/releases/maps.json` 的每一项已经带有官方缩略图地址：

```json
{
  "name": "Kidou",
  "thumbnail": "https://ddnet.org/ranks/maps/Kidou.png",
  "...": "..."
}
```

- 目录解析时把 `thumbnail` 存进 `QmVoteMaps::SMap::m_Thumbnail`；服务器投票选项合并出来的条目可能没有该字段，此时不显示封面。
- 只有 `https://ddnet.org/ranks/maps/<文件名>.png` 形式的地址会被接受，避免把目录数据里的任意 URL 变成下载行为。

## 本地缓存

- 目录：`qmclient/mapcovers/`（`IStorage::TYPE_SAVE`），创建于首次使用。
- 文件名：`cover_<官方文件>.png`，与官方地址末段一致，便于人工核对；加 `cover_` 前缀避免与 Windows 设备名冲突。
- 下载通过 `IHttpRequest::WriteToFileAndMemory` + `ValidateBeforeOverwrite(true)`：先写临时文件，确认响应是合法 PNG 后才由 `OnValidation(true)` 落到缓存路径；非法响应的临时文件会被删除。
- 缓存文件不设过期时间：地图缩略图由官方按地图更新，客户端在缓存被判定损坏时删除并重新下载即可。

## 合成与绘制

缓存命中或下载完成后，在工作线程里完成解码、缩放与拖尾合成，主线程只做纹理上传，避免菜单帧里出现解码卡顿。

1. **缩略图**：在输出宽度的左侧 69% 里按目标高度等比缩放并居中裁切，保留原图比例。
2. **压暗**：RGB 乘固定系数（列表行 0.84，详情条 0.88），和深色面板衔接，同时保证缩略图仍然清楚。
3. **拖尾**：右侧 31% 宽度采样缩略图最右边缘的列，缓慢向内扩展；三层不同长度、不同相位的噪声错切叠加渐隐，得到「参差 + 分层」的尾巴。噪声种子取自封面 URL，同一张地图的行与详情条走向一致。
4. **圆角**：缩略图左侧两角 7/9 输出像素圆角，右侧拖尾已是透明，不需要额外遮罩。
5. 输出固定为 RGBA 纹理，绘制时纹理 alpha 就是最终覆盖率。

纹理按「地图 + 用途」缓存，尺寸固定、不随窗口宽度和滚动条动画变化：

- 列表行：167×72；详情条：278×120。
- 绘制时缩放到行高/详情条高度，行高从 24 提到 32（UI 单位），缩略图在绘制尺寸下约 45×30 UI。
- 纹理上限 192 张，按最近使用淘汰并释放 GPU 纹理；每帧最多 6 个合成任务、4 次上传、2 个并发下载、8 次缓存读。
- 页面打开时视口上下各预取一小段（向上 8 行、向下 12 行），滚动时行一出现就直接有封面。

旧版按目标像素尺寸缓存的做法会在窗口或滚动条变化时不断产生新尺寸，来回滚动会反复重合成；固定的「用途」尺寸消除了这类抖动。

## 渲染接线

- 列表行：行内顺序为「收藏星标 → 完成标记 → 封面缩略图 → 地图名」，选中/悬停底色由地图库自己绘制，封面压在底色之上、文字之下。
- 详情条：左侧放选中地图的封面缩略图（高度随详情条自适应），右侧依次是名称、分类/作者/日期与分数统计。

## 生命周期

- 离开地图库页面、关闭 ESC 菜单、连接状态变化时 `Release()`：取消排队与进行中的下载/任务，保留磁盘缓存与已生成的纹理。
- `CMenus::OnShutdown` 里 `Shutdown(Graphics())` 释放全部纹理（此时图形接口仍存活）。
- 窗口尺寸变化不影响纹理尺寸，不需要重建。
