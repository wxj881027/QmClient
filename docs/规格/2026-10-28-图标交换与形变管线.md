# 图标交换与形变管线

状态：实现完成，单测通过，客户端视觉已验收（设置卡片折叠箭头、密码框眼睛、战争列表排序箭头、绑定下拉箭头）。本文只描述「同一位置 A↔B 图标切换」这一条管线，不涉及图标系统的其它部分。

## 玩家行为

- 设置 → 图像 → 图标 新增「密码图标动画」分段控件：`淡化` / `形变`，对应 `qm_ui_password_icon_style`（0=淡化，1=形变，默认 1）。
- 密码类输入框统一带眼睛按钮，`ui_widget::PasswordField` 一处定义：Gores 主号/分身、翻译页 8 个 API Key、Spotify `sp_dc`、语音房间密码、标题赞助码。
- 设置卡片标题区的折叠箭头点按后旋转 180°，0.26s `EASE_IN_OUT`，与卡片高度动画同拍；同一卡组里各卡片的箭头互不联动。
- 关闭动效（`qm_ui_motion_level 0`）时全部瞬时切换：补间与弹簧两条驱动同语义，都会直接落到目标并停掉旧轨道。

## 硬约束：纹理边长必须按物理像素取

QmUi 画在虚拟分辨率上（`CUi::Screen()` 高 = `600 / qm_ui_scale`），到物理像素还有一个倍率；字体由 FreeType 按物理像素光栅化（`ActualSize = FontSize × FakeToScreen`），所以字形永远锐利。用贴图当图标时，纹理边长必须乘 `1 / CUi::PixelSize()`：

```cpp
const float PhysicalScale = qm_password_icon::ResolvePhysicalScale(Ctx.m_pUi->PixelSize());
const int Pixels = qm_password_icon::ResolveFrameTexturePixels(Side, PhysicalScale);
// quad 尺寸仍用 UI 单位，位置对齐物理像素网格
const float DrawX = std::round((Rect.x + (Rect.w - Side) * 0.5f) * PhysicalScale) / PhysicalScale;
```

同一帧的实测（1266 高窗口 → 2.11 倍物理缩放，目标边长 30px）：

| 来源 | 峰值 | 实心像素 | 边缘过渡 | 墨量 |
|---|---|---|---|---|
| 静止态字形 | 255 | 42 | 48 | 64.9 |
| 帧条：按物理像素取 30px | 255 | 36 | 58 | 63.3 |
| 帧条：按 UI 单位取 14px 再被 GPU 放大 | 220 | **0** | 170 | 63.1 |

第三行「实心像素 0 个」就是「动画里图标发糊发白」的全部原因：没有任何一处达到不透明的白。换档位、加锐化都改不动它，因为放大发生在 GPU 采样阶段。

## 管线三段

1. **离线烘焙**：`qmclient_scripts/qm_build_password_icon_frames.py` 从随包 Phosphor TTF 抽轮廓（fontTools），按三种模式生成 24 帧 × 64px 的横向帧条：
   - `semantic`：拓扑变化的对（eye ↔ eye-slash），按语义分解（瞳孔缩到零、斜杠按线长生长）；
   - `rotate`：同形状旋转（chevron），0°→180° 逐帧；
   - `pair`：轮廓配对形变（play ↔ pause）。**配对必须按界标分段（边对边、角对角），不能按周长均匀重采样**——两端形状边长比例不同，周长对齐会把短边映到长边上，中间帧的弦来回拧（2026-10-29 实翻车：线条歪歪扭扭）。play 沿画布中线剪成左右块：左块界标 = [左上, 左下, 切口下, 切口上]，右块 = [切口上, 切口下, 顶点, 顶点]（顶点重复表示零长弧，插值中顶点展开成杠的外缘），与杠的 [左上, 左下, 右下, 右上] 逐段对应，每段独立均匀采样后逐点插值。
   - `cross-face`：跨字面配对（star 收藏点亮，描边 ↔ Fill 实心）。两端同码位、外环形状一致，Fill 轮廓**绕向相反**（CW vs CCW），必须先反转成同向再配对，否则顶点插值中途出现自交蝴蝶结；内孔对称收缩到孔质心闭合（t=1 零面积，非零环绕下整星填实）。界标识别不能逐点找局部极值（字体曲率抖动会给出 18 个假尖顶）——「到心距离」先循环移动平均（窗口 ~n/18）再找峰得 5 个尖顶，凹谷在相邻尖顶的索引区间取原始距离最小点；两端界标序列还要按极角序列找最优旋转对齐（两端轮廓起点索引不同，不对齐就会跨角扭转）。
   纹理是上下两半：上=填充，下=描边（与 `QmGrowGlyphOutline` 同算法的圆盘外扩，半径按字号分级）。

   **画布共心规则（play/pause 引出）**：Phosphor 的 play 与 pause 墨迹中心不重合（play 偏右 96 单位），而运行时把帧条画在图标盒中心、静止态字形由渲染器按墨迹宽度居中。所以轮廓对烘焙前必须各自按墨迹中心平移到原点，端点才与静止态逐像素对齐（实测首末帧与字形差 ≤42px、最大差 32/255 的边缘噪声）。新增非对称字形对时都要遵守。
2. **运行时**：`ui_widget::DrawIconSwap(Ctx, Rect, Pair, FontSize, Progress, Color)`。有资产 → 按 `Progress` 取帧、先描边后填充；无资产（Fill 字重）→ 交叉淡化（smoothstep + 0.90 反向缩放）。
3. **触发**：调用方算 `Progress` 并决定「画帧条还是画静止态字形」。这两件事已经收进 `ui_widget`：
   - `ResolveIconSwapProgress(Ctx, NodeKey, Pair, Target, &Active, Seconds, AutoSpring)` 推进轨道。内部一律按 `Ctx.m_pAnim != nullptr ? Ctx.m_pAnim : Ctx.m_pUi->QmAnimationRuntime()` 取运行时（设置页内容趟 `m_pAnim` 恒空），并在 `AnimationsBlocked()` 的趟里只读不推。
   - `ResolveIconSwapBinding(...)` 把两条静止态字形 + 进度打包成 `SIconSwapBinding`，`DrawIconSwapBinding` 按绑定绘制：轨道活跃走 `DrawIconSwap`，静止走 `DrawQmIcon`。
   - 按钮托管的图标（`DoButton_QmIcon`）传 `SIconButtonIconDraw{&DrawIconSwapBinding, &Binding}`，按钮底色/hover/命中不变，图标换成绑定绘制。

资产命名：`qmclient/ui/<pair>_swap_<weight>.png`；密码对沿用历史名 `password_icon_<weight>.png`。字重覆盖 light/regular/bold，Fill 跳过。

## 验证记录（play/pause、play/stop、plus/minus）

- 端点保真：三个 pair 的首/末帧 vs 直接光栅化的字形逐像素差分，全部落在 8–56px、最大差 32–79/255（抗锯齿噪声级）。
- 中间帧：play/pause 三角形在中线分裂成两杠；play/stop 三角形顶点展开成方块右缘；plus/minus 外框常量、加号竖笔平滑缩入横臂；star 收藏点亮内孔对称收缩闭合。对照图 `tmp/*_check.png`。
- **轮廓配对的硬规则**（2026-10-29 踩坑全集）：① 必须按界标分段（边对边、角对角），禁止整条周长对齐——中间帧的弦会拧；② 每条轮廓采样前必须归一绕向（CW 轮廓 + sign 翻转会变成 CCW，把孔填实）；③ 裁切线与多边形边缘重合时半平面裁切产生零宽退化块（加号竖臂边缘恰在减号条厚度线上），改用胶囊构造绕开；④ 组装画布前确认所有几何都在居中坐标系里；⑤ 跨形状界标配对后必须按极角序列旋转对齐两端起点（两端轮廓起点索引不同，不对齐会跨角扭转）。
- star 端点保真：帧 0 vs 描边星字形、帧 23 vs Fill 实心星字形，三字重改变像素 2–6、最大差 32–48/255。

## 新增一对图标的三步

1. 在生成脚本里登记：旋转对写进 `ROTATE_PAIRS`，语义对写一个 `build_plan` 分支，轮廓对写 `render_*_frames`（参考 play/pause 的「归心 → 裁切/配对 → 重采样 → 插值」）；跑脚本产出三个字重的 PNG。
2. 在 `CMakeLists.txt` 的 `EXPECTED_DATA` 里登记资产，并在 `EQmIconSwapPair` + `IconSwapAssetName` 里加映射（映射放头文件，单测不必链接绘制实现）。
3. 调用 `ResolveIconSwapBinding` 后交给 `DrawIconSwapBinding`（或作为 `DoButton_QmIcon` 的图标回调）。静止态**不要**换成帧条，只在轨道活跃时替换，避免背景渲染趟与内容趟画出两种形态。

## 已知限制

- 源资产 64px：目标边长超过约 64px（>2.5 倍物理缩放的 4K 窗口）会开始轻微放大。真遇到再升到 128，不要靠锐化补偿。
- 旋转帧是位图重采样，45° 附近锐度略低于字体 hinting；0°/90°/180° 与字形一致。
- Fill 字重的 eye 是实心眼眶加孔、chevron 是实心块，语义分解不成立，不提供资产，自动回落淡化。
