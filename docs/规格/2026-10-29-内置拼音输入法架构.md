## 1. 背景与目标

现状（见审计报告）：客户端已经完成"系统 IME + 自绘候选"，但为了 Windows 自绘候选，必须解析 IMM/TSF 通知、SDL 候选事件，并为搜狗、微软拼音等厂商写时序启发式。每接一种输入法就多一份兼容逻辑，这是维护无底洞。

目标：让**中文输入不再经过系统输入法**，候选数据由客户端自己产生，于是：

- 厂商差异消失（不再经过搜狗/微软/QQ 输入法的组合与通知）；
- 候选 UI 全平台可控（本期先 Windows）；
- 输入路径可单测、可回归、可复现；
- 系统 IME 退回成"直通模式"，只处理非中文/其他语言，且**不解析候选**。

## 3. 总体架构

```
SDL 事件
   │
   ▼
CInput::Update（engine/client/input.cpp）
   │  内置模式且文本输入激活：
   │    KEY_DOWN → IImeProvider::OnKey（消费的游戏键不再入队）
   │    TEXT_INPUT / TEXT_EDITING / CANDIDATES 事件不处理（SDL 文本输入已停）
   │    提交回调 → CInput::AddTextEvent（沿用唯一提交路径）
   │    状态快照 → m_CompositionString / m_ImeCandidates
   ▼
IInput getter（引擎接口不变）
   ├─ CLineInput::Render：内联 preedit、组合选区、锚点
   └─ CQmImeManager：候选弹窗（现有 capsule，不改绘制）
   ▲
   │ 注册、启用、每帧驱动
   │
IImeProvider 实现 = CQmImeEngine（game 层，新模块）
   ├─ CRimeAdapter：librime 会话、键位映射、部署、上下文/提交
   ├─ CQmImeDomainLexicon：玩家名/地图名/命令词/学习词
   └─ 合并与选择纯函数（domain 在前、Rime 页在后、数字映射）
```

### 3.1 分层与所有权

- **接口在 engine 层**：`src/engine/input.h` 新增 `IImeProvider` 与状态结构；`CInput` 只负责"什么时候调用、怎么同步、怎么提交"。
- **实现在 game 层**：`src/game/client/components/qmclient/ime/`。符合"Qm 功能优先落 game/client"的边界；provider 需要 `CGameClient`、`IStorage`、配置，正好在 game 层。
- **状态所有权**：组合串/候选仍由 `CInput` 的 `m_CompositionString`/`m_ImeCandidates` 对外暴露（现有消费者一行不改）；provider 每次交互后输出快照，CInput 同步进这两个成员。这样 `CLineInput`、候选弹窗、`HasComposition()`、组合期按键过滤全部沿用现有语义。
- **提交所有权**：provider 通过回调提交文本，CInput 在事件顺序内 `AddTextEvent`，保证"一次提交只写一次"。

### 3.2 两模式生命周期

| 阶段 | 系统直通（现状） | 内置拼音（新增） |
| --- | --- | --- |
| 激活 | `SDL_StartTextInput`，Windows 解析候选（现状） | 不调用 `SDL_StartTextInput`（必要时先 `SDL_StopTextInput`），provider `Activate()` |
| 组合 | SDL `TEXT_EDITING` | provider 自己维护；键不进入 SDL 文本输入 |
| 候选 | 现状（IMM/SDL 解析） | provider 产生，合并动态词后写快照 |
| 提交 | SDL `TEXT_INPUT` | provider 回调 → `AddTextEvent` |
| 停止 | `SDL_StopTextInput` | provider `Deactivate()`，清状态 |
| 切换 | 运行时改 `qm_ime_engine`：`CQmImeManager` 检测到变化时 `StopTextInput` → 重建会话 → 新路径 | 同左 |

## 5. 接口契约（A 在 Day 1 冻结）

> 原则：接口放在 `src/engine/shared/qm_ime_provider.h`，只依赖标准库与现有基础类型；不依赖 SDL/librime/游戏类型。A 先落地头文件，B 按头文件开发。

```cpp
// 键位修饰：与 X11 modifier mask 对齐，Rime 直接消费
enum
{
	QM_IME_KEYMASK_SHIFT = 1 << 0,
	QM_IME_KEYMASK_LOCK = 1 << 1,
	QM_IME_KEYMASK_CONTROL = 1 << 2,
	QM_IME_KEYMASK_ALT = 1 << 3,
};

// provider 每个交互周期输出的快照；CInput 原样同步到现有成员
struct SQmImeProviderState
{
	bool m_Active = false;      // provider 会话是否激活
	bool m_Composing = false;   // 是否有组合（preedit 或候选）
	std::string m_Preedit;      // 已提交前的组合串（UTF-8）
	int m_Cursor = 0;           // preedit 内字节偏移
	std::vector<std::string> m_vCandidates;
	std::vector<std::string> m_vComments; // 与 candidates 等长，本期可全空
	int m_Selected = -1;        // -1 表示无高亮
	int m_PageStart = 0;
	int m_PageSize = 0;
	int m_TotalCount = 0;
};

using FImeCommitCallback = std::function<void(const char *pText)>;

class IImeProvider
{
public:
	virtual ~IImeProvider() = default;

	// CInput 设置提交回调（在 Activate 前设置一次）
	virtual void SetCommitCallback(FImeCommitCallback Callback) = 0;

	virtual void Activate() = 0;
	virtual void Deactivate() = 0;
	virtual bool IsActive() const = 0;

	// 由 CInput 在事件顺序内调用；true = 该键由输入法消费，不再进入游戏键事件
	virtual bool OnKey(int Key, int Modifiers, bool Press, bool Repeat) = 0;

	// 焦点丢失：取消组合（默认丢弃，不提交）
	virtual void OnFocusLost() = 0;

	// 每帧调用：Rime 维护/通知、动态词导入节流、候选刷新
	virtual void OnFrame() = 0;

	virtual const SQmImeProviderState &State() const = 0;

	// 由 CQmImeManager 每帧设置：当前是否允许内置输入法接管
	virtual void SetEnabled(bool Enabled) = 0;
	virtual bool IsEnabled() const = 0;
};

// 动态词接口：A 的引擎调用，B 实现
enum class EQmImeLexiconSource : unsigned char
{
	PLAYER = 0,
	MAP,
	COMMAND,
	LEARNED,
	NUM_SOURCES,
};

struct SQmImeLexiconEntry
{
	std::string m_Text;
	std::string m_Pinyin;   // 无声调、空格分隔，例如 "xiao ba wang"
	std::string m_Abbrev;   // 首字母，例如 "xbw"
	int m_Weight = 0;
	EQmImeLexiconSource m_Source = EQmImeLexiconSource::LEARNED;
};

class IImeDomainLexicon
{
public:
	virtual ~IImeDomainLexicon() = default;

	virtual void BeginSession() = 0;                                // 清空本局来源
	virtual void FeedPlayerNames(const std::vector<std::string> &vNames) = 0;
	virtual void FeedServerName(const char *pName) = 0;
	virtual void FeedMapName(const char *pMapName) = 0;
	virtual void FeedCommands(const std::vector<std::string> &vCommands) = 0;

	// code 为 Rime 原始输入（无声调、无分隔，例如 "nihao"/"xbf"）；
	// 返回命中数，最多写 MaxOut 条，按权重排序。
	virtual size_t Match(const char *pCode, SQmImeLexiconEntry *pOut, size_t MaxOut) const = 0;

	virtual void OnCommitted(const char *pText) = 0;                // 学习
	virtual void ClearLearned() = 0;
	virtual void Load() = 0;
	virtual void Save() = 0;
	virtual void SetEnabled(bool Enabled) = 0;
	virtual bool Enabled() const = 0;
};
```

## 6. 生命周期与事件流

### 6.1 激活

```
CQmImeManager::OnFrame()
  Wanted = 有存活活动输入框 && 无玩法覆盖层 && 客户端持有输入管理权
  Input()->SetImeEngineEnabled(Wanted && g_Config.m_QmImeEngine != 0）
  → CInput::StartTextInput() 被调用时：
       if (内置可用 && Enabled) {
           SDL_StopTextInput(Window());   // 确保系统 IME/文本输入关闭
           ClearImeState();
           m_pImeProvider->Activate();
       } else {
           现有 SDL 路径（完全不变）
       }
```

### 6.2 按键

在 `CInput::Update` 的 `SDL_EVENT_KEY_DOWN/UP` 分支：

```
Key = TranslateKeyEventKey(Event.key)
if (内置激活) {
    Consumed = m_pImeProvider->OnKey(Key, Mods, Press, Repeat)
    if (Consumed) {
        if (Press) m_aProviderConsumedKeys[Key] = true;
        if (Release) m_aProviderConsumedKeys[Key] = false;
        SyncProviderState();   // 同步组合/候选快照
        continue;
    }
    if (!Press && m_aProviderConsumedKeys[Key]) { m_aProviderConsumedKeys[Key] = false; continue; }
}
AddKeyEventChecked(...)      // 未消费的键走原路径
```

规则：

- provider 消费的按下键，其对应释放键也丢弃，避免按键状态残留（历史上有 Shift 卡键问题）。
- 鼠标、滚轮、窗口焦点事件不经过 provider。
- 内置激活时忽略 `SDL_EVENT_TEXT_EDITING/TEXT_INPUT/TEXT_EDITING_CANDIDATES`（SDL 文本输入已停，属异常事件）。

### 6.3 状态同步与提交

- provider 的 `State()` 在每次 `OnKey`/`OnFrame` 后同步：写 `m_CompositionString`、`m_CompositionCursor`、`m_ImeCandidates`（新增 `UpdateFromEngine()`，绕过"提交后迟到候选抑制"）。
- 提交回调直接 `AddTextEvent(pText)`；空串忽略。保证与按键同序，`CLineInput` 只写一次。
- `OnFrame` 里若 provider 处于部署/维护状态，本帧不接收键（`OnKey` 返回 false），避免部署期卡输入。

### 6.4 停止、焦点丢失、模式切换

- `StopTextInput`：`provider->Deactivate()`（丢弃组合，不提交）→ 清空状态 → 现有 `SDL_StopTextInput`。
- `SDL_EVENT_WINDOW_FOCUS_LOST`：调用 `provider->OnFocusLost()`；释放所有 `m_aProviderConsumedKeys`。
- 运行中把 `qm_ime_engine` 从 0 改到 1 或反向：`CQmImeManager` 检测到变化 → 若活动输入存在，`StopTextInput()` → 清态 → 下次 `StartTextInput()` 走新路径。设置项即时生效，不重启客户端。

## 7. 键盘路由规则（MVP）

| 键 | 组合中 | 空闲中文 | 空闲英文（ascii_mode） |
| --- | --- | --- | --- |
| 字母 | Rime | Rime | Rime（提交原字母） |
| 数字 1–9 | 合并候选选择 | Rime | Rime |
| 空格 | 选合并第 1 项 | Rime | Rime |
| 回车 | Rime（上屏原始组合或选中项） | 不消费（聊天提交由 UI 处理） | 不消费 |
| Esc | 取消组合并消费 | 不消费 | 不消费 |
| Backspace/Delete | Rime | 不消费（CLineInput 处理） | 不消费 |
| 左/右/Home/End | Rime 光标 | 不消费 | 不消费 |
| PageUp/PageDown | Rime 翻页 | 不消费 | 不消费 |
| Tab | 不消费 | 不消费 | 不消费 |
| Shift 单击（无组合） | — | 切英文 | 切中文 |
| Ctrl/Alt/GUI 组合 | 不消费 | 不消费 | 不消费 |
| `/` 且当前行为空或已以 `/` 开头 | — | 提交 ASCII `/` 并切 ascii_mode（保证聊天命令可用） | 提交 `/` |

实现建议：英文模式直接使用 Rime 的 `ascii_mode` 选项（`set_option`），让 Rime 提交原始字母，省掉一套自定义 ASCII 打字逻辑；若 M1 验证发现 ascii_mode 行为不满足（空格/回车语义），再退回"provider 自己映射 US 布局字母"的备选方案。非 US 键盘布局本期不支持，设置页文案说明可切回系统直通。

## 8. 动态游戏词库

### 8.1 数据模型

每条：`文本 / 全拼（无声调、空格分隔）/ 首字母 / 权重 / 来源 / 提交次数 / 最后使用时间 / 是否持久化`。

来源与基础权重：

| 来源 | 示例 | 基础权重 | 生命周期 |
| --- | --- | --- | --- |
| 玩家名 | 当前计分板/聊天可见玩家 | 300 | 会话级；被选用后转学习词 |
| 地图名 | 当前地图名 | 300 | 会话级 |
| 服务器名 | 当前服务器名 | 200 | 会话级 |
| 命令词 | 静态常用命令（`/w`、`/team`、`/me`、`/pause` 等） | 150 | 会话级 |
| 学习词 | 用户提交过的中文词条 | 100 + 25×次数，封顶 400 | 持久化 |

### 8.2 拼音索引

- 运行时加载 `data/ime/qm_pinyin_chars.txt`（单字→无声调读音列表，构建期由 `pinyin-data` 生成）。
- 多音字不做组合爆炸：匹配时按音节切分输入 code（贪心最长音节），逐字对齐名字；每个字允许任一读音。名字长度 > 12 或输入长度 > 24 直接跳过。
- 首字母匹配：名字逐字取任一读音的首字母，与 code 前缀比较。
- 纯 ASCII 名字（如 `QmClient`）：不参与者匹配（英文直接由 ascii_mode 输入），但可作为学习词按文本命中？本期不处理。

### 8.3 匹配与合并

- 触发：Rime 有组合（`get_input()` 非空）时，用原始输入 code 查词库，取最多 `qm_ime_domain_max`（默认 3）条。
- 去重：与 Rime 当前页候选文本相同的 domain 项丢弃（避免"学了普通词又排在前面"）。
- 顺序：domain 项在前，Rime 候选在后，按页容量（9）截断；本期 domain 只在第一页出现，翻页后只看 Rime。
- 选择：数字 1–9 对应合并下标；domain 项 → 直接提交文本并 `clear_composition`；Rime 项 → `select_candidate_on_current_page(index - domainCount)`，再 `get_commit` 取提交文本。
- 空格：选中合并列表第 1 项（有 domain 时即 domain 首项，否则 Rime 高亮项）。
- 页信息：`m_TotalCount = domainCount + Rime 总数`（第一页）；后续页沿用 Rime 的页信息。

### 8.4 自动学习

- 触发：任何一次提交的文本，若为 2–8 个 CJK 字符（允许中间夹 ASCII 字母/数字），调用 `OnCommitted`。
- 更新：不存在则新建学习词；存在则次数 +1、更新最后使用时间；权重按公式重算；总数超 5000 时淘汰"权重最低 + 最久未用"条目。
- 去重策略：学习词即使与 Rime 词库重复也保留，但合并时按文本去重，所以不会重复显示；只有 Rime 未给出的词才会出现在前面，这正是"游戏专名"的收益。
- 关闭：`qm_ime_learning 0` 时只读不写；"清除学习记录"删除持久化文件并清空内存。

### 8.5 持久化

- 文件：`Storage()->OpenFile("qm_ime_lexicon.tsv", IOFLAG_*, IStorage::TYPE_SAVE)`，与现有 Qm 用户数据同目录。
- 格式：首行 `qmimelex v1`；每行 `source \t count \t last_used \t text \t pinyin`；UTF-8；文本转义制表符/换行。
- 写入：合并或每 5 分钟、退出时、显式清除时原子写（临时文件 + 替换）；读失败/格式非法时忽略并保留空库，不能阻断启动。
- 不在本周：多客户端同步、云词库、跨设备迁移。

### 8.6 节流与性能

- 玩家名/地图名/服务器名轮询每 2 秒一次，只在服务器或地图变化时重建会话级词条；词条数上限 512（会话）。
- 匹配在每键组合变化时执行一次，目标 < 0.2ms；词库用全拼前缀 trie 或按 code 前缀的排序数组 + 二分。
- 学习写入异步化不做，MVP 同步写但只在提交时；单次提交写盘 ≤ 1 次（合并 5 分钟窗口）。

## 10. 词典构建

### 10.1 输入与许可

| 数据 | 版本/来源 | 许可 | 用途 |
| --- | --- | --- | --- |
| jieba `dict.txt` | 固定 tag | MIT（仓库声明） | 词 + 词频 |
| `phrase-pinyin-data` `pinyin.txt` | 固定 tag（Arch 打包标记 MIT） | MIT | 词组读音（多音字） |
| `pinyin-data` `pinyin.txt` | 固定 tag | MIT，另附 Unihan 的 Unicode License V3 | 单字读音表（动态词匹配用） |
| librime | 1.17.0 | BSD-3-Clause | 引擎 |

`phrase-pinyin-data` 的固定版本 Makefile 把 CC-CEDICT 和汉典数据合并进 `large_pinyin.txt`，当前生成器只读 `pinyin.txt`。初始来源 python-pinyin/Hotoo 的 MIT 署名及 Unihan 的 Unicode 许可已随生成物保留；固定 README、Makefile 的来源与哈希见 `data/ime/LICENSES.txt`。不得改用 rime-ice（GPL-3.0）或官方 LGPL 主词库。

### 10.2 生成流程（`qmclient_scripts/ime/build_rime_dict.py`）

1. 读取 jieba 词条，过滤：纯 CJK、长度 1–8、词频 ≥ 阈值；按词频取前 10 万条（目标最终编译后 ≤ 8MB）。
2. 词组读音：`phrase-pinyin-data` 优先；未命中时逐字用 `pinyin-data` 主读音拼接。
3. 去声调、`ü` 转 `v`、音节空格分隔，生成 code；weight 取 `clamp(round(log10(freq)*100), 1, 10000)`。
4. 输出 `qm_pinyin.dict.yaml`（columns: text/code/weight，sort: by_weight）。
5. 输出 `qm_pinyin_chars.txt`：`U+4E00\than` 每行单字多读音空格分隔（供 §8.2）。
6. 输出 `LICENSES.txt` 与词条/体积统计；脚本打印可复核的 totals。
7. 脚本必须可离线复现：输入版本固定在脚本顶部常量，失败时明确报错。
