# 移动端触控与观战端架构

日期：2026-11-01
状态：方案（待实施）

## 一、现状与根因

底层输入已经是 SDL3 的原生触摸事件：`src/engine/client/input.cpp` 的 `HandleTouchDownEvent` / `HandleTouchMotionEvent` / `HandleTouchUpEvent` 把 `SDL_EVENT_FINGER_*` 归一化成 `IInput::CTouchFingerState`（`src/engine/input.h`：`m_Finger`、归一化 `m_Position`、每帧 `m_Delta`、`m_PressTime`）。`CGameClient::OnUpdate` 把同一份手指列表依次广播给组件的 `OnTouchState`，任一组件返回 true 就 `ClearTouchDeltas()`。

问题不在 SDL，而在**没有统一的触摸归属层**：

- `CTouchControls`、`CQmMobileSpectator`、MOTD、重要提示各自实现 `OnTouchState`；
- 聊天直接读 `Input()->TouchFingerStates()`（本次修复新增的 `CChat::UpdatePointerState`）；
- 控制台、表情、旁观菜单、轮盘各自调用 `CUi::UpdateTouchState`；
- CUi 菜单走 `CUi::Update()` 里的另一套 `CTouchState`，并且原来把触摸按下延迟一帧（第一次点只移动光标，第二次才命中）；
- 输入法由 `CQmImeManager` 管焦点，但聊天/控制台又各自在点击时 `EnsureScreenKeyboardShown`；
- Android 返回键/边缘手势没有进入客户端，控制台、菜单、聊天各自靠 Esc 语义。

结果就是：多个层同时命中、第一次点只移动光标、tooltip 常驻、输入法反复 Stop/Start、关闭入口和返回栈不一致。继续在单个组件里打补丁只会把问题搬来搬去。

## 二、目标分层

### 1. 引擎层：只提供原始事实

保留现有 `CTouchFingerState` 和每帧 delta。新增两件事：

- **Android 返回/边缘手势**：Activity 覆写 `onBackPressed` / `OnBackInvokedCallback`，把“返回一次”作为命令送给客户端；需要游戏自己识别边缘滑动时，在 Activity 的 `dispatchTouchEvent` 里识别从屏幕左/右边缘起始的横向滑动，再发命令。不要把系统返回键硬编码成 Esc。
- **IME 会话**：输入法只有“当前是否有文本焦点”一个状态。聚焦时 `StartTextInput`，失焦时 `StopTextInput`；已经显示时绝不再 Stop/Start。返回键优先收键盘，键盘收起后再交给返回栈。

### 2. 游戏层：触摸路由（核心）

新增 `CTouchRouter`（`src/game/client/` 下），它是唯一读取 `TouchFingerStates()` 的地方：

- **归属栈**：模态弹窗 > 聊天/控制台 > 菜单/计分板 > HUD 按钮 > 游戏相机。按下时取栈顶命中者，整段手势锁定给它，其它层收不到。
- **命中注册**：每个界面把可点区域（屏幕像素矩形 + ID + 允许的手势）注册给路由器，不再各自算坐标。
- **手势状态机**（每根手指）：
  - `Tap`：按下到抬起在 slop 内、短于长按阈值；
  - `LongPress`：超过阈值未移动；
  - `Drag`：移动超过 slop 后锁定方向；
  - `Pinch`：第二根手指加入且归属层允许缩放；
  - `EdgeSwipe`：起点在边缘 16dp 内、向内滑动。
- **单指主指针**：第一根手指是主指针；第二根手指加入时取消未完成的 tap，按归属层决定是否进入 pinch。
- **返回栈**：`Back` 先交给栈顶（关弹窗/收聊天/关计分板），空栈时打开退出确认；连续两次边缘滑动等价于“退出”。

### 3. CUi 适配器

CUi 保留，但只通过一个适配器接收路由结果：

- 按下同帧设置 `MousePos` 并产生 `MouseButton` 按下，**不再延迟一帧**；
- 触摸没有 hover：不更新 hot item、不画光标、不显示 tooltip；
- 抬起产生 click；拖动转成 scroll region 的滚动；长按转成右键；
- 所有菜单/设置/弹窗因此自动获得一致的“一下命中”。

### 4. 焦点与输入法

新增 `CFocusManager`：全局只有一个文本焦点。点输入框 → 聚焦 + 显示键盘；点空白/关闭界面 → 失焦 + 收键盘；返回键先收键盘。聊天、控制台、搜索框都接这一套，不再各自 `EnsureScreenKeyboardShown`。

## 三、原生触控交互（以观战端为主）

DDNet 的桌面交互可以逐项映射，但观战端只保留需要的：

| 桌面交互 | 观战端触控 |
| --- | --- |
| 鼠标移动视角 | 单指拖动平移；双指捏合缩放；按钮切换“轮盘/拖动”模式 |
| 按住 Tab 看计分板 | 计分板按钮打开底部面板；点玩家行跟随；下滑/返回关闭 |
| 回车/ T 聊天 | 聊天按钮或点输入行；自动弹键盘；历史区拖动；同一按钮关闭 |
| 右键玩家菜单 | 点玩家行跟随；行尾「…」按钮打开玩家卡（不依赖隐藏长按） |
| 投票 F1 菜单 | 顶部投票条 + 两个大按钮 |
| Esc 菜单 | 菜单按钮打开半屏面板；返回键逐层关闭 |
| 控制台 | 删除交互式控制台；新增“聊天记录”页（搜索/筛选/复制/跳转），保留游戏内聊天框 |
| 武器/钩子/跳跃/假人 | 全部移除 |
| 实体层/前后景 | 实体层按钮循环切换（游戏层/背景层/全部） |

相机手势要直接改 `m_Controls.m_aMousePos` / `m_Camera`，不要模拟鼠标；按钮只做离散动作。

## 四、观战端裁剪

目标不是“手机版 DDNet”，而是**观战客户端**。建议先做运行时开关 `QmSpectatorOnly()`，稳定后再做编译期 flavor。

保留：

- 服务器浏览、收藏、直连；
- 观战相机、跟随/自由视角、缩放；
- 计分板、玩家卡、聊天、投票；
- 聊天记录页（原控制台的聊天历史/复制能力，改成手机 UI）；
- 资源页（贴图/材质/实体/粒子/HUD，直接影响画面）；
- 皮肤下载与加载（官方、社区、自定义社区 URL；不做皮肤编辑器）；
- 回放列表、播放、录制 demo、剪辑回放、渲染回放、导出（Android SAF/MediaStore，iOS DocumentPicker/分享）；
- 设置的一个子集（画面、HUD 缩放、聊天、翻译、资源、皮肤、回放、文件）；
- 退出。

移除/隐藏：

- 本地服务器、地图编辑器、皮肤编辑器、HUD 编辑器、绑定编辑器、远程控制台；
- 本地玩家操作（开火/钩子/跳跃/武器/假人/队伍加入）；
- 大部分 ESC 菜单页签（游戏/玩家/服务器信息里的操作项）；
- 桌面控制台交互（改成聊天记录页）。

实现上用 `CONF_QM_SPECTATOR_ONLY` 编译期裁剪菜单注册、输入绑定和大块组件，运行时再用 `QmSpectatorOnly()` 兜底隐藏入口；Android 单独 flavor，避免把编辑器/本地服务器打进 APK。

## 五、Vulkan 策略

本次实机错误是 `SDL_Vulkan_CreateSurface` 失败（`backend_vulkan.cpp` 的 `CreateSurface`），不是着色器/设备问题；手机设置里保存了 `gfx_backend "Vulkan"`。Android 上 Vulkan surface 依赖 ANativeWindow 的生命周期，客户端初始化过早或窗口重建时都可能失败。

结论：**Android 以 Vulkan 为目标后端**，必须把 surface 生命周期解决掉；GLES 只作为驱动/窗口异常时的应急回退，不作为默认。

实施：

- 在 `SDL_EVENT_WINDOW_SHOWN` / surface 真正可用后再 `SDL_Vulkan_CreateSurface`，不要在用 `InitVulkanSDL` 的 PreInit 阶段硬创建；
- Android 上 `surfaceCreated`/`surfaceDestroyed`/前后台切换要成对处理：销毁时暂停渲染、重建时重造 surface/swapchain（现有 `Cmd_WindowCreateNtf` 已有部分逻辑，补齐初始路径）；
- 首次创建失败做有界重试（例如 500ms），日志记录 `SDL_GetError()` 和窗口 flags；仍失败才回退 GLES，并明确提示；
- 生命周期用例：冷启动、切后台再回、旋转、锁屏、通知栏下拉、分屏。每个用例都要实机验证。

## 六、实施顺序

1. `CTouchRouter` + CUi 适配器（解决一下点不中、第一次只移动光标、tooltip/光标、输入法闪烁）；
2. 聊天/计分板/菜单/控制台迁移到路由器，删除各自的触摸补丁；
3. 焦点管理器 + Android 返回/边缘手势；
4. 观战端按钮与相机手势（计分板、视角模式、实体层）；
5. 观战端运行时裁剪，再评估编译期 flavor。

每一步都用“触摸坐标 → 命中 ID → 动作”的日志和实机截图验收，不再用“看起来对”。
