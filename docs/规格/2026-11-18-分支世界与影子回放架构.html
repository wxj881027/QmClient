分支世界、Rank 1 与 Ghost 影子回放架构

QmClient 客户端侧并行时间线的现状、边界与演进路线

规格日期 2026-11-18 基线提交 104ff23b9a 快速练习平行化 已落地 影子机关世界 规划中

一句话结论：QmClient 现在有三条明确分开的时间线——服务器世界、快速练习分支世界、影子回放轨道。分支世界已经是“可独立推进的沙盒”，影子回放仍然是“只看不碰的轨迹层”。把两者接成 demo 式影子世界，下一步缺的不是物理，而是一个只读机关世界和更宽的轨迹数据模型。

1. 三条时间线模型

DDNet 原生只有一条时间线：服务器快照决定一切。QmClient 在这个前提上增加了两类“客户端侧时间线”，它们权威范围不同，不能混为一谈。

服务器世界CGameClient::
m_GameWorld
权威来源是服务器快照与预测。负责真实联机、其他玩家、聊天、计分、比赛时间、击杀信息。快速练习期间仍然存在并继续接收快照，但不驱动练习参与者。
快速练习分支CFastPractice::
m_PracticeBaseWorld
从服务器世界 CopyWorldClean fork 出来的本地沙盒，参与者（本体 + 分身）的权威状态在这里。每帧经 m_PredictedWorld 往返推进，再写回分支。门、拖拉、静态激光、拾取物、机关炮按整张地图重建，因此走出网络裁剪范围仍然成立。
影子回放CLocalWorld +
CGhost 手动渲染
只保存轨迹、事件与开关状态，不持有可玩世界。Rank 1 与练习组共用同一套播放/查看模式；影子只画，不勾人、不挡人、不吃机关。
能力服务器世界练习分支影子回放
推进时钟服务器 tick + 客户端预测自己按预测 tick 追赶播放头（可暂停/拖动）
参与者碰撞是是否
门 / 拖拉 / 激光快照 + 预测整图重建 + 分支开关目前只读快照；规划为只读机关世界
聊天 / 计分 / 击杀权威不参与（仍显示服务器）不参与
能否影响主世界—只通过最终回到服务器时同步位置绝对不能

2. 快速练习分支世界

2.1 生命周期

启用练习→ InitPracticeWorld()→ CopyWorldClean(&m_GameWorld)→ 清掉继承实体→ LoadPracticeMapMechanisms()→ PrunePracticeWorld()→ EnsurePracticeParticipants()

关键入口：src/game/client/components/tclient/fast_practice.cpp:1171。分支不是“服务器世界的一份引用”，而是一棵独立实体树；CopyWorldClean 只复制世界配置、队伍、开关和实体，之后两边各自推进。

  • 重新 fork 前必须先切段：InitPracticeWorld 开头调用 m_Recorder.MarkBoundary()，否则重绑/重开会在轨迹里连出一条穿墙直线。
  • 开关状态跨 fork 保留：只有 base 世界仍然装着上一条练习时间线时，才把 Switchers() 暂存并在新 fork 上按 tick 差平移，避免 /setswitch 被服务器快照冲掉。
  • 参与者重绑：TryRebindPracticeParticipants()（fast_practice.cpp:451）在 client id 变化时迁移命令状态，并把旧分支的 /solo 寄存到 m_PendingLocalSolo/m_PendingDummySolo，等新角色建好再写回。

2.2 时钟与 tick 平移

分支时钟永远不倒退：PracticeClockTarget()（fast_practice.cpp:601）取“预测 tick”和“当前分支 tick”的较大值，专门防 cl_dummy 刚切换连接时预测 tick 停在 0 导致的世界倒退。

函数平移范围使用场景
ShiftPracticeWorldTicks()
fast_practice.cpp:608		 轨迹 tick、事件屏障、世界实体、攻击 tick、眼表情结束 tick 服务器暂停恢复、旁观进入前对齐、超过两秒的断崖追赶
ShiftPracticeWorldEntityTicks()
fast_practice.cpp:637		 角色、投射物、激光、等离子、练习灯、开关 m_aEndTick/m_aLastUpdateTick /restart 从入口快照恢复；不碰轨迹与事件屏障

为什么 /restart 不能直接改 m_GameTick：入口快照里的投射物、激光和定时开关都带着“启用练习那一刻”的绝对 tick。直接把世界时钟改到现在，它们会全部被判定为早已过期，机关相位会一次性错位。正确顺序是“先把实体平移到当前时刻，再落世界时钟”。

静态地图激光的 m_EvalTick 是 -1（没有开火时刻），平移时必须跳过，否则光柱会重新播放生长动画。该判断在 ShiftPracticeWorldEntityTicks() 内。

2.3 参与者渲染权威

渲染发布统一在 CGameClient::UpdateRenderedCharacters()（src/game/client/gameclient.cpp:7445）。对练习参与者，以下字段以分支为准：

字段写入来源原因
位置 / 速度 / 角度分支 CCharacterCore练习参与者的真正物理状态
武器 / 攻击 tick分支 GetActiveWeapon() / GetAttackTick()快照武器在旁观时不会跟随分支
表情ResolvePracticeEyeEmote()服务器会把长期中性输入判成 AFK 并强制眨眼
挂机坐姿参与者屏蔽 m_Afk坐姿是服务器 AFK 姿态，不是练习状态
冻结分支 m_FreezeEnd、m_DeepFrozen、m_LiveFrozen冻结隐身、解冻进度与 HUD 必须和分支碰撞一致

参与者判定入口是 IsPracticeParticipant(ClientId)，角色解析入口是 ResolvePracticeCharacter(ClientId)。前者决定“是不是这条分支的人”，后者在分支未建立或非参与者时返回 nullptr。

2.4 机关重建与渲染

分支世界不能依赖快照范围，否则走出镜头就会“看不见但还在挡”。LoadPracticeMapMechanisms()（fast_practice.cpp:784）直接读地图三层的实体 tile，按服务端创建规则重建：

拾取物

护甲、武器、生命、忍者，按 ENTITY_* 还原类型与子类型。

门

CDoor，记录 hub、方向、长度；ResetCollision() 把门碰撞端点写进当前碰撞缓存。

拖拉

CDragger，记录强度、穿墙、开关编号与目标。

静态激光

CPracticeLight，复用快照端点与服务器 eval tick，保留生长相位。

机关炮

m_vPracticeGuns 单独模拟，按 MoverSpeed 跟随移动平台，按队伍/solo 选择目标。

渲染在 CItems::OnRender()（src/game/client/components/items.cpp:598）内完成。练习机关段从 items.cpp:678 开始，按 ENTTYPE_LIGHT、ENTTYPE_DOOR、ENTTYPE_DRAGGER 遍历分支世界，并把 hub 收集到去重表；随后快照激光如果与分支 hub 重合就跳过，避免双重曝光。

渲染门控不跟 Predict() 走：旁观和服务器暂停时 Predict() 为假，但分支仍在推进碰撞。机制段只要求“非小地图渲染且分支世界存在”，因此不会出现“看不见的激光把人冻住”。（items.cpp:678，提交 104ff23b9a）

门与拖拉的渲染语义

实体开启关闭实现
门 从 hub 画到碰撞端点，长度取碰撞几何而不是快照可视端点 折叠到 hub，保留激光头，与原版快照一致 CDoor::RenderData()（door.cpp:148）
拖拉 有目标时画向目标，无目标时保留零长度轮毂 开关关闭时整只不画（与原版闪烁规则一致） CDragger::RenderData()（dragger.cpp:163）
静态激光 按分支开关与 eval tick 绘制 开关关闭时不画 CPracticeLight::RenderData()

开关编号越界按“开启”处理，与客户端快照的 Inactive 判定一致；无效队伍不回退到 0，而是不判定为关闭，避免把整只机关误隐藏。

2.5 队伍与 solo：只是开关索引

快速练习不是团队玩法，队伍号在这里只做一件事：选择开关、门、激光、拖拉和机关炮读取哪一组 m_aStatus[Team]。因此不实现本地 /team，也不让分支队伍与服务器分叉。

  • 队伍号：SyncPracticeWorldConfig()（fast_practice.cpp:722）只同步参与者本人；服务器是 TEAM_SPECTATORS 时跳过，避免旁观期间把可玩队伍覆盖掉。
  • solo：分支本地状态，/solo、/unsolo 直接写分支 m_Teams；fork/重绑时按旧角色迁移。
  • Rank 1：.qmevt 记录 m_Team，回放时按录制队伍还原开关，不套用查看者当前队伍。这是队伍字段真正有跨时间线意义的地方。

2.6 旁观：时间继续走

旧行为是旁观期间冻结分支、回来一次性对齐。现在的行为是：

  1. OverridePredict() 识别旁观（fast_practice.cpp:2166），不把分支铺进 m_PredictedWorld，因为那时它归服务器预测所有。
  2. PrepareForSpectating()（fast_practice.cpp:1743）先把分支对齐到当前预测时刻，实体 tick 一起平移。
  3. 每帧调用 TickPracticeWorldDuringSpectate()（fast_practice.cpp:2094）：本体与分身使用中性输入，继续步进、机关炮、死亡 tile 反馈、计时、轨迹/事件/开关采样。
  4. 事件先交给录制采样，再只做去重记账，不直接播放音效/特效，避免把练习世界的声音叠到当前旁观视角。
  5. 退出旁观不补跳；主循环从当前分支 tick 继续追赶，超过两秒才走断崖平移。

因此旁观者看到的是“练习世界在自己走”，而不是一张暂停的画面；回到游戏时也不会出现时间跳变。

3. Rank 1：官方 demo 到本地影子

来源链路先说清楚：Rank 1 下载的是官方 demo，不是官方 .qmevt。官方站点没有 .qmevt 这种文件；.qmevt 是 QmClient 在本地解析 demo 时生成的 sidecar（事件、开关状态、成绩消息）。

manifest→ 官方 demo 下载→ StartParse()→ 逐 tick 解析→ trackN.gho + events.qmevt→ EnterViewMode()
  • 清单：rank_demo_manifest 提供地图、名次、demo 地址、时间、ghost 成员列表。空 ghosts 只阻止“生成影子/查看”，不阻止“仅下载回放”。
  • 下载：CRankGhost::StartDemoFetch() 取官方 demo 到缓存目录；断点/重试/跨图等待由 m_RetryLoadPending 维护。
  • 转换：StartParse()（rank_ghost_parse.cpp:341）打开 demo，逐 tick 采样目标玩家轨迹，结束时调用 WriteViewTimeline()（rank_ghost_parse.cpp:544、:636）写出 .qmevt。界面文案就是 “converting the replay”。
  • 查看：EnterViewMode()（rank_ghost_view.cpp:81）把多轨交给 CGhost::StartRenderManual()，用独立播放头驱动轨迹、事件、消息与开关状态，不播放 demo 快照，也不改服务器世界。

3.1 两段式进入

按最新交互，Rank 1 行上的 “View replay” 分两步：

  1. demo 未缓存：只下载 demo，不自动切画面；按钮在任务期间置灰，下载结束后恢复。
  2. demo 已缓存、影子未生成：点击后加载/解析影子，完成后进入查看模式；这是玩家明确点击的结果，不是下载的副作用。

实现入口：CRankGhost::RequestGhostViewForDemo()（src/game/client/components/qmclient/rank_ghost.cpp:624）。双击行等同“下载回放”，不会直接进查看模式。

下载任务共用一套 demo 请求状态机，因此多个回放按 FIFO 排队：当前条目结束后自动开始下一条，排队中的行显示任务状态。Rank 1 条目左侧另有官网按钮，优先打开 https://ddnet.org/watch/?uuid=<uuid>&time=<time>；缺少 uuid 时回退到 demo 路径。

4. Ghost：本地练习组回放

4.1 练习组是什么

快速练习里 /pg 保存的不是单个文件，而是一个目录：

practice_group/
  track0.gho      # 本体轨迹
  track1.gho      # 分身轨迹（如果有）
  events.qmevt    # 事件 / 开关 / 消息 sidecar

.qmevt 单独没有 Tee 轨迹，不能独立播放；Ghost 页扫描的是“目录里同时有 events.qmevt 和 track0.gho”的练习组。menus_ingame.cpp:2363 起是扫描入口。

4.2 入口与交互

  • Ghost 页中显示为 [Practice] 玩家名，用青色区分。
  • 动作按钮是 “View replay”（旧版是含糊的 “View”），双击条目等价。
  • 点击调用 CRankGhost::ViewPracticeGroup()（rank_ghost_view.cpp:49）：清掉跨图 Rank 的等待状态，按组目录加载所有轨，复用 Rank 1 的查看模式与 .qmevt 读取。
  • 练习组没有源 demo，因此查看模式隐藏切片/导出；进度与总时长由 ManualEndTick() 计算。

4.3 影子为什么不参与物理

CLocalWorld（src/game/client/components/qmclient/local_world.h:131）只保存轨迹会话，不持有 CGameWorld。CGhost 手动渲染把轨迹插值成虚影，没有角色实体，也没有碰撞查询。这是设计底线：Rank 1 和 Ghost 都来自“另一个平行时空”，只允许看。

4.4 双模式路线图

模式 A · 原版影子（默认）

只画轨迹与事件，零物理、零机关。适合边玩边看，成本最低，保持现状。

模式 B · Demo 式影子世界

新建只读 CGameWorld，复用本轮的门/拖拉/静态激光重建与 RenderData，用 .qmevt 的开关状态驱动机关，半透明绘制。不写入共享 CCollision、不加入主世界 tick、不影响聊天。

模式 B 的分阶段实现

阶段内容可行性
B1 门、拖拉、静态激光影子化：只读机关世界 + .qmevt 开关驱动 高本轮的分支机关重建与 RenderData 可直接复用
B2 移动方块、机关炮影子化 中需要按播放头重放平台位移与炮位，不能只读当前 tick
B3 多 Tee：所有玩家/分身同时显示 中MAX_TRACKS 从 2 扩成按 ClientId 的 N 轨；demo 解析记录所有角色
B4 音效/特效本地播放开关 低复用 SQmFocusModeDecisions 与预测事件门控，默认关闭避免盖住主世界

边界：影子世界即使拥有完整机关，也不能写共享碰撞、不能向服务器发送输入、不能修改主世界实体。它可以有“影子碰撞”仅用于影子内部演示，但绝不能参与玩家判定。

7. 诊断与失败模式

  • qm_local_world_dump 输出 render_pos（本地/分身/相机）与 dummy_tee（位置/速度/角度/最新输入），用于区分“位置问题”和“武器字段问题”。
  • qm_local_world_dump 的 spec: 行显示 active、use_position、spectator_id、branch_spec、local_team，用于确认旁观是否真的进入。
  • 练习机制日志：map mechanisms: pickups=... doors=... draggers=... lights=...；开关携带日志：switch carry: live=... has=... count=... status0=...。
  • 分支 tick 追赶日志：tick shift: +N branch_tick=... track_start=... frames=...，只在单次平移 ≥10 tick 时打印。
  • Rank 1 转换日志：converting the replay (N%)；时间线写出日志：view timeline written: N events, N switch states, N messages。
