# 歌词显示与哼歌

状态：原有功能及网易云译文采集修复已集成 `master`。本轮补充主岛宽度跟随开关，验证状态见下。

## 歌词显示

歌词卡提供“仅原文 / 仅译文 / 原文＋译文”三档。默认仅原文。译文使用音乐源已有的翻译轨；当前句没有译文时回退原文，原文与译文相同时只显示一行。

“灵动岛分离”默认关闭。开启后，歌词从主岛底部移到独立附岛，默认位于主岛下方并留出空隙。附岛复用主岛的背景色、透明度和模糊设置。没有播放歌词时，编辑器仍提供占位内容，便于调整位置。

“歌词岛跟随主岛宽度”（`qm_lyrics_island_follow_width`）默认开启。开启后，附岛始终取主胶囊当前帧的实际宽度，包括主岛入场动画和 HUD 缩放，不包含眼睛等附岛。单行、双语、窄视口都不独立改变这个宽度。HUD 编辑器仍可移动歌词岛，但不会应用旧布局中的歌词岛独立缩放，也不允许滚轮单独缩放。没有对应主岛或媒体面板时不生成固定宽度的跟随附岛。

关闭宽度跟随后，歌词岛恢复独立宽度和已保存的 HUD 缩放。传统媒体面板显示时，跟随该面板的实际宽度。HUD 布局格式保持不变。

歌词总开关与岛内显示开关继续控制显示。哼歌具有独立开关，不受显示语言、附岛位置或歌词显示开关影响。切换音乐源仍使用现有的来源互斥设置。

## 哼歌

“梦的小功能”卡新增“哼歌”，默认关闭。开启并满足在线、当前连接有效、音乐正在播放且当前歌曲有完整歌词时，先等待随机 30～90 秒，再从当前歌曲随机选择连续三句有效原文，逐句发送到公共聊天。句间隔为 3 秒，下一组从上一组结束后重新计时。

每句附加音符前缀，避免歌词中的斜杠被解释为指令；长句按 UTF-8 字符边界限制长度。哼歌不进入自动出站翻译队列。

关闭功能、切歌、音乐源或播放器实例改变、暂停、断线、切换主副连接或本地身份时，丢弃等待中和尚未发出的句子。普通聊天仍有待发消息、刚发送过消息或发送失败时，取消该组并等待下一次随机间隔。帧停顿后不集中补发。

## 歌词数据

汽水、酷狗、QQ 音乐和 Spotify 复用现有完整歌词数据。独立 LRC 翻译按时间戳对齐，酷狗还读取 KRC 内嵌翻译。

网易云的原有 v5 当前句快照保持原布局。完整原文与翻译由 helper 的独立共享内存通路提供，按播放器进程、歌曲和 generation 对齐。单份原始歌词总量上限为 512 KiB。客户端后台解析完整歌词，旧歌曲和旧任务的结果不会应用到当前歌曲。

现代网易云从 `async:lyric` 同时读取 `lyricLines` 原文与 `tlyricLines` 译文，以各自的时间戳序列化。上报去重同时比较原文和译文；译文后到或单独修订时会重新上报，不要求原文版本变化。网易云自身的翻译显示开关不影响 QmClient 获取现有翻译轨。

缺少译文时显示原文；缺少完整歌词或不足三句有效歌词时不哼歌。旧 helper 只能继续提供原有当前句，完整歌词和译文需要配套的新 helper。不同音乐源能否提供译文仍取决于其实际歌词数据。

## 验证记录

原有功能已生成十二种语言资源，网易云译文修复随 PR #512 合入 master。其 Release 与 Setup 3.3 已构建；显示语言、哼歌和歌词通路的行为测试未执行，游戏内视觉及哼歌真实发送路径未验收。

本轮宽度跟随补充旧缩放值、主岛入场动画、眼睛等附岛边界、窄视口及关闭跟随的行为测试，未执行。此前只约束默认布局宽度，独立缩放及主岛入场动画仍能使两者不同宽；本轮在实际绘制和编辑器变换中共同执行约束。

已完成差异和测试库存静态检查。新开关及计分板数据源说明已写回维护源，十二种语言资源已按完整提取结果生成；当前源串新鲜度与语言覆盖检查通过。翻译验证仍报告一条已有的哼歌简中数字排版错误，该译文与本轮基线相同，未扩大修改范围。

脚本行为测试入口：`node --test qmclient_scripts/tests/test_netease_frontend.cjs`。脚本测试只替换播放器、时钟和报告边界，不连接实际播放器。

宽度跟随仍需在真实客户端检查主岛动画、旧 HUD 布局、单行/双语、长句滚动和窄视口下的显示效果。
