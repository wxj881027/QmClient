# Wiki 与设置卡片的后续计划

记录 2026-10-23 这一轮之后仍然要做的收尾工作，以及顺序与验收方式。
已完成的部分见 [Wiki 内容系统](2026-10-22-Wiki 内容系统.md) 与
[弹窗与二级菜单交互规范](2026-10-21-弹窗与二级菜单交互规范.md) 的 §6.1。

当前基线：`dyl_dev` 上的 `019edb0b17`（编辑框滚动到光标 + 编辑状态机）与
`e4ea7c4445`（搜索卡配色），加上本轮的「超长文档拒绝进入编辑」。
编辑状态机、光标跟随、ⓘ 槽位、字形光标换算都有自动化测试；**观感与手感仍需实机确认**。

## 1. 先做实机验收（不写代码，先确认已提交的东西没走样）

窗口化（`gfx_fullscreen 0`）启动 `cmake-build-release/DDNet.exe`，按下面顺序走一遍，
任何一条不符合预期都先回到对应实现，而不是继续加功能：

1. 设置 → 搜索页：输入卡背景色/边框与同页其它卡片是否同一套配色；ⓘ 紧贴折叠箭头（该卡没有宽度按钮）。
2. 其它设置卡：右侧动作是否仍是「ⓘ 宽度 折叠」从右往左的顺序；悬浮 ⓘ 是否出现首段摘要。
3. 点 ⓘ 打开面板 → Esc 关闭；编辑态按 Esc 只退出编辑、草稿仍在。
4. 编辑长文档：末尾打字时光标跟随、滚轮能在框内上下滚、点空行能在空行打字。
5. 保存后状态行显示 `wiki/<语言>/<路径>.md`；「还原」后回到内置内容。
6. 正文里点 `qm:` 链接能在同一面板换卡片；目录条目点一下把小节顶到可视区。

验收结果记进 `.agents/worktree-state.local.json` 的 `wiki_card_panel_commit`，
不要只留在聊天里。

## 2. 面板级集成测试（补现在只有代码级证据的三条路径）

现状：编辑状态机已经是可测的（`CQmWikiEditorTest`，9 项），但**面板自身的三条交互**
还没有真实 UI 上的测试，只能靠实机。计划加进 `qm-ui-popup-tests`：

- 目录点击 → 滚动目标块落到可视区顶部（驱动 `qm_wiki_markdown::RenderBlocks` 的 `TocTarget`）。
- 编辑态 Esc → 只退出编辑；阅读态 Esc → 关闭面板（`ConsumeHotkey(HOTKEY_ESCAPE)` 的消费顺序）。
- ⓘ 在绘制阶段用 `DoButtonLogic(... BUTTONFLAG_CURRENT_HIT)` 命中 → 弹出面板；
  同时锁住「折叠卡片每帧不再关掉面板」这条回归（用 interaction source 计数断言）。

前提是先把 `QmCardWikiPanel` 的弹层入口在测试里拉起（真实 `CUi` + 真实文字引擎 + 真实 `IStorage`，
参考 `qm_real_ui_fixture.h`）。如果发现为了测试要大改面板结构，就先停手回到 §1 的实机结论再决定。

## 3. 媒体与长文档（有明确用户感知的卡顿点）

- **行内公式图仍是同步解码**：文档里公式多时打开面板会掉帧。做法与其它图片一致——先按原始尺寸占位、
  可见时解码、把解码放进每帧预算（`qm_wiki_media::ResetFrameBudget`），并让公式块的排版高度可等待。
- **首次打开带大图/动图的文档仍会卡一下**：预算目前是「每帧最多一张」，需要按文档大小动态分配
  （例如首帧允许 2 张、之后回到 1 张），并把超预算的图降级为占位直到有空档。
- 需要一次实测数据：带 8 张图 + 2 个动图的页面，打开时的帧时间分布（`qm_perf` 输出），
  用它决定预算参数，而不是猜。

## 4. 编辑体验补完（按需要做，不影响发布）

- 覆盖文件写入加一个小头（版本 + 源 stableId + 时间戳）或改用独立扩展名，避免与随包文件混淆；
  读取时忽略头部并保留纯正文。**未发布前不做配置迁移**，但文件格式一旦有用户覆盖就要考虑兼容。
- 编辑时的「未保存」提示：切页/关菜单前若 `m_EditDirty`，用 Toast 或确认框拦一次。
- 撤销/重做（至少单步）：目前改错了只能靠「还原」回到内置内容，代价太大。

## 5. 发布前必须处理

- 把 `QmCardWikiPanel.cpp` 的 `WIKI_AUTHORING_ENABLED` 改成 `false`，确认编辑按钮、写文件与相关文案整体消失。
  这一步要在正式版分支上单独提交，并配上「作者工具已关闭」的说明。
- 旧弹窗迁移（规范 §6 P3 批 3）：`CMenus::PopupMessage/PopupConfirm` 约 62 处按 §1.5 映射到
  Alert/ConfirmDialog/Toast，并加 `audit_overlay_usage.py` 防回潮。
- 破坏性操作补确认（N6，20+ 处）：删皮肤预设、删 Profile、删战争名单、删地图历史、删 ghost、Sync 中断等。

## 6. 工程卫生

- **i18n 缓存需要一次全量重整**：`extracted_strings.txt` 已落后于源码（`validate.py` 会报
  "out of date"），本轮只补了 `wiki_ui.toml` 的新键与 12 个 `data/languages/*.txt`。
  下一次有人动 i18n 时统一跑 `extract_strings.py` + `generate_all.py`，一次把并行任务的
  pose / 视频导出字符串一并收进去，避免反复半量生成。
- `SWikiRenderStyle::m_Surface` 目前没有任何渲染路径读取，确认用途后删掉或接上。
- 这一轮的阶段证据整理完成后，把实施类文档移进 `docs/归档/`，只留规格与未完成验收清单在 `docs/规格/`。

## 7. 明确不做的

- 不解析 TeX：公式继续走预渲染图片。
- 不做 Wiki 编辑器的语法高亮与实时预览：作者面向的是少数开发者，收益低、维护面大。
- 不为编辑框引入独立的文本组件：现有 `CLineInput` + `DoEditBoxMultiLine` 已经能覆盖需求，
  换组件会把字形/光标换算、IME 组合、选区这些已经修好的东西重做一遍。
