## 已确认并修复的问题

### F01 严重：脚本队伍和位置查询缺少可用状态检查

入口为 `chai` 命令注册后的 `state("team")`、`state("ddnet_team")`、`state("location")`。`CGameClient::OnReset` 把本地 ID 设为 `-1`，原队伍查询直接索引玩家数组或传入 `CTeamsCore::Team`，两者都没有内部范围保护。配置文件又早于组件 `OnInit` 执行，启动脚本的位置查询可能访问尚未建立的地图层。

- 位置：[scripting.cpp](../../src/game/client/components/qmclient/scripting.cpp)、[state.h](../../src/game/client/components/qmclient/scripting/state.h)。调用依据：`client.cpp` 的配置执行顺序、`gameclient.cpp` 的重置、`maplayers.cpp::OnInit` 和 `teamscore.cpp::Team`。
- 修复：在线或回放之外返回空值；本地 ID 越界时不调用队伍读取；地图不存在、尺寸无效或坐标非有限时返回空值。位置分区先限制浮点范围，再转换下标。
- 配套：4 项 `QmScriptingState.*` 测试覆盖非法 ID 不调用读取、换号/重连后的当前 ID、无效位置和分区边界。测试调用共享生产接口；没有启动 Chai 解释器或客户端。

### F02 严重：音频解码在分配失败后继续使用空缓冲

原 Opus 解码的 `calloc` 结果直接交给 `op_read`；WavPack 的中间缓冲与最终 PCM 分配都没有空指针检查。内存不足时可以进入解码器空写入或转换空写入。Opus 总帧数还在验证前从 64 位缩为 `int`；WavPack 文件长度会缩为有符号 reader 长度。

- 位置：[sound.cpp](../../src/engine/client/sound.cpp) 的 `DecodeOpus`、`DecodeWV`，以及 [sound_buffer.h](../../src/engine/client/sound_buffer.h)。消费者包括地图声音、游戏音效和音频包编辑器。
- 修复：验证总帧数、单/双声道、交错采样数、分配乘法及 WavPack reader 长度；分配成功才调用填充/解码。失败不发布 PCM，解码器和临时缓冲使用 RAII 释放。没有调整文件格式。
- 配套：`SoundBuffer.*` 测试用可失败的分配边界验证不调用解码、拒绝异常计数、正常交错数据和解码失败不发布。它们不代替真实 Opus/WavPack 解码器的集成测试；该集成场景仍待补充。

### F03 严重：皮肤灰度副本分配失败后继续读取像素

`CImageInfo::DeepCopy` 已在分配失败时返回空图，但 `CSkins::PrepareSkinData` 随后仍按原图身体尺寸读取灰度图，可能空指针解引用。该入口同时用于本地皮肤和下载皮肤的预处理。

- 位置：[skins.cpp](../../src/game/client/components/skins.cpp) 的 `PrepareSkinData`，与 [image.cpp](../../src/engine/gfx/image.cpp) 的 `DeepCopy` 对照。
- 修复：灰度副本为空时返回失败，沿现有失败路径保留皮肤回退；未改变正常皮肤的灰度算法。临时像素由 `SQmSkinSourceData` 释放。
- 缺口：尚无真实 `PrepareSkinData` 分配失败的故障注入测试。没有用源码字符串断言或模拟灰度算法冒充该回归。

### F04 重要：重采样溢出或失败仍被当作加载成功

原输出帧数从浮点值直接转换为 `int`，异常采样率/长度可能超出表示范围。四个加载入口均忽略 `RateConvert` 返回值，分配或转换失败后仍返回有效样本 ID。

- 修复：在转换整数前检查输出帧数与声道容量；转换失败时卸载样本并返回既有的加载失败值 `-1`。
- 配套：生产帧数计算的测试覆盖上采样、下采样、无效采样率、零帧输出和超限输出。四个加载入口的实际失败恢复未做进程验证。

### F05 重要：下采样的循环起点可能落在音频末尾

例如 3 帧、48 kHz 的样本转换为 16 kHz 后只剩 1 帧，原循环起点为 2 时，四舍五入得到 1，已在有效帧之后。`AdvanceVoice` 此后不能推进该循环声音；这是确定的循环播放缺陷，未声称已经复现线程卡死。

- 修复：重采样后的循环起点限制为 `[0, 输出帧数 - 1]`。
- 配套：`SoundBuffer.DownsampledLoopAlwaysHasAtLeastOnePlayableFrame` 约束该边界及普通循环位置。真实设备听感尚未验证。

### F06 严重：异步读回请求扩容使渲染线程持有的结果地址失效

`BeginRenderTargetReadback` 把请求内部 `CImageInfo` 的地址写进命令，提交后立即返回。下一个请求在前一份命令完成前扩容 `std::vector`，会搬走结果对象；后端仍向旧地址写入图像。第二次提交之前才等待旧命令，不能保护此前发生的扩容。

- 位置：[graphics_threaded.cpp](../../src/engine/client/graphics_threaded.cpp)、[graphics_threaded.h](../../src/engine/client/graphics_threaded.h)；修复后的请求状态集中在 [render_target_readback_queue.h](../../src/engine/client/render_target_readback_queue.h)。
- 修复：使用地址稳定的请求队列管理图像、完成信号和回收状态；取消中的请求仍持有输出，收到完成信号后才复用槽位。图形前端继续负责生成和提交 GPU 命令。
- 触发范围：连续使用异步读回接口。当前扫描未发现玩家功能直接调用该接口，按客户端公开接口的内存安全缺陷处理；没有把它归因为已发生的玩家崩溃。
- 配套：7 项 `RenderTargetReadbackQueue.*` 单元测试涵盖扩容后写回、取消后完成、槽位复用、空结果、单次接管、乱序完成和设备清理。使用生产队列与真实完成信号，不包含 GPU 或真实渲染线程。

### F07 重要：设备重建后旧读回句柄可能匹配新请求

原请求数组在图形 `Init` 时清空，每个新槽位的代数又从 1 开始。持有旧设备读回句柄的调用者可能读到或取消同一索引的新请求。

- 修复：请求队列清空时保留代数计数，新分配继续递增并跳过 0；旧句柄不会在重建后的第一次分配中复活。
- 配套：`RenderTargetReadbackQueue.ResetDoesNotReviveHandleFromPreviousDevice` 验证清理后同索引重用、旧句柄查询与取消不影响当前请求。整个设备丢失和窗口重建流程尚未运行。

### F08 严重：字体扫描异常逃出工作线程

启动恢复与系统字体候选扫描共用 `CQmFontScanJob`。枚举、文件名/哈希字符串与结果容器分配可以抛出异常，`CJobPool::RunLoop` 直接调用 `Run()`，原扫描未处理异常，内存分配失败可沿线程入口终止进程。

- 位置：[qm_font_scan_job.h](../../src/engine/client/qm_font_scan_job.h)、[qm_system_fonts.h](../../src/engine/client/qm_system_fonts.h)。调用点为 `text.cpp` 的 `RequestSystemFontRestore`、`RequestSystemFontScan` 与 `UpdateSystemFontScan`。
- 修复：在扫描作业内记录失败并结束，保留此前完成的文件；读取回调抛错时释放已经交出的缓冲。Windows 注册表键改为 RAII 持有，枚举中途异常也会关闭。
- 配套：4 项 `QmFontScanFailure.*` 集成测试使用真实作业池、扫描任务和恢复协调器，注入枚举、读取、分配失败，检查下一任务仍能执行、部分结果可接收、改选后可再次请求。未运行真实系统字体目录或注册表场景。
- 剩余：字体扫描总量、FreeType face 数量和前台装载失败仍需后续审查；本批没有取得内存压力或启动实测证据。

第二批同时核对了已有保护：`FreeDescriptorSetFromPool` 释放后清空记录；Vulkan 离屏目标销毁入口已有延迟处理和提交等待；`ShutdownJobs` 早于文本引擎释放。上述候选未新增修复，尚不据此判定整个 Vulkan 或退出流程已经审完。

### F09 严重：离屏通道内销毁目标后立即复用槽位

`DestroyRenderTarget` 原先立即把前端槽位放回空闲链表。Vulkan 在离屏通道活跃时延迟销毁其他目标，并忽略当前目标的销毁；随后同帧 `CreateRenderTarget` 若复用该槽位，后端创建入口会直接释放旧 framebuffer、image 和 descriptor，绕过原本的 GPU 提交等待。

- 位置：[graphics_threaded.cpp](../../src/engine/client/graphics_threaded.cpp)、[render_target_pool.h](../../src/engine/client/render_target_pool.h)；对应后端见 `backend_vulkan_qm_render_targets_impl.h`。
- 修复：销毁立即使调用方句柄失效，但离屏通道结束前保留槽位；先排入 End，再排入 Destroy，最后允许复用。沿用后端已有的提交与等待，其他图形后端也按相同前端顺序接收命令。
- 配套：6 项 `RenderTargetPool.*` 单元测试覆盖延迟回收、重复释放、回收顺序、扩容、非法 ID 和设备重置。测试使用生产槽位池，不包含完整前端或 GPU。
- 触发范围：客户端接口允许的离屏通道内销毁/新建组合；已追踪 HUD、UI、聊天柔光调用，但尚未确认当前玩家路径会在同一通道内完成该组合。

### F10 严重：命令数据长度在进入容量检查前截断

`AllocCommandBufferData` 及图层命令使用 `size_t`，`CCommandBuffer::AllocData` 原先接收 `unsigned`。在 64 位进程中，超过 `UINT_MAX` 的请求会先截断；若截断值很小，容量检查可能成功，后续复制仍使用原长度。32 位上的分配加法也存在绕回风险。

- 位置：[graphics_threaded.h](../../src/engine/client/graphics_threaded.h)。
- 修复：分配入口保留 `size_t`，分别检查对齐填充和剩余容量，以减法避免容量检查自身溢出；失败不推进已用长度。
- 配套：4 项 `GraphicsCommandBufferAllocation.*` 单元测试检查大于 `unsigned` 的长度、最大 `size_t`、失败后的容量、对齐和重置。
- 可达性：地图非分组 quad 已按 GPU 批次限制，常规路径没有发现同类超量输入；其他命令入口的计数乘法与超大输入仍需继续审查。本项未取得玩家崩溃复现。

### F11 严重：字体图集扩容先破坏旧资源，再进行可能失败的分配

`IncreaseGlyphMapSize` 原先先卸载旧纹理，再依次 `new[]` 分配并替换填充/轮廓数据。分配异常会中断扩容；后续上传缓冲失败时也已经失去旧纹理，且扩容仍报告成功。

### F12 重要：离屏通道活跃时发起读回会中断命令录制

前端读回入口原先没有检查 `m_RenderTargetActive`。Vulkan 的中途提交函数只结束交换链通道；若离屏通道仍活跃，就会在未结束该通道时结束命令缓冲，进入图形错误路径。

- 修复：活跃离屏通道内返回无效读回句柄，调用方需在 `EndRenderTarget` 后请求。

### F13 重要：关闭系统字体显示后仍扫描全部文件，退出也无法取消

### F16 严重：文本测量越过显式字节范围，空文本参与无效字号换算

- 配套修复：字号缓存向调用方返回设置结果；FreeType 设置失败时停止测量、光栅化或字偶间距计算，避免沿用此前的字号。

### F17 严重：实体文字位图只限制子区域，没有限制实际图像

### F18 严重：纹理槽位扩容失败留下不同步的数组和未释放的上传资源

原空闲索引与代数数组分别扩容。第二次分配失败时，索引数组已经变长；后续分配会跳过扩容并访问仍较短的代数数组。普通纹理和成对字体纹理上传也缺少统一的槽位、像素接管回滚。本项关闭 B08。

- 配套：9 项生产槽位池单元测试，覆盖扩容失败与重试、成对申请中途失败、提交前异常、重复释放、旧句柄和设备重置。已补充测试，未执行；完整图形前端上传、真实 GPU 分配及各后端错误分支仍未运行验证。
