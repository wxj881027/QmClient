# 2026-11-05 术语表

术语表是翻译与 UI 文案的唯一口径，新增术语先补这里：本文档定口径，`qmclient_scripts/languages_qmclient/prompt_assets/terminology.toml` 做机器校验与机翻提示，`qmclient_scripts/languages_qmclient/translations/i18n/*.toml` 存译文，`data/languages/*.txt` 只是生成产物，不手改。

## 口径规则

1. 新增或改动术语按四步走：本文档 → `terminology.toml` → 对应模块 TOML 译文 → `extract/generate/validate` 全绿。
2. 单键标签（模式徽标、变体名、分类名、来源标签）只用短词，不写解释性长句；解释文字放配置说明或 Wiki 文案。
3. 同一个英文词在不同语义下必须拆开：优先在源码给 `Localize` 带上 context；拿不到 context 时只能选一个译法，并写进下面「已知冲突」。
4. 中文译文沿用现有中英混排规则：数字/英文与汉字之间留一个半角空格，句内标点用全角。

## 已知冲突与待办

1. **Hold 两义共用一个 identity**：demo 相机关键帧过渡 `SMOOTH / LINEAR / HOLD` 里的 Hold 是「保持不动」（`src/game/client/QmUi/QmDemoCameraPanel.cpp`），按键语义是「按住」（`src/game/client/components/qmclient/bind_workshop_ui.cpp` 的工坊模式徽标）。两处 `Localize("Hold")` 共用同一 identity，只能有一个译法，现按用户要求定为「按住」；相机过渡标签要正确显示需要源侧改用 `Localize("Hold", "Demo camera transition")` 并单独给译文。
2. **「古典」= DDmaX（已确认）**：DDmaX 系列的中文就叫「古典 / 古典 Easy / 古典 Next / 古典 Nut / 古典 Pro」，与 `menus.h` 的「古典图」一致。此前的错误不在译名，而在显示层：投票菜单、游戏内地图类型、收藏地图卡、卡片搜索索引把这几个组显示成 `Classic` / `Classic easy/next/nut/pro` 键，导致「古典」跑到 `Classic*` 上、工坊的 `Classic` 变体也被译成「古典」。现四处全部改用 `DDmaX*` 自己的键，「古典」只挂在 `DDmaX*` 上；`Classic` 只剩工坊变体一条，译「经典」。
3. **单键标签现在走源码字面量**：工坊变体名与分类名已登记在 `src/game/client/components/qmclient/bind_workshop_ui.cpp` 的 `BindWorkshopStaticLocalizableKeys()`（`apPresetLabelKeys`），由提取器正常扫描；此前临时挂的 `source_keys.EXTRA_LOCALIZE_STRINGS` 条目已删除。新增同类标签时仍按这里登记，不要再回 `EXTRA_LOCALIZE_STRINGS`。
