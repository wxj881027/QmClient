# 版本号与发布通道

状态：已确认。自 2026-10-02 起采用两段版本号，停止新增三段式版本。

## 版本与显示

- 基础版本固定为 `X.Y`。`X` 是产品大代，只在明确开启新一代时调整；`Y` 是正式发布序号，功能更新和修复更新都递增一位。
- 顺序为 `3.8 → 3.9 → 3.10`，不能按小数或字符串排序。新一代从 `4.0` 开始。
- 正式版显示 `3.3`，Git Tag 为 `v3.3`。不显示额外代号。
- 预览版显示 `3.4 Preview 1`，机器版本为 `3.4-preview.1`，Tag 为 `v3.4-preview.1`。预览批次是发布通道的附加信息，不是第三段正式版本号。
- 同一基础版本下按 `3.4-preview.1 < 3.4-preview.2 < 3.4` 排序；新的基础版本高于上一版本。
- 正式版可以直接发布，不要求先发布预览版。正式版发布后，下一轮预览面向下一个基础版本。

## 唯一来源

`src/game/version.h` 的 `QMCLIENT_BASE_VERSION` 和 `QMCLIENT_PREVIEW_NUMBER` 是本地版本来源。预览批次为 `0` 表示正式版；正整数表示预览版。客户端显示、安装包、更新清单和 Android 元数据使用相同定义。

版本只能通过 `qmclient_scripts/bump_version.py` 修改：

```text
python qmclient_scripts/bump_version.py --tag v3.3 --dry-run
python qmclient_scripts/bump_version.py --tag v3.3
python qmclient_scripts/bump_version.py --tag v3.4-preview.1
python qmclient_scripts/bump_version.py --describe
```

普通提交不递增正式版本号；开发提交用 Git SHA 区分。停用独立的 `QMCLIENT_DEV_VERSION` 数字线和 `QMCLIENT_STABLE_BUILD` 通道开关。发布 CI 根据目标 Tag 生成同一份版本定义，不允许安装包显示与 Tag 不同的版本。

Android 的内部 `versionCode` 单独编码，保证预览批次递增、正式版高于同版本预览版，并高于旧三段式版本使用的编码。它不作为公开版本号显示。

## GitHub 发布

- 正式版和预览版共用 `.github/workflows/build.yml`。正式版标为 Latest；预览版标为 Pre-release，不能占用 Latest。
- `.github/workflows/nightly.yml` 是预览调度入口，复用上述工作流，不再覆盖 `nightly` Release 和 Tag。旧 Nightly 可作为历史记录保留。
- 同一提交重跑 CI 使用原版本。新提交的预览包递增批次；正式版本只有在决定正式发布时递增。
- Windows、Linux、macOS、Android 均完成构建，Windows 更新清单及包签名完成后，先把全部附件上传至草稿，再检查上传状态与大小，最后公开 Release。
- 已公开的 Tag 和附件不得改写或覆盖。只有用户明确要求撤回时才删除对应 Release 和 Tag；删除的编号不再复用。
- 未公开的失败 Tag 也保留其原提交。修复源代码后选择新的预览批次或正式序号，不增加第三段补丁号。
- 发布说明以前一个已公开的正式 Release 为基线，不把失败构建留下的 Tag 当作上一正式版本。

## 客户端更新

更新通道跟随安装的构建：正式包只接收正式版；预览包可接收更新的预览版及正式版，安装正式包后回到正式通道。版本比较必须按整数和通道排序，不能降级或把同一预览批次反复作为新版本。

历史一段、三段、四段纯数字版本只用于识别已有安装与生成历史说明，不再用于新发布。预览更新仍执行相同的清单、包签名和内容校验。
