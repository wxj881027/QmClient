## 0. 结论（三句话）

1. **不是缺弹窗，是一个组件被当成四种语义用。** 历史上 `CUi::ShowPopupConfirm` 用一个布尔值同时扮演模态确认与气泡确认；术语层没有定义，`Popup` 一个词指过动作菜单、消息框、确认框、二级面板。
2. **缺三个语义位**：Toast（菜单域）、Popconfirm、InlineHint。已在 2026-10-21 补齐前两个。
3. **一词一物**：`Popup` 不再作为组件名出现；每类交互只有一个公共入口，AI 写 UI 时按 §1.4 决策树选型，禁止照抄最近一处调用。

## 1. 名词与层级模型

### 1.1 九个名词

| 名词 | 一句话定义 | **不是** | 入口 |
|---|---|---|---|
| **Toast** | 操作结果的非阻断短反馈，自动消失 | 不是弹窗，不需要关闭，不抢焦点 | `qm_ui::Toast` |
| **Tooltip** | 悬停补全「这是什么」 | 不承载段落说明、不放命令全文、不做交互 | `CTooltips::DoToolTip` |
| **InlineHint** | 常驻或点 ⓘ 展开的行内解释 | 不是 tooltip，不悬停触发 | `QmInlineHint`（未实现） |
| **Popconfirm** | 附着在触发控件上的二次确认 | 不是模态，不锁页面、不画遮罩 | `qm_ui::Popconfirm` |
| **ActionMenu** | 一组同权动作的展开列表 | 不是下拉选择器、不是确认框 | `CUi::DoPopupMenu`（待包装） |
| **Alert** | 必须知会的单按钮弹窗 | 不是成功提示、不做决策 | `CUi::ShowPopupMessage` |
| **ConfirmDialog** | 需决策的（破坏性）确认弹窗 | 不是单条可恢复操作（那用 Popconfirm） | `CUi::ShowPopupConfirm` |
| **SecondaryPanel** | 居中大面板，承载需滚动的次级任务 | 不是页面、不做一次确认；**属于 Modal 一族**（全阻断 + 遮罩 + 显式关闭） | `CSecondaryPanel` |
| **Page** | 主任务切换的全屏区域 | 不是浮层、不是页签、不是卡片 | 菜单 `PAGE_*` |
| Drawer | **本项目不引入**，由 SecondaryPanel 覆盖 | — | — |

### 1.2 层级栈（Z 序由策略决定，不由注册顺序决定）

| 层 | 成员 | 阻断 | 消失时机 |
|---|---|---|---|
| L0 | Page | — | 切换即替换 |
| L1 | SecondaryPanel | 全阻断 + 遮罩 | X / Esc / 点外部 |
| L2 | ActionMenu、Popconfirm | 局部（Popconfirm 只锁锚点） | 执行 / 点外部 / Esc（=取消） |
| L3 | Alert、ConfirmDialog | 全阻断 + 遮罩 | 必须点按钮 / Esc |
| L4 | Toast | 永不阻断 | 2.5–4s 自动；≤3 条 |
| L5 | Tooltip | 永不阻断 | 移开 0.25s 淡出 |

### 1.3 五条铁律

1. **能非阻断就不阻断**：局部确认优先 Popconfirm，全局确认才上 Modal。
2. **阻断必须可见**：要么有遮罩，要么锚点归属清晰（有阻断事实就必须有阻断暗示）。
3. **危险动作不默认确认**：确认按钮带危险色、正文含对象名；**回车不绑定确认**（本项目裁定：回车在确认类浮层里一律无效，只能点按钮），Esc 恒等于取消。
4. **成功不打断，失败要可行动**：成功=Toast；失败=Toast + 重试动作，或需要读详情时 Alert。
5. **重建过程不外露**：列表刷新（下载/删除/重扫）只允许用户看到「多一张 / 少一张」，禁止把清空、重扫、重解码的过程展示给用户（详见 §4）。

### 1.4 决策树（按顺序问，命中即停）

1. 需要用户做决定吗？→ 不需要：**Toast**（结果）/ **Tooltip**（名称）/ **InlineHint**（解释）。
2. 决定只影响**眼前这一行/这一个对象**，且错了能重来？→ 是：**Popconfirm**；否：**ConfirmDialog**。
3. 内容需要滚动、多个控件、或要读一段东西？→ **SecondaryPanel**。
4. 只是几个同权动作的入口？→ **ActionMenu**。
5. 属于主任务切换？→ **Page**。

## 3. 组件规范

### 3.1 Toast（`qm_ui::Toast`）

- **定义**：操作结果的非阻断短反馈；底部居中；最多 3 条（超出丢最旧）；约 3.5s 自动消失；左侧语义条区分成功/失败；可带一个动作按钮（如「重试」）。
- **入参**：`Toast(EQmToastKind, const char *pText)`；动作按钮重载带回调。
- **硬约束**：不接收坐标；不进入 Tab 链；本身不接收点击（除动作按钮）；≤2 行，超出改用 Alert；失败必须带重试动作。
- **动效**：0.18s 上滑淡入 / 0.12s 加速离场（`CToastQueue::FADE_IN_SEC` / `FADE_OUT_SEC`）；动效等级 0 直接出现。
- **反例**：承载需要决策的事；当错误详情用（详情走 Alert）。

### 3.2 Tooltip（`CTooltips::DoToolTip`）

- **定义**：悬停 0.35–0.75s 出现的名称/单位/快捷键补全；≤300px；黑 40% 圆角、无箭头。
- **硬约束**：不承载段落说明（那是 InlineHint）；不放完整命令串；定位需避让兄弟控件。
- **本项目现状**：删除/下载等图标按钮必须配 Tooltip（资源商店已接）。

### 3.3 InlineHint（未实现）

- **定义**：常驻或点 ⓘ 展开的行内解释，10–11px 次级文字，0.12s 高度过渡。
- **用途**：替代「tooltip 塞整段说明」的越界用法；卡片 Wiki tips 的正文形态之一。

### 3.4 Popconfirm（`qm_ui::Popconfirm`）

- **定义**：附着在触发控件旁的轻确认气泡。用于**单条、可恢复、代价低**的动作（下载、单条删除）；不可逆或跨范围的操作必须用 ConfirmDialog。
- **硬约束**：
  - 必须锚定触发控件矩形，禁止传屏幕坐标；
  - 不画遮罩、不锁页面滚动；**只锁锚点热区**；
  - 摆放边界是**所在列表的裁剪区**（`CListBox::ClipRect`），不得飞进导航栏；
  - **跟随列表滚动**：每帧按目标控件当前矩形重放；目标滚出视口 → 自动关闭并按取消处理；
  - 点外部 = 取消；Esc = 取消；**回车无效**（防误触删除）；
  - 内部第一次按下必须直达按钮（`m_PressInsideGoesToContent`），不允许出现「要点两下」；
  - 结果已产生（确认/取消）后不得再重放气泡；
  - 关闭后焦点回锚点。
- **入参**：`SQmPopconfirmContext`（消息、按钮文案、危险色标记）+ `QmShowPopconfirm(pUi, ctx, anchorRect, pBounds)`。
- **动效**：0.18s 从锚点展开。

### 3.5 ActionMenu

- **定义**：2–7 个同权动作的展开列表；包裹触发按钮外框；≤8 行滚动。
- **约束**：不承载确认文案、不承载表单；行尾「⋯」或右键触发。
- **状态**：底层能力可用（DoPopupMenu），待包装成唯一入口。

### 3.6 Alert（`CUi::ShowPopupMessage`）

- **定义**：必须知会的单按钮居中弹窗（掉线、失败详情、版本公告）。必须有标题；Esc = 关闭；不做决策。

### 3.7 ConfirmDialog（`CUi::ShowPopupConfirm`）

- **定义**：需要决策的确认弹窗，用于**不可逆、跨范围、需解释**的操作。
- **硬约束**：
  - 必须有标题 + 对象名（`Delete "xxx"?`）；
  - 危险操作确认键用危险色（`ETone::DANGER`）；
  - **回车不触发任何按钮**；Esc = 取消；
  - 按钮文案用 Cancel/OK，不用 Yes/No（指代不明）。
- **状态**：新路径已达标；旧 `CMenus::PopupConfirm`（22 处）迁移在批 3。

### 3.8 SecondaryPanel（`CSecondaryPanel`）

- **定义**：居中大面板（约 780×470），承载需要滚动与多控件的次级任务（资源详情、商店、地图预览、**卡片 Wiki tips**）。
- **判定**：它**是 Modal 一族**——全阻断 + 遮罩 + 显式关闭（X / Esc / 点外部）；"长得大"不是 Page 的理由，阻断与遮罩才是。
- **约束**：必须有标题栏与关闭；只用于需要滚动的次级任务；一次确认、短提示不得放进来。

### 3.9 Page

- **定义**：主任务切换的全屏区域；只由导航切换。全局页 0.22s 位移转场；设置页**有意不做位移**（卡片入场淡入代替）。

## 4. 资源页刷新与列表动效规约（2026-10-21 新增）

> 资源页（设置 → 资源）有两条几乎复刻的布局分支：`UsesCombinedAssetList` 类目（实体背景等，本地+商店合并一个网格）与独立网格类目（表情/游戏/粒子等）。**改任何一条前必须先确认类目走哪条分支**，两条都要接。

### 4.1 软重扫原则（铁律 5 的落地）

- 下载完成 / 删除资源后的列表刷新，**禁止** `ClearCustomItems`（清空列表 + 卸全部贴图 + 异步重扫）。
- 正确做法：复位加载状态（`ASSET_LOAD_STATE_UNLOADED` + warmup 复位）让后台重扫目录；合并发布**按名字去重**（已有条目连贴图带状态原样保留，只追加新出现的）；整份扫描完成后用 `DropMissingLocalAssetEntriesTyped` 摘掉真正被删除的条目（顺带卸载其贴图）。
- **必须跳过合成条目**：`default`、空白材质（`IsProtectedAssetName`）不在磁盘扫描结果里，摘掉它们=删贴图再重建（曾导致「先集体上移又下移 + 贴图消失」）。
- 实体背景页例外：走 `RefreshEntityBgHierarchyView`（对象保留式重建：旧条目按名字搬回贴图与预览状态，只卸载真正消失的条目）。
- 合并是分帧 chunk 应用的（64 条/帧）：**去重放 publish 内，摘除只能放整份扫描完成之后**，否则会误删。
- 刚下载的资源：本地卡片先借用商店已加载的缩略图（`Asset.m_ThumbTexture`）顶住本地预览解码窗口，避免灰块。

### 4.2 换位动画（槽位追随，`CQmSlotReflow`）

- **只按槽位序号差**（第几行第几列）算位移，**禁止用上一帧屏幕矩形**做 FLIP（切页/列表重建时会算出巨大位移把卡片画到裁剪区外——已发生过的事故）。
- 欠阻尼弹簧 k=380 c=26（ζ≈0.66，约 0.3s 收尾回弹）；换位那一帧必须完整停在旧位置（先返回后推进）。
- 积分步长：调用方把 Dt 钳到 100ms，弹簧按 1/60 拆成固定小步积分（`StepSpringStable`），窗口帧不再发散（工作区未提交，测试 `QmSlotReflow.SlowFramesKeepDisplacedCardBoundedAndSettle`）。
- 换位跨超过 8 个槽位或 3 行 → 判定为「换了一个列表」，直接对齐不做动画。
- 切页、换列数、动效等级 0 → 直接对齐。
- 步距必须用**真实列距**（`StableList.w / Columns`），不能用 `Margin+TextureWidth`（低估导致滑动错位）。
- 已接线：独立网格（`s_ListBox`）与合并列表（`s_WorkshopAssetsListBox`，本地与商店两个分支）。
- 换位诊断日志（`assets_reflow: slot a -> b ...`）已按用户要求删除；再排查时临时加回，不要长期占日志。

### 4.3 尺寸过渡

- `CListBox` 默认开启滚动条占位过渡（`m_AnimateScrollbarReserve=true`）：滚动条出现/消失时内容宽度连续变化，滑块随轨道展开淡入。
- 裸 `CScrollRegion` 使用处需显式 `ScrollParams.m_AnimateScrollbarReserve = true`（好友列表已开，其余待推广）。

### 4.4 已知未解（诚实清单）

- **下载/删除后的残留闪烁（第三轮：按代码路径定位，非盲修）**。没有走帧级取证，而是把「软重扫 → 合并 → 重排 → 预览队列」这条链逐跳读通，定出四处可证缺陷：

  | # | 缺陷 | 用户可见表现 | 修法 |
  |---|---|---|---|
  | 1 | 合并把新条目一律追加到尾部，收尾时 `EnsureDefaultAssetVisible` 整表 `std::sort` 把所有卡片重新编号 | 新卡先落到最底部、下一帧集体跳回正位；`CQmSlotReflow` 按巨大槽位差再走一遍 = 两次位移 | `PublishSettingsAssetMergeEntriesTyped` 改为增量归并：新条目按 `AssetResourceNameLess` 排好后归并进已有序前缀，收尾的整表排序变成幂等操作 |
  | 2 | 合并完成即 `++epoch` 并清空解码/就绪队列，但条目 `m_PreviewState` 仍停在 `LOADING`，且 `StartPreviewDecode` 对 `LOADING` 直接返回 false —— 再也不会被重新调度 | 卡片永久灰占位＝用户报的「贴图缺失」 | 合并入口先调 `RestartOrphanedCustomPreviewDecodes`：无贴图且挂 `LOADING` 的条目退回 `UNLOADED`。只对当前 tab 生效（别的 tab 不发起解码，且 `gs_vpSearch*` 只为当前 tab 重建，遍历别的 tab 会读过期指针） |
  | 3 | 句柄身份用 `m_Index`（搜索列表下标）判定，合并重排后下标漂移 | 解码结果被判「过期」丢弃，贴图加载完又变灰 | 新增 `SettingsAssetPreviewHandleReferencesAsset` 只按名字认领；`FindCustomItemByPreviewHandle` 先试下标再按名兜底 |

## 7. 工程注意事项（写给后续 AI）

- **LTCG 陷阱**：新跨编译单元接口的签名里不要出现 `CUIRect`（头文件里被前置声明为 `struct`、实际是 `class`，`/GL` 链接会 LNK2001）。用 `CUi*` 内部取矩形。
- **CMake 合成提交**：主目录 CMakeLists 常混有并行会话改动，提交时用 `git show HEAD:CMakeLists.txt` + 定点替换合成 blob（`hash-object -w` + `update-index --cacheinfo`）。**替换锚点必须先 assert 出现次数，否则会重复插入条目**（曾导致重复源文件条目 + 引用已删文件，全新 checkout 配置失败）。
- **构建锁**：`tmp/build-locks/*.lock` Permission denied = 并行会话在构建，轮询等待即可，不要删锁、不要杀进程；`LNK1104 DDNet.exe` = 用户客户端还开着，等它关闭。
- **资源页双分支**：任何资源页改动都要同时核对 `UsesCombinedAssetList` 两条路径（§4 开头）。
- **时序问题先上日志**：`dbg_msg` 一次性日志 + 用户复现，是本页所有疑难（气泡、闪烁、动画）唯一可靠的排障路径。
- **数字口径**：本文的「≈N 处」是 `src/game/client` 内的调用点计数（剔除声明与定义，`PopupMessage(` 不匹配 `ShowPopupMessage(`）；Wiki 条目按 `QmCardWiki.cpp` 的表项计，翻译条数按 TOML 的 `[[message]]` 计。行情变化时重测，不要凭记忆改数。
