# UI 抗锯齿与模糊/FSAA 解耦方案

状态：核心 SDF 常驻、旧配置清理、背景/文字分层已完成；整帧历史快照因文字光晕被否决并保持撤回。

## 背景与约束

- FSAA 保持与上游 DDNet 一致：继续由 `gfx_fsaa_samples` 驱动交换链/后缓冲多重采样，不新增样本档位、不改变上游语义。
- UI 在 1080p 下主要依赖抗锯齿平滑圆角、细边框和半透明面板边缘；MSAA 对整屏 UI 的填充成本过高。
- 模糊源优先来自背景边界处捕获的交换链，而不是最终后缓冲：世界/地图/菜单背景画完后、任何 HUD/聊天/菜单文字之前捕获一次并冻结，随后前景直接画到交换链。只有后端不支持交换链捕获时，才回退到与交换链同采样数的离屏背景层。

## 已实施：核心 UI SDF 常驻

`qm_enhanced_rendering` 和 `qm_enhanced_sdf` 已删除。Vulkan 启动时无条件尝试创建圆角 SDF 与 Media Island SDF 管线；可选程序化圆环仍由 `qm_enhanced_procedural_ring` 控制。SDF 创建失败时只回退对应效果，不关闭其他 SDF 能力，也不把失败扩大为图形初始化失败。旧配置名会在加载时被清洗，不再写回配置文件。

`QmEnhancedMarkDisabled` 只在设备丢失/可选管线创建失败时熔断 Media Island 和程序化圆环；圆角 SDF 能力保留，保持 UI 核心 AA 常驻。OpenGL 原本就无条件加载 SDF 程序，保持不变。

UI 侧已有公共路径：

- [CUIRect::Draw](../../src/game/client/ui_rect.cpp) 在 `HasRoundedRectSdf()` 时走 `DrawRoundedSurface`；
- [rounded_rect_sdf.frag](../../data/shader/rounded_rect_sdf.frag) 用距离场覆盖率做逐像素抗锯齿；
- [UiSurface.cpp](../../src/game/client/QmUi/UiSurface.cpp) 负责填充、边框和四角半径。

后续仍需审计仍直接调用 `DrawRect`/`QuadsDrawFreeform` 的圆角 UI 路径，把非高频 HUD 的表面统一迁到 `DrawRoundedSurface`。

## 被否决：整帧帧边界历史快照

曾实现 `IGraphics::CaptureBackbufferForNextFrame` + `CUi::m_GaussianBlurHistory`：帧末把最终画面保存到 1/4 单采样目标，下一帧模糊直接采样它。这样可以去掉帧中 MSAA resolve/pass 重启，但实机截图暴露了严重问题：

- 帧末画面包含上一帧的服务器列表、聊天、标题等文字；
- 下一帧把整帧历史当背板模糊，文字被一起模糊成亮色光晕，叠在当前文字下方，表现为“文本发亮”；
- 模糊源不是背景层，而是整帧，语义上也不正确：面板不应该把自己的文字模糊成背景。

因此整帧历史不能作为模糊背板。相关捕获调用、`CaptureBackbufferForNextFrame` 接口和 `m_GaussianBlurHistory` 实现已撤回；模糊回到“在 UI 文本之前捕获当前背景”的路径，避免继续污染文字。等背景层独立后再重新设计背板快照接口。

## 已实施：背景层与文字层分离

渲染在 `CGameClient::OnRender` 中按显式边界分成两段：

```text
背景层（离屏，与交换链同采样数）：
  世界 / 地图背景 / 菜单背景
  结束时 resolve 为单采样纹理，再降采样到 1/4 模糊源

前景层（交换链，FSAA 保持上游）：
  HUD / 聊天 / 菜单文字 / 控件 / 弹层
  不进入模糊源
```

具体实现：

- `CUi::BeginBackgroundFrame` 在背景边界优先捕获一次交换链作为模糊源；只有 `IsBackbufferCaptureSupported()` 为假时才创建 `CUi::BeginBackgroundLayer` 的离屏目标，`EndBackgroundLayer` 结束时由后端 resolve 并合成回交换链，模糊再从 resolve 图降采样。
- 实测部分 Vulkan 驱动上离屏多采样目标 resolve 后内容不完整，导致模糊背景只覆盖左侧一块；因此可捕获后端默认走捕获路径，离屏层仅作为不支持捕获时的回退。
- 组件顺序在 `m_Hud` 之前收口：`m_Menus.RenderBackgroundLayer()` 先恢复 `Ui()->MapScreen()` 并清除上一帧可能残留的裁剪区，再画菜单背景，然后结束背景目标并调用 `CUi::BeginBackgroundFrame()`。HUD、聊天、菜单页和弹层都在其之后绘制。这里不能省略 `MapScreen()` 或裁剪清理：组件边界处仍残留世界/HUD 的投影或服务器列表的窄裁剪，菜单背景会整体左移或只剩左侧一条。
- Vulkan 的离屏多采样 render pass 复用交换链附件格式与子通道结构，因此直接复用普通世界/菜单管线；OpenGL 使用多采样 renderbuffer，结束时 blit 到单采样纹理。
- HUD Media Island 不再维护第二套捕获/模糊目标，统一复用 `CUi` 的背景模糊结果。
- 背景层只包含世界和菜单背景。面板背板本身是前景半透明材质，模糊采样的是它后面的背景，因此不会把面板自身文字或控件再模糊一次；嵌套面板的颜色混合仍由正常 alpha 合成完成。
- 后端支持交换链捕获时，在背景边界捕获一次当前交换链；后端不支持捕获时，才回退到多采样离屏背景层。`CUi` 仍禁止在未声明背景边界时捕获，避免把已经绘制的文字带进背板。

实机截图（1280x720）：Vulkan FSAA 4 与 OpenGL FSAA 4 均为背景模糊、文字清晰；Vulkan FSAA 0 走回退捕获路径，效果一致。菜单背景位置另用同一窗口的 blur 0/1 对照核对，见 `tmp/blur-layer-verify/menu-blur-off-reference.png` 与 `menu-aligned-after-map-screen.png`。全部证据在 `tmp/blur-layer-verify/`。

## FSAA 保持上游

- 不改变 `gfx_fsaa_samples` 的取值、上限和默认值。
- 不把 FSAA 改成离屏/实时两套配置。
- 背景层使用与交换链相同的采样数，前景层仍直接写多采样交换链；两层都保留 MSAA，模糊只读取背景层 resolve 后的单采样图。
- SDF 是 UI 的主 AA 路径，FSAA 仍按上游对交换链生效；两者是叠加关系，不是互斥开关。

## 渐变填充 SDF（已完成）

`DrawRoundedGradientSurface` 原先在多于一种颜色时使用 32×16 网格近似填充，只在边框走 SDF；圆角处仍可能出现多边形边缘。现在把渐变参数并入圆角 SDF 的同一份 uniform（`SRoundedRectSdfParams`，5 + 7 色 + 3 组参数 = 15 个 `vec4`），由片元按 CPU `SQmColorGradient::Position/Sample` 的同一套线性/径向/角向/反射/菱形语义采样，再乘 SDF 覆盖度。普通纯色填充仍走同一管线，只多一个按 draw 一致的启用分支。

- 渐变颜色数上限 7，与 `CMessageGradient::MAX_COLORS`、`SQmColorGradient` 一致。
- 边框仍使用独立颜色和外/内 SDF 差；渐变填充不会出现“边框垫底透出”的旧问题。
- 不使用 SDF 时保留原网格回退；不支持 SDF 的后端不会因为渐变新增依赖。
- OpenGL、Vulkan、Metal 三个着色器入口保持同一份语义，合同测试约束 uniform 布局和函数入口。

## 圆角 SDF 与 Media Island SDF 保持两条管线

不合并为一条。两者共享“有符号距离”思想，但语义和资源完全不同：

- 圆角 SDF：无纹理、固定 15 个 `vec4`、单矩形/四角半径/边框，是普通 UI 的核心路径。
- Media Island SDF：采样背景纹理，最多 12 个附加项，包含液体平滑并集、轮廓环、卫星环、阴影和内容裁剪。

合并会让每个普通卡片都多带纹理描述符、附加项分支和更大的 uniform；Media Island 的失败也会扩大为整个 UI 圆角失败。保留两条管线、共享公共创建/绑定代码，是更稳妥的边界。渐变能力已并入圆角管线，不需要第三条。

## 不采用 MTSDF（已实机验证并回退）

MTSDF（多通道 SDF）用 RGB 存不同方向的伪距离、A 存真实距离，主要解决**纹理图集**里的尖锐角重建。

图标与文字这两条图集链曾实际做过 MSDF/MTSDF：烘焙脚本、图集资源、专用 shader 和字体回退都接上过，实机结果是用处不大、成本还高，因此已整体回退，当前代码与随包资源里不再有 MSDF/MTSDF 图集、shader 或生成脚本；安装器只保留清理旧版本残留文件的指令。

回退原因同样适用于圆角表面：

- 圆角矩形在片元里已有精确解析距离，不需要预烘焙纹理；
- MTSDF 会引入图集分辨率、采样过滤、内存和额外管线；
- 图集分辨率固定，缩放和高 DPI 下反而比解析 SDF 更差；
- 图标本身是随包字体字形，走字体图集已经够用，再加一层 MSDF 只增加链路。

结论：圆角表面继续用解析 SDF；文字和图标继续用现有字体/图集路径，不再评估 MSDF/MTSDF。

## 渐变 SDF 的真实 GPU 像素回归（已完成）

候选栏是 `DrawRoundedGradientSurface` 的唯一生产调用点，而渐变是否连续、圆角是否约 1 像素羽化只有 GPU 片元能决定，CPU 单测和 shader 语法检查都证明不了。补了一条真实 GPU 像素回归：

- 探针只由测试环境变量 `QMCLIENT_TEST_IME_GRADIENT_PROBE` 开启，**不提供控制台命令**：它会在屏幕上画出彩色胶囊，不能成为玩家可触发的正式功能。开启后 `CGameClient::OnRender` 在组件之后、交换之前，把**同一份生产绘制函数** `DrawRoundedGradientSurface` 画到交换链左上角的固定 512×128 胶囊上：纯黑底板 + 纯绿 2px 边框 + 左红右蓝线性渐变。不带该环境变量时，探针代码不会被调用，控制台也不存在对应命令。
- 用引擎自己的 `screenshot` 取回最终呈现像素，Python 侧按颜色掩码逐像素断言：
  - 渐变跨度 ≥ 240，最大平台 ≤ 4 像素，无反向跳变（250 / 2 / 0）；
  - 外缘圆弧 1 像素环带上有 ≥ 40 个覆盖度混合像素（实测 113），硬阶梯边缘为 0；
  - 胶囊尖端列高 / 中心列高落在 (0.02, 0.75)（实测 0.20）；
  - 上下边框各覆盖 ≥ 370 像素（实测 396）。
- 探针先铺纯黑底板是必要的：菜单背景本身是渐变，羽化像素没有固定底色就无法逐像素判定。
- `screenshot` 只在窗口持有输入焦点时才真正取像素（否则 `WindowActive()` 为假、命令被静默丢弃），所以脚本每轮重试都会重新聚焦。

验证入口：`python qmclient_scripts/integration/ime_gradient_sdf_smoke.py <build-dir>`。分析器本身有 4 个 Python 单测（`test_ime_gradient_sdf_smoke.py`），其中两个是反向用例：纯色填充会被判定为「渐变跨度不足」，去掉羽化会被判定为「边缘未抗锯齿」。

两次真实回归注入都已被捕获：把渐变量化成 8 级台阶后报「渐变平台 64 > 4」，把 `Coverage` 改成硬阈值后报「0 blended pixels on the outer arc < 40」。恢复后指标回到 250 / 2 / 113。

探针使用固定已知颜色（纯黑/纯红/纯蓝/纯绿）而不是 `ui_token`，因为断言需要确定基准；已在 `audit_ui_color_tokens.py` 的文件白名单中登记理由。

## 实施顺序

1. 核心 SDF 常驻（已完成）：删除 `qm_enhanced_rendering` / `qm_enhanced_sdf`，Vulkan 始终创建圆角与 Media Island SDF。
2. 整帧帧边界快照（已否决并停用）：文字被模糊成光晕，不能作为背板。
3. 背景层/文字层分离（已完成）：背景层与交换链同采样数，resolve 后作为模糊源；前景层继续走交换链与 FSAA。
4. 补齐 UI 直绘圆角路径，确保普通菜单/卡片/弹窗全部走 SDF。
5. 用 1080p/125% 缩放的设置页、二级弹窗、输入框、细边框截图核对 SDF 质量，并对比 `FSAA 0/2/4/8 × blur 0/1` 的 GPU 时间。

## 未完成与风险

- 已完成 1280x720 的 Vulkan/OpenGL FSAA 4 与 Vulkan FSAA 0 回退路径实机截图；尚未完成 1080p、125% 缩放、FSAA 2/8 和 GPU 帧时间矩阵。
- 背景层会引入一次额外的全屏离屏合成（世界/菜单背景写入多采样目标后 resolve 并回绘）。是否在低端 GPU 上需要按 `blur=0` 跳过该层、或对静态菜单背景缓存，需要帧时间数据决定。
- 面板背板仍在交换链前景层；如果未来需要“面板叠面板”的背板也进入模糊源，需要新增更细的背板快照边界，不能复用当前整帧背景。
- SDF 的 feather 目前约 1 像素；如果 1080p 下仍偏硬，可在保持像素对齐的前提下调到 1.25～1.5 像素，并用截图对比，不能只凭感觉加宽。改动后要重跑 `ime_gradient_sdf_smoke.py`：它会把 1 像素羽化量化为外缘环带混合像素数，超过现有范围就说明羽化被改宽或改没了。
- 设备丢失后的会话熔断仍会关闭 Media Island 和程序化圆环；圆角 SDF 保留。是否在设备丢失后也停用圆角 SDF，需要实机故障数据再定。
