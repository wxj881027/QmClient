## Bind：当前蓝图能做什么

**当前蓝图适合可视化单键的命令串。目标蓝图要能打开真实 CFG，读清楚文件引用和命令顺序，并能原样保存。** 两者可共用画布，执行模型需要换掉。

## Bind：目标交互与数据

```text
右上角导航「Bind 编辑器」 → 独立工作区（类似地图编辑器）
┌─ 工具栏：打开 / 保存 / 撤销 / 应用 / 返回 ──────────┐
│ 文件与入口键  │ CFG 引用画布   │ 原文、行序与诊断 │
│               │ 3D 键盘 / 鼠标（底部可收起）      │
└──────────────────────────────────────────────────┘
```

1. **键盘和蓝图在同一个工作区联动。** 进入后直接展示蓝图和底部 3D 键盘；键盘可收起给画布让空间，重新展开保留选中键。复用现有读键与修饰键处理，点键就在画布高亮绑定及其引用，右侧显示当前命令串和占用情况；点画布里的绑定也会反向选中对应键。简单 Bind 可在右侧原地编辑，复杂引用直接在同一画布内定位。键盘和蓝图共享当前工程、选中项和草稿，操作过程无需切页。绑定在 F1 或运行 CFG 后被改写时刷新当前值，保留未保存草稿并提示冲突。退出工作区时处理未保存修改，返回进入前的页面。
2. **蓝图总览以文件为块，文件内部以文本顺序为准。** 双击打开 CFG，列出行号、命令和注释；同一行的多个命令按引号外分号拆开展示。实线标「立即执行」，虚线标「为某键安装引用」，线可定位到具体来源行。共享文件可以只画一块，但每次调用都要保留出处和顺序。移动节点只改布局；拉线需显示插入哪一行、写入什么命令。首版用明确的端口和目标选择器，跨文件右键长按拖线可后续加。
3. **CFG 原文是执行来源，图是可编辑的视图。** 保留空行、注释、引号、顺序和未知命令；未知命令保留原文、标成未解析。图上操作更新对应文本范围；位置、缩放、折叠等另存，改标题不改变实际路径。工程按客户端相同的存储搜索规则解析路径；缺失目标、工作区外的目标和无法解析的命令分别提示。不会为了生成图而执行导入内容。
4. **先修改草稿，再保存或应用。** 保存只写文件；应用先展示将安装的入口键、当前值、新值，以及可静态识别的后续重绑。应用时重新检查键位和文件版本；仅在文件成功落盘后写入入口键，失败时恢复已改文件。编辑撤销与应用撤销分开；不把任意 CFG 执行后的游戏状态或聊天副作用承诺为可撤销。
5. **校验按 DDNet 实际语义做。** 先复用命令注册表与解析规则；命令长度、引号、目标缺失和即时调用深度分别报告。当前帮助的「`exec` 最多五层」[实际对应的是旧蓝图的 Bind 文本计数](../../src/game/client/components/qmclient/bind_workshop.cpp#L1264)，不能沿用为引擎规则。文件依赖按需索引、缓存并局部刷新，画布避免每帧扫盘或展开整条依赖树。沿即时调用预览顺序遇到递归就停止；延后绑定保留为导航边。
