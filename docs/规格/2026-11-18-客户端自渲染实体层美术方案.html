0. 结论与定位

这是一份纯美术方案。性能维度已经结案：常规对局（1080p–4K、zoom ≤ 1）下实体层单层顶点带宽约 0.4–1.6 MB/帧，几何量不是瓶颈；任何"合并网格 / 自渲染"带来的帧时间收益都在测量噪声以内。

因此本方案只定义接管哪些实体的外观、外观长什么样、美术资产如何被渲染管线消费，不承诺性能收益。

另一条前提：TClient 的墙体轮廓（qm_outline_*）已经把这件工作做掉了大半——类型网格、8 邻域缓存、逐边 quads（含转角收口）都在 components/tclient/outlines.cpp 里跑着。它缺的只是"内部填充"与"隐藏原贴图"，不是"轮廓"。因此 P0 不需要新开着色器管线，详见 2.2 与 5.4。

做

Freeze / Deep Freeze / Unfreeze / Deep Unfreeze / Death / Start / Finish，共 7 类、9 个 tile 常量。

不做

Solid / Nohook 复用既有轮廓，并补圆角与内部填充；不替换 tileset 贴图。Through 系列不可见本身是玩法信息。

2. 现状架构

实体层的数据与外观是分离的：地图加载时把 tile 表读进内存给碰撞与预测用；渲染侧在 Init() 阶段把整层实体烘焙成静态顶点缓冲，每帧只按可见行提交索引区间。替换外观只需要替换片元着色这一段，几何、剔除、层级都不用动。

2.1 当前实体层的四个事实

  1. 几何是静态的。UploadTileData 在载入期把每层每一格展开成 4 顶点 / 6 索引，写进一条容器缓冲。
  2. 剔除是每帧现算的。渲染时按视口算出可见行列，拼成索引区间列表一次提交；CPU 成本只与可见行数有关。
  3. 分类是分子层的。Game 层实际建了 6 份缓冲：基础一份 + Death / Freeze / Unfreeze / DeepFreeze / DeepUnfreeze 各一份，以便分别应用透明度。
  4. 外观只有一种来源。片元取 CMapImages::GetEntities()，也就是用户选定的实体皮肤图集（默认 editor/entities_clear/<mod>.png），tile 索引即纹理数组层号。
第 4 条决定了本方案的性质：我们要替换的是"实体长什么样"，而不是"实体在哪里、什么时候画"。也正因如此，它与现有的实体皮肤系统天然冲突，必须在配置层显式二选一（见第 6、7 节）。

2.2 既有实现：TClient 墙体轮廓

仓库里已经有一套和本方案高度重合的东西：src/game/client/components/tclient/outlines.cpp（配置前缀 qm_outline_*）。它在 OnMapLoad 时把 Tele / Game / Front 三层压成一张类型网格，在 OnRender 时逐可见格画边。轮廓、连通性、转角收口都是现成的。

4. 视觉规格

4.1 三条设计原则

边缘优先

可通行 / 不可通行、安全 / 致命的判断发生在边界。内部质感永远服务于边缘，不得压过边缘的对比度。

动效克制

任何循环动画的亮度变化不超过 ±18%，周期不短于 2.4 s。高速跑图时闪烁会直接损害可读性。

形状先于颜色

红绿色盲下 Freeze 与 Unfreeze 必须靠纹理方向/边缘形态区分，不能只靠冷暖色。

4.2 颜色与语义层级

七类实体归入四级语义，层级决定饱和度与亮度上限：危险 > 冻结 > 解冻 > 目标。同级之间只允许色相区分，不允许亮度竞争。

Death
#D64545

唯一允许高饱和红。靠近时提亮，但底色透明度不随之上升。

Freeze
#5AA9E6

冷蓝、低饱和。深层冻结转向紫（#6B5BD6）并提高边缘对比。

Unfreeze
#E08A3C

暖橙。与冻结相邻时，两侧边缘都要比内部亮，形成一道"冷暖缝"。

Start / Finish
#2F9E63 / #C9A227

起点偏绿、终点偏金。二者形态必须不同：起点短横线，终点整面光幕。

4.3 单格的构造层次

所有实体共用同一套"四层"结构，只是参数不同。层次从上到下叠加，越往下越贵，允许按画质档位裁剪后两层。

4.4 逐类定义

Freeze / LFREEZE

  • 底色：冷蓝 22% alpha；内部两层缓慢滚动噪声（周期 6 s 与 9 s，反向）
  • 边缘：1px 亮边 + 向内 8px 衰减，边界只在真正的外部边绘制
  • 四角：内凹处做 6px 圆角过渡，避免"马赛克台阶"
  • 动效：整体亮度呼吸 ±10%，周期 3.2 s
  • LFREEZE：叠加一层随开关状态改变的低频脉冲，周期 1.6 s

DFREEZE

  • 底色：深紫 26% alpha，色相向 #6B5BD6 偏移
  • 纹理：棱角化的晶格条纹（方向 45°），频率高于普通冻结 1.8 倍
  • 边缘：对比度比普通冻结高 30%，与普通冻结紧邻时形成可见分界
  • 不得使用与普通冻结相同的噪声相位，否则相邻区域会看起来"同一块"

Unfreeze / DUNFREEZE

  • 底色：暖橙 18% alpha，内部为向上漂移的横向波纹（周期 4 s）
  • 边缘：虚线框（dash 6 / gap 4），与冻结的实线形成形态差异，保证色盲可读
  • DUNFREEZE：虚线更密、色相偏琥珀，与 DFREEZE 的紫形成互补对照
  • 边缘亮度必须低于相邻 Freeze 的亮边，避免抢走"危险/安全"的判断顺序

Death

  • 底色：红 16% alpha；内部斜向警示条纹，周期 7 s 缓慢移动
  • 边缘：2px 实线，是全套里唯一允许"常亮"的边缘
  • 距离响应：本地 Tee 距边界 3 格内，边缘亮度与呼吸频率提升（周期 3 s → 1.4 s），底色不变
  • 不做全屏闪烁、不做屏幕外提示，避免干扰视野中心

Start

  • 形态：格内一条竖直光带（宽度 40% 格宽），两侧羽化
  • 动效：向上流动的扫描线，周期 0.8 s；亮度恒定，不呼吸
  • 方向由 tile flags 决定，旋转后光带方向必须跟着转
  • 不做数字、不做文字，编号信息交给 HUD

Finish

  • 形态：整面半透明金色光幕，中心亮、上下衰减（与起点"线"明确区分）
  • 动效：横向扫过的光带，周期 2.2 s，相位沿着光幕方向推进
  • 与起点相邻时，两者亮度差不超过 15%，靠形态而非亮度区分

4.5 状态与动效时间轴

4.6 缩放与像素密度

  • 所有边缘过渡必须由 fwidth 推导，不写死像素阈值；zoom 从 0.5 到 2.0 变化时描边视觉宽度保持一致。
  • 描边在最终画面上不得低于 1 个物理像素；4K + 高 DPR 下允许 1.5–2 个物理像素。
  • 内部纹理的空间频率按屏幕导数钳制，远端（小 zoom）自动降频，避免贴图缩小后常见的糊边与高频闪烁——这正是 32px 图集在拉远时的主要短板。
  • 实体层透明度滑杆（qm_entity_overlay_*_alpha）必须仍然作用于新外观，且乘在最终 alpha 上，不改变颜色。

4.7 墙体作为整体：结构 → 转角 → 填充

目标不是"每格画一个圆角方块"，而是让一片墙体读起来是一个整体。整体感由三件事构成，缺一不可：

层次要解决的问题视觉判据
结构边界是"区域的外轮廓"，不是"每格的边框"直边连续、没有逐格台阶；同一条边只出现一次
转角只在真正的转角收弧，且内外角规则不同外角圆、内角补料、端头收口；1 格通道不被画窄
填充内部是一块材质，不是 N 个格子材质跨格连续，看不出 32px 的接缝

关键判断：整体感来自"结构连续 + 材质连续"，不来自"合并成一个 mesh"。材质按世界坐标采样时，逐格填充与合并后填充在视觉上等价；是否真的合并三角形，是性能与实现的选择，不该成为美术的前置条件。反过来，如果材质按格内 UV 采样，即使真的合并了几何，也会在每 32px 处露出重复的花纹——那才是最伤整体感的。

半径、线宽与收口

参数建议值（32px 格）规则
凸角半径 R6px（0.19 格），可用 4–10只作用于区域的外凸角；直段不产生弧
凹角补料半径 Rin4px，约为 R 的 2/3只在两侧都有材料时生效，向空角补料，不切料
边界带宽 W2–3px画在区域内侧，不外扩；与碰撞边界对齐
端头（1 格宽的死胡同）方头 + 向内 2px 收口不做圆头，避免"看起来能穿过去"

为什么不能"每格各自圆角"

与碰撞的一致性

所有视觉外扩不得超过 1px。圆角是向内收的装饰：不能把可通行区域画小，也不能把墙体画大。1 格通道的半径钳制、端头的方头收口都是为此存在——玩家在高速通过时依赖的是轮廓，任何一像素的偏差都会被读成"能过 / 不能过"。

5. 技术契约

5.1 单格的四边掩码

外观的"连续外轮廓"不靠合并几何，而靠每格的 8 邻域判断：只有当某个方向没有同类相邻格时，才在那个方向画描边。这套判断在 2.2 的实现里已经存在——qm_outline_neighbors.h 把邻域位懒缓存进类型网格的高位；P0 直接复用，P2 若走着色器路径再把它改写成顶点属性。

两种承载方式的取舍：复用缓存 → 每帧逐格判断，零新缓冲；写进顶点属性 → 每帧零判断，但要么新开顶点布局，要么重建整层缓冲。以当前可见格数量（1080p 约 2 000 格、4K 约 8 000 格）计，前者足够，后者属于 P2 的优化空间。

5.2 顶点与属性（路径 B）

以下属性布局只在走路径 B（P2）时成立；路径 A 复用现有 quad 与类型网格，不新增顶点格式。两种路径共用同一套视觉参数（颜色、线宽、填充 alpha），只是承载方式不同。

沿用现有"4 顶点 / 格"的拓扑与剔除结构，另外定义一套顶点属性（不是复用现有的纹理坐标布局）。全部使用浮点属性传递，不引入整数顶点属性、不引入整数纹理——这样 OpenGL 2 回退路径也能原样走通。

属性类型含义来源
位置vec2 float世界坐标，1 格 = 32.0现有缓冲
格内 UVvec2 float0..1，格内归一化坐标由位置推导，或现有 texcoord 复用
邻域掩码float（0..255）8 位掩码，见 5.1载入期计算，随顶点上传
实体类型float（0..15）Freeze / DeepFreeze / Unfreeze / …载入期分类

每格新增约 20 字节，相对现有每格约 220 字节的缓冲占用可以忽略；换来的好处是片元完全不需要纹理采样，也不需要邻接纹理。

5.4 落地路径

因为有 2.2 的既有轮廓实现，落地分成两条路径。P0 只走 A：不新增图形命令、不碰三个后端，靠现有 quad 批量接口就能得到"填充 + 连续轮廓"的效果；B 是 P2 的可选升级，用来换取渐变、噪点与逐像素抗锯齿。

5.5 混合与顺序

  • 样式 0（跟随皮肤）保持现有六次提交不变；样式 1/2 下，被接管的类别跳过 atlas 提交，改由填充 + 轮廓两次提交承接，总提交次数不增加。
  • 混合模式保持 BlendNormal，实体层不得改写深度。
  • Front 层在 Tee 之后绘制这一顺序不变；半透明光幕遮挡玩家是既有行为，不修正。

6. 配置提案

新增一个风格开关，其余沿用现有滑杆。已存在的外观设置卡片（个人化 → 实体透明度）不拆不合并，只在卡片顶部插入风格选择。

配置类型 / 范围默认说明
qm_entity_render_styleint 0–200 = 跟随实体皮肤，1 = 程序化，2 = 程序化（轻量，仅底色 + 描边）
qm_entity_motion_levelint 0–210 = 关闭循环动效，1 = 标准，2 = 强化（仅供录制/展示）
qm_entity_overlay_*_alpha沿用100不变，乘在最终 alpha 上
qm_outline_*沿用现有值线宽与颜色继续由轮廓自己的配置决定，填充只读取它，不复制一套
不建议给每一类实体再各加一个开关。现有八个透明度滑杆已经让这张卡片偏长；风格选择 + 动效等级两个维度足够覆盖"低配 / 竞技 / 展示"三种诉求。

7. 兼容与风险

风险影响处置
与实体皮肤系统冲突用户挑选的实体图集被绕开，Assets 页的预览与实际不一致默认 0（跟随皮肤）；切到程序化时在设置页给出一次性说明；切回即恢复皮肤
地图作者的表达被覆盖地图内嵌的实体图（配色随地图定制）失去意义P2 增加"继承地图主色"：从实体图取中位色作为基色，形状仍程序化
demo 回放与录像动效相位不一致会看出"回放和录制不同"时间源统一取游戏时间，禁止使用墙钟
OpenGL 2 / GLES 回退整数属性与 texelFetch 不可用本方案不使用整数属性与纹理，纯浮点即可，回退路径与主线共用同一着色器源
低端核显内部噪声层带来每像素 ALU 成本提供轻量档（仅底色 + 描边），并把噪声层数作为画质档位的一部分
轮廓与填充各算一套邻域同一条边上出现双线或 1px 错位填充必须调用同一份邻域缓存（QmOutlineCachedNeighbors），禁止另写一套判定
Through 系可见化玩法信息优势明确不实现，写入边界

8. 验收清单

视觉

  • 1080p / 1440p / 4K × zoom 0.5 / 1.0 / 2.0 六组截图，Freeze 与 Unfreeze 相邻处无接缝、无 1px 亮线
  • 整块冻结区域的四个内凹角为圆角过渡，不外溢到相邻格
  • 拉远到 0.5 时边缘与内部纹理仍可辨识，无高频闪烁；拉近到 2.0 时描边不糊、不出现锯齿
  • 起点光带方向随 tile flags 旋转正确；终点光幕与起点在灰度图下可区分
  • 死亡区在玩家 3 格内出现脉冲，离开后 400 ms 内回到静息
  • 八个透明度滑杆从 100 拖到 0 时外观线性淡出，无颜色偏移
  • 填充边缘与既有轮廓线对齐，开启 qm_outline_* 时不出现双线、错位或 1px 缝隙
  • 关闭实体层（cl_overlay_entities 归零）时，填充与轮廓同时消失，不残留

行为

  • 切换风格后不需要重进地图，当前地图立即重绘
  • demo 录制的成品与回放画面在动效相位上一致
  • 实体层总开关关闭时，新路径同样整层跳过
  • 地图内嵌实体图 / 用户自定义皮肤下，风格 0 的表现与改动前逐像素一致

后端与性能

  • OpenGL3 / Vulkan / Metal 三后端截图一致（允许 ±1 色阶）
  • OpenGL2 回退路径可运行、外观降级符合轻量档定义
  • 同图同视角下，帧时间不回退超过 3%；轻量档不回退
  • 不新增每帧绘制提交次数

11. 附录：着色器接口草案

以下是契约级别的片段，用于对齐美术与实现的预期，不是最终代码。所有参数来自 5.2 与 5.3。

// 顶点：把 8 位掩码与类型原样传到片元
in vec2 a_Pos;
in vec2 a_LocalUV;
in float a_Mask;      // 0..255
in float a_Type;      // 0..15
in float a_Rotate;    // 0..3
out vec2 v_LocalUV;
flat out int v_Mask;
flat out int v_Type;

// 片元：先算到外沿的距离（世界单位），再按类型叠加内部质感
float EdgeDistance(vec2 uv, int m)
{
    float d = 1e9;
    if ((m & 1) == 0) d = min(d, uv.x * 32.0);          // 左
    if ((m & 2) == 0) d = min(d, (1.0 - uv.x) * 32.0);  // 右
    if ((m & 4) == 0) d = min(d, uv.y * 32.0);          // 上
    if ((m & 8) == 0) d = min(d, (1.0 - uv.y) * 32.0);  // 下
    // 对角位（bit4..7）用于内凹圆角修正，本草案不展开具体 SDF
    return d;
}

void main()
{
    float Edge = EdgeDistance(v_LocalUV, v_Mask);
    float AA = max(fwidth(Edge), 1e-4);
    float Stroke = 1.0 - smoothstep(2.0 - AA, 2.0 + AA, Edge);   // 2px 外沿
    float Glow = exp(-Edge / 8.0);                               // 向内 8px 衰减
    vec3 Base = CategoryColor(v_Type);
    vec3 Color = Base * (0.22 + 0.55 * Glow) + vec3(Stroke) * 0.35;
    FragColor = vec4(Color, CategoryAlpha(v_Type) * (0.22 + 0.6 * Stroke + 0.18 * Glow));
}
实现注意：bit()、flat、fwidth 在 GLSL 1.20 下并非全部可用，实际实现需要按后端提供等价写法；这也是 P0 必须在 OpenGL2 上先跑通一遍的原因。
