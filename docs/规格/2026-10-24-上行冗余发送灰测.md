# 上行冗余发送灰测

状态：灰测实现，尚未编译或运行验收。基于 PR [#485](https://github.com/wxj881027/QmClient/pull/485) 的 `9e33ff73a5`、`c77e83ce2e`，保留来源提交。

## 已确认行为

- 功能名称为“上行冗余发送（实验性）”，放在 DDNet 游戏设置的“预测事件（实验性）”下方；搜索页复用同一卡片。
- `qm_upstream_redundancy` 默认 `0`，关闭时单发游戏包，也不发送本功能的探针。
- `qm_upstream_redundancy_max_copies` 默认 `3`，可选 `2` 或 `3`；份数包含原包。关闭功能后保留该设置。
- 仅在原生 UDP 连接在线、服务器支持 `PINGEX` 时启用采样。KCP 使用已有发送策略，不叠加本功能。
- 主连接的往返探针每 0.5 秒发送一次，探针自身保持单发；沿用原 PR 的两秒判定期限、十秒窗口、至少十个样本和平滑策略。未形成估计时保持单发。
- 根据往返未确认率选择一至三份，并受用户上限约束。该指标同时受到上行、下行和服务端响应的影响，不能称为准确的上行丢包率。
- 主连接与分身连接独立保存发送份数，分身使用主连接的链路估计；断线或禁用后恢复单发。服务器浏览、STUN、控制包和无数据的确认/重传请求不受影响。

## 实现边界

复制在游戏连接的包发送层进行，在编码 0.6/0.7 标志位之前判断是否包含游戏数据。一个逻辑包只压缩、编码一次，所有副本逐一通过 `net_udp_send`，统一累计发送字节、包数和失败次数。发送失败后停止该包剩余副本。

不修改服务端协议和输入处理。普通 UDP 输入没有通用副本去重，晚到副本仍可能重新进入输入队列；默认关闭和实验性提示不能视为解决了这一风险。往返探针不能区分单向丢包，复制也不保证改善突发丢包或拥塞。灰测中应观察实际收益和输入行为，再决定是否适合正式集成。

灰测分支与提交策略遵循根 `AGENTS.md` 的“执行与授权”。本次不变更版本号、不发布安装包。
