# Wiki 内容系统

日期：2026-10-22
状态：进行中（内容层与编辑能力已实现，TClient 卡片入口与文案迁移待做）

## 1. 目标

- 卡片说明不再只有三段纯文本，而是能写标题、要点、表格、代码、公式和图片。
- 说明可以带**短动图**（类似 GIF 的循环小片段），用来演示交互或状态变化。
- 未发布版本允许直接**在客户端里改文案**并立即预览；发布后同一个开关改成只读。
- 内容与代码解耦：文案是数据文件，改文案不需要重新编译。

## 2. 内容格式

说明文档使用“简易 Markdown”。解析器是 `src/game/client/QmUi/QmWikiMarkdown.cpp`，
只实现说明文需要的子集，不做 CommonMark 全兼容。

| 语法 | 效果 |
| --- | --- |
| `#` ~ `######` | 标题，1~3 级有字号层级 |
| 空行分隔 | 段落，连续多行合并为一段 |
| `- ` / `* ` / `+ ` | 无序列表，两个空格缩进一级 |
| `1. ` / `2) ` | 有序列表，按写入的数字显示 |
| `> ` | 引用块，左侧竖条 + 弱化文字 |
| `---` / `***` / `___` | 分割线 |
| 三个反引号 | 代码块，保留换行 |
| `| a | b |` 加 `|---|---|` | 表格，第二行冒号控制左/中/右对齐 |
| `![说明](文件)` | 图片或动图，整行书写 |
| `$$ ... $$` | 数学块，优先找预渲染图片，找不到就按等宽文本显示 |
| `**粗体**`、`*斜体*`、行内代码 | 行内样式 |
| `[文字](地址)` | 链接：悬停高亮下划线，可点击（浏览器或卡片互跳） |
| `$公式$` | 行内公式，按强调色显示原文 |

中文按字断行、英文按词断行；超长单词会逐字拆行，不会溢出面板。

## 3. 图片与动图

动图统一用 **WebP**：导入脚本把 mp4/webm/gif 转成动图 WebP，客户端直接解析
RIFF 里的 `ANMF` 帧（`WebPDecodeRGBA` 逐帧解码后拼成图集），不需要 libwebpdemux，
也不需要额外的视频解码器。

- `voice.mp4` → `media/voice.webp`，说明里写 `![](voice.webp)`。
- 静态图支持 png/webp；jpg 会在导入时转成 webp。
- 旧资源仍可用雪花图（`name.sheet.png` + `name.sheet.txt`），播放逻辑与 WebP 图集一致。
- 缺图不会报错，会画占位框并显示路径，方便发现写错。

## 4. 公式

公式用**预渲染图片**：Markdown 里照常写 TeX，导入脚本把每条公式渲染成
`data/wiki/media/math/<slug>.webp`，客户端按同一套 slug 规则查找。

- 行内 `$a^2+b^2=c^2$` 渲染成行内图片，按行高缩放并与文字基线对齐。
- 块级 `$$...$$` 居中显示，宽度受面板限制。
- 找不到图片时退回显示 TeX 源码，不会报错。
- 渲染链：KaTeX + 无头 Edge 截图（`tmp/wiki_tools` 里装 katex），白色字形透明底，
  客户端按主题文字色着色。
- slug 必须与 `QmWikiMarkdownRender.cpp` 的 `MathSlug` 逐字节一致：
  保留 ASCII 字母数字和 `-`/`_`，其它字节折叠成一个 `_`，最多 72 字节，末尾去掉 `_`。

## 5. 导入外部 Markdown

    python qmclient_scripts/wiki/import_wiki.py external.md --id qm:voice --lang simplified_chinese

脚本会：把 mp4/webm/gif 转成动图 WebP、静态图转 WebP、公式渲染成 WebP，
并把图片引用改写成 media 目录里的文件名，最后写到 `data/wiki/<语言>/<id>.md`。
外部写好的 Markdown 可以直接粘贴保存成文件再导入，公式保持 TeX 原文即可。

## 6. 内容来源与解析顺序

每张卡片、每篇文档按以下顺序取内容：

1. **本地覆盖**：`wiki/<语言>/<路径>.md`（在用户目录，可在客户端里改）
2. **随包 Markdown**：`data/wiki/<语言>/<路径>.md`
3. **内置表**：`QmCardWiki.cpp` / `QmWikiDocs.cpp` 里的三段文案，按标题自动拼成 Markdown

`<路径>` 由 id 转换：`qm:voice` → `qm/voice`，`deck:xxx` → `deck/xxx`，弹窗文档同理
（`demo:video_export` → `demo/video_export`）。语言目录取 `cl_languagefile` 去掉 `.txt`，例如 `simplified_chinese`。

内置表仍然是 i18n 维护源：12 种语言都在 `card_wiki.toml` 里，没写 Markdown 的语言
自动回落到它，所以不会出现“只有中文有说明”的空窗（缺译的原样显示英文 source，见 §8）。

### 6.1 参考游戏 Wiki 写文案

DDNet 官方 Wiki（wiki.ddnet.org）讲的是游戏机制，不是本客户端的设置项；写文案时用它核对
术语和玩法，避免把钩子、分身、队伍这些概念写错。

抓取方式遵守站点规范，用 MediaWiki 自带的整页导出，不要逐页抓 HTML：

    https://wiki.ddnet.org/wiki/Special:Export?curonly=1&pages=Dummy

- 一次最多几页，页与页之间留出间隔；只取需要参考的页面，不全站抓取。
- 导出的 XML 放进 `tmp/ddnet_wiki/raw`，用脚本转成笔记：

    python qmclient_scripts/wiki/ddnet_wiki_notes.py --input tmp/ddnet_wiki/raw --output tmp/ddnet_wiki/pages

- 笔记只用于写作参考，不随客户端发布；正式文案写进 `data/wiki/<语言>/` 或内置表。
- 中文镜像 ddrace.cn/wiki 是社区爬取版本，更新可能滞后，仅在官方页面拿不到时参考。

### 6.2 首批中文卡片

142 篇卡片说明（`deck/` 69、`qm/` 52、`tclient/` 21，stableId 无重复）都已写成中文 Markdown，放在
`data/wiki/simplified_chinese/<命名空间>/<id>.md`，四段结构统一为
「这个设置做什么 / 怎么调 / 注意 / 相关」，卡片之间用 `[文字](stableId)` 互链。

写作时对照了游戏 Wiki 的术语，但控件行为以客户端实现为准。复核中发现 5 张卡的内置英文摘要

## 7. 客户端内编辑

未发布版本允许直接改：

- 面板右上角「编辑」→ 正文变成多行输入框，保存后立即按新内容渲染；回车插入换行，粘贴保留换行（CRLF 会统一成 LF），单行输入框不受影响。
- 保存写到用户目录的 `wiki/<语言>/<路径>.md`，不改动仓库文件和随包内容。
- 「还原」删除本地覆盖，回到随包 Markdown 或内置文案；删除失败会显示错误而不是假装成功。
- 编辑态按 Esc 只退出编辑（草稿留在输入框，再点「编辑」继续），不会整块关掉面板丢草稿；换文档时草稿清空。
- 工具条左侧的状态行默认不显示字：保存后显示实际写入路径，还原后显示已回到内置内容，出错时显示失败原因并前置红点；草稿与内置内容的区分只体现在状态点颜色（草稿用强调色）。

发布时把 `src/game/client/QmUi/QmCardWikiPanel.cpp` 里的
`WIKI_AUTHORING_ENABLED` 改成 `false`，编辑按钮和写文件逻辑整体不再出现。

## 8. 文案现状

- 77 张目录卡片、31 张 TClient 卡片和视频导出文档已有三段式英文文案；`validate.py` 的 blocking
  violations 为 0，两个历史条目里的「dummy 控制」按术语表改成「分身控制 / 分身同步」。
- **翻译现状（未完成）**：`card_wiki.toml` 现 431 条，traditional_chinese / japanese / korean
  已全译；simplified_chinese 仍缺 TClient 那 93 条，其余 8 种语言缺 102 条。缺译条目在运行时
  回退英文 source，面板不会空白，但中文界面里这 31 张 TClient 卡片暂时是英文说明。
- 新的 Markdown 能力让作者可以写要点和表格；`data/wiki/simplified_chinese/qm/voice.md`
  是第一批“小白化”示例：先讲是什么，再讲怎么用，最后列常见坑。
- 迁移方式：按卡片逐步把三段表升级成 Markdown 文件，先中文验证观感，再按语言补齐。
  未迁移的卡片继续用内置表，不需要一次性大改。

## 9. 已知限制与后续

- TClient 的卡片本来就在 deck 上（`BuildTClientCard`），已补全 31 张卡的 Wiki 文案与覆盖测试；旧 section 链路只用于缓存/预热。
- 没有粗体/斜体字体，粗体用重复绘制模拟，斜体暂时与正文同形。
- 链接已可点击：`https://` 交给系统浏览器，`qm:` / `tclient:` / `deck:` 在同一面板内换卡片。
- 目录（TOC）已接上：正文有 2 个以上标题时，面板顶部列出可点的「目录」，点击把该小节顶到可视区；
  只是纯文字列表，没有折叠与高亮当前小节。
- 公式需要预先导出图片，客户端不解析 TeX。
- 编辑框内没有“滚动到光标”，长文档需要手动滚动；超过 24575 字节的覆盖文件仍会被输入框截断。
- 图片/动图在**布局阶段同步解码**，首次打开带大图的文档会有一次卡顿；现在有硬预算（静态图 64 MB、
  动图逐帧副本 64 MB、图集 96 MB，单帧画布 ≤2048²、帧数 ≤48），超预算按缺图处理，不会吃爆内存。
- 多列表格在很窄的面板里仍可能挤，单元格内容宽度至少按一个字排版，不会退化成逐字换行。
