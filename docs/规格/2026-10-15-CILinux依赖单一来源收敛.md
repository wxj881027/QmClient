# 2026-10-15 CI Linux 依赖单一来源收敛

## 背景

两轮远程 CI 失败同因：`clang-tidy` 与 `codeql` 工作流缺 `libcurl4-openssl-dev`，CMake 静默落到 `ddnet-libs/curl/linux/lib64/libcurl.so`（8KB 假桩，无 `curl_share_*` API），DNS 共享特性在链接期才失败。5 个 workflow 里共有 4 处独立的 Linux apt 依赖清单，同一份包列表散落多处，是这类事故的结构性原因。

## 方案与实现

### 单一来源：`.github/actions/linux-deps/action.yml`

仓库首个复合 action（此前无 `.github/actions/` 先例）。主清单定义一次，全部 Linux 构建作业以 `uses: ./.github/actions/linux-deps` 消费；作业专属包通过 `with: extra:`（空格分隔）追加。action 内含 curl 能力探针：编译并运行一个调用 `curl_share_init` 的最小程序，系统 curl 开发包漏装时安装步骤当场失败，不再等到链接期。

### 改造范围（5 个 workflow）

| Workflow | 改动 |
| --- | --- |
| build.yml（Linux 发布 job） | 切换 action；`extra: libdbus-1-dev libogg-dev libopus-dev libopusfile-dev libwavpack-dev` |
| build.yml（Android job） | 切换 action（无 extra）；cargo-ndk/rustup 目标安装拆为后续独立步骤 |
| clang-tidy.yml | 切换 action；`extra: libmariadb-dev libwebsockets-dev libminiupnpc-dev`（可选特性构建） |
| clang-sanitizer.yml | 切换 action（无 extra） |
| codeql-analysis.yml | 切换 action；`extra: libmariadb-dev libwebsockets-dev` |
| style.yml | 切换 action；`extra: ddnet-tools shellcheck tidy graphviz python3-clang wget gnupg ca-certificates`；clang-format-22/LLVM 源/ruff 保留独立步骤（纯工具安装） |

### 关键决策：哪些包进主清单、哪些留在 extra

行为等价性依据 CMake 实测（`PREFER_BUNDLED_LIBS` 在 Linux 默认 OFF，`set_extra_dirs_lib` 把捆绑目录列为 `PATHS`，系统库优先于 `ddnet-libs`；仅 Windows 默认 ON）：

- **`libglew-dev` 与 `libnotify-dev` 不进主清单**。build.yml 的 Linux 发布清单今天就没有它们：缺 `libnotify-dev` 时 CMake `find_package(Notify)` 只打印 "library not found" 继续走，通知支持静默禁用；缺 `libglew-dev` 时走 `src/engine/external/glew` 源码捆绑实现。若统一清单装上这两个包，Linux 发布产物会从"无通知库 + 捆绑 GLEW"变为"动态链接系统 libnotify + 系统 GLEW"，静默改变产物运行时依赖。四个被收敛的检查类 workflow（tidy/san/codeql/style 原清单）里 GLEW/Notify 的有无差异因此被主清单（不含）+ 检查构建现状（含/不含各按原样）保持：tidy/codeql 原本就装了这两个包，但其产物只用于静态检查，不入发布包，等价性不受影响。
- `libdbus-1-dev`（MPRIS）、`libogg/opus/opusfile/wavpack-dev` 只在 build.yml 原清单出现，保留在该作业 `extra`。
- `libmariadb-dev`/`libwebsockets-dev`/`libminiupnpc-dev` 对应 `-DMYSQL/WEBSOCKETS/UPNP=ON` 可选特性，只在启用它的作业 `extra`。
- Android 作业原清单里的 `curl`（CLI，非 -dev）与非构建工具统一省略；Python 构建依赖（fonttools/Pillow）build.yml 走 setup-python pip 安装，不依赖 apt 版本。

### 防漏措施：守卫脚本 + gate 注册

`qmclient_scripts/check_ci_deps.py`：

- 残留 `apt-get install` 步骤的包名必须被主清单、该 workflow 注册的 `extra` 或 `ALLOWED_STANDALONE` 白名单（当前仅 `p7zip-full` 与 clang 工具安装步骤）覆盖；
- 各 workflow `extra` 包必须与 `EXPECTED_EXTRA` 注册表双向一致（缺登记、漏声明都失败）；
- `-DMYSQL/WEBSOCKETS/UPNP=ON` 的作业，`extra` 必须包含对应系统包；
- action 主清单必须含 `libcurl4-openssl-dev` 且保留 `curl_share_init` 探针。

注册表：`EXPECTED_EXTRA`、`ALLOWED_STANDALONE`、`FEATURE_PACKAGES` 就在脚本头部，新增依赖时同步登记即可。非纯逻辑测试路径：`check_sources(dict)` 接受内存文本，`run_checks(repo_root)` 读真实文件后委托给它；单元测试全部内存驱动，不建临时目录。

gate 注册：`qmclient_scripts/gate/checks/ci_deps.py`，`quick/default/full` 三档生效，检查名「CI 依赖单一来源守卫」。

### 验证证据（本地 Windows，受限会话）

- `python qmclient_scripts/check_ci_deps.py`：通过。
- `python -m unittest qmclient_scripts.tests.test_check_ci_deps`：10/10 通过（含真实仓库现状守卫、extra 注册表双向、特性-包对应、探针与 libcurl 缺失、venv/pip token 不误判）。
- 8 个 `.yml`（action + 7 workflow）`yaml.safe_load` 解析通过。
- ruff format/check：通过。
- quick gate：**未完整执行**——本会话沙盒拒绝进程在 `tmp/` 下创建目录（会话策略状态，非 NTFS 授权问题；`tmp` 授权已人工修复但受限进程仍被拒），既有 gate 合同测试与报告写入依赖 `tmp/`。新增检查本身的依赖（守卫脚本、单测、ruff）已全部直跑通过。完整 quick gate 需在不受限会话或完全权限下补跑；远程 CI（style.yml 跑 quick gate）会再验一次。

## 风险与回滚

- 原子性：action 与全部 workflow 改造同 PR 提交；引用必须在同一提交内成立，否则引用方 workflow 直接红。
- 行为面：检查类 workflow 比原清单多了 libogg/opus/wavpack/png/ssl 等 base 包（无害）与 curl 探针步骤；Linux 发布作业包集合不变（base ⊇ 原），Android 省略 `curl` CLI 不影响 SDK 安装与 Gradle。
- 回滚：revert 单个提交即可，复合 action 与消费方同时消失，恢复原内联清单。
- `ddnet-libs/curl/linux` 假桩未动（服务于本地/交叉场景）；CI 侧靠 `PREFER_BUNDLED_LIBS=OFF` 默认路径 + 探针兜底。
