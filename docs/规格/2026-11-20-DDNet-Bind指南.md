# DDNet Bind 指南

Bind 是客户端的「键位 → 控制台命令串」映射。可以绑定字母、鼠标键、滚轮或组合键；命令串可以改设置、触发游戏操作、执行 CFG，也可以重新绑定某个键。以下基础写法适用于 DDNet，QmClient 扩展单独标明。

## 先学会查看、设置和恢复

游戏里按 `F1` 打开本地控制台。下面用 `j` 举例，先运行第一条并记下旧绑定；如果这个键在用，就换一个空闲键。设置后关掉控制台，再短按按键试效果。

```cfg
bind j
bind j "echo Bind works"
binds
```

- `bind j` 或 `binds j` 查看指定键，`binds` 列出全部绑定。键名以控制台输出为准，例如 `mouse4`、`mousewheelup`、`ctrl+j`。
- `bind j "…"` 替换这个槽位的整条命令。对同一槽位连续写两次，后一次覆盖前一次；要一键执行两条命令，应把两条写进同一个引号内，用 `;` 分隔。
- 恢复时重新输入之前的 `bind j "旧命令"`；如果原本没绑定，用 `unbind j`。`unbindall` 会清空全部键位。绑定会随客户端配置保存，重启不等于撤销。
- `j` 和 `ctrl+j` 是两个槽位，匹配到组合键时不会再额外执行裸键绑定。组合未绑定时，部分组合会回退到裸键，具体由客户端输入规则决定。

## 按下、松开和切换是三件事

| 写法 | 实际行为 |
| --- | --- |
| `bind j "echo hello"` | 按下执行 `echo`，松开不执行它。 |
| `bind j "+jump"` | 游戏把按下与松开交给 `+jump`，命令自己处理开始和结束。 |
| `bind j "toggle cl_showhud 0 1"` | 每次触发在 `0` 和 `1` 之间切换；当前不是第一个值时就写第一个值。松开不改值。 |
| `bind j "+toggle cl_showhud 0 1"` | 按下写 `0`，松开写 `1`，并不记住原值。 |
| `bind j "+toggle_restore cl_showhud 0"` | **QmClient 扩展。** 按下写 `0`，松开恢复首次按下前的值。 |
| `bind j "+toggle_exec Bind/down.cfg Bind/up.cfg"` | **QmClient 扩展。** 命令根据游戏传来的输入方向选择执行哪份文件。 |

`bind` 自己没有「按下脚本／松开脚本」两个字段。输入层把事件传给控制台，控制台为已注册的 `+` 命令传入输入方向，具体行为由该命令决定。长按可产生键盘重复事件，普通命令和开关也可能重复触发；验证一按一切时用短按。`zoom+` 这样的命令名以 `+` 结尾，不是这里说的输入方向命令。

## 读懂一份 CFG

- **顺序**：CFG 从上到下执行；同一行中引号外的 `;` 分命令，也按文本顺序交给控制台。换行和分号都不会等待下一帧，也不代表服务器已经处理完前一条聊天指令。
- **引号**：`bind j "echo first; echo second"` 现在只安装绑定，短按 `J` 才执行两条 `echo`。再嵌套一层时，内层引号要转义，如 `bind j "bind k \"echo one; echo two\""`。短按 `J` 改绑 `K`；随后短按 `K` 打印两行。链条复杂时拆成多个文件更易读。
- **注释与提示**：引号外的 `#` 开始注释，可以独占一行，也可跟在命令后面。`echo` 在执行时打印到本地控制台；`say` 会向当前服务器发送聊天，是否接受 `/…` 指令由服务端决定。
- **`exec` 与 `bind … exec`**：`exec Bind/a.cfg` 立即调用文件，调用返回后继续下一条命令；`bind j "exec Bind/a.cfg"` 只安装键位，等此键触发才会调用。相对路径按客户端存储搜索规则查找，不能假定从当前 CFG 所在文件夹开始。建议写完整的配置目录相对路径，如 `Bind/demo/hud_on.cfg`。
- **`+` 命令放在哪里有区别**：物理键直接绑定 `+jump` 时，按下和松开可以相隔一段时间。普通 `exec` 执行文件中的一行时，会通过 `ExecuteLine` 处理该行的按下和松开阶段；把 `+jump` 搬到 `exec` 文件里，不会把它延长到物理键松开。

## 示例：同一个键在两份 CFG 间轮换

示例文件：[install.cfg](Bind示例/install.cfg)、[hud_on.cfg](Bind示例/hud_on.cfg)、[hud_off.cfg](Bind示例/hud_off.cfg)。DDNet 以配置目录为搜索起点之一，Windows 通常是 `%APPDATA%\DDNet`。示例的运行位置是该目录下的 `Bind/demo/`，建议使用 UTF-8。使用其他键时，入口和两份状态文件的键名都要一起改。

```text
F1: exec Bind/demo/install.cfg
    └─ 安装 J → hud_on.cfg；此时不改 HUD
短按 J → hud_on.cfg  → 先显示 HUD，再把 J 改绑到 hud_off.cfg
短按 J → hud_off.cfg → 先隐藏 HUD，再把 J 改绑回 hud_on.cfg
```

第一次加载前，可用 `bind j` 和 `cl_showhud` 查看原值。试完恢复原值和原绑定。入口只指定第一次触发的文件；如果 HUD 本来已经显示，第一次不会产生可见变化，可用 `F1` 里的 `echo` 验证。

这是**重绑回环**：一次按键只执行当前文件，下次才进入另一份文件。不要把两个文件改成互相直接 `exec`，那是同一次执行中的递归；引擎会拦截执行栈里重复的文件名，并限制嵌套深度。文件总数和单次 `exec` 链深是两回事。

本地 `Bind/分身控制` 用同样的手法：开启文件设置 `cl_dummy_control 1`，再把 `grave` 指向关闭文件，关闭文件反向重绑。`Bind/枪锤切换` 多了一层：开启时立即调用 `锤子.cfg`；以后 `mouse4` 在锤子和手枪间轮换，`z` 单独控制整套模式。读这种包时，先找入口键，再按行读每份文件，把「立即调用」和「改绑后才调用」分别标出来。

## 查错顺序

1. 按键没反应：在 `F1` 输入 `bind <键>`，看当前槽位和命令。检查是否被后加载的 CFG 覆盖，然后关掉控制台再试。
2. 找不到文件：检查 `exec` 使用的配置目录相对路径；单独执行一份状态文件也会真的修改设置和重绑，调试前先看原文。
3. 切换跳了两次：先用短按排除键盘重复，检查两份文件是否都重绑同一个键。常用按键若包含 `+` 动作，不宜在持有它时一并改绑。
4. 单行越写越长：优先拆成 CFG 行或文件，别把蓝图或工坊的输入限制当成所有 DDNet 版本通用的引擎限制。
