# 移动端观战端适配

状态：进行中。

已落地：页签裁剪（只隐藏 TClient）、字体卡片并入画面页、内容区触控滑动滚动（含惯性、跟手增益 1.5）、移动端设置字号整体放大 1.35 倍。前四项已构建进 APK 并在模拟器安装；字号放大与配套单测因本次会话的 shell 失去工作区写权限（`mkdir`/`touch` 全盘 Permission denied，`tools.write` 正常）未能编译验证。

## 目标

手机端不是桌面端的缩小版，而是专门的**观战 / 回放端**：进服即旁观、触控操作、界面为大屏触摸重排，桌面专属能力一律不呈现。

## 一、设置页签裁剪

判定集中在 `SettingsPageHiddenForMobile(Page, MobilePlatform)`，通过 `SettingsPageVisibleInRightTabBar()` 生效；`MobilePlatform` 显式传参，桌面单测可直接覆盖判定表。隐藏的页也不能成为落地页，`RenderSettings` 里回落到通用页。

| 页签 | 手机端 | 说明 |
| --- | --- | --- |
| 通用 | 保留 | 语言、Demo/视频目录、更新率；收起自动录像/截图/CSV |
| 皮肤（Tee） | 保留 | 观战要看别人的皮肤 |
| 外观 | 保留 | 名牌、拖尾等观战观感 |
| 控制（绑键） | **保留** | 手机没有键盘，绑定是独立入口 |
| 画面 | 保留 | 画质与缩放；TClient 的字体卡片并入此页 |
| 声音 | 保留 | |
| 资源 | **保留** | 游戏内录制与观战片段的来源 |
| DDNet | **保留** | 官方设置 |
| TClient | 隐藏 | 桌面兼容向；字体卡片移到画面页 |
| QmClient / 搜索 / 贡献者 | 保留 | |

## 三、待实现

### 1. 触控滚动（当前完全缺失）

`CScrollRegion`（`src/game/client/ui_scrollregion.cpp`）只有两条滚动路径：滚轮，以及**拖动滚动条滑块**（`BeginThumbDrag`）。内容区按住拖动不会滚动，这在手机上等于不会用。需要新增：

- 内容区按下 → 跟随手指位移滚动（`SetOffset` 按手指增量）；
- 松手后惯性衰减，越界回弹；
- 与列表项的点击判定互斥：位移超过阈值即取消点击；
- 与双指捏合、摇杆等已有手势的优先级关系。

服务器列表、设置卡片、Demo 列表、资源列表都走同一套，改 `CScrollRegion` 一处即可全覆盖。

## 六、UI 尺度与聊天触控（2026-10-31 进行中）

本节取代早期“设置字号整体放大 1.35 倍”的做法；那个方案只放大字号，排版仍会挤，且未完成编译验证。

- **整体缩放**：手机端默认把虚拟屏幕高度缩到 1/1.3（`QmUiMobileScaleBoost()`），菜单、列表、卡片、设置页按虚拟单位一起等比放大。系数只在 Android/iOS 生效，桌面端保持 1.0，只受 `qm_ui_scale` 控制。
- **左右安全区**：菜单页取整屏宽的 4%（2640 宽下约 106px），设置页、服务器列表、新闻、统计、回放、收藏地图共用同一矩形；只缩页面布局矩形，`CUi::Screen()` 与触摸映射保持整屏。100% 与 1.3 下实测都是 106 / 2534。
- **开始菜单**：1.3 下主按钮组会顶到 logo；logo 现在按主按钮上方可用高度等比缩小，正常高度保持原尺寸。
- **聊天字号**：聊天使用独立的 300 高虚拟屏，不随 `qm_ui_scale` 放大；手机端 `FontSize()` 默认再乘 1.3，桌面端不变。
- **聊天触控（根因）**：聊天原来用 `Input()->KeyPress(KEY_MOUSE_1/2)` 判断按下，触摸不会产生鼠标按键事件，所以点输入行、拖滚动条、复制菜单、翻译按钮都没反应。现统一改用 CUi 的 `Ui()->MouseButton/Clicked`，鼠标和触摸共用一套。
- **输入行**：补了按点击位置移动光标（自绘输入框原来没有维护 `SMouseSelection`），松手调用 `EnsureScreenKeyboardShown()` 重新拉起被系统收起的软键盘。
- **软键盘**：`EnsureScreenKeyboardShown()` 只在键盘确实隐藏时 Stop/Start；进入聊天（`EnableMode`）和输入行松手时请求一次。键盘已显示时再强制 Stop/Start 会表现为“弹出又消失”，已去掉。聊天指针状态直接读原始触摸，避免 CUi 在游戏内未逐帧更新导致点不到。
- **触控第一下**：CUi 原来把触摸按下延迟到下一帧，第一次点只移动光标、第二次才命中；现改为同帧生效，菜单和翻译按钮都应一下命中。
- **移动端光标/提示**：手机端不再绘制菜单/聊天/控制台/计分板鼠标光标，tooltip 整体关闭；翻译按钮下方的黑色块是 hover tooltip，已消失。
- **Graphics Error**：实机设置里 `gfx_backend` 被存成 `Vulkan`，Vulkan surface 创建失败；已把手机配置改回 `GLES`，并修正 Android 启动参数把 `"gfx_backend GLES"` 拆成两个参数。
- **待实机**：以上触控/输入法改动在 16:0x 的 APK 中，但安装时手机再次掉线，尚未逐项验收。
- **左侧留白**：手机端聊天整体右移 10 个聊天单位（约 40px），翻译按钮从屏幕左边缘移开；桌面端不变。
- **历史滚动**：单指在历史区上下拖动按行累加，最终仍写 `m_BacklogCurLine` 并 `RebuildChat()`，与滚轮/滚动条共用同一状态。
- **翻译按钮**：触摸轻点打开设置，长按（CUi 合成右键）切换自动翻译。
- **关闭聊天**：手机没有 Esc；非观战由 `CTouchControls` 的原聊天按钮关闭，观战由 `CQmMobileSpectator` 的 CHAT 按钮关闭。聊天激活时其它触控按钮隐藏，但原聊天按钮仍绘制，作为可见的关闭入口；打开聊天的那一次按住不会立刻被判为关闭。
- **记录修正**：1.3 缩放不会导致掉帧，之前“放大掉帧”的结论不成立，已从注释和本记录删除。
- **待验证**：实机点输入行重开 IME、历史拖动、观战/非观战聊天按钮关闭、1.3 下聊天字号与边界；桌面构建确认缩放回到 1.0。

## 七、输入行分区与私聊（2026-11-01）

上一节把触摸接进了聊天，但整条输入行都当正文处理：点「全体:」前缀和点翻译按钮也会唤起输入法，而手机上没有快捷键切私聊。本节把输入行拆成三段，并补上发送对象选择。

- **三段命中区**：输入行从左到右是翻译按钮、发送对象前缀、正文区。只有正文区会移动光标并在松手时 `EnsureScreenKeyboardShown()`；前缀只用于切换发送对象；翻译按钮仍走自己的轻点/长按逻辑。
- **发送对象弹层**：点前缀打开 `CUi` 弹层（`CChat::m_TargetPopupContext`），列出「全体」「队伍」与服务器上的其他玩家；自己（主/副连接）不出现，选中玩家即进入私聊。列表超过弹层高度用 `CScrollRegion` 滚动，行高 24、间距 3。
- **私聊发送**：`MODE_WHISPER` 下正文用 `BuildWhisperCommand` 拼成 `/w "名字" 消息`，按公开频道发给服务器执行；目标名称在发送时从 `m_aClients` 实时取，改名后不会发到旧名字。
- **目标失效**：目标离开服务器时丢弃这条消息并提示，绝不退回公开频道——退回会把私聊内容发给所有人。前缀显示「私聊 <名字>」，名字超过 12 字节截断，保证正文仍有可用宽度。
- **第一下命中**：`DoDraggableButtonLogic` 与 `DoValueSelector` 也改成触摸同帧按 `Inside` 起手，滑条与数值框不再需要先点一次。
- **单测**：`QmChatWhisperTargets.*` 覆盖自己/假人过滤、空名与离线跳过、容量上限，以及 `/w` 指令拼接（`qm_chat_interactions_test.cpp`）。
- **待实机**：前缀与正文的边界（点「全体:」不弹输入法、点右边弹输入法）、弹层滚动与选中、私聊实际收到、目标离线提示。

## 八、观战端按钮补齐（2026-11-01）

按架构文档「观战端按钮与相机手势（计分板、视角模式、实体层）」把缺的三个按钮补上。

- **布局**：右下网格成 3x2——上一人 / 选择 / 下一人，自由视角 / 计分板 / 实体层；右上角依次是取景方式、暂停（仅回放）、聊天、菜单。
- **计分板**：`+scoreboard` 是 stroke 命令，按下走 stroke 1、关闭走 stroke 0。面板打开时 `ControlsAvailable()` 为假，所以单独开一条 `ScoreboardOnlyControls()` 分支：只画并只响应这枚按钮，作为关闭出口；打开面板的那一根手指按 `m_PressTime` 排除，不会刚开就关。
- **实体层**：循环 `cl_overlay_entities` 0 → 50 → 100 → 0，对应「只看地图背景 / 两者叠加 / 实体层铺满」；按钮图标下方直接写百分比，设置页里的同名选项同步反映。
- **取景方式**：`qm_mobile_camera_mode` 0 = 左下摇杆推进，1 = 单指拖动画面（拖动模式下摇杆既不绘制也不再吃命中，左下整片区域都能拖）。拖动位移由 `CTouchState` 在空白区域累计（与捏合、按钮互斥），`DragPan()` 乘 `m_Camera.m_Zoom` 后写进 `m_aMousePos`，画面与手指 1:1；拖动模式下不再画摇杆，按钮点亮表示当前状态。
- **单测**：`QmMobileSpectator` 补实体层循环、拖动位移（含 zoom 与非法 zoom）、空白区起手才算拖动、按按钮不算拖动、按钮不越界不重叠，以及新按钮都计入「控件区域不算镜头手势」。
- **待实机**：三个新按钮的点击、计分板开关、实体层三档观感、拖动取景手感（含缩放后跟手比例）。

## 九、计分板、玩家卡、投票与返回（2026-11-01）

对应架构文档第 4 步之后的三类按钮与返回栈。

- **计分板在手机上直接可交互**：桌面要先 `toggle_scoreboard_cursor` 解锁光标才能点行，手机没有悬停，面板一打开就按已解锁处理（`m_MouseUnlocked = true`），滚动、玩家行、「…」和面板里的投票按钮都直接可点。
- **点行跟随**：手机端点玩家整行 = 跟随（`SpectatePlayer()`：旁观中直接切目标，否则 `say /spec "名字"`），随后关闭面板回到画面；桌面保持整行点开玩家卡。
- **玩家卡**：行尾「…」按钮打开既有玩家卡（好友 / 静音 / 表情静音 / 复制名字 / 复制皮肤 / 复制皮肤 ID + Spectate）；「…」与整行用两个独立按钮 ID，互不吞点击。
- **下滑关闭**：从面板顶部区域（屏高 30% 以内）起手、向下滑过 12% 屏高即关闭；从列表内部下滑仍是滚动，不会误关。Android 返回键在手机上直接关面板，桌面仍然只是把光标锁回去。
- **顶部投票条**：`QmMobileVoteBarLayout(Screen)` 给出横幅 / 描述 / 原因 / 进度条 / 两个大按钮的几何，`CQmMobileSpectator::RenderMobileVoteBar` 绘制，触控层按手指命中并调用 `Vote(±1)`，只在新按下时投一次。手机端不再画左下角那个带按键提示的小投票框；计分板打开时改由计分板里的投票面板承担。
- **返回栈**：`QmMobileBackTarget()` 决定这一下返回关哪层——弹层 → 聊天 → 计分板 → 旁观列表 → 菜单，空栈时打开菜单；800ms 内第二次返回升级为退出确认（`ShowQuitPopup`）。手势触发为左边缘（屏宽 6% 内、屏高 10%–55%）起手右滑超过 7% 屏宽。
- **单测**：投票条几何（按钮在横幅内、至少 24 单位高、是/否不重叠）、可见性真值表、返回栈真值表。
- **待实机**：行跟随与「…」、下滑关闭与列表滚动不冲突、投票条两个大按钮、左边缘返回与退出确认。

## 十一、实机第二轮反馈（2026-11-02 凌晨）

- **计分板关闭**：面板矩形以归一化坐标记录（`CScoreboard::MobilePanelNdc`），触控层判断「点在面板外」即关闭；关闭按钮也从右上角挪到面板自己的右上角（`ScoreboardCloseRect`），随面板位置走，不会再出现「按钮消失、退不出去」。
- **最近 Tee 按钮**：「…」网格第四格改成 `NEAREST_TEE`（眼睛图标），取 `m_Camera.m_Center` 最近的活跃玩家并跟随，跳过自己、旁观者与无实体项；没有候选时提示「No tee nearby」，不会乱切。选人逻辑抽成 `QmNearestTeeClientId()`，单测覆盖自己/不活跃/空列表。
- **底部观战灵动岛**：`SLayout::m_Island` 常驻底屏居中，显示「Free view」或「Following: 名字」，点一下回自由视角（原「自由视角」按钮职责）。它计入控件区域，手指不会穿透去拖画面。
- **提示条**：字号 12、高度 36、最小宽度为屏宽 32%，显示 2.4 秒；计分板分支也会画，面板打开时同样能看到反馈。
- **准星**：`qm_render_cursor_spec` 的屏幕中心准星在手机端不再绘制（本来就是给鼠标用户标示中心用的）。
- **刘海铺满（已整体回退）**：上一轮给 `<activity>` 加的 `android:windowLayoutInDisplayCutoutMode` 不是合法清单属性；随之出现的「地图背景左右灰边」怀疑是窗口尺寸与表面尺寸不一致所致，因此清单属性与 `ClientActivity` 里的 `SHORT_EDGES` 调用都已移除，渲染路径回到已知可用状态。

## 十二、实机第三轮反馈（2026-11-02 傍晚）

- **计分板不再画关闭按钮**：面板上不叠任何控件，点面板外关闭（`MobilePanelContains` 判定），下滑关闭保留；原来的叉号会压住玩家行。
- **灵动岛与提示条宽度自适应**：岛体宽度 = 文字宽 + 30（下限 120、上限屏宽 60%），命中判定用同一矩形 `m_IslandRect`；提示条宽度 = 文字宽 + 40（下限 140）。两侧不再留大片空白。
- **滚动模式不再误触跟随**：手机端记录按下点，位移超过 8 个单位即按拖动处理，松手不触发行跟随；「…」玩家卡同样抑制。
- **滚动模式面板加高**：`QmScoreboardScrollPanelHeight()` 让手机滚动模式吃到可视区（上限 520），非滚动模式仍是原高度。
- 以上均以 `QmUiMobilePlatform()` 门控，桌面行为不变。

## 十三、旁观选择面板（手机独立放大）

- 面板（中间那片面 TEE 的列表，`CSpectator`）整体按 `LayoutScale = 1.35` 等比放大：行距、字号、Tee 尺寸、圆角、列宽、行点击框、首行起点、面板高度一起缩放，列数与每列行数仍沿用桌面规则，只放大尺寸不改排布。
- 为此把 `qm_spectator_layout::Build()` 面板半高参数化（默认 300，桌面行为不变），手机传 `300 * LayoutScale`。
- 桌面端完全不变（`QmUiMobilePlatform()` 门控）；手机端与桌面是两套尺寸。

### 待定（需人工指认）

## 十五、安卓 Vulkan 表面失效（2026-11-03）

- **现象**：切到后台再回来（HOME → 回到应用）时报「图形错误」，用户读作「初始化不了 Vulkan」；更早的版本这一步是 native 段错误（tombstone 在 `vkGetSwapchainImagesKHR`）。
- **根因**：安卓在回到前台时会换掉 `ANativeWindow`，旧 `VkSurfaceKHR` 随即失效。重建 swapchain 一直拿旧表面去建，只有 `VK_ERROR_SURFACE_LOST_KHR` / `VK_ERROR_NATIVE_WINDOW_IN_USE_KHR` 失败一路返回，最终落到图形错误对话框。
- **修复**：`RecreateSwapChain()` 在首次重建失败后，按当前窗口 `DestroySurface()` + `CreateSurface(m_pWindow)` 重建表面再重试一次；成功则继续渲染，不用重启。
- **实机证据**：logcat 依次出现 `acquire next image failed -1000000000` → `surface lost` → `native window in use` → `swapchain fsaa requested=0 selected=1`，随后前台回到 ClientActivity，截图正常，`logcat -b crash` 为空。



- **待查**：地图背景左右出现灰边（本轮未能复现/确认原因：设备在验收中途断开；已排除清单属性的干扰，若仍存在则优先怀疑 cutout 模式或按钮模糊的背板捕获）。


## 十、手感与反馈（2026-11-01 晚，实机反馈后）

- **拖动取景改成 1:1 跟手**：`DragPan()` 不再乘 `m_Zoom`，改用 `Graphics()->CalcScreenParams(aspect, Camera.m_Zoom)` 得到的可见世界尺寸换算——手指划过整屏，画面正好走一整屏的世界距离。旧写法在拉远（zoom > 1）时只走 1/zoom，实际约慢 4 倍，这是「灵敏度偏低」的来源。
- **按钮底板加高斯模糊**：`DrawButtonSurface()` 统一先 `Ui()->RenderGaussianBlur()` 再叠半透明色，观战按钮、摇杆、投票条、关闭按钮和提示条都走它。CUi 的模糊源每帧只准备一次，多个按钮各画一次不会重复捕获画面。
- **按钮按下给提示**：`ShowToast()` 在屏幕顶部居中显示 1.8 秒（最后 400ms 淡出），说明这次生效了什么——「计分板: 开/关」「实体层 50%」「镜头: 拖动/摇杆」；投票条出现时提示自动让到它下面。
- **翻译按钮不再拉起输入法**：触摸落在翻译按钮上时先记 `m_TouchTranslatePressed`，松手才打开翻译弹窗，并优先于正文区判断——之前这条路径走的是 CUi 鼠标命中，手机上取不到位置，结果被当成点正文弹输入法。
- **刘海区铺满**：`AndroidManifest.xml` 给 ClientActivity 加 `windowLayoutInDisplayCutoutMode="shortEdges"`，`ClientActivity.onCreate` 里同时按 API 28+ 设置 `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES`，避免软键盘弹起重新布局后顶部退回安全区出现黑边。
