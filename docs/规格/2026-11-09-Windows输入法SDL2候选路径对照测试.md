# Windows 输入法 SDL2 候选路径对照测试

状态：Windows Release 客户端、服务端和 Setup 均构建成功；等待搜狗实机反馈。草稿 PR：[#605](https://github.com/wxj881027/QmClient/pull/605)。

## 目标与范围

用户反馈 3.3 正式版的搜狗输入正常，希望在最新 master 中尽量还原 SDL2 的输入法逻辑，制作 Setup 交给用户测试。尚未取得异常机器的具体症状、消息记录和同环境复现证据。

比较基线：3.3 正式版 `9ad73e4dd18431867894ad346a386406cda3eee0`；master `82d13f65829767f6279a8eb54ce9adc138244ba3`。前者使用 SDL2，当前依赖头文件版本为 SDL 3.4.18。

这次保留 SDL3 和当前候选外观，只还原 Windows 候选来源、通知接入位置与候选状态转换。焦点交接、组合期间的编辑键保护和退出清理保护继续保留；不声称完整恢复了 3.3 输入环境。

## 测试包行为

- 从客户端窗口过程观察 `IMN_OPENCANDIDATE`、`IMN_CHANGECANDIDATE`、`IMN_CLOSECANDIDATE`，包含同步发送的通知；所有消息继续传给原窗口过程。
- 通知排入 SDL 事件队列，消费时使用 Windows IMM 读取当前候选页。该接入位置对应 SDL2 的 `SDL_SYSWMEVENT`，替换当前 SDL3 消息循环钩子。
- Windows 不再用 SDL3 候选快照覆盖、清空或补齐 IMM 候选；其他平台继续使用 SDL 候选。
- 文字仍由 SDL 的文本提交事件输入。提交清空候选并抑制迟到刷新，新的非空组合文本或打开候选通知解除抑制。
- 候选更新读取失败时保留旧页；打开候选读取失败时清空旧页；关闭候选时清空列表。
- 停止输入时移除窗口观察并清理通知队列；窗口销毁时自动移除观察，防止持有失效窗口。

这只能测试上述适配路径的影响。若新包恢复正常，仍需结合实机记录区分遗漏通知、混合候选源及状态转换的影响，不能直接判定 SDL3 库自身存在缺陷。
