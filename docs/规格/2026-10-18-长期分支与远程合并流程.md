# 长期分支与远程合并流程

## 目标

合并要同时满足三件事：

1. 对方分支的真实新增进入主目录；
2. 主目录已有的修复和当前设计不被旧快照覆盖；
3. 已经明确删除的功能、配置和 UI 入口不被旧提交重新带回来。

删除也是有效改动。合并时保留一处删除，和保留一处新增同等重要。

## 合并前

1. 先同步引用，确认基线：

   ```text
   git fetch --all
   git rev-parse HEAD
   git merge-base HEAD <remote>
   git log --oneline <merge-base>..<remote>
   ```

2. 单独列出对方分支里的删除和移除，不要只看新增：

   ```text
   git log --oneline --diff-filter=D --summary <merge-base>..<remote>
   git log --oneline -S'<功能符号或配置名>' <merge-base>..<remote>
   ```

   关注提交信息中的 `DEL`、`移除`、`删除`、`回退`，以及配置项、按钮、卡片、语言 key 的消失。

   同时检查 `Revert "Merge ..."` 一类提交。回退整个 merge 会把更早的删除一起恢复；要把被回退 merge 的净差异按同一删除清单逐项核对，不能把“回退”当作恢复旧快照的许可。

3. 在合并记录里先写两列：

   - **对方新增/修复**：准备并入的内容。
   - **已确认删除**：功能、配置、UI 入口、翻译 key，以及删除依据（提交、issue、远程说明）。

4. 长期分支或 reset 过的分支（例如 WT-1 一类）先确认它实际带了哪批工作。到 `rescue/*`、reflog、远程分支核对，不要假设“分支名相同就是同一批改动”。旧提交只作为实现参考，按当前主目录的卡片、配置和接口重写/移植，不整批 cherry-pick 旧文件。

## 合并中

1. 使用标准 `git merge`，不要用 rebase、reset 或强推改写双方历史。
2. 冲突逐个 hunk 按**当前主目录语义**解决：
   - 对方新增、主目录已删：保持删除，除非有新的需求依据。
   - 主目录新增、对方仍是旧实现：保留主目录，再把对方真正的新逻辑按当前接口接入。
   - 双方都新增：两侧内容都要保留，检查 ID、配置名和作用域是否冲突。
3. 对不确定的符号先查历史，再决定：

   ```text
   git log --all --oneline -S'<符号>'
   git log --all --oneline --grep='<功能名>'
   ```

4. 每解决一批冲突运行 `git diff --check`，并至少构建受影响的目标；接口变化要同时检查测试替身和独立目标。

## 合并后

1. 对比合并前后的主目录，确认净差异只包含双方预期内容：

   ```text
   git diff --stat <main-before> HEAD
   git diff <main-before> HEAD -- <高风险文件>
   ```

   重点看删除行：每一行都应是对方真实删除，或主目录当前设计的有意替换。

2. 对合并涉及的关键符号再做一次反向检索，确认没有被旧提交重新引入。例如 ESC 菜单、HUD 开关、配置清理、卡片注册、语言 key。涉及 `Revert "Merge ..."` 时，额外核对被回退 merge 的删除项是否被重新带回。
3. 构建和验证按风险选择，至少覆盖：

   - `game-client`、`testrunner`；
   - 有 UI 测试时构建并运行 `qm-ui-popup-tests`；
   - 全量 C++ 测试、quick/default gate；
   - 翻译改动按 i18n 流程完整提取/生成/校验；
   - 需要时补真实客户端烟测或可见窗口验收。

4. 在 `docs/规格/` 的合并记录中写清：基线 SHA、合并提交、冲突解决语义、保持删除的条目、验证结果和剩余风险。已删除功能在记录里保留一行，后续合并先查这张表。

## 删除功能时的同步动作

删除一个功能不能只删按钮：

- 入口按钮、布局宽度和间距；
- 状态机、HTTP/后台逻辑和成员变量；
- 配置项；旧配置键加入 `StoreUnknownCommand` 的清理名单，避免继续写回；
- 文档中的入口说明；
- `Localize` 字符串，同时删除 i18n TOML 源中的对应 key，重新提取/生成语言产物；
- 相关测试、合同和库存注册。
