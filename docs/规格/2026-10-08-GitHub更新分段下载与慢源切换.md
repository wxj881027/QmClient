# GitHub 更新分段下载与慢源切换

状态：已实现并通过下述自动验证，实际 PAC/WPAD 和企业认证代理环境仍待人工验收。本文规定当前行为；历史行为参见 [更新镜像回退与完整包发布](../归档/更新镜像回退与完整包发布.md)，其中整包下载、旧慢源判断及镜像继承环境代理的旧行为由本文替代。

## 目标和范围

更新器只下载批准的 GitHub Release 及其镜像附件，格式为 7z、ZIP 或 EXE。参考 Ketch 的 SegmentCalculator、SegmentDownloader 的连续区间划分、边界检查和单段重试机制，使用现有 C++、libcurl 和 Job 接口独立实现，不集成 Kotlin 引擎，不新增可配置限速、通用下载列表或其他协议。

参考代码：<https://github.com/linroid/Ketch/blob/main/library/core/src/commonMain/kotlin/com/linroid/ketch/core/segment/SegmentCalculator.kt>、<https://github.com/linroid/Ketch/blob/main/library/core/src/commonMain/kotlin/com/linroid/ketch/core/segment/SegmentDownloader.kt>。没有复制其代码或注释。

## 下载和校验

包先请求 bytes=0-0，严格检查 206、Content-Range 和正文长度，取得总大小。大包按连续区间分成最多四段，每段至少约 1 MiB；小包使用一个区间。未知大小、忽略 Range、416 或不完整的区间能力回退为整文件下载。后续单段忽略 Range 时也回退整包，不能把 200 正文追加到已有区间。

每段写独立文件；所有分段完成后在后台按偏移顺序合并，同时计算 SHA-256。主线程仅轮询状态与聚合进度，不读写完整包。HTTP 层拒绝错误区间、超量或截断的正文；协调器检查各段总大小一致，合并时再核对落盘长度。

合并完成仅表示下载完成。安装前继续验证现有 Ed25519 清单签名、版本、包大小、SHA-256 和包摘要签名；Range 或探测成功不能替代真实性验证。每次换源继续使用独立会话目录，旧 HTTP 或后台作业的迟到结果不能覆盖新批次。

## 测速和换源

源探测对包正文做最多 256 KiB 的前缀采样，并检查 7z/ZIP/EXE 魔数。官方采样吞吐低于 100 KiB/s 时优先可达镜像，否则优先官方；镜像按采样吞吐和延迟排序，运营组去重、批准源与冷却规则保持。

实际下载以所有分段的合计传输字节测速。首个包传输请求真正开始后才起算五秒窗口；官方连续窗口低于 100 KiB/s 且存在可达备用源时换源，不再要求备用镜像快两倍。镜像低速仍要求下一候选明显更快，避免无收益的连续切换。剩余不超过 256 KiB 时完成当前包，避免最后一小段导致整包重下。分段重试造成进度下降时重新起算测速窗口。

首字节十秒、后续无进展二十秒，排队和 PAC 解析不消耗分段传输期限；正常有进展的大包没有总时长上限。分段网络失败、5xx 或停滞时，只重试该段一次，已完成的其他段保留。继续失败则结束当前批次并沿现有候选队列换源。429/Retry-After 禁止原路即时重试，并传递外层源冷却。

当前不保存跨进程断点，也不从失败分段的中断偏移续传。换源仍创建新下载会话，不复用上一源的残片；单段重试保留的是同批次其他已完成分段。

## 代理

只有批准的官方 API、Release、Raw URL 可以使用代理。官方保留 libcurl 的环境代理优先级、NO_PROXY 和 Windows 系统代理、绕过列表、PAC/自动发现；没有代理时走直连。镜像显式设置空代理，屏蔽环境及系统代理。

记录选择的环境代理和 curl 实际是否使用代理，使环境 HTTP/SOCKS 代理故障也能进入官方最多一次直连回退；连接代理之前失败时，不能只依赖 CURLINFO_USED_PROXY。显式代理的现有判断保留兼容，NO_PROXY 仍交由 curl 原生处理，包括重定向各主机的绕过决定。限流与 Retry-After 不绕过。当前不增加代理认证配置；PAC、WPAD、企业认证代理和实际 GitHub HTTPS 重定向仍需环境实测。

## 验证

行为测试覆盖区间解析和规划、乱序完成后的文件/哈希、Range 失效回退、局部分段重试、重复失败、限流、取消、首字节及停滞期限、排队预算、旧批次迟到完成与新批次隔离，以及 100 KiB/s 判断。

本地真实 HTTP 探针覆盖四段并发、7z/ZIP/EXE 字节拼接与哈希、忽略 Range、错误区间、截断、429、HTTP/SOCKS5 代理、NO_PROXY 和镜像直连。Google Benchmark 测量区间规划和现有测速策略，不证明公网吞吐提升。

2026-10-08，Windows x64 Release 自动验证结果：客户端、testrunner、下载探针和 qm-benchmarks 均构建成功；C++ 全量 3907 项通过（包含单元、集成和静态合同，不能全部称行为测试）；本地真实 HTTP 验收 21 个场景通过。停滞场景在约 20.28 秒完成重连及合并，共六次请求（一字节探测、四段和一次重试），没有重下其他三段；最终文件和 SHA-256 一致。

quick gate 十二项通过；测试库存的混合声明、未注册、缺失源码与重复 ID 均为零。Google Benchmark 五个 case、每项五次重复完成测量：覆盖进度期限、速度窗口与 1 KiB/100 MiB/5 GiB 的区间规划。本次没有同条件旧实现基线，也没有公网、磁盘合并吞吐或玩家帧时间的性能提升结论。
