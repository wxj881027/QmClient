## 一、Teeworlds mod 是什么

**定义**：Teeworlds 生态中，mod 是对游戏的独立改造单元。经典形态是服务端 mod（DDRace、FNG、City、blocklands 等——自带服务器二进制、注册一个 gametype）；客户端 mod（DDNet、TaterClient 等）则是保持协议兼容的客户端 fork。Teeworlds 没有运行时插件系统，所以 mod 的形态一直是"整树 fork"，但这不改变它的组织理念。

**mod 理念**（从生态里提炼，共五条）：

1. **自包含**：mod 的逻辑、资源、配置归属自己，不散落进宿主代码。
2. **声明式接入**：宿主不认识具体 mod，只认接口——服务端注册 gametype，客户端在组件表里挂一行。
3. **低侵入**：接入一个 mod 不需要改造宿主的分发逻辑。
4. **可剥离**：拿走这个单元，宿主照常运行。
5. **命名空间自治**：配置、存档、网络消息用前缀隔开，互不污染。

QmClient 本身就是一个大 mod（DDNet 的 fork），`qmclient/` 目录是它的领地。理念的正确推论是：**mod 内部的每个功能单元（卡片），也应该按 mod 的方式组织——mod 里套小 mod。**

## 二、现状对照：宿主已就位，卡片未就位

今天实测 `menus_qmclient.cpp` 6173 行，43 个卡片渲染函数全部堆在一个翻译单元里；deck 用 `switch(EQmModuleId)` 手写分发（渲染、测高、revision、preLayout 各一套 switch）。

关键是：**宿主侧的三件套已经按 mod 宿主的形态建好了**——

| mod 概念 | QmClient 对应物 | 状态 |
| --- | --- | --- |
| 宿主 | `CSettingsCardDeck`（声明式协调器：排序、拖拽、滚动） | ✅ 已建 |
| mod 清单（注册表） | `QmCardRegistry`（stableId / tab / column / order / 搜索词） | ✅ 已建 |
| 玩家自定义布局 | `qm_card_order::CModel`（持久化、迁移） | ✅ 已建 |
| mod 本体 | 每张卡片（渲染 + 测高 + revision + 注册，同文件） | ❌ 还是 switch 分支 |

所以答案明确：**能做到，而且宿主已经做到位了。缺的只是把 43 张卡片从大文件的"肢体"变成注册的"单元"。** 拆分不是新建体系，是把已经建好的体系填满。

## 三、简章六条

1. **一张卡片 = 一个文件**。渲染、测高、revision、注册声明四处同文件。这是"高度单一真相源"从规约变成物理事实的唯一途径。
2. **页面只声明**。deck 页面只列出卡片 id，不含任何卡片内容代码。页面是卡片清单，不是功能容器。
3. **分类由数据表达**。卡片属于哪页由注册声明里的字段决定，不由目录决定；换页改一行声明，不动文件。
4. **共享控件下沉**。多张卡片共用的小控件（checkbox、label、keybind row）放 framework 层，禁止卡片互相引用。
5. **新增卡片零侵入**。新增一张卡片 = 新增一个文件 + 一行注册，不修改任何既有文件。做不到这条，拆分就没到卡片维度。
6. **拆分是搬运不是重构**。行为不变，构建过、测试过、界面观感一致。搬运过程中顺手改逻辑视为失败。

## 四、判定标准

| # | 标准 | 对应 mod 理念 |
| --- | --- | --- |
| 1 | 新增卡片不需要编辑任何既有文件 | 低侵入 |
| 2 | 删除卡片 = 删文件 + 删注册行，其余代码不动 | 可剥离 |
| 3 | 卡片跨页移动 = 改一行声明 | 命名空间自治（位置是数据） |
| 4 | 单卡文件典型 70–800 行；单函数 ≤300 行 | 自包含 |
| 5 | deck 页面文件里看不到任何 `switch(EQmModuleId)` 分发 | 声明式接入 |
| 6 | 单个源文件 ≤2000 行 | 自包含（宏观） |

## 五、执行顺序（引用方案）

1. 先拆 `menus_qmclient.cpp`——43 张卡片到 `qmclient/cards/{visual,function,hud}/`，纯搬运；
2. 再拆 `menus_tclient.cpp`——先解掉 2261 行的单函数，再按文件拆；
3. 最后对齐上游 `menus_settings*.cpp` 的 14 文件结构。

前置条件：上游合并完成后启动，否则冲突翻倍。

## 六、一句话结论

**全局卡片理念就是 Teeworlds mod 理念在 UI 层的重演**：宿主（deck + 注册表）只认接口，卡片（mod）自包含、声明式接入、可插拔。宿主已经建好，剩下的是 43 次搬运。
