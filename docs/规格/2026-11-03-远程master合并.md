## 合并后复核（两路子代理）

冲突解决与「两侧意图是否都真正落地」各跑了一路只读复核，结论一致：生产代码没有阻断级缺陷，但合并后有两处测试必失败，另有三处意图缺口。逐条处理如下。

### 必修（会让测试红）

1. `qm_mobile_spectator_test.cpp:424` 写于旧签名 `Layout(Screen, JoystickActive)`，合并后签名是 `(Screen, Demo, JoystickActive)`，`false` 落到 Demo 上，摇杆仍抢手指，`DragModeHandsTheJoystickAreaOverToPanning` 三条断言失败。改为 `Layout(Screen, true, false)`。生产侧 `:536` / `:677` 的实参含义本来就是对的。
2. `qm_card_registry_test.cpp:35` 仍在查对方已替换掉的 `Use embedded HUD progress bar`，而 `SearchCards` 是全 token 命中，查询必然返回空。改为 `Progress bar location`。

### 意图缺口（功能不完整）

3. 头衔风格标签缺卡：`Fluid` 只移植进赞助头衔卡，真正带风格下拉的 Title display 卡（`QmCardCatalogFallback.inc` 417 起的数组）一条风格标签都没有，补 `Fluid` / `Normal` / `Platinum highlight`，并把 Sponsor 卡里的 `Fluid` 挪回字母序位置。
4. 进度条位置下拉的 `Player stats` / `Standalone` 没进 `qm:player_stats` 索引，补齐后 `check_card_search_index.py --strict` 的缺口表清空。
5. 收藏星标语义不一致：投票页注释还写着「关着时两端同形」，但合并进来的 `CQmFavoriteStarFillScope` 已让字形先按收藏状态决定，按实际行为重写注释；服务器浏览器的收藏筛选星标没有套同一作用域，一并对齐。

### gate 修复方式

按「代码需要」而不是放宽检查：三处裸颜色都是移动端触控层/赞助聊天/聊天气泡的黑色压暗层与白色文字，改用 `ui_token::color::NEUTRAL_BLACK`、`NEUTRAL_WHITE`、`SURFACE_OVERLAY` 加 `WithMultipliedAlpha` 组合，RGBA 数值逐项不变（含 `ColorRGBA(1,1,1,0)` 这种 0 alpha 也保持同值），绘制结果完全不变；随后按实际存量把基线从 169 收紧到 161。
