# 设置页 Token 与一致性改动报告

日期：2026-11-11
范围：QmClient 设置页（外观 / QmClient / TClient / DDNet）与公共 UI 组件（按钮、输入框、下拉框、列表、卡片骨架）

---

## 0. 一句话

设置页此前每个卡片各自决定字号、行距、圆角、内边距和图标大小：同一个"正文"有三套来源，同一排控件字体不一样大，箭头比文字大一半，列表选中态三种形状。这次把它们收成**单一定义源 + 语义档位**：调用点只选语义，不再写数字。

## 1. 设计原则

1. **一个事实只有一个来源**：字号来自 `SSettingsContentMetrics`（随视口缩放），图标来自"字形 em = 文字字号"，间距来自档位函数，圆角来自按尺寸推导。
2. **图标与文字同 em**：`IconGlyph = BodySize`、`IconBox = Glyph / 0.8`，与 `QmIconFontSize`（盒 × 0.8）严格互逆，走一圈回到文字字号。
3. **行距只有一条规则**：每个可见行自己声明行距（子行 0.5× / 行间 1× / 分区 2× / 卡尾动作 4×），不再"行后补 Space"、也不再有"组自带尾距"。
4. **公共能力优先**：动画、滚动条、胶囊行、互斥分支都做成组件能力，调用点只开关，不各写一套。

## 3. 改动报告（按领域）

### 3.1 字号统一
- 单选行字号不再被"未缩放的 12"托底，回到 `m_BodySize`（窄窗口 10）；
- TClient 卡片 13 个隐式全局度量改成 `CTClientCardMetricsScope` RAII，23 个入口全接入；
- 硬编码 `11.2` 等正文号收口到 Metrics；
- 侧栏页签：预热与绘制统一到 `TAB_FONT_SIZE`(13)，修掉"预热容器每帧被判脏、token 不生效"；
- `Hookable tiles` / `Unhookable tiles` 补中文（原来只在 `[Editor]` 段）。

### 3.2 行距统一（A 型规则）
- 确立规则：**每个可见行自己声明行距**（`Control(id, h, rect, spacing)`）；
- `DoSettingsToggleGroup`：删"首行特判 0"与"组尾补一档"，与普通行同规则；
- `DoSettingsToggleButtonGroup`：同步，非声明式 raw 路径显式补一档保持总高不变；
- 29 处折叠区、42 处条件行接入显隐动画；跨文件 4 个 helper 转 A；
- `cards/` 132 处 `Flow.Space(` 中真正「紧跟同层 Control」的只有 9 处，已全部并入下一行第 4 参（ChatCompletion、DDNet×3、General、Graphics×2、TClientConfigs、TranslateContent）；其余 123 处按例外保留（条件/循环内 73、helper 或行工厂 lambda 内 39、下一条是 Text 4~6、折叠/互斥槽位与卡片尾 7），本节数字以 2026-11-11 实测为准；
- 修 `Control()` 与 `Space()` 行距被**系数平方**压缩、`Text()` 行距完全不缩放的 bug。

### 3.3 间距档位化
- 新增四档（见 2.3）；
- 迁移 12 处：`+2.0f`→行间、`+5.0f`→分区、`0.35/0.4/0.5/0.6`→子行、`0.75/1.15`→行间、卡尾 `4×`→`ActionGap`；
- 真分区位置（General 5、DDNet 2、TClientConfigs 2、外观 1）保留并注明理由。

### 3.4 控件内部尺寸
| 控件 | 改前 | 改后 |
|---|---|---|
| 按键识别行垃圾桶 | 盒 0.48h → 字形 7.68 | 字形 = 键名 em，盒 = 字形/0.8 |
| 下拉 chevron | 0.8×(h−4)，行高 28 时 19.2 | 字形 = 标签字号（永远同大） |
| 普通按钮字号 | 写死 12，窄窗口不缩 | `BodySizeFromScale` |
| 输入框/数值框字号 | `min(给定, 0.8h×0.8)` 双 0.8 | 给定优先，兜底只用一次 0.8 |
| 菜单按钮图标盒 | `Text.h`（比约定大 6%） | `IconBox(字形)` + token 间距 |
| 弹层条目文字 | 贴左缘 | `EntryInsetX` 内退 |

### 3.5 列表组件（CListBox / CScrollRegion）
- 胶囊行（`SetCapsuleRows`，**显式开启**，不影响服务器浏览器/demo/投票等 20+ 旧页面）；
- 容器圆角按尺寸推导（原固定 5）；
- 行内容区 `m_ContentRect` + 行内内距；
- 自适应高度：`SetVisibleRowRange(min,max)`，显示模式 1–8、皮肤队列 1–6、预设栏 2–3；
- 覆盖式滚动条：不占行宽、fade + 横向滑出（0.12s），内容不再溢出时仍画完渐隐，淡出期不接受拖动。

### 3.6 卡片默认布局
- 删除注册表里逐张手写的列/序，改为**对称瀑布**：按累计高度进更矮列，全宽卡独占一行并清零；
- 用户已保存的位置优先；59 张卡默认列变化；
- 相关测试从"逐卡期望列序"改为**性质断言**（每卡恰好一次、进更矮列、列内序是注册顺序子序列、聊天页两列高度差 ≤25%）。

### 3.7 颜色默认值
- 重置默认色从手抄字面量改为引用 `CConfig::ms_<Name>`（90 处，15 文件），定义上消除"默认≠重置"；
- 聊天气泡背景出厂值 `0x18181B00`（alpha 0 透明）→ `0xCC000000`（黑 80%）；
- 7 个"按 RGB 写进 HSL 字段"的出厂值修正为 HSL 打包（武器轨迹橙、3D 粒子灰绿、地图进度绿、铭牌辉光青、命中框品红/青/黄）；
- 修 `QmShowCenterColor` 重置把 HSL 位模式当 RGBA 的 bug。

### 3.8 动画
- 交互显隐：布局高度按进度缩放 + 内容淡入，ease-out 0.14s，一帧只推一次（量高趟）；
- 互斥分支组件 `CSettingsExclusiveReveal`：同槽位交叉淡化，槽高恒定，翻译卡切后端不再叠加；
- 折叠行：分割线可关、右侧小字 + chevron、暗沉→悬停强调色、整行可点、chevron 与文字同字号且走卡片标题同一条形变轨道；
- 展开状态持久化 `qm_expanded_sections`。

## 8. 第三轮：弹层条目内退的轴向修复（2026-11-11 下午）

### 8.1 根因：`HMargin` 是纵向，`VMargin` 才是横向

实机反馈「显示模式下拉里的条目文字贴着胶囊左缘」在第一轮改完后仍在。定位结论：**不是常数太小，是轴向用错**。

`CUiRect` 的三个边距方法只差一个 vec2 分量（`src/game/client/ui_rect.cpp:177-200`）：

| 方法 | 实现 | 实际方向 |
|---|---|---|
| `Margin(vec2(X, Y))` | `x += X; w -= 2X; y += Y; h -= 2Y` | X 横向、Y 纵向 |
| `VMargin(Cut)` | `Margin(vec2(Cut, 0))` | **横向**（左右） |
| `HMargin(Cut)` | `Margin(vec2(0, Cut))` | **纵向**（上下） |

`DoButton_PopupMenu` 里写的是 `Label.HMargin(ResolvedInsetX)`，于是内退被加到 y/h：文字横向一分没退（横向只剩 `m_EntryPadding` 的 1~2 UI），纵向还被压掉两段行高。数值上把第三档从 12 加到 16 只是把错误方向压得更狠，所以「改常数没反应」是必然的。

同一轴向错误出现在三处：`ui.cpp` 的 `DoButton_PopupMenu`、`chat.cpp` 的「发送给」弹层与聊天行右键菜单、`SecondaryPanel.h` 的提示条。

### 8.2 修复

| 位置 | 处置 |
|---|---|
| `ui_token::dropdown::EntryInsetX(FontSize, RowHeight)` | 第三档从 `max(…, spacing::LG=16)` 改为 `min(EntryInsetX(FontSize), 行高/2)`：行高只当上限，不再把内退越推越大 |
| `ui_token::dropdown::EntryLabelRect(Row, Padding, FontSize, InsetXOverride)` | 新增：`Margin(Padding)` + `VMargin(内退)`，轴向只在这里算一次，四处调用共用 |
| `CUi::DoButton_PopupMenu` | 改用 `EntryLabelRect`（显式 `TextInsetX` 仍优先） |
| 聊天「发送给」、聊天行右键菜单、二级面板提示条 | 丢掉各自的硬编码 `VMargin(7/4)` + 错轴 `HMargin`，统一走 `EntryLabelRect`；横向内退 8~9 UI |
| `QmUiTokensTest.cpp` | 新增 2 个用例：档位随字号/行高（8、9、按行高夹取、退化行高不为负）+ **矩形只在左右内退、纵向只受 Padding 影响**（把 `VMargin` 改回 `HMargin` 该用例立刻失败） |

## 9. 行与文本的命名约定

同一处文字在代码里有六七种写法（`Flow.Control` + 右侧小字、`Flow.Text` 独立说明行、折叠行、分区标题、卡尾按钮），口头沟通时「说明」「提示」「小字」「副标题」经常指向不同东西。这一节只定「设置页里一行字该叫什么、该走哪个入口」，口径与 §1 一致，不引入新 token。

### 9.1 七个词

| 术语 | 是什么 | 何时用 | 代码里唯一正确入口 | 禁止的做法 |
|---|---|---|---|---|
| **主控行** | 承载可交互控件的普通行；它的存在与父项无关 | 设置项的默认形态 | `CSettingsContentLayoutFlow::Control(id, 高度, Rect, 行前间距)`（`src/game/client/QmUi/SettingsContentLayout.h:249`），间距取 `ui_token::settings::RowGap / SubRowGap / SectionGap / ActionGap` | 行后再补 `Flow.Space`（双计）；把间距写在上一行的尾部 |
| **从属行** | 只有主控行**当前值**成立时才存在的行；父项关掉时**不参与布局、不占高、不可交互** | 开关打开后才出现的参数行 | `CSettingsConditionalRows` + `CSettingsContentRevealScope`（`src/game/client/QmUi/SettingsRowReveal.h:125`、`:91`） | 用禁用态/置灰冒充隐藏；用固定高度留白；在 `if` 里直接不声明（高度瞬跳、无过渡）；自己算显隐进度 |
| **行尾说明** | 同一行内、控件右侧或紧随控件的**常显**短提示 | 单位、当前值、一行内放得下的补充约束 | 暂无统一 helper。输入框/数值框内的后缀走 `ui_widget::SInputFieldOptions::m_pTrailingText`（`src/game/client/QmUi/UiForms.cpp:353`）；独立行尾提示**待补 `DoSettingsInlineHint`**（见 9.6） | 写成长句或换行；为它单开一行高度；用 tooltip 代替常显提示；自己 `DoLabel` 且字号/颜色各写一份 |
| **说明行** | 独立一行、自己占行高的解释文字 | 一句话说不完、需要换行的补充说明 | `CSettingsContentLayoutFlow::Text(id, 文本, 缩进, FontSize, 行后间距, 测量, 绘制)`，字号用 `m_SmallSize`，如 `src/game/client/QmUi/cards/QmCardCatalogGeneral.cpp:305` | 把它塞进行尾说明（挤爆同行）；再补 `Flow.Space`（`Text` 第 5 参本身就是行后间距） |
| **折叠行** | 「个性调整」这类「小字 + chevron」、整行可点的行，控制一段内容的展开 | 把低频高级项收进一段 | `SettingsFoldRow(...)`（`src/game/client/QmUi/SettingsPersonalization.h:136`）+ `ResolveSettingsFoldRowStyle`（`:127`）；行本身按主控行声明行距 | 再画分割线（已取消，见 9.5）；用标题字号冒充；展开态不持久化（`qm_expanded_sections`） |
| **分区标题** | 卡片内一段内容的标题 | 一张卡里有两段以上内容 | 暂无统一 helper。外观卡是局部 lambda `DoAppearanceHeading`（`src/game/client/QmUi/cards/QmCardCatalogAppearance.cpp:104`，内部 `Flow.Control` + `DoSettingsLabelStreamed`）；**待补 `DoSettingsSectionHeading`**（见 9.6） | 各卡用 `Flow.Text` 自己写一份、字号与行前间距各写一份；与分区间距叠加（标题行已声明 `SectionGap` 时再补 `Flow.Space`） |
| **卡尾动作区** | 卡片末尾的整卡级动作（「全部设为…」） | 一次性作用于整卡或整列表的操作 | 主控行 + `ui_token::settings::ActionGap(行距)`（4×），如 `src/game/client/QmUi/cards/QmCardCatalogAppearance.cpp:1411` | 用分区档（2×）当卡尾；动作区前后再补 `Flow.Space` |

词汇边界：主控行/从属行讲的是**存不存在**；行尾说明/说明行讲的是**文字放在哪**；折叠行讲的是**一段内容怎么收**；分区标题/卡尾动作区讲的是**这一段是什么**。

术语最容易混的一对是「从属行 vs 禁用行」：禁用态（`ReadOnly`、置灰）表示「这一行存在，但当前不能改」；从属行表示「这一行不存在」——不占高、不进命中、连快捷键提示也不该出现。

### 9.2 从属行的判定与最小写法

判定只用一条：**把父项关掉，看这一行还剩什么。**

- 仍占高、仍吃点击 → 不是从属行（多半是主控行，或恒占位的分区内容）；
- 变灰但占高 → 写法错，这是「禁用态冒充隐藏」；
- 不占高、不可点，且高度与内容一起过渡 → 合规。

三条硬约束：

1. 存在性只依赖父项**当前值**；`CSettingsConditionalRows` 里记的是动画进度，不是判定依据，不要拿进度反推显隐。
2. 关闭时 DECLARE 趟**不 push 这一行**，不是 push 一个 0 高度行——否则 `Flow.AdvancedHeight()`、卡片测高和卡片高度动画都会把它算进去。
3. 测高与绘制同一入口：`Update(...)` → `Fade(...)` → `CSettingsContentRevealScope`，不要在绘制趟另算一次显隐。

最小正确写法（`src/game/client/QmUi/cards/QmCardCatalogDDNet.cpp:197-210`，行内业务省略）：

```cpp
static CSettingsConditionalRows s_ReplayOptionsRows;
if(s_ReplayOptionsRows.Update(g_Config.m_ClReplays, GameClient()->UiRuntimeV2()->FrameDt(), g_Config.m_QmUiMotionLevel))
{
	const CSettingsContentRevealScope ReplayOptionsRevealScope(Ui(), Flow, s_ReplayOptionsRows.Fade(g_Config.m_QmUiMotionLevel));
	if(Flow.Control("replay-length", DDNetMetrics.m_LineHeight, Button))
	{
		DoDDNetNumericField(...); // 行内业务，略
	}
}
```

两类「看起来像但从属行」的东西别混用：

- **互斥分支**（同一槽位二选一/三选一）用 `CSettingsExclusiveReveal` + `CSettingsExclusiveBranchScope` + `SlotPadding()`（`SettingsRowReveal.h:176`、`:391`）。它保证过渡期槽高恒定；拿它写从属行会平白占一档槽高，正是「用固定高度留白」。
- **整卡「个性调整」开关**走 `PersonalizationReveal`（`CMenus::PersonalizationReveal`，`src/game/client/QmUi/cards/QmCardCatalog.h:140`；渲染钩子版 `QmCardRenderHook::PersonalizationReveal`，`QmCardCatalog.cpp:64`），它管的是整段内容露头，不是单行的从属关系。

现状（待迁移，见 9.6）：`src/game/client/QmUi/cards/QmCardCatalogBackground3DContent.cpp:197`、`:211`、`:225`、`:237` 仍是裸 `if(g_Config...)` 直接声明行——主控行关掉时这些行是瞬跳的，既没登记 `CSettingsConditionalRows`，也没有高度过渡。

### 9.3 行尾说明的档位与最小写法

| 项 | 来源 |
|---|---|
| 字号 | 行级 `SSettingsContentMetrics::m_SmallSize`（`src/game/client/QmUi/SettingsPageLayout.h:116`，派生见 §2.10：`clamp(10×UiScale, 9, 10)`） |
| 颜色 | `ui_token::color::TEXT_SECONDARY`（`src/game/client/QmUi/UiTokens.h:65`，`{1, 1, 1, 0.72}`） |
| 右侧宽度 | **不做固定预留**：按实际文本量宽（`TextWidth(字号, 文本)`），超宽用 `SLabelProperties::m_EllipsisAtEnd` 收尾，不挤控件、不换行 |

输入框/数值框内的单位后缀是另一条既有链路：字号 `FontSize × ui_token::control::SUFFIX_RATIO`（0.82，`UiTokens.h:211`），排版由 `ResolveInlineTrailingTextLayout`（`src/game/client/QmUi/UiForms.h:180`）一次算完。两者是**不同层级**——后缀属于「控件内部排版」（§2.5），行尾说明属于「行级文字」（本节）。数值同档（0.82×12 ≈ 9.84，`m_SmallSize` 在 Scale 1 时是 10）但来源不同，同一行里不要两套并用。

行级行尾说明目前**没有** helper：`src/` 下不存在 `InlineHint` / `TrailingHint` / `DoSettingsHint` 之类的定义，带 `Inline` 的只有上面的输入框后缀链路。所以这条约定现在只有「应当长成的样子」：

```cpp
// 待补 helper（见 9.6）：同一行右侧、常显、超宽省略、不占独立行高
DoSettingsInlineHint(&Row, HintText, Metrics); // 内部固定：m_SmallSize + TEXT_SECONDARY + TEXTALIGN_MR + m_EllipsisAtEnd
```

helper 落地前，新增的行尾说明按上表三档来源手工写，**不得**引入第四种字号或颜色；存量写法不算合规，统一归 9.6 的入口。

### 9.4 一句话复述

- 「A 是 B 的从属行」= B 关掉，A 就不存在（不占高、不可点、有过渡），不是「A 变灰」。
- 「预测事件配一条行尾说明，不写说明行」= 那行本来就有控件那一行的宽度，短提示贴着控件右边常显就够了，不要为它单开一行。

### 9.5 与既有说法的关系

| 既有说法 | 关系 |
|---|---|
| §1.1「一个事实只有一个来源」 | 一致。**缺口**：行尾说明的字号/颜色各有一个来源，但入口还没收成一个（9.3/9.6）。§9 是对 §1.1 的延伸要求，不取代它 |
| §1.3「每个可见行自己声明行距，不再行后补 Space」 | 一致。补一句口径：**Control 行声明的是行前间距，Text 行（说明行）的第 5 参是行后间距**，两者不可互相替代——「行自己声明」不等于「位置随意」。§9 沿用此口径，不改 §1.3 |
| §2.9「行类型 `ui_token::settings::row`」 | 并存但**未迁移**。`GROUP_HEADER` / `DIVIDER` / `NOTE` 是未缩放的旁路 token，和卡片派生链不是同一套数值（`GROUP_HEADER.m_Spacing = 16`，而卡片分区间距是 `SectionGap = 2×行距`）。**§9 的「唯一正确入口」一律指派生链那一套**，`settings::row` 只在已迁移的调用点使用 |
| §3.8「折叠行：分割线可关」 | **被取代**。折叠行已不画分割线（`SettingsPersonalization.h:119-120`，`:195` 注明 `DrawDivider` 只是历史参数），调用点也不再为分割线预留高度（`cards/QmCardCatalogTranslateContent.cpp:657` 已改为 `RowGap`）。以 §9.1 为准 |
| §5.4「`m_LineSpacing` 未批量换成 `RowGap(...)`」 | 不冲突：§9 定的是「行距由行自己声明」，值与写法是两件事 |
| §2.5 `SUFFIX_RATIO` | 分工明确：控件内后缀 vs 行级行尾说明，见 9.3 |
