# Axiom 分身登录与启动卡顿修复

状态：实现与本机自动验证完成，真实 0.7 连接/回放及 Axiom 实服认证、鼠标交互验收待完成。开始基线为 `e6c2801156b62b82df38bf265a74b8ed2943b1e6`，修改在主工作树。

## 目标与确定原因

快捷键 `dummy_connect` 连接的分身应与 HUD 连接的分身一样自动登录 Axiom。原实现只在 HUD 点击时设置允许重连标记，又将该标记作为登录的前提，因此快捷键连接被遗漏。登录和重连现在分别由生产状态管理：任何已连接且配置了密码的分身可登录一次；只有已有 HUD 重连意图才自动重连，手动断开和服务器切换清除该意图。

启动后进入服务器列表的秒级停顿已在真实 Windows 开发客户端复现。首次采集最长帧为 1214.370ms；组件细分采集确认自定义社区刷新 `on_render` 达到 1056.052ms。进一步拆分得到缓存文件读取 1035.754ms，同帧组件回调 1036.740ms。服务器列表更新本身约 5–6ms，菜单内容同帧约 1–2ms。证据分别在 `tmp/serverlist-startup-baseline/`、`tmp/serverlist-startup-attribution2/` 和 `tmp/serverlist-startup-phases3/`。采集时间为 2026-10-13 凌晨。

自定义社区下载改用 HTTP 文件和内存双输出；启动旧缓存的读取和解析、成功在线响应的解析均交给后台任务，主线程只接收完成结果并应用社区数据。加载页和服务器列表采用相同线程约束。旧缓存和在线解析独立持有任务：只有有效在线结果才能取消尚未发布的缓存，损坏响应保留旧数据与仍在进行的缓存读取。更换 URL、关闭功能和组件销毁取消旧任务；响应任务持有 HTTP shared_ptr，确保解析期间响应内存有效。生产加载接口能够独立验证与 benchmark，应用社区数据保留主线程阶段计时。

另一次组件更新阻塞为 199.036ms，主要来自 `skins7` 的 198.615ms。原实现在普通启动时也加载 0.7 皮肤，后台部件完成后在主线程扫描并逐个读取 JSON 描述。

## 0.7 资源启用与生命周期

按用户要求，普通启动、服务器列表中出现 0.7 地址、0.6 连接，以及通用刷新入口，均不能启动 0.7 资源扫描或加载。只有实际处于 0.7 CONNECTING、LOADING、ONLINE 才允许加载；0.7 DEMOPLAYBACK 保留资源需求，以保持已有回放兼容。

生产生命周期统一约束首次加载、重复更新、显式刷新、离开取消与重新进入。退出 0.7 上下文时移除当前任务，迟到结果不能再发布。已完成的纹理作为只读缓存保留，避免现有部件引用失效；无 0.7 上下文时不执行加载/消费工作。首次再次进入使用该缓存；未完成的旧加载已取消时重新发起。

0.7 皮肤描述与六个部件目录的扫描、描述读取与解析、圣诞帽和机器人附加 PNG 读取与解码交给独立任务。任务只持有存储与 CPU 数据，不调用 UI、客户端或图形接口。部件任务的读取、解码、灰度化、描边与聊天头像也在后台完成。主线程分批创建部件任务、上传纹理，在全部部件向量稳定后分批绑定描述引用，并通知受管理的皮肤信息刷新。批处理使用约 1ms 软预算，保留全局 GPU 上传数量限制；单次驱动调用无法抢占，因此不是整帧 1ms 的保证。描述绑定后立即释放各自 JSON，避免最后一帧集中销毁全部解析树。占位部件保证资源尚未完成时的安全回退。刷新与退出取消旧任务，不能混入旧描述。
