# Demo 视频导出现代化实施方案

状态：方案已立项，未开工。各里程碑独立验收，按顺序推进；每阶段开工前核对本文与源码现状是否仍一致。

## 背景与现状

现有实现集中在 `src/engine/client/video.cpp`（约 1179 行）与 `src/engine/client/video.h`，经 2026-10-16 源码核对确认的限制如下：

| 编号 | 现状 | 位置 |
| --- | --- | --- |
| L1 | `avcodec_find_encoder(CodecId)` 按 CodecID 取默认编码器，无法指定 libx264/h264_nvenc/h264_amf/h264_qsv 等具体实现 | video.cpp:939 |
| L2 | 像素格式写死 `AV_PIX_FMT_YUV420P`（8-bit 4:2:0），彩色文字、锐利边缘损失色度 | video.cpp:1025 |
| L3 | `gop_size` 写死 12 帧 | video.cpp:1024 |
| L4 | 工作线程数 = `hardware_concurrency() + 2`（音频线程 = 一半 + 2），每线程独立全尺寸 RGBA 缓冲；4K 下 16 逻辑线程即 18 个视频线程，仅 RGBA 缓冲理论占用约 570 MiB | video.cpp:179-181 |
| L5 | `avcodec_send_frame` 返回值两处丢弃，编码背压与错误不传播 | video.cpp:1071、1123 |
| L6 | PTS 取自编码器内部 `frame_num`，时间戳管理依赖编码器状态 | video.cpp:668-671 |
| L7 | Stop 收尾集中等待线程、flush 编码器、写尾部，异常中断后普通 MP4 缺索引不可播放 | video.cpp:342 起 |

已具备的基础（本 worktree 已超前于公开 master）：容器可选 mp4/mkv（`cl_video_container`，`QmVideoRuntimeContainer()` 带 `av_guess_format` 回退）；已引入 `avcodec_get_supported_config` 条件编译层（video.cpp:972-978）；已有 x264 preset 标签 UI 与单元测试（`qm_video_preset_labels.h`、`qm_video_preset_labels_test.cpp`）。依赖侧：ddnet-libs 本地分支 ffmpeg-matroska 重编了 FFmpeg 7.0.1（libavcodec major 61），lib64 补了 matroska muxer。

玩家反馈的三个核心痛点：默认参数导出画质不理想；数小时 Demo 导出极慢；中途崩溃后数小时计算全部作废。

## 目标与非目标

三目标，按优先级：默认画质足够好；长时间渲染足够快；渲染失败可恢复。

非目标：不改协议、snapshot、物理与 demo 格式；不追求 FFmpeg 版本号本身；不把 FFmpeg 全部参数搬进 UI（只做预设 + 高级自定义）；不在本方案内做真正的 10-bit HDR 渲染管线（仅留路径）。

## 阶段规划

对应外部评估的 P0-P3 四阶段，按本仓库现状细化为八个里程碑。M1/M2 为 P0 级（稳定与资源），M3/M4/M5 为 P1 级（可恢复、硬件编码、依赖升级），M6/M7 为 P2 级（剪辑工作流、画质进阶），M8 为 P3 级（架构进阶）。同里程碑内任务串行，里程碑之间除 M5 外不互相阻塞。

### M1 编码错误处理修复

- `avcodec_send_frame` 两处调用检查返回值；`EAGAIN` 表示编码器需要先收包，需按 FFmpeg 文档处理背压，其余负值记录 `av_strerror` 并置错误标志。
- `WriteFrame`/`FinishFrames`/`CloseStream` 建立可传播的错误状态，Stop 后 UI 能显示导出失败原因而非静默产出坏文件。
- 显式管理帧序号与 PTS：在 `CVideo` 维护独立的帧计数器生成 PTS，替代读取编码器 `frame_num`（L6），保证 flush 阶段与取消路径时间戳一致。
- 涉及文件：video.cpp、video.h。验收：编码器故意注入错误（无效参数）时导出失败且日志可见，正常导出音画同步不变。

### M2 资源与吞吐重构

- 以固定上限的有界帧队列 + 少量转换工作线程替换按核数分配的线程与缓冲（L4）。初始值建议：转换线程 2-4 个，队列深度 8-16 帧，均可配置并 clamp 上限；实际数值以 4K/1080p 实测调优。
- 离线 Demo 渲染允许生产端在队列满时等待（反压），不丢帧、不无界缓冲。
- 编码提交仍经 `m_WriteLock` 串行，但转换与编码解耦；CPU 编码并行性交给编码器自身 `thread_count` 与帧级并行（x264 frame-threads）。
- 涉及文件：video.cpp、video.h。验收：4K 导出常驻内存相对现状下降且不随 CPU 核数线性增长；1080p60 与 4K60 导出耗时不变差。

### M3 分段渲染与断点续渲

- 支持把一次导出拆成固定时长片段（默认建议 5 分钟，可配），每段独立封装、验证（读尾部成功）并记录进度。
- 进度持久化：任务清单（源 demo、起止 tick、片段大小、编码参数指纹、已完成片段）写入 videos 目录旁的进度文件；导出重启时跳过已完成片段。
- 片段边界要求：起止对齐编码关键帧（片段首帧强制 IDR）；音频时间戳连续；Demo 侧按 tick 定位还原状态，必要时预热若干 tick 使特效、聊天等状态与整段导出一致。
- 拼接策略：片段编码参数一致时用 FFmpeg 流复制 concat 拼接；参数不一致或用户要求时保留独立片段。拼接前校验各片段流参数一致。
- 崩溃可恢复的容器侧：7.0.1 下 mkv 天然比 mp4 抗中断；FFmpeg 9 的 hybrid_fragmented MP4 列为 M5 后的可选增强。
- 提供 Demo 时间范围选择（复用上游 `demo_slice_start`/`demo_slice_end` 定位逻辑，UI 上在渲染确认弹窗加起止点），支持只渲染选区或多片段批量任务。
- 涉及文件：video.cpp/h、client.cpp（渲染状态机）、menus_demo.cpp（UI）、新增分段任务管理模块（建议 `qmclient/video_export/` 下）。验收：3 小时长 Demo 中途 kill 进程后重启能跳过已完成片段继续；整段与分段+拼接产物时长、帧数、音画同步一致。

### M4 编码器抽象与硬件编码

- 编码器按名称选择：新增字符串配置（如 `qm_video_encoder`，空值 = 现行为），`avcodec_find_encoder_by_name` 解析；为空时维持 `avcodec_find_encoder(CodecId)` 兼容。
- 像素格式协商：用已接入的 `avcodec_get_supported_config`（AV_CODEC_CONFIG_PIX_FORMAT）取编码器支持列表，从用户期望格式（420/422/444/rgb0 等）按优先级协商，替代写死 YUV420P（L2）。
- 硬件路径：NVENC（h264_nvenc）、AMF（h264_amf/hevc_amf/av1_amf）、QSV（h264/hevc/av1_qsv）、VideoToolbox（h264/hevc/prores_videotoolbox）。三层检测分离：FFmpeg 构建是否含该编码器（编译产物枚举）→ `avcodec_alloc_context3` + `avcodec_open2` 实际初始化探测 → 指定像素格式/参数能否打开。探测结果缓存，UI 只展示当前环境可用的选项。
- 各编码器独立质量控制：x264 用 CRF/preset；NVENC 用 CQ/preset；AMF/QSV/VideoToolbox 各自的质量参数映射。禁止一个 CRF 值跨编码器套用；高级参数按编码器动态显示。
- GOP 可配置（L3），默认值改为按用途评估（当前 12 偏小，评估 60-120 帧区间），分段渲染的片段首帧强制 IDR 不受此影响。
- 硬件失败回退：探测或运行失败时明确报错并可回退软件编码器，不静默换编码器。
- 涉及文件：video.cpp/h、config_variables.h、menus.cpp/menus_demo.cpp（编码器选择 UI）、新增编码器能力探测模块。验收：RTX 4060 Ti 上 h264/hevc/av1_nvenc 可选且导出成功；无独显环境 UI 不出现不可用项；x264 路径行为不变。

### M5 FFmpeg 升级（与 M4 可换序）

- 目标版本评估顺序：9.0.x（libavcodec ABI 63）> 8.1.x > 7.1.5（与 7.0.1 同 soname，drop-in，但 7.0 分支已停更）。升级必须连带重放 ddnet-libs ffmpeg-matroska 分支的 matroska muxer 定制（该定制存在于本地分支，origin 上游无此重编）。
- 兼容层已备：`avcodec_get_supported_config` 条件编译已就位；升级时核查 `avcodec_send_frame` 语义、声道布局 API、被移除的旧选项（如 NVENC 旧参数）。
- 升级后回归：全部既有导出预设音画同步、mkv/mp4 容器均正常；DLL 体积与安装包增量记录。
- 涉及文件：ddnet-libs 子模块（新分支）、qmclient_scripts 构建脚本如涉及。验收：C++ 测试套件通过 + 短 Demo/长 Demo 导出对比无回归；子模块提交与 VERSION 记录一致。

### M6 剪辑工作流与预设

- 新增编码格式：ProRes（prores_ks， MOV；macOS 可选 prores_videotoolbox）、DNxHR（dnxhd，MOV）、FFV1（MKV 无损归档）、HEVC Main10（可选 AV1）。每格式绑定推荐容器（MP4/MOV/MKV）与音频编码器（AAC/PCM/FLAC 按容器与用途）。
- 导出预设体系：「日常分享」（H.264/AAC/MP4）、「高效高画质」（HEVC Main10/MP4）、「专业剪辑」（ProRes 422 HQ/MOV）、「无损归档」（FFV1/MKV）、「自定义」。预设展开为编码器 + 容器 + 像素格式 + 质量参数组合，UI 按编码器动态过滤可选项。
- 色彩元数据：为输出流写入完整的颜色原色/传输特性/矩阵/range 标记（当前仅 `colorspace = BT709`，video.cpp:1026），保证 Premiere/Resolve 导入颜色一致。
- 涉及文件：video.cpp/h、`src/engine/shared/video.h`（格式名/后缀工具）、menus.cpp、config_variables.h。验收：ProRes 422 HQ 与 DNxHR HQX 产物在 Premiere 与 Resolve 中正确导入、颜色与帧率一致；FFV1/MKV 无损可逆。

### M7 画质进阶

- 独立渲染分辨率与超采样：导出时允许以高于输出的分辨率离屏渲染再缩小（如 2x 渲染 → 1080p 输出），改善 2D 图形边缘锯齿；需要独立离屏渲染目标，而非只改 FFmpeg 输出宽高。
- sRGB → Rec.709 SDR 转换路径固化并实测（截图、彩色文字、激光线、快速移动场景对比）；10-bit 输出路径仅在捕获链路升级到 10-bit 后有意义，本阶段仅确认协商机制可承载。
- 默认预设调优：以 DDNet 实际画面（彩色文字、Tee 轮廓、快速移动）对比 CRF/preset 组合，必要时调整 `cl_video_crf`/`cl_video_preset` 默认值并更新推荐文案。
- 涉及文件：video.cpp/h、图形后端 readback 相关（`GetReadPresentedImageDataFuncUnsafe` 调用路径）、menus.cpp。验收：超采样开启时文字与边缘主观明显改善；色彩元数据经 ffprobe 验证正确。

### M8 渲染架构进阶（远期）

- 异步 GPU readback（PBO/ staging 纹理）与 GPU 色彩转换，减少 GPU→CPU 拷贝与 CPU swscale 开销。
- 渲染子进程：导出任务放独立客户端子进程执行，主客户端可正常游玩；任务管理器展示进度、速度、内存与错误日志。
- 立项时机：M1-M6 交付并实测瓶颈分布后再决定是否启动。

## 关键设计决策

- 反压优先于丢弃：离线渲染场景帧都是必须的，队列满时生产端等待，绝不丢帧。
- 编码器选择以「名称字符串 + 能力探测」为准，CodecID 仅作回退；所有 UI 可选项必须来自运行时探测，不做硬编码设备表。
- 分段渲染的任务状态是纯数据文件（JSON 或键值对），不引入数据库；文件损坏时按「从头渲染该片段」处理。
- 时间戳唯一权威在导出任务层（帧计数器 × 1/FPS），编码器与容器只做转换。
- 配置前缀沿用 `qm_`/`Cl` 现行规则，新配置进 config_variables.h 相邻区域并附中文注释按现有文件惯例。

## 依赖与风险

- ddnet-libs 子模块是唯一 FFmpeg 供给方，matroska muxer 定制只在本地分支（ffmpeg-matroska，当前未推送）；M5 升级须在新分支重放该定制并保留分支说明。子模块对照仅走 GitHub API 只读（沙箱内 git fetch 会被终止）。
- 4:2:2/4:4:4 与多数硬件编码器不兼容（NVENC 10-bit H.264 需 Blackwell+），协商失败必须回退 420 并提示，不能让用户选了不支持的组合后导出坏文件。
- QSV 在 Windows 依赖驱动实现，AMF 版本差异大；探测必须真实 `avcodec_open2`，不能只看编码器注册存在。
- 长任务与并行会话：构建与测试遵循固定槽位规则，同 build 目录串行；方案实施周期长，各里程碑在本文档更新验证记录后交接。

## 测试与验收策略

分层（按 src/test/AGENTS.md）：单元测试覆盖像素格式协商、PTS 生成、分段任务状态机、编码器参数映射；集成测试覆盖分段任务管理（进度文件读写、断点跳过、拼接参数校验，用内存/临时目录 fake）；端到端冒烟与关键路径放 `qmclient_scripts/integration/`（短 Demo 导出、中断续渲、异常注入：磁盘不足、编码器初始化失败、强制终止）。

性能验收基线：1080p60 与 4K60 短 Demo（约 1-3 分钟）各测 x264 与 NVENC 导出耗时与常驻内存；3 小时长 Demo 验证内存不持续增长、断点续渲正确性。微基准不能替代导出实测。

每里程碑交付时：过滤相关单元/集成测试 + 构建受影响目标；跨容器、编码器选择等影响启动或导出全路径的改动补端到端场景；本文档「验证记录」一节登记实际运行的层级与过滤范围。
