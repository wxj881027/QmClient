# Windows 原生安装界面

状态：原生安装器已完成编译与本地打包；安装、升级、卸载及视觉验收待完成。未发布新版本。

## 行为

用户确认采用原生 UI 与现有 Inno 安装内核。正常双击 `QmClient-Setup.exe` 打开 Win32 / Direct2D / DirectWrite 界面，提供可编辑安装路径、浏览文件夹、桌面快捷方式、实际安装进度、完成启动和失败日志入口。界面跟随 Windows 深浅色与显示器 DPI，输入、按钮和状态文本使用原生控件承载键盘交互与辅助技术信息。

左侧复用原安装向导的粉色兔子背景，按钮、进度条、完成提示和圆角复选框使用统一的粉色。Windows 11 原生标题栏跟随界面深浅色设置背景与文字颜色；较早系统保留标准标题栏。关闭、最小化、拖动、Tab 与空格切换复选框仍交给系统处理。

默认安装到 `%LOCALAPPDATA%/Programs/QmClient`。检测同一 AppId 的旧安装后预填路径和快捷方式选项，仍可修改。内核继续负责文件覆盖、已知旧资源清理、快捷方式、卸载登记及保留未知用户文件。安装标记、AppId、发布附件名和客户端签名验证链保持原值。

安装器只在成功退出时清理旧更新器遗留的 `DDNet.old`。便携包更新在全部文件替换成功后执行同样清理。更新失败保留旧备份；本次事务的回滚目录沿用既有恢复与清理逻辑，其他 `.old` 文件不会被批量删除。旧备份被占用时记录清理失败，不回滚已经完成的更新。

取消请求交给 Inno 的正常取消流程；前端等待内核退出后显示结果，不强杀安装进程。完成页由玩家选择立即启动或退出。

`/SILENT`、`/VERYSILENT`、帮助以及不由原生界面管理的高级参数，整体交给原 Inno 向导处理，保留现有自动更新及无人值守安装行为。正常界面支持 `/DIR=`、`/LOG=`、`/NOICONS`、`/NORESTART`、`/LANG=zh_cn` 和 `/SP-`。未知参数也走原向导，避免丢失 Inno 的现有选项。

参考 [Pulse 原生安装 UI](https://github.com/jimmgreen/pulse/blob/main/src/setup/setup_ui.cpp) 的技术组合，界面和安装桥接在本仓库独立实现。此范围保持完整离线安装，不增加组件下载与镜像配置。

## 打包与接入

`qmclient_scripts/build_windows_setup.py` 先编译原有 `.iss`，再通过 `qmclient_scripts/cmake-windows.cmd` 编译 `src/qm/setup/` 的独立 CMake 项目。Inno EXE 作为 RCDATA 资源嵌入最终 EXE；原生前端使用静态 MSVC 运行库，安装前不依赖客户端目录中的 DLL。内核的进度事件通过 `native_bridge.iss` 回传，进度消息限制到千分位变化。

独立界面构建目录中的 `engine/QmClient-Setup.exe` 是内部载荷。公开产物使用 `--output` 指定目录下的 `QmClient-Setup.exe`，CI 仅收集该确定路径。本地 `package_windows_release` 同样调用这个入口。

开发安装必须使用独立 `--app-id` UUID，前端旧目录查询与 Inno 内核从同一参数取得身份。完整载荷仍先由 `prepare_setup_source.py` 从普通客户端构建目录生成。

```powershell
python qmclient_scripts/build_windows_setup.py --source tmp/setup-payload --output tmp/setup-output --build-dir tmp/setup-ui-build --version 3.3 --app-id B0AB5D1A-7228-45F7-9DDC-AD453939B6EA
```

上述隔离 AppId 命令为安装验证入口，尚未执行。正式打包省略测试 AppId，默认从 `.iss` 读取现有正式身份。编译日志放在界面构建目录中，运行日志放在本次安装的系统临时目录；失败页提供日志入口。
