# 全局卡片统一方案

> 状态：方案草案，尚未实施。更新日期：2026-10-01。
> 本方案把搜索页完整显示卡片、卡片展开/收起保存和大文件拆分放在一起安排。

## 一、要做成什么样

玩家在搜索页找到一项设置后，应能直接修改它，不必先跳回原页面。同一张卡片在搜索页和原页面使用相同的内容、控件和高度计算，设置结果也一致。定位按钮继续保留，方便查看附近的其他设置。

搜索输入卡放在内容最上方，和结果一起滚动。这里的“置顶”指排列在最前面。

卡片展开或收起后记住玩家的选择：切页、重新搜索和跨页移动都不丢失，正常保存配置并重启后恢复。搜索页与原页面共享这一选择。

代码按卡片拆开。页面负责列出卡片和安排位置，卡片负责自己的内容。迁移一张卡片时，同时让原页面和搜索页使用它，并移除被替代的旧代码。

## 二、当前还差多少

2026-10-01 的注册表共有 134 个条目，但注册条目不全是独立设置卡片：

| 范围 | 注册条目 | 已能通过共享入口完整显示 | 说明 |
| --- | ---: | ---: | --- |
| 栖梦，`qm:` | 46 | 43 | 另外 3 个是指向其他卡片的搜索入口 |
| TClient 主设置，`tclient:` | 21 | 0 | 原调研漏列了这一组 |
| 其他卡片，`deck:` | 67 | 0 | 包含 59 张设置卡、6 张贡献者/链接卡和 2 个搜索页面条目 |

完整显示的设置卡片目标是 **123 张**，其中 **80 张还需要接入共享入口**。Tee 与 Tee7 等内容按当前协议选择显示，不会同时展示所有卡片。贡献者和链接可以继续导航，搜索输入和空结果提示由搜索页管理。

这修正了原调研的两个口径：46 个 `qm:` 条目不能全部算作已有完整卡片；全量工作还包括 21 张 TClient 主设置卡。“约 23 张贡献者/链接卡”也不对应当前注册表，卡内的人物和链接行不能另算成设置卡片。

已有基础设施可以继续使用：`SettingsPageLayout` 安排页面和列宽，`SettingsCard` 绘制公共卡片外框，`CSettingsCardDeck` 管理排列、滚动和缓存，`QmCardRegistry` 管理卡片信息与默认位置。搜索页也已有独立的临时排列模型，不需要再建一套。

真正没统一的是卡片内容和状态。很多卡片仍由原页面的局部函数拼装；43 张栖梦卡虽然有共享入口，许多内容也还留在 `menus_qmclient.cpp`。目前几个主要文件仍很大：栖梦菜单约 5878 行，普通设置约 8959 行，TClient 菜单约 8086 行。

展开/收起也有两套做法：栖梦卡已经使用 `qm_sidebar_card_collapsed` 配置，普通卡主要保存在卡组的内存缓存中。要让所有页面都能恢复状态，需要统一这两套做法。

## 三、页面与卡片的行为

### 搜索输入和结果

搜索输入是同一滚动区域中的第一张全宽卡。卡组统一计算输入与结果的位置、滚动范围和裁剪。现在“先手动画输入，再缩小结果滚动区”的做法应移除。

空查询仍只显示输入卡，不列出全部设置。若保留空查询时的居中效果，由页面布局安排空白。有查询后输入回到内容顶部；查询改变时结果回到顶部，同一查询下调整配置不应反复重置滚动。输入收起后保留卡头和展开按钮，再次进入搜索时应能方便地输入。

结果在宽窗口默认双列，窄窗口改为单列。列表、网格和较大的预览需要足够宽度，可以声明最小宽度并使用全宽；不能把所有卡强制塞进半宽后靠缩小文字补救。

一项功能可能有多个搜索入口。例如名牌文字和激光增强的旧入口，实际指向外观页中的设置卡。搜索应保留这些入口的关键词，但按实际承载功能的卡片 ID 合并结果，避免同一份内容出现两次。

迁移期间，尚未接入共享入口的卡片继续显示描述和定位按钮。全部设置卡接入后，这种导航形式只留给贡献者、链接等本来就以导航为主的内容。

### 展开和收起

设置卡的用户选择按卡片的稳定 ID 保存，与页签、列和排序位置无关。原页收起后，搜索中同样收起；搜索中展开后，回原页同样展开。收起只隐藏内容，卡头始终保留。

使用一个共享状态模型，运行时直接查询缓存，变更后更新客户端配置。建议新增全局折叠配置项，例如 `qm_global_card_collapsed`，与现有排序配置分开，保留 `qm_global_card_order` 的格式。磁盘保存复用现有配置保存流程，不在每次点击时单独写文件。

没有用户选择时采用卡片默认状态。“用户明确展开”和“还没有选择”要能区分，否则迁移旧配置时可能把玩家刚展开的卡再次收起。只有真实用户操作或外部配置变更能改变保存状态；测量、预热和文本收集不能写配置。

旧栖梦配置通过现有 ID 映射迁入。新配置里的明确选择优先，旧配置只补缺失项。迁移成功后才更新完成标记；重复加载不能再次覆盖用户选择。配置格式有误、空间不足或保存失败时，保留原值和待保存状态，可以重试，不能静默截断。暂时不认识或已移除的 ID 在容量允许时保留，避免切换版本丢状态。

关闭 `cl_save_settings` 时仍有本次运行的缓存，但不会承诺重启恢复。这里要求的是正常保存后的恢复，不新增崩溃前即时落盘功能。

搜索词、滚动位置、动画、鼠标悬停、焦点和弹窗属于临时状态。搜索输入卡可以保留会话状态，但不与设置内容卡一起写入全局折叠配置；空结果提示不提供折叠。

### 高度、尺寸和输入

一张卡片使用同一套布局来测量和绘制。能顺序消耗内容矩形的卡片，继续复用现有内容探针；只绘制预览、不消耗矩形的卡片，由共享布局函数算出高度和位置，测量与绘制都读取这个结果。

影响高度的开关、列表数量、设备状态、协议、宽度和语言变化，都必须触发相应缓存更新。空闲时复用缓存，不能为了掩盖遗漏而每帧重新测量所有卡片。

卡头标题、定位按钮和折叠按钮共同分配宽度。卡内按钮和标签按内容、字体与缩放计算尺寸，优先使用公共布局能力。长译文、窄窗口和非默认缩放下，控件不能重叠或越过卡片边界。

卡片收起、从结果中移除或离开页面时，要关闭它的弹窗并释放输入占用。二级菜单应支持外部点击关闭、ESC 先关闭最上层、父层关闭时清理子层，以及取消后重新打开。内层列表或弹窗消费滚轮后，外层页面不能在同一帧再滚一次。

## 四、代码怎么拆

### 按卡片组织内容

延续[大文件拆分方案](大文件拆分方案.md)的方向：一张卡片的内容、布局测量、高度依赖和构建入口尽量放在同一个模块文件。共享的开关行、数值输入、文本和按钮辅助单独维护，卡片之间不互相借用私有代码。

复用现有 `src/game/client/QmUi/cards/` 目录。分类页和搜索页都通过共享构建入口取得 `SSettingsCardDefinition`，再交给已有卡组。卡片所属页面和默认位置由数据表达，换位置不需要搬代码。

普通设置页的外壳可以沿 `menus_settings_*` 的方式按页拆文件；页内内容再按卡拆开。把一个两千多行函数整体放进新文件，只能改变文件位置，不能解决卡片之间混在一起的问题。

新增卡片只需要新增模块及必要的注册、构建清单，不再修改宿主的分派逻辑。这里不要求引入自动插件注册，也不扩展到与设置卡片无关的引擎、预测或服务端大文件。

### 把页面依赖带清楚

当前构建上下文的折叠状态按 Qm 模块编号索引，构建分派也先解析 Qm ID。应改成能处理所有设置卡的稳定 ID，共享折叠模型也使用同一 ID。

有些业务状态由专门对象持有，例如 Controls 的绑定、搜索和手柄状态。卡片需要明确取得这些对象及所需服务，避免复制业务状态，也避免把所有页面的私有成员塞进一个大上下文。

卡头文字已使用稳定卡片 ID，内容标签也要逐步改成“卡片 ID + 卡内文字 ID”。字体、宽度、缩放和语言仍参与缓存失效，卡片所在页面不再决定这份文字的身份。

搜索结果也只保留一套实际接入页面的模型。当前页面使用“空查询无结果、双列排列”，另一组未被页面调用的辅助函数却使用“空查询列出全部模块、整行排列”。迁移时合并这两套路径，删除被替代的函数和只为它们存在的测试。

## 五、先做哪些

最终目标是全部设置卡完整显示，首批先做 DDNet、常规和控制页的 18 张卡。首批数量较小，便于验证共享方式；没有使用统计，不能保证这 18 张覆盖大部分搜索需求。

| 批次 | 内容 | 做完后应达到的结果 |
| --- | --- | --- |
| 基础 | 搜索输入回到滚动流；统一折叠状态、保存和旧配置迁移 | 输入与结果一起滚动，设置卡状态能保存和恢复 |
| DDNet | 4 张卡 | 原页与搜索共用完整卡片，验证动态行、数值输入和高度更新 |
| 常规、控制 | 5 + 9 张卡 | 首批 18 张完成，补足列表、独立业务对象和设备变化场景 |
| 其他普通设置 | Player、Sound，再到 Graphics、Tee/Tee7、Appearance | 逐页替换旧构建方式，同时检查列表与预览的宽度和输入行为 |
| TClient | 主设置 21 张及其他子页 | 按卡片边界拆解大函数，全部接入共享入口 |
| 收尾 | 搬出剩余 Qm 卡片内容，整理页面外壳，清除旧分派和无效辅助代码 | 页面只列卡片，共享模块承担内容和状态 |

已有 Qm 卡片的拆分可以穿插进行，不要求全部拆完才开始 DDNet。每张卡迁移后，原页和搜索同时切换到共享实现。保留行为的代码搬运与新增搜索、状态保存的行为改动分开审查，方便定位回归。

DDNet 试点必须连同保存、布局和测试做完。若它还依赖页面复制内容、临时拼接文字 ID 或每帧测高，应先修正共用方式，再扩展到其他页面。

## 六、怎么确认做对了

测试直接调用生产代码并检查结果。例如切换开关后断言实际内容高度变化，保存并重新加载后断言折叠选择恢复。已有源码字符串断言应随对应模块迁移逐步替换，不能只改断言里的文件名。

主要检查这些使用过程：

- 在搜索页修改设置，回原页得到相同结果；旧搜索入口只显示一张实际内容卡。
- 原页收起、搜索读取、搜索展开、原页读取，再保存重载；移动卡片后状态不变。
- 旧配置迁移、重复加载、用户明确展开、坏数据、容量不足、保存失败后重试；测量和预热没有配置写入。
- 配置开关往返、列表增删、宽度和语言变化后高度正确；空闲帧不重复测量。
- 卡片收起、结果移除和离页后，旧弹窗与输入释放；外部点击、ESC、取消重开及滚轮归属正常。
- 客户端中检查输入与结果一起滚动，长译文、窄窗口、非默认缩放及网格和预览；正常退出重启后恢复状态。

公共卡组已有几何和测量次数的诊断接口，可用来观察真实布局与缓存。只测试一个策略函数，不能代替卡组、配置或弹窗的模块协作。

性能使用现有 Google Benchmark，测量生产搜索、构建分派、折叠状态查询和布局代码，分别记录稳定缓存、状态变化和结果重建。原有卡片 revision 用例只能证明这个接口的开销。

真实客户端还要检查第一次搜索、大量结果、连续改查询和滚动时的帧尖峰。不可见卡片跳过绘制，不代表首次测量也跳过。需要限制峰值时复用已有预算和预热能力，并用相同条件的前后数据比较。

构建、相关行为测试和人工页面检查随每批进行。Windows 使用现有构建封装，同一构建目录的构建、测试和 benchmark 串行运行。功能测试、性能测量和人工交互分别记录，任何一项通过都不能替代另外两项。

## 七、工作量与范围

原估算的 6–10 个会话、净改动 2000–3500 行，没有包含完整的 TClient 主设置、全局折叠保存和已有 Qm 内容拆分。净增行数也看不出搬运与测试替换的成本。

目前建议按以下范围预留时间，DDNet 试点完成后再用实际成本修正：

| 交付范围 | 初步预算 |
| --- | --- |
| 搜索与折叠基础，加 DDNet 4 张试点 | 2–4 个工作会话 |
| 上述基础，加完整首批 18 张 | 累计 4–7 个工作会话 |
| 80 张未共享设置卡全部迁移，包含状态保存和主要自动验证 | 累计 10–16 个工作会话 |

这些是安排工作的粗略范围，不是已测出的工时；人工反馈等待、设备和跨平台验证另计。只有 2–3 个会话时，先交付 DDNet 与基础功能，剩余页面继续保留明确的迁移清单。

本轮完成了代码和文档核对，尚未修改功能代码，也没有运行本方案的构建、测试、性能测量或客户端验收。旧记录中的通过结果不能算作新方案已经完成。

## 同组短开关组件规范

2026-10-11 更新。适用于同一组件的多个简短布尔设置，以及能组成明确语义分组的多个短开关。采用共享入口 `CMenus::DoSettingsToggleGroup`，不在页面或各张卡片中复制网格实现。

- 每项标签在上、开关在下，两者居中对齐；同组项目按原顺序横向排列并自动换行。
- 全宽卡最多四列，半宽卡最多两列。使用卡片实际可用宽度和当前设置壳的列宽判断，宽半卡也保留两列上限。单列页面按可用宽度适配。
- 列数同时受项目数量和当前译文宽度限制。长译文先减列；单列仍放不下时标签换行并增加行高，保持正文字号。尾行不补占位控件。
- 主开关、会展开从属内容的开关和带较长独立说明的设置保留原有层级。对互不相关的设置先划分语义分组，不为横排把它们合在一起。
- 控件 ID 和配置地址保持稳定。普通布尔项默认以配置地址为 ID；同一位掩码配置的各项提供独立 ID 和掩码。分组不拥有配置、译文或跨帧状态。
- 整个单元格可点击，复用现有开关动画、配置提示和临时接管策略。被临时接管的项灰化并提示来源；只读、文字预热和测量阶段不写配置。
- 卡片通过同一份消费式内容回调测量与渲染。预布局使用 `LAYOUT` 跳过相同布局，使用 `INPUT` 处理相同命中区域；不得继续用旧的固定行数定位后续控件。
- 普通页面与搜索页共用卡片目录和相同组件；宽度、语言和缩放改变后重新测量。新增设置继续复用本规范，不按页面另建一套布局。

实现位于 `src/game/client/QmUi/SettingsToggleGrid.h` 与 `SettingsCard.cpp`，菜单类仅声明共享入口。本轮接入碰撞体积、直播隐私、姓名牌文字效果、禅模式、Gores、解冻辅助、计分板、好友通知、梦的小功能、按键状态、通知分类及外观 HUD／聊天中的同组开关。饼菜单保留其带配色操作的专用单元格，并共用底层网格计算。

已补充网格尺寸、全宽／半宽列数、长标签空间、布尔与位掩码切换、只读与临时接管的行为测试，未执行。未编译、未运行 gate、未启动客户端；中英文、窄窗口、非默认缩放和搜索页的视觉及交互验收待完成。
