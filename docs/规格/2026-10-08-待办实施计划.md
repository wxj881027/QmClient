## A. 先修复影响使用的问题

- [ ] **A1. 修复新版 IME 吞字和非输入状态唤起。**

  以微软拼音为主要复现场景，沿组合输入、候选选择、文本提交、输入框接收这条链定位字符丢失。组合串更新与最终提交分开处理，一次提交只写入一次。正常游玩时，只有聊天框取得可编辑焦点才允许输入法工作；设置、控制台和地图编辑器仍由各自输入框管理焦点。表情、饼菜单和按键绑定捕获不唤起 IME。

  **完成标准：** 空格和数字选词、回车确认、退格、切换中英文、关闭后重新打开聊天均不吞字、不重复提交。关闭聊天后按 Left Shift 不弹候选框；搜狗五笔等原本正常的输入方式保持可用。

- [ ] **A2. 修复 IME 内容滞后与闪烁。**

  最新组合串、候选内容和选中项在收到更新后的下一渲染帧使用。保留现有面板位置、尺寸动画和短时文字淡出；输入提交不等待动画结束。短暂的空组合串不清除仍有效的候选列表；真正取消、提交或失去焦点时清理候选。

  **完成标准：** 连续快速输入、长短候选交替、翻页和快速开关聊天时，最新内容及时出现，面板不反复消失再出现，旧文字不会持续叠在新文字上。

- [ ] **A3. 恢复地图编辑器输入框。**

  修正服务器设置、CP 点等输入框的焦点和文本事件路由。编辑器输入框取得焦点后，由编辑器接收字符；客户端的游戏输入法限制不能截断这条路径。数值框继续遵守原有数值范围和字符限制。

  **完成标准：** 服务器设置可输入中文、英文和命令，可选择、粘贴、删除及提交；CP 等数值输入框可修改合法值。切换字段、关闭弹窗和再次打开后仍能输入，输入期间不触发编辑器快捷键。

- [ ] **A4. 修复中文发往日语时被误判为无需翻译。**

  日语的本地同语种判断必须有假名证据，不能仅凭汉字判为日语。纯汉字属于无法可靠区分的情况，交给翻译服务处理；用户明确填写的来源语言优先。统一检查出站的“始终翻译”模式，避免它被前置的同语种判断提前跳过。

  **完成标准：** 目标为日语时，“我来帮你”和“東京”都能进入翻译请求；含假名的日语在按需模式下可跳过；“始终翻译”仍会请求。空文本、纯数字和聊天命令保持原有排除规则。补齐这些行为的回归测试。

- [ ] **A5. 将翻译服务拒绝与报错转换为本地化提示。**

  在服务适配层区分成功译文、内容拒绝、限额、鉴权失败和网络失败。优先读取结构化拒绝字段、结束原因及服务明确的错误码；确需处理文本提示时，只识别对应服务的已知错误格式，不能按长度或几个常见词判定。拒绝提示使用“翻译服务拒绝处理这条内容，请修改后重试”；只有服务明确给出原因时才显示更具体的说明。

  **完成标准：** 服务的大段拒绝说明不作为译文展示或发送到聊天；提示跟随客户端语言。正常长译文、包含“不能翻译”等字样的普通句子不被误拦。失败后的原文发送策略沿用现有设置。

- [ ] **A6. 调整聊天翻译按钮，回归输入区对齐。**

  保留已进入代码的聊天类型与正文基线修复。给翻译按钮分配独立的右侧区域，文本、光标、选区和水平滚动范围统一扣除该区域；按钮与输入行垂直居中，多行输入时固定在输入区右上方。

  **完成标准：** 全体、队伍聊天在中英文、不同字体和缩放下首行对齐；长文本与多行输入不覆盖翻译按钮，按钮也不遮挡光标、选区或候选框。

- [ ] **A7. 修复 HUD 移开后无法重新贴边。**

  用同一套可见内容边界计算拖动范围、缩放后位置和贴边锚点，消除绘制坐标与编辑器钳制坐标的偏差。装饰留白不能阻止内容贴边；保存与恢复继续使用现有布局格式。

  **完成标准：** 原本贴边的 HUD 移到中间后，可以重新贴回四边和四角；改变缩放后仍可贴边。退出编辑、重新进入和保存后重启，位置不向屏幕内侧漂移。

  同组短开关采用“标签在上、开关在下”的单元格，单元格横向排列。全宽卡最多四列、半宽卡最多两列；宽度不足时按标签所需宽度减列，不缩小文字。饼菜单设置先接入。自动回复卡使用“规则列表／回复内容／触发限制”内部页签，各页只承载现有对应设置。

  **完成标准：** 中英文和窄窗口下标签、开关不重叠；切页签不丢未提交编辑，不改变配置值。动态页签高度正确，原页与搜索页使用同一个组件。

- [ ] **B7. 明确按钮的反馈规则。** **补充方案。**

  普通操作按钮使用背景明暗反馈；卡头图标按钮使用浅背景和短促图标缩放回弹；状态切换按钮用持续的选中底色表达状态。全宽／半宽、定位和折叠按钮全部接入对应规则。禁用状态不响应点击，也不播放点击动画。

  **完成标准：** 仅看悬浮、按下和选中状态即可区分可操作项；全宽／半宽按钮有明确反馈。相同用途的按钮使用相同效果，动画不改变命中区域。

- [ ] **B8. 饼菜单扇区增加圆角。**

  对扇区内外弧与径向边的连接处做圆角，保留扇区间隙和原有选项顺序；圆角半径受扇区角度、内外半径约束，选项多时自动收小。绘制与命中判定共用几何参数。

  **完成标准：** 少量和大量选项、不同菜单大小下都没有尖角、裂缝或相邻扇区重叠；视觉空隙不能点击到错误选项，键盘与鼠标选择行为保持一致。

## C. 配置规范与默认体验

- [ ] **C1. 将 TClient 遗留配置的 `tc_` 前缀统一为 `qm_`。**

  先建立一对一名称映射并处理同名冲突，再同步变量、控制台命令、卡片绑定、配置说明与 Wiki。保留旧键读取兼容，保存时只输出新键；新旧键同时存在时，以新键为准。绑定命令中的配置标识按命令结构迁移，不能对任意文本做全局替换。

  **完成标准：** 旧配置和引用旧名称的绑定仍有效，重新保存后使用新名称，重复加载不会覆盖用户的新值。只处理 TClient 配置前缀；例如 `qm_translate_tc_*` 中表示腾讯云的 `tc` 不属于本次改名。

- [ ] **C2. 分离官方默认与栖梦推荐预设。** **补充方案。**

  与 DDNet 共有的配置以仓库对应上游版本的默认值为基准；Qm 专属项使用各功能声明的默认值。新增可手动应用的“栖梦推荐”外观预设，以现有 Qm 外观设置为基础整理固定清单，字体使用 LXGW WenKai。应用前展示会修改的具体项目，应用范围仅包含字体、界面布局和外观。

  **完成标准：** 全新配置启动时不自动应用推荐预设；已有用户配置不因升级被覆盖。手动应用后得到可重复的结果，账号、绑定、连接信息和游戏操作配置不受影响；字体资源不可用时有明确提示并继续使用可用字体。

- [ ] **C3. 固定常见分辨率和比例的默认布局。**

  按可用逻辑宽度调整列数、最小卡宽、间距和滚动区域，不为每个分辨率维护一套硬编码页面。以官方默认和栖梦推荐两套配置检查服务器列表、设置、聊天、IME、饼菜单及 HUD 编辑器。

  **完成标准：** 覆盖 1280×720、1366×768、1920×1080、2560×1440、3840×2160，以及 1280×1024（5:4）、1600×1200（4:3）、1920×1200（16:10）、2560×1080（21:9）。再以 1920×1080 检查 125%、150%、200% UI 缩放和高 DPI 窗口。页面按钮可达，内容不越界；空间不足时减少列数或滚动，不挤压文字。

- [ ] **C4. 补齐本轮涉及组件的外观设置。** **补充方案。**

  首批范围固定为：IME 的文字、背景、选中颜色和字号；翻译按钮的启用／关闭颜色；提示气泡的背景、文字颜色、字号和动画开关；饼菜单的普通／选中颜色、整体大小和效果开关；按键统计的颜色、字号和显示标签。已有配置直接复用，缺失项归入对应功能卡，每组提供恢复默认。

  **完成标准：** 修改后立即预览，保存后重启恢复；关闭视觉效果保留功能操作。原页与搜索页修改的是同一份配置，不新增内容重复的外观卡。

## D. 联机辅助与服务

- [ ] **D1. 补齐 Steam 识别诊断与回归。** **补充方案。**

  复用已有安装探测与未安装时静默跳过的流程。在 Steam 卡片显示“未找到／已安装未启动／已运行”和找到的路径，提供“重新检测”及可选的手动客户端路径。Windows 自动探测覆盖当前用户与系统注册项、正在运行的客户端路径和常见安装路径；只使用确实存在的客户端程序。

  **完成标准：** 未安装时启动 QmClient 不弹错误窗口；自定义盘符、含空格路径及已经运行的 Steam 可识别。自动启动关闭时不启动 Steam；自动探测失败后，手动指定有效路径仍能使用。调试记录能说明命中了哪种来源或为什么没找到。

- [ ] **D2. 接入服务器列表镜像。** **补充方案。**

  在现有 Qm 服务提供与官方相同格式的 `servers.json` 镜像，每 60 秒同步一次并记录最近成功时间；超过 5 分钟未成功同步时，标记为过期，不作为新鲜列表来源。客户端把镜像加入现有 HTTP master 候选与可用性选择流程，复用原解析器。失败刷新保留上次成功结果，并显示列表是否过期；不使用空响应覆盖正常缓存。

  **完成标准：** 官方源不可达时仍能从镜像获得列表；镜像失败或数据过期时可使用其他有效源。全部失败时保留旧列表并提示刷新失败。切换来源不重复服务器条目，也不丢收藏、筛选和当前选择。

- [ ] **D3. 实现免配置翻译的多服务回退。** **补充方案。**

  保留现有 MyMemory 适配器，在 Qm 翻译服务端接入 DeepL，并提供统一的自动服务入口；客户端仅提交文本、来源语言和目标语言。服务端保存维护者配置的 API 凭据，按服务及凭据分别管理额度、并发和冷却时间；客户端不内置公共密钥。首版顺序为可用的 DeepL → MyMemory，之后通过服务端配置调整。
  超时、临时服务错误、限流或额度耗尽时尝试下一个可用服务；同一请求对同一服务最多尝试一次，首版最多两次服务请求，单次最长 5 秒、全链路最长 10 秒。明确的内容拒绝返回 A5 的提示，不继续轮询服务。取消后不再启动后备请求。服务限额读取实际配置或接口结果，不把原始待办中的估算数字写死。

  **完成标准：** 新用户选择自动服务后无需注册服务账号或填写密钥；用户主动启用翻译后即可请求。已有的手动服务选择与个人密钥保持有效。主服务故障能切换；全部不可用时给出简短原因，不把错误正文发进聊天；过期结果不覆盖新请求。服务端可用后再将自动服务设为新安装的默认后端。

## E. 可选交互功能

- [ ] **E1. 延长连发表情弹射的可见时间。** **补充方案。**

  默认存活时间从当前的 3 秒调整为 5 秒，最后 0.5 秒淡出；在现有表情卡提供 1～10 秒的显示时长配置。每个弹射实例独立计时，同一玩家继续发送不会重置或清空上一枚；达到现有实例数量上限后才回收最旧实例。

  **完成标准：** 两端都使用支持此规则的 QmClient、且接收方启用他人弹射显示时，连续发送的表情都按接收方配置显示完整时长。忽略名单、关闭他人表情和现有发送限制继续生效；不通过提高发送频率延长显示。

- [ ] **E2. 在输入显示组件增加按键计数。** **补充方案。**

  增加默认关闭的“显示按键次数”，统计输入显示布局中启用的键盘键和鼠标键。一次按下计一次，长按和系统重复事件不累计；只在游戏取得操作焦点时计数，聊天、菜单和控制台输入不计入。统计范围为本次客户端会话，提供手动清零；关闭功能时暂停计数，重新开启保留本次会话累计值。位置与缩放沿用输入显示和 HUD 编辑器。

  **完成标准：** 按下十次显示十次，长按只增加一次，松开重按继续增加；切换主号／分身不会重复计数。清零即时生效，退出客户端后重新开始；关闭显示不影响游戏输入。

- [ ] **E3. 增加草、番茄、鸡蛋三种装饰投掷物。** **补充方案。**

  在表情菜单增加投掷物页签，选中后向当前瞄准方向抛出，允许绑定快捷键。复用已有弹射运动与视觉碰撞，新增三套透明素材；命中后播放短粒子效果并消失，没有伤害、冻结或推动角色的效果。功能默认关闭，显示开关放在表情卡。
  同步通过现有 Qm 实时通道新增独立的可选事件，携带投掷物类型、起点和方向，沿用同服身份校验与发送限制。接收端校验类型、坐标与方向；旧客户端忽略未知事件。此功能不要求修改 DDNet 游戏协议。

  **完成标准：** 支持该功能的同服 QmClient 能看到同一种投掷物；不支持的客户端不报错。关闭他人效果或屏蔽发送者时不显示；命中动画不改变角色状态，切图和断线后清理残留实例。
