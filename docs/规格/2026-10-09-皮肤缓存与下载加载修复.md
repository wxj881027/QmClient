截图中皮肤列表存在大量 default 占位和持续等待。调查确认下载任务把本地缓存的显示绑定到远端请求结束；网络等待占用通用作业线程，且失败日志被关闭。官方与社区下载地址原先二选一，社区开关开启后也不能按官方 404 再回退。

本次把下载生命周期集中到 CQmSkinDownloadSession：缓存与响应解码使用短 CPU 作业，HTTP 在主线程异步轮询；有效缓存立即交给已有分帧纹理上传入口。远端请求、404 或图片验证失败保留已交付缓存。成功的新图片先完成 CPU 验证才允许替换磁盘缓存，新纹理逐精灵上传完成前继续保留旧纹理。

社区开关关闭时只访问用户配置的官方地址；开启后允许官方 404 回退到用户配置的社区地址。网络错误及其他 HTTP 状态不触发换源。来源切换不复用文件修改时间条件，避免把不同来源的缓存当作同一验证器。有效缓存的 304 不解码；无有效缓存的 304 至多重试一次无条件请求。

请求有 30 秒总超时、10 秒连接超时和原有低速检测，启用 HTTP 失败日志。刷新、卸载、来源改变与关闭撤销所属会话；取消后的解码结果不能提交磁盘缓存。测试通过生产会话接口，使用真实单线程作业池与隔离 IStorage，fake 只提供传输响应和解码结果，不访问互联网或真实用户目录。

用户要求所有源码改动在主工作树完成；使用根目录下的 cmake-build-release-skins 独立构建，不使用固定槽位或 tmp 内的构建目录。基线提交 de667846cf031e2f13fb93d46ad0c68ace9a7b66。主目录存在其他 AI 的未提交改动，本任务不回退或纳入它们；CMake 只增加皮肤模块、回归测试与 benchmark 注册。
