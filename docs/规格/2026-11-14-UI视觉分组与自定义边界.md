# UI 视觉分组与自定义边界

状态：现行规格（2026-11-14 建立）。适用范围：`src/game/client/QmUi/` 与 `src/game/client/components/qmclient/` 下所有面向玩家的界面、设置卡片与预览组件。

## 一、这份规格解决什么

界面配置项会随功能增加不断膨胀。每加一个控件就顺手加一条颜色配置，结果同一屏里出现三套「按钮底色」，玩家要调两次才能改对一块区域。本规格把「什么必须统一、什么才允许自定义」写成可审查的规则，并给出对照组件的既有实现。

一句话原则：**按视觉层分组，一层一份配置；配置只表达角色，不表达控件。**（用户原话：该统一的统一，不要因为高度自定义化而让各种控件自定义颜色。）

## 二、分组判据

同一视觉层满足全部三条时，必须合并为一份配置：

1. 玩家在同一屏里不会认为它们是「不同的东西」。
2. 改其中一个而不改另一个，会让界面看起来不一致（按钮深灰、输入框蓝灰）。
3. 两者的绘制路径可以共用同一个角色 token（`ResolveConfigured*Surface()` 这类入口）。

当前生效的视觉层与唯一配置：

| 视觉层 | 唯一配置项 | 派生入口 |
| --- | --- | --- |
| 界面表面（菜单、面板、计分板） | `qm_ui_color` / `qm_ui_opacity` | `ResolveUiTheme`、`ResolveInputFallbackTheme` |
| 控件底（按钮、下拉触发器、输入框、筛选胶囊） | `qm_ui_control_color` / `qm_ui_control_opacity` | `ResolveConfiguredControlSurface`、`ResolveConfiguredInputSurface`、`ResolveConfiguredDropdownSurface` |
| 弹层底（展开列表、二级菜单、浮层） | `qm_ui_layer_color` / `qm_ui_layer_opacity` | `ResolveConfiguredDropdownListTheme`、`ResolveConfiguredSecondaryPanelTheme` |
| 设置卡片 | `qm_ui_card_color` / `qm_ui_card_opacity` + `qm_ui_card_border_color` | `QmSettingsCardTheme` |
| 强调色（选中、焦点环、滑条填充） | `qm_ui_accent_color` / `qm_ui_accent_opacity` | `ResolveConfiguredAccentColor` |
| 文字 | `qm_ui_text_color_mode`（白/黑/彩虹/自定义） | `ResolveConfiguredTextColor` |

**选中项颜色不设独立配置。** 选中态是强调色的派生档（`ui_token::ResolveUiTheme(...).m_Selected = Accent.WithAlpha(0.22f)`）。给选中单独一条配置，会让「强调色」和「选中色」长期漂开。

**活动态描边固定白色。** 悬停/按下/选中的 1px 描边取 `ui_token::feedback::ACTIVE_BORDER`，不跟随强调色。强调色偏红时，跟随的描边会把每个悬停读成错误态。

## 三、允许自定义的白名单

只有满足「玩家会希望它与界面其它部分不同」的角色才新增配置项：

- 界面表面、控件底、弹层底、卡片底与卡片描边、强调色、文字模式。
- 明确跨主题表达语义的表面：计分板已并入界面表面，不再单列。
- 组件内部的角色色（见第四节）**不是**玩家配置项，只作为 token 存在。

反例（已按本规格整改，不要回退）：

| 反例 | 问题 | 现状 |
| --- | --- | --- |
| 按钮背景色 + 输入框背景色分成两条 | 同一层两份配置，必然漂开 | 合并为控件背景 |
| 展开列表背景色 + 二级菜单背景色分成两条 | 同上 | 合并为弹层背景 |
| 计分板表面色单独一条 | 与界面表面同层 | 并入界面表面与界面透明度 |
| 选中项颜色单独一条 | 强调色的派生档 | 删除，走强调色 |
| 每个饼菜单选项旁边一个色块 | 同一件事两个入口，且色块本身是不可复用控件 | 删除色块，颜色只在预览扇区上点选 |
| 状态栏卡片写 `ColorRGBA(0,0,0,0.5f)` | 组件角色色散落在绘制代码里 | 收进 `ui_token::status_bar` |

## 四、组件角色色

一个组件内部的多种颜色（底轨、条目底、常态标签、选中标签）属于「角色」而不是「配置」。规则：

- 放进该组件自己的 token 命名空间，例如 `ui_token::status_bar`、`ui_token::discrete_slider`、`ui_token::glow`。
- 命名空间注释写清「这是同一组件内部的角色，不是给玩家逐项自定义的配色」。
- 绘制代码禁止出现裸 `ColorRGBA(...)` 字面量；「不描边」写 `ui_token::color::COLOR_TRANSPARENT`。
- 同一角色出现在两个组件里（例如「预览区暗化背板」）时，用共享 token，不各自复制一个近似值。

## 五、组件契约

1. **同一个视觉件只有一个组件。** 胶囊页签、多选一、按钮、输入框、滚动区、选项池都各有唯一实现；两个页面出现同一视觉件时必须来自同一组件（`ui_widget::CapsuleTabBar`、`CMenus::DoSegmentedChoice`、`ui_widget::FilterChip`）。
2. **预览优先于表单。** 玩家能直接操作预览（点击扇区改颜色、拖动选项进出饼菜单）时，不再提供等价的表单控件。表单只承担预览表达不了的部分（数值、文本）。
3. **数值只在 token 里。** 组件不自带像素常量；高度、内边距、圆角由 `ui_token` 派生函数给出（`ui_token::control::PadX`、`ui_token::list::ContainerRadius`）。
4. **状态必须跨趟可重入。** 设置卡片有声明、测量、输入、绘制多趟；拖动、展开等状态只在交互趟推进，测量趟与只读趟直接落到目标值。

## 六、拖拽池模式（选项在/不在某集合）

用于「一组选项里挑出要用的那些」。当前实现：`src/game/client/QmUi/QmPieOptionPool.h` + `src/game/client/components/qmclient/pie_menu_settings.cpp`。

排版：

- 预览容器占满卡片宽度，预览本体（圆饼）在容器内居中；容器背景取 `ui_token::color::PREVIEW_BACKDROP`，描边取 `BORDER_SUBTLE`。
- 两个池上下排列，各带一行标题：启用池在最上（默认操作的对象），关闭池在其下。
- 池容器圆角取 `ui_token::radius::MENU`，胶囊圆角取 `ui_token::radius::PILL`，池内换行由宽度自动决定。
- 空池保留一行胶囊的高度并显示一句提示，否则最后一个选项被拖走时整卡高度会跳。

交互：

- 池内胶囊只有一条热区；拖动起手记录「池 + 选项」，指针离开 `ui_token::spacing::XS` 后才算拖动（低于阈值仍是点击）。
- 松手时落点判定顺序：胶囊 → 池容器 → 原池。落到另一池才改配置项。
- 原地单击等价于切换归属，保证不拖动也有路径。
- 拖动中画幽灵胶囊（带 `ui_token::elevation` 偏移的投影），并用 `ACTIVE_BORDER` 高亮落点池。
- 幽灵胶囊与落点高亮只在绘制趟画，输入趟只推进状态。

## 七、审查清单

改界面配置或组件时逐条对照：

1. 新增的配置项是否落在第二节的视觉层里？不在表里就先说明为什么它是独立角色。
2. 同一层是否已有配置项？有就复用，不新增。
3. 新颜色是否进了 token？组件内部角色是否放进该组件的命名空间？
4. 同一视觉件是否已有组件？是否又自绘了一份？
5. 预览能表达的交互是否又做了一套表单控件？
6. 空集合、超长文本、极窄窗口、动效关闭这四种边界是否都定义过？
7. 是否有行为测试覆盖新组件的几何与状态迁移？纯源码字符串不算覆盖。
