# Axiom 移动方块与移动水预测

状态：已实现，等待编译和运行验收。更新时间：2026-10-24。

## 玩家入口

在“Qm 设置 / 功能 / Gores”卡片中提供“移动方块与移动水预测（实验性）”。配置为 `qm_axiom_quad_prediction`，默认关闭，与 Gores 自动切锤独立。仅在线客户端显式启用；关闭后撤销额外碰撞，恢复常规预测。需要服务器地图遵循 Axiom 的 Q 图层规则。

TC 原有的“在实体层显示移动方块”移入同一卡片，继续使用 `qm_moving_tiles_entities` 及原有保存值。它控制纯实体模式下移动水和方块的显示。TC 页面不再保留该控件；搜索也归到 Gores 卡片。

## 预测范围

- 识别 Axiom 的 QHook、QStopa、冻结与解冻系列、QTune、QReJump 和 QCfrm 图层，按地图组、图层和四边形顺序处理。
- 使用服务器 tick 相对 round-start tick 的时间计算平移、旋转和透明度。支持预测回退、重复推进、包络偏移和负时间。
- 方块参与人物盒体碰撞、钩子和武器射线；钩住旋转或移动的方块后保留局部锚点，消失或被裁剪时松开。
- 移动冻结区沿用现有冻结预测配置和状态处理，后命中的解冻层可覆盖冻结层。死亡和过关仍由服务器确认。
- QTune 的碰撞区与客户端接收的 tuning 分区保持一致，服务器显式分区覆盖优先。
- 快照演化、常规预测、平滑预测和本地练习按各自 tick 查询。每段临时模拟退出时恢复共享碰撞时间。
- 公共碰撞模块不读取客户端配置。服务端未启用额外四边形碰撞；协议与文件格式不变，回放仍使用原有路径。

## 参考与适配

参考 [Xyrion 的四边形碰撞实现](https://github.com/Xyrion-0805/xyrionclient/blob/main/src/game/axiom_quad_collision.cpp) 和 [Axiom 的 collision.cpp](https://github.com/TeeworldsAxiom/teeworlds-Axiom/blob/master/src/game/collision.cpp)，并核对 Axiom 的 quad_animation_manager.cpp、layers.cpp、gamecontroller.cpp 和角色处理。

审阅后做了以下适配：

- Xyrion 跳过视差组并应用组偏移；Axiom 服务端直接按四边形原坐标碰撞。移植按服务端规则处理，避免这些图层上的坐标偏差。
- 共享碰撞时间由作用域保存和恢复，避免一个预测世界的最终 tick 留给其他世界。每段模拟内部只逐 tick 推进，避免每一步都回到渲染时间。
- 关闭功能与地图重载释放四边形缓存；默认关闭时保留原有静态图块路径。
- 退化面积判定使用相对坐标，避免远离地图原点的小方块因浮点消减而丢失碰撞。

## TC 轮盘右键交换

设置卡片会分别回放 INPUT 与 DRAW。原预览在两趟都读取 `MouseButtonClicked` 并交换条目，同帧两次交换会恢复原顺序。因此属于缺陷。交换、选择与中心取消仅在 INPUT 趟提交，绘制趟保留显示。
