# QmClient DDNet 20.0 基线审计

本文件只记录重构分支当前基线中已经核对过的官方事实。旧 dyl_dev、旧 QmClient/TClient 文件和历史文档只能作为功能来源，不得反向决定新架构。功能迁移的完整登记见同目录的 feature-migration.tsv。

## 1. 分支与依赖

- 重构分支：codex/qmclient-20.0-refactor。
- 当前起点：官方 DDNet 20.0 提交 a5a61806e434ef22141b622db989087fbba8ed21。
- 当前新增起点提交：713d00f0c243db2657ac2a2b4ef2b4d147223fb4。
- ddnet-libs 保留现有依赖快照 24a9a5e3c22ffd26d8b8ba4bbf70d0b698bdd0a3。它是构建依赖，不等于旧 QmClient 代码；除非单独提出兼容性问题，本阶段不迁移或升级它。
- 构建目录统一使用仓库内的 `E:/Coding/DDNet/QmClient/cmake-build-release`，并由 `.gitignore` 排除，避免构建生成物进入提交。

## 2. 官方版本与组件生命周期

src/game/version.h 在官方 20.0 基线中声明：

- DDNET_VERSION_NUMBER 20000。
- GAME_RELEASE_VERSION_INTERNAL 20.0。
- 网络版本仍由官方 GAME_NETVERSION 和 GAME_NETVERSION7 定义。

CGameClient 的官方组件系统具有以下合同：

- m_vpAll 的插入顺序同时影响初始化、更新和渲染顺序；官方组件列表在 src/game/client/gameclient.cpp:122-169。
- 组件初始化在 OnInit 中逆序执行；地图加载时 OnMapLoad 与 OnReset 按列表正序执行。
- 输入不是 m_vpAll 的隐式子集，而是独立的 m_vpInput 栈；官方输入优先级在 src/game/client/gameclient.cpp:171-184，按键释放事件还必须继续转发给所有组件。
- 渲染按 m_vpAll 正序执行，见 src/game/client/gameclient.cpp:778-824。渲染组件的位置不能通过最后注册这一事实自动推导出正确的绘制层。
- 消息分发存在前置处理和短路：tuning、翻译失败、change-info cooldown 与 dummy 消息可能在完整组件广播前返回，见 src/game/client/gameclient.cpp:1058-1134。
- 官方 CComponentInterfaces 暴露 GameClient() 以及多个完整引擎接口，见 src/game/client/component.h:14-157。因此新 Qm feature 不得继承 CComponent，也不得通过 context 间接持有 CGameClient。

## 3. 当前 Qm composition root

当前分支增加一个官方组件集成点，以及一组不包含 Qm 类型的 engine/client 诊断 hook：

- src/game/client/components/qmclient/core/qm_runtime.h
- src/game/client/components/qmclient/core/qm_runtime.cpp
- src/game/client/components/qmclient/core/qm_game_state_adapter.h
- src/game/client/components/qmclient/core/qm_game_state_adapter.cpp
- src/game/client/gameclient.h
- src/game/client/gameclient.cpp
- CMakeLists.txt
- src/engine/client/client.h
- src/engine/client/client.cpp

CQmRuntime 当前是生命周期哨兵和 composition root：

- 记录 OnInit、OnShutdown、OnMapLoad、OnReset、OnStateChange。
- 不进入 m_vpInput。
- 不解析网络消息。
- 不在头文件中拥有或暴露 CGameClient 状态；官方状态读取集中在 `qm_game_state_adapter.*`，runtime 只接收可消费的 feature frame。
- 不包含 CTClient、TClient 或 tclient.h。
- 已接入首个探索性样板 `QmPlayerIndicator`；该 feature 是普通类，不进入 `m_vpAll`，由 runtime 使用窄的 `SQmPlayerIndicatorFrame` 调用。

runtime 当前位于 `m_DamageInd` 之后、`m_Hud` 之前，作为首个游戏内 presentation 样板的绘制槽位。
它不是通用业务聚合器；需要输入或其他特定渲染槽位的功能，仍必须先设计稳定的官方 adapter，
并在迁移台账记录其位置、线程、默认行为和回归测试。

engine/client 的 `IGameClient::OnFrameStart` / `OnFrameEnd` 和 graphics init hook 是独立的
`Qm_ADAPTER` 触点：它们只调用接口上的默认空实现，不 include Qm 头文件，也不改变官方
输入、预测、网络、demo 或 renderer 同步语义。上游同步时必须分别重放这两个窄 hook，
不能把它们误记为仅有 `gameclient.cpp` 的组件注册改动。

为获得完整 frame interval，官方 `IGameClient` 增加了默认空实现的
`OnFrameStart` / `OnFrameEnd` hook，`CClient` 在 `Render()` 和 `Swap()` 外围调用，
`CGameClient` 仅转发给 Qm runtime。该 hook 不改变官方输入、预测、网络和 demo 语义。

`qm_game_state_adapter.*` 是 Qm 侧的窄适配边界：它可以读取 DDNet 20.0 的
`CGameClient` 快照、客户端数据和 camera 状态，但不拥有这些状态，也不向 feature
暴露完整 `CGameClient`。后续上游字段变化只应影响该 adapter，不应扩散到 runtime、UI
或 player-indicator 逻辑。

## 4. CMake 与资源

官方 20.0 使用根 CMakeLists.txt 的 set_src(GAME_CLIENT GLOB_RECURSE src/game/client ...)。set_src 会通过 set_glob 检查源文件集合和字母排序，定义见 CMakeLists.txt:359-417，game-client 清单从 CMakeLists.txt:2484 开始。新 Qm 文件当前遵循官方清单，不额外引入无约束的递归 glob。

资源由官方 DATA 清单集中收集，见 CMakeLists.txt:1923 附近。新增图标 atlas、字体、shader、脚本或语言产物时，应在资源来源、生成命令、版权和运行时失败回退之间建立可追溯关系，不能只把生成文件复制到 data。

## 5. 图形后端与线程边界

DDNet 20.0 当前代码路径明确涉及：

- OpenGL：src/engine/client/backend/opengl/backend_opengl.cpp。
- OpenGL ES：src/engine/client/backend/opengles/backend_opengles3.cpp。
- Vulkan：src/engine/client/backend/vulkan/backend_vulkan.cpp。
- 统一线程封装：src/engine/client/backend_sdl.cpp、src/engine/client/graphics_threaded.cpp 和 src/engine/client/graphics_threaded.h。

当前没有独立的 Metal backend。macOS 相关的线程等待条件不能被记录成 Metal 后端已经存在。

图形线程在 backend_sdl.cpp:56-75 等待并执行 command buffer；主线程通过 threaded graphics API 投递命令。因此后续图形诊断必须遵守：

- backend 线程只写固定大小的 snapshot 或事件，不直接写 Qm 文件、不调用 Qm UI。
- 主线程或独立 writer 消费事件。
- 每个 graphics submission 使用稳定的 session_id、graphics_epoch、frame_id 和 command_buffer_id 关联。
- GPU query 若未来加入，只能异步延迟回收，不能在当前帧同步等待。
- 不可用 GPU query 时必须写 gpu_time_available=false 和原因，不输出伪造的 gpu_ms。

Vulkan 的 acquire、submit、present、device lost 和 swapchain recreate 入口已经存在，但需要后续 adapter 补充结构化事件和完整 attempt 上下文。OpenGL/GLES debug callback 需要限流、去重和独立标记，默认不能让同步 debug 日志污染 1% low。

## 6. 性能观测基线

官方主循环记录的是两次渲染时间点之间的间隔，并混合了 update、render limiter、vsync、线程等待和 present 等因素。它不能直接当作 CPU render time 或 GPU time。

第一阶段的指标分层：

    loop_interval
    cpu_update
    cpu_render_prepare
    graphics_submit_enqueue
    graphics_worker
    present_or_vsync_wait
    sleep_or_frame_cap

1% low 使用固定窗口的真实 frame-time 样本：

    k = max(1, ceil(0.01 * sample_count))
    frame_time_worst_1pct_mean_ms = mean(largest_k_frame_times)
    fps_1pct_low = 1000 / frame_time_worst_1pct_mean_ms

frame_time_p99_ms 作为独立分位数记录，不能再用其倒数冒充 1% low。每个会话必须写入样本数、窗口长度、构建类型、刷新率、vsync、backend、设备、场景，以及是否包含加载、resize、切后台、demo seek。

自动记录要求：

- 诊断 session 必须在图形初始化之前启动，以便记录后端初始化失败。
- 默认自动落盘到用户可写的诊断目录，不依赖用户手动设置 logfile。
- 高频路径使用固定容量 ring buffer、原子计数或低开销采样。
- 独立 writer 周期性 checkpoint，退出和异常路径尽力完成最终摘要。
- 写盘失败降级为内存模式并记录 persist_failed，不能阻塞游戏线程。
- 禁用详细 trace 时不做字符串格式化、动态分配或磁盘 IO。

## 7. 新代码硬门禁

从本分支开始新增或迁移的 Qm 代码：

- 禁止 include tclient.h。
- 禁止引用 CTClient、TClientComponent()、m_TClient 和任何 TClient 聚合字段。
- 禁止通过 CGameClient 或万能 Context 间接读取 TClient 状态。
- 旧 TClient 字段只能出现在历史来源分析或迁移适配代码中，适配代码必须有独立 owner 和删除条件。
- feature 的状态必须由 feature/model/service 自己拥有，并通过只读 view 或明确 adapter 取得官方数据。
- 每项迁移必须覆盖配置、命令/快捷键、资源、持久化、线程取消、生命周期和 online/dummy/spectator/demo 等模式。

## 8. 本审计的下一步

1. 完成功能迁移台账的来源、配置、资源和生命周期补全。
2. 为 runtime 生命周期哨兵增加最小合同测试，验证初始化逆序、地图正序和 shutdown 行为不会被误读。
3. 补齐自动诊断 writer、早期 graphics bootstrap 和后端专属事件，再接入 graphics adapter。
4. 继续以不触碰协议、预测、物理和输入优先级的低风险 feature frame 作为垂直迁移切片。
5. 每条切片在合并前进行构建、测试、运行时 smoke、功能保全 review 和性能回归记录。
