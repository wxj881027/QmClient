# 约定

QmClient 不新增运行时翻译系统，直接跟随 DDNet 官方 `Localize` 和 `data/languages/*.txt`。i18n 的实现侧全部放在 `qmclient_scripts`：

- `translations/i18n/qmclient/qmclient.toml` 是唯一维护源，`key` 直接使用英文 source key。
- `qmclient_i18n.py` 扫描 `Localize(...)` / `Localizable(...)`，校验 source coverage 和占位符。
- `translate` 通过 OpenAI-compatible API 调用 DeepSeek，默认 `https://api.deepseek.com` / `deepseek-chat`，把译文写入 TOML。
- `generate` 读取 TOML 和现有官方语言文件，只更新 Qm source/context，输出最终 `data/languages/*.txt` 格式。

扫描只负责发现 Qm 源码中的字面量调用；registry 或配置里的动态 source key（例如卡片标题）必须直接登记在 TOML，不能依赖扫描器推断。

运行时 source identity 是英文 `key` 加 context，和官方语言文件完全一致。翻译必须保留 `%s`、`%d`、`%.2f`、`\\n` 等占位符。

## 工作流

```text
py -3 qmclient_scripts/qmclient_i18n.py migrate --write
py -3 qmclient_scripts/qmclient_i18n.py scan --write
py -3 qmclient_scripts/qmclient_i18n.py validate
py -3 qmclient_scripts/qmclient_i18n.py translate --languages simplified_chinese --write
py -3 qmclient_scripts/qmclient_i18n.py generate --languages simplified_chinese --output-dir data/languages
py -3 qmclient_scripts/qmclient_i18n.py validate
```

`migrate --write` 只用于从旧的 Qm key/fallback 布局迁移到官方 source-key 布局。`scan --write` 为源码中新增且未登记的英文文案添加 source 条目。`translate` 默认只补缺失语言；`--rewrite` 才会重翻已有译文。DeepSeek key 从 `DEEPSEEK_API_KEY` 读取，也可用 `--api-key-env` 更换变量名。没有 `--write` 时只预览，不修改 TOML。

生成语言文件前先设置：

```powershell
$env:DEEPSEEK_API_KEY = "..."
```

默认输出到 `tmp/qmclient-languages`，确认结果后才指定 `--output-dir data/languages` 覆盖官方语言文件。不要手工维护生成的 txt。
