# 当前阶段

`CQmI18n` 定义窄 lookup/fallback 接口：feature 通过稳定 key 和可选 context 请求文本，找不到翻译时返回调用方提供的 fallback。lookup 只保存无状态函数指针，不保存裸 `void *`，也不复制 DDNet 的语言加载、字体或文本缓存系统。

runtime 初始化时把该接口绑定到官方 `Localize`，因此 Qm feature 不需要直接依赖语言数据库；旧 UI 和新 UI 都可以通过同一个 feature/card model 读取文案 key。`Text` 对空 key、空 context 和空翻译均有 fallback 行为。

当前已完成接口和官方 lookup 接线。`translations/i18n/qmclient/qmclient.toml` 提供 source skeleton，`qmclient_scripts/qmclient_i18n.py` 提供 source 校验和 catalog 生成，但当前 catalog 尚未接入构建或运行时，也不冒充完整的语言生成流水线。语言 txt 仍只作为未来生成物；正式接入前必须补齐 source、消费点、fallback、语言切换和资源生命周期台账。

source skeleton 采用 `[[messages]]` 数组。该格式目前只是 QmClient 的维护约定，不是已接入的官方生成器接口；后续可在不改变 key 的情况下扩展语言和生成器：

```toml
[[messages]]
key = "qm.player_indicator.title"
fallback = "Player indicators"
context = ""
```

当前 legacy 设置页仍使用官方 `Localize(fallback)`，因此 skeleton 不会改变现有运行时文案。

## 工具

```text
py -3 qmclient_scripts/qmclient_i18n.py validate
py -3 qmclient_scripts/qmclient_i18n.py generate --output tmp/qmclient.en.json
```

`validate` 检查 TOML schema、`qm.*` key、重复 key、fallback/context 类型，并扫描 QmClient 源码中使用字面量的 `Localize` 文案是否已登记。动态文案和非 QmClient 源码不由这个扫描器推断，必须在对应 feature 条目和 source 中人工登记。`generate` 先执行同样的校验，再按 key 稳定排序输出 JSON catalog；输出是中间产物，未接入运行时前不应手工修改或提交。

这个脚本是 i18n source 的维护工具，不属于 `check_qmclient_boundary.py`，也不承担 TClient 依赖、include 纯度、台账同步、命名结构、配置归属、行为覆盖或性能检查。当前阶段不接 Git hook、CI、官方语言 txt 生成器或运行时 catalog 加载。

## 验证

- `QmI18n.UsesLookupAndFallback` 覆盖 lookup、缺失 key、空 key、context 覆盖和 fallback。
- Release `run_cxx_tests`：395/395 通过，3 个既有 disabled。

## 未完成

- 当前 source skeleton 和 JSON catalog 生成脚本已在本分支；尚未接入正式语言生成、语言切换通知或运行时 catalog 加载。
- 尚无真实旧 UI/新 UI presentation 调用点；当前 model 只提供共享的 descriptor 和状态读取边界。
