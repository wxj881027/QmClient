# QmClient 重构功能目录

更新时间：2026-09-07

本文把 `docs/模块/` 中的远程功能提示词压缩为本地可执行的功能目录。它是**候选功能和重构顺序清单**，不是远程源码的事实清单，也不是本地架构规则。

## 使用规则

- 远程模块提示词只提供功能范围、行为线索、测试场景和可能的旧入口；不得直接相信其中的源码路径、当前状态、配置声明或实现方案。
- 旧行为对照根目录为 `tmp/qm-dyl-dev-6d37ad1c/`。先在该目录确认真实入口、调用链、配置、资源和测试，再决定本地是否保留行为。
- 本地新实现必须遵守根目录 `AGENTS.md`、`docs/qmclient/architecture.md` 和当前阶段表；旧代码只作行为参考，不把旧聚合器或字段依赖带入本分支。
- `docs/模块/` 的“已有实现”不等于本地完成。只有本地入口接管、测试、集成或 smoke、生命周期和性能证据齐全，才可在 `feature-ledger.md` 标记 `DONE`。
- 本目录只做导航和收口，不复制每份远程提示词的长篇内容。需要具体行为时，打开对应的远程模块文档和旧版源码。

## 状态

| 状态 | 含义 |
| --- | --- |
| `UPSTREAM_BASELINE` | DDNet 官方已有能力；默认保持官方实现，本地只在需要时做 adapter。 |
| `CANDIDATE` | 远程资料提出的候选功能，尚未完成本地源码和旧行为核对。 |
| `AUDIT` | 已发现本地或旧版入口，仍需整理行为、配置、资源和生命周期。 |
| `IN_PROGRESS` | 已进入当前重构，但尚未达到功能完成标准。 |
| `MIGRATED_SLICE` | 已完成纯逻辑或局部切片；真实 UI、联网、demo 或多人验证仍可能未完成。 |
| `DEFER_EXTERNAL` | 外部服务、媒体、helper 或平台依赖，等基础验证和边界明确后处理。 |
| `DEFER_SCOPE` | 当前明确不属于 QmClient 阶段 0–6 的范围。 |

## 重构顺序

1. 先收口阶段 0–5 的公共底座和验证矩阵。
2. 第一波：纯逻辑、配置绑定、低风险 HUD 和视觉展示。
3. 第二波：输入、聊天、双角色和需要真实渲染验证的功能。
4. 第三波：网络协议相关、回放、服务器交互和状态同步。
5. 第四波：HTTP、媒体、歌词、语音、社区、helper 和平台服务。
6. 地图编辑器和底层图形后端按独立风险评估处理，不与普通 Qm feature 混成一个迁移批次。

## 与功能台账的关系

- 本目录回答“远程资料提示了哪些功能、应该分在哪个板块、什么时候可以考虑”。
- `docs/qmclient/feature-ledger.md` 回答“某个本地 `qm.*` 功能现在具体做到哪、行为是什么、证据在哪里”。
- 当候选功能真正开工时，先在本目录确认板块和波次，再在 `feature-ledger.md` 建立或补全对应条目；代码、台账和必要的官方触点同一批次更新。
- 已有 `MIGRATED_SLICE` 只表示局部重写完成，不代表整份远程模块已经实现。调试和行为修复应在重写过程中完成，但必须保留旧版行为对照和回归证据。
