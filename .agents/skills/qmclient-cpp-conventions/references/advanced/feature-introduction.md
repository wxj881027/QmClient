# 特性引入参考

用于新增功能、配置或用户可见行为。根据当前请求明确要解决的问题、默认行为和影响范围；只有结果依赖缺失信息时才澄清，不重复讨论已批准设计。

- 保持官方 DDNet 兼容性；协议、玩法与格式授权遵循根规则。
- 新配置用 `qm_` / `Qm`，说明默认值及已有用户配置如何处理。
- 涉及后台任务时明确取消、发布、预算与失败回退；涉及热路径时判断新增成本。
- 只做当前功能需要的结构，不为未来扩展先建空模块或观测系统。

实现与验收按风险安排：小功能可直接实现并验证；复杂状态或高风险设计先记录关键决策，使用必要的行为测试和场景检查。验证集合由 `qmclient-verification-gate` 决定，不要求每个新配置单独建设计文档、源码合同测试或回滚开关。
