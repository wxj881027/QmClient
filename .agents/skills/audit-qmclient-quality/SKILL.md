# QmClient 质量审计

## 范围与授权

用户指定范围优先；未指定则以当前 diff 及直接影响面为起点。只读审计交付报告；用户已要求修复或加固，则验证候选后继续最小修改，不重复请求确认。

先读实际变更、相关有效规格和调用点；旧文档、模板入口和工具索引仅作定位线索。不要将上游遗产或不相关风险纳入当前整改。

## 检查方法

1. 从玩家路径和实际变更识别高风险状态，选择相关功能场景及横向风险。
2. 追踪入口、owner、状态转换、失败回退和已有保护；用真实触发路径验证候选。
3. 只对相关假设给出确认、排除或待运行时验证结论；无需为无关项建覆盖表。
4. 以文件位置、触发条件和影响报告确定缺陷，按严重度排序；不确定项明确说明证据缺口。

按需参考见 [quality-scan-prompt.md](references/quality-scan-prompt.md)。无匹配模板直接查实现；不要求现场编写模板，不以模板数量决定轮次。用户明确要求完整矩阵时记录覆盖和未执行项，否则只保留有用的证据。

## 协作与交付

委托遵循根 `AGENTS.md`：独立风险域且能节省时间或提升质量时派只读审查；明确范围和问题，主代理核对候选、去重后给结论。参与最终结论的审查需等待返回，失败或未完成要说明。

findings 格式按 `qmclient-code-review`。修复按相关实现约定进行，测试与 gate 统一按 `qmclient-verification-gate`，不另加一套全量要求。可确定复现且有回归价值的问题优先转行为测试，设备/视觉风险采用对应场景证据。

完成时说明审查范围、确定问题与实际验证限制；没有缺陷就直接说明，不以构建成功替代运行时或跨平台结论。新增自动 gate 必须确定、可解释且无自动修复副作用，不把 AI 判断直接设成阻断。
