# QmClient 代码审查

读指定 diff/模块、直接调用点与已有保护；未指定范围时从当前 diff 及直接影响面开始。优先检查正确性、未定义行为、生命周期、线程、热路径及 DDNet 协议/玩法/格式兼容。

用户只要求审查时交付报告；已要求修复则验证候选后继续修复并维护架构一致性。授权、项目边界和委托条件遵循根 `AGENTS.md`，验证统一由 `qmclient-verification-gate` 决定。

## 检查重点

以下要求适用于本地审查；委托时在任务说明中显式带入相关项和实际影响面，主代理复核 findings 与证据缺口。

- 功能：正常路径之外检查边界输入、失败回退、取消、重复调用、重入、用户配置覆盖、并发及 owner 生命周期；沿真实状态转换确认触发条件。
- 测试：通过生产接口断言输出或状态变化，检查目标行为回归时测试是否会失败。禁止复制算法、重写状态机、截取函数体或查找源码字符串证明运行时行为；区分单元策略和真实模块协作，静态合同边界遵循根规则。
- 性能：检查热路径的扫描、分配和重复工作，以及生产实现能否独立测量。相关热路径优先复用 Google Benchmark 目标，过滤范围、环境、结果和基线要求见验证 skill 的 [性能参考](../qmclient-verification-gate/references/performance.md)；没有同条件基线不声称性能提升。
- UI：检查共享卡片和组件入口、长译文/缩放/窄视口下的尺寸适应与兜底，以及嵌套层活动权、外部点击关闭、ESC、键盘提交、父层关闭清后代、离页失效、取消后重开和滚动输入归属。用行为测试约束组件回归；缺少自动观察点时说明缺口，实机验收遵循用户安排。
- 架构：同类行为由适当的共享生产模块统一负责，避免重复策略和分散补丁。不能为减少改动量牺牲统一性、可测性或增加后续维护成本；抽象服务于实际职责和 benchmark 能力，不扩张到任务无关的上游重构。

## 深度审计

用户要求深度审计、完整状态覆盖、发布风险复核，或问题确需系统性检查时，按需读取 [质量审计索引](references/quality-scan-prompt.md)。普通 diff review 不默认加载全部材料。

1. 从玩家路径与实际变更选相关功能场景和横向风险；有效规格辅助判断，旧文档仅作线索。
2. 追踪入口、owner、状态转换、失败回退和已有保护，用真实触发路径确认候选。
3. 对相关假设标记确认、排除或待运行时验证；用户明确要求完整矩阵时记录覆盖和未执行项，无匹配模板时直接查实现。
4. 独立风险域可按根规则委托只读复核；参与最终结论的结果需等待并去重，失败或未完成需说明。

新增自动 gate 必须确定、可解释且无自动修复副作用，不把 AI 判断直接设为阻断。

## Findings 与交付

- 仅列能说明触发条件和具体影响的缺陷，不把风格偏好或未验证猜想当 bug。历史兼容需求不明时继续查真实代码，无法确认的疑点单列待验证。
- 每项 finding 包含严重度、文件行号、触发与影响、修复建议和共享影响面，按严重度排序。
- `严重`：崩溃、数据丢失、安全或兼容性破坏；`重要`：真实功能 bug、生命周期或性能回退；`轻微`：低风险边界或维护问题。
- 可复现且有回归价值的缺陷优先转为行为测试；设备/视觉风险保留对应场景证据，不额外建立重复的全量验证要求。
- 完成时说明审查范围、确定问题、实际验证和限制；没有确定缺陷就说明“未发现确定缺陷”，不能据此宣称代码完全正确。
