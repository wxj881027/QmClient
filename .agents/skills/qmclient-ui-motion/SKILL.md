# QmClient 交互与动效

围绕用户指定的玩家路径工作。先说明操作怎样得到回应，再决定哪些元素需要运动。授权、验证和交付遵循仓库 `AGENTS.md`；本 skill 不引入额外工具或运行时。

## 设计依据

先读取当前工作树中与路径有关的有效规格。实验规范位于仓库相对路径 `docs/规格/2026-10-13-QmClient交互与动效语言.md`；路径相对仓库根解析。该规范尚未合入或不存在时，以当前有效规格和已确认需求为准，不根据安装副本推断产品已实现的行为。

需要解释 Apple 原则或查官方 API 时，按需读取 [资料与取舍](references/sources.md)。其中社区项目提供方法参考，具体数值、平台规范和 API 以官方资料为依据。Windows 鼠标、键盘和游戏内菜单的输入语义需单独判断。

## 从路径到方案

- 选一个完整操作，例如设置分类到子页，或打开弹层后关闭并回到原控件。说明用户意图、立即反馈、过渡中的操作、取消和恢复。
- 区分业务目标与画面当前状态：选择已经生效时，滑块仍可移动；动画完成事件不承担普通导航的提交。
- 同类动作优先共享现有 token 和组件。给位移、尺寸、透明度分别选择合适的运动方式，不为统一外观强制全部使用弹簧或同一时长。
- 仅移动有空间或状态含义的元素。内容密集页面的装饰应让位于阅读、定位和操作；材质、回弹幅度和节奏属于待场景验收的设计选择。
- 评审时给出具体触发、可观察结果和修改建议。优先处理响应丢失、内容跳变、焦点丢失和规则冲突，再讨论装饰。

## 接入 QmUi

先沿真实入口读取页面编排、共享组件、动画解析与输入 owner；不要仅凭 token 名称判断最终行为。

| 路径 | 优先读取的生产入口 |
| --- | --- |
| 分类与子页 | `ModernSettingsPage.cpp`、`SettingsNavigation.*`、实际菜单调用点 |
| 导航选中反馈 | `UiNavigation.*`、`UiMotion.h`、`UiTokens.h` |
| 卡片入场与重排 | `SettingsCardDeck.*`、`SettingsCardDeckLogic.*`、`SettingsCardGeometry.*` |
| 动画接续 | `QmAnimResolve.*`、`QmAnim.*`、`QmAnimationBackend.*` |
| 弹层和输入 | `ui.*` 中的交互 owner、弹层栈和绘制阶段 |

- 核对节点身份与生命周期。稳定元素用稳定轨道；新实例不继承其他页面的偶然指针或局部静态状态。
- 区分卡片定义缓存、模型索引与显示周期。前两者刷新时保留 Deck 共享入场；回归测试应走实际 `RenderCached` 到卡片最终坐标，不能只测试偏移 helper。
- 快速连续操作时检查当前位置、速度和目标的交接。复用后端的目标合并能力，避免人为重置可见元素或排队播放过时导航。
- 区分交互绘制、背景绘制和测量。背景应读取当前画面值，不借机初始化或重定向轨道；测量不得重复提交画面。动画时间由原有统一入口推进。
- 用实际显示几何核对命中、裁剪、滚动和焦点。动画不能让失去归属的旧页面继续处理输入，也不能通过整段锁输入掩盖交接问题。
- 检查现有动效等级和功能开关；关闭或减少动效后，状态反馈仍须清楚。先复用已有策略，避免为内部修复增加设置项。

## 证据与复用

测试调用生产选择器、组件和动画后端，观察返回选择、最终绘制几何及状态变化。比较中断前后与未中断参考轨迹时保持相同时间步；fake 只替换设备和外部边界。

按本次路径选择连续点击、反向、背景覆盖、关闭重开、关闭动效等相关场景。UI 截图可以展示层次，连续录屏和帧时间才能进一步解释运动与延迟；静态阅读不产生视觉或性能结论。
