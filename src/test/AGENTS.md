# 测试编写入口

本目录及子目录遵循本文末「测试规则」一节；根 `AGENTS.md` 只保留不可协商的边界。修改前读对应生产实现与现有行为测试；旧测试的写法不自动成为可沿用规范。

- 独立生产接口行为放 `unit/<功能域>/`，模块协作放 `integration/<功能域>/`；静态合同放 `contract/<功能域>/` 并使用 `*_contract_test.cpp`。共享辅助代码放 `support/`，Google Benchmark 放 `benchmark/`，Qm 跨进程测试放 `qmclient_scripts/integration/`。
- 一个文件只承载一个功能域和一个主要验证层级，保持混合文件与混合声明为零。不要为通过分类检查将运行时源码断言改名为合同；按「源码合同边界」删除重复检查或补生产观察点。
- 通过生产接口安排输入、执行操作并断言可观察结果。新增测试先明确“哪项生产行为出错会使此测试失败”；不能回答时重新设计测试，不复制算法或用源码字符串代替行为。
- 修改配置、时钟、缓存、logger 等共享状态时显式初始化所需状态并恢复；测试须能单独运行，不能依赖其他 suite 留下的默认值。fake 只替换外部边界，不重写待测生产职责。
- 参数矩阵用于同一行为的输入组合；失败、取消、重入、恢复等不同路径独立命名。文件与 suite 的拆分阈值见「编写与保留」。
- 新增、迁移或删除编译单元时同步 CMake 注册、辅助引用和只为它存在的数据；不要仅运行旧二进制。按 verification skill 构建受影响目标并运行相关过滤。

完成前运行 `python qmclient_scripts/test_inventory.py --json` 核对库存，并按 verification skill 运行适用 gate。库存 gate 检查结构和注册，不证明行为覆盖或断言质量。`README.md` 供目录导航，规则权威来自本文件、根 `AGENTS.md` 的边界与专项 skill.

# 测试目录

C++ 测试按层级和功能域组织；生产接口与测试名保持稳定，目录只表达职责。AI 编写入口为本目录 `AGENTS.md`，benchmark 另有 `benchmark/AGENTS.md`；本 README 只提供导航。

| 目录             | 职责                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------- |
| `unit/`        | 独立函数、策略、状态机和小型类的行为测试                                                |
| `integration/` | 两个及以上生产模块的协作；当前包含上传生命周期、翻译后端/任务队列与菜单性能日志协作测试 |
| `contract/`    | 现有合同文件，逐步收敛到构建、平台、生成资源和迁移终态约束                              |
| `mixed/`       | 历史混合文件已完成分离，当前没有 C++ 测试文件；库存继续检测新增混杂                     |
| `support/`     | 共享 fixture、fake、源码合同读取器和链接 stub，不计为独立测试场景                       |
| `benchmark/`   | Google Benchmark，直接测量生产实现，不并入 Google Test 数量                             |

各层内部按 `base`、`engine`、`client`、`server` 和 `qmclient/<功能域>` 区分。`test.cpp`、`test.h` 是公共入口。`QmAnimDropdownTest.cpp` 已归入 `unit/qmclient/ui/`。

新增测试应通过生产接口观察输出或状态变化，在根 `CMakeLists.txt` 的对应目标显式注册。新增公共辅助代码放在 `support/`，使用 `<test/support/文件名.h>`；使用公共入口时包含 `<test/test.h>`。跨进程测试仍放在 `qmclient_scripts/integration/`。

运行 `python qmclient_scripts/test_inventory.py` 检查递归库存、未注册文件、注册但缺失的源码和重复测试名；`--json` 输出完整数据。数量表示测试宏声明，参数化与类型化实例不展开。CMake 声明统计包含条件分支和独立目标，不能当作本机实际执行数。`mixed` 单独统计，不把整个文件的行为声明算成静态合同。合同后缀只是文件职责声明，不能证明每项断言都符合合同边界。

quick/default/full gate 的“测试层级与注册库存”检查扫描当前完整仓库，混合声明、未注册文件、缺失源码或重复 ID 会导致失败；扫描不执行真实测试，也不能判断合同是否合理或 benchmark 测量是否有效。

目录移动应同时更新注册、辅助头文件引用、路径型 include guard 和使用旧路径的脚本，并构建受影响目标、核对实际测试发现。禁止只移动文件后依赖库存数量判断执行成功。

监控遗留未注册文件已完成逐功能核对并删除，有效行为迁入对应目录；库存工具继续报告未注册文件和缺失注册源码。JSON schema 为 7，汇总区分合同、混合、单元与集成文件，计数表示宏声明。

卡片行为按页面布局、表单状态、外观几何、放置排序、动画与交互进入 `unit/qmclient/settings/`；碰撞几何和武器行为进入 `unit/qmclient/client/`。对应资源标签与源码接线继续由 `contract/` 承载。混合文件声明已清零；源码合同债务仍独立保留并继续按观察点审查。

库存 schema 7 同时识别源码读取 helper 和直接 `TestSourcePath("src/…")` / 仓库根流式读取，避免只把 helper 调用去掉就漏计。聊天、IME、增强模式、HUD 与 UI tokens 已按行为/合同分离；HUD 行为继续按生命周期与场景拆文件。

# 测试规则

本节是测试层级、编写与保留、源码合同边界和覆盖规则的唯一正文；根 `AGENTS.md` 只保留层级名称、证据纪律和放置边界。

## 测试层级

- 单元测试验证一个可独立调用的函数、状态机或小型类；通过生产接口输入并断言输出或状态变化，不启动完整客户端、服务端或真实外部服务。
- 集成测试验证两个及以上生产模块的协作边界，例如组件与存储、解析器与缓存、调度器与消费者。允许使用 fake、内存实现或工作区临时目录，但不得用源码字符串代替模块协作。
- 端到端测试构建并启动真实客户端、服务端或辅助进程，从外部命令、网络连接、日志和退出状态验证完整玩家路径。根 `scripts/` 属于 DDNet 上游同步区；QmClient 专属端到端与冒烟测试统一放在 `qmclient_scripts/integration/`，由 QmClient gate 编排。需要复用上游 runner 时复制到 QmClient 目录后独立适配，不向上游脚本加入 QmClient 特化行为。
- 冒烟测试是端到端或集成测试的最小关键子集，只证明程序能启动、连接并完成基本操作；不能替代功能回归、异常路径或完整端到端覆盖。
- 静态合同测试只验证无法通过稳定运行时接口观察的构建、平台、生成链、注册表、迁移终态和资源清单约束；文件使用 `*_contract_test.cpp` 或对应脚本合同测试名称，不得混入运行时测试文件。

## 编写与保留

- 优先验证真实行为和可观察结果。测试应调用生产实现，不复制算法、重写状态机或按当前实现逐行构造预期结果。
- 可复现缺陷优先先写能在修复前失败的回归测试；至少覆盖触发条件、修复后的状态转换，以及本次缺陷相关的恢复、重复调用或用户覆盖路径。
- 每项测试表达一个因果行为，名称说明条件和结果。共享准备代码放最小 fixture 或测试辅助模块，不把多个迁移阶段、多个功能域和数百个断言塞入一个 `TEST`。
- 同一文件只承载一个功能域和一个主要验证层级。超过 1500 行、80 项测试、单个 suite 超过 50 项，或单个 `TEST` 超过 100 行时必须检查拆分；除非共享 fixture 或参数矩阵能证明拆分会明显降低可读性，否则应按状态机、组件或场景拆文件。
- 参数矩阵仅用于同一行为的输入组合；不同失败原因、生命周期阶段或用户路径使用独立测试。表驱动测试失败时必须能定位具体输入。
- 测试不得依赖执行顺序、真实用户目录、已安装客户端、互联网、固定端口或无界等待。并发和异步测试使用可观察条件与明确超时，不用任意长 `sleep` 掩盖竞态；临时数据放测试提供的隔离目录。
- 删除过时或无效测试时，同时删除只为它存在的 helper、fixture、测试数据和构建注册。不要把已失效的实现镜像迁移到新文件继续保留。

## 源码合同边界

- 禁止用 `ReadTestSourceFile`、`ReadRepoFile`、函数体截取或字符串查找证明运行时行为、调用顺序、局部变量名、具体分支写法或 UI 玩家体验。
- 只有缺少稳定运行时观察点，并且约束本身属于构建或架构边界时才保留源码合同。测试中应说明该约束为何不能由行为测试覆盖，并尽量检查单一稳定事实。
- include、函数名、局部符号、代码片段存在或不存在通常不是独立合同。确需约束注册、平台宏、生成文件、公开 API 删除或迁移终态时，优先解析结构化清单或调用专用校验器，最后才使用源码字符串。
- 同一行为已有单元或集成测试后，删除重复的源码合同；静态接线合同不能替代对应状态机的成功、失败、取消、重试和恢复测试。

## 覆盖与验证

- “测试数量”“测试通过”和“代码覆盖率”是不同证据。没有生成 line、function、branch coverage 报告时，不得声称达到某个代码覆盖百分比。
- 混合测试文件与声明保持为零；新增声明归入现有层级和功能域，同步更新构建注册。quick/default/full gate 使用库存检查阻断混合声明、未注册文件、缺失源码和重复测试 ID；不能通过改后缀、移入合同目录或增加豁免掩盖行为测试中的源码断言。
- 测试层级库存统一由 `python qmclient_scripts/test_inventory.py` 生成；其中 `process_smoke_runners`、`process_smoke_scenarios` 和 `e2e_scenarios` 必须分别报告，不能用 smoke 场景数量冒充端到端覆盖。
- 评估覆盖时至少区分正常路径、边界输入、失败回退、取消或重入、持久化兼容、并发或生命周期，以及适用的平台分支；按实际功能风险说明已覆盖和缺漏。
- 局部修改运行直接相关的单元或集成测试并构建受影响目标。跨进程、连接、启动、地图或编辑器路径变化时补对应端到端或冒烟场景；准发布验证按 verification skill 选择 gate。
- 最终回复记录实际运行的测试层级、过滤范围和未覆盖场景。源码合同通过只能称静态合同通过，构建成功不能称运行时、端到端、视觉或跨平台行为通过。
