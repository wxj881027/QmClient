# 测试编写入口

本目录及子目录遵循根 `AGENTS.md` 的测试层级、编写与保留、源码合同边界和覆盖规则。修改前读对应生产实现与现有行为测试；旧测试的写法不自动成为可沿用规范。

- 独立生产接口行为放 `unit/<功能域>/`，模块协作放 `integration/<功能域>/`；静态合同放 `contract/<功能域>/` 并使用 `*_contract_test.cpp`。共享辅助代码放 `support/`，Google Benchmark 放 `benchmark/`，Qm 跨进程测试放 `qmclient_scripts/integration/`。
- 一个文件只承载一个功能域和一个主要验证层级，保持混合文件与混合声明为零。不要为通过分类检查将运行时源码断言改名为合同；按根规则删除重复检查或补生产观察点。
- 通过生产接口安排输入、执行操作并断言可观察结果。新增测试先明确“哪项生产行为出错会使此测试失败”；不能回答时重新设计测试，不复制算法或用源码字符串代替行为。
- 修改配置、时钟、缓存、logger 等共享状态时显式初始化所需状态并恢复；测试须能单独运行，不能依赖其他 suite 留下的默认值。fake 只替换外部边界，不重写待测生产职责。
- 参数矩阵用于同一行为的输入组合；失败、取消、重入、恢复等不同路径独立命名。文件与 suite 的拆分阈值遵循根规则。
- 新增、迁移或删除编译单元时同步 CMake 注册、辅助引用和只为它存在的数据；不要仅运行旧二进制。按 verification skill 构建受影响目标并运行相关过滤。

完成前运行 `python qmclient_scripts/test_inventory.py --json` 核对库存，并按 verification skill 运行适用 gate。库存 gate 检查结构和注册，不证明行为覆盖或断言质量。`README.md` 供目录导航，规则权威来自本文件、根规则与专项 skill.

# 测试目录

C++ 测试按层级和功能域组织；生产接口与测试名保持稳定，目录只表达职责。AI 编写入口为本目录 `AGENTS.md`，benchmark 另有 `benchmark/AGENTS.md`；本 README 只提供导航。

| 目录             | 职责                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------- |
| `unit/`        | 独立函数、策略、状态机和小型类的行为测试                                                |
| `integration/` | 两个及以上生产模块的协作；当前包含上传生命周期、翻译后端/任务队列与菜单性能日志协作测试 |
| `contract/`    | 现有合同文件，逐步收敛到构建、平台、生成资源和迁移终态约束                              |
| `mixed/`       | 历史混合文件已完成分离，当前没有 C++ 测试文件；库存继续检测新增混杂                     |
| `support/`     | 共享 fixture、fake、源码合同读取器和链接 stub，不计为独立测试场景                       |
| `benchmark/`   | Google Benchmark，直接测量生产实现，不并入 Google Test 数量                             |

各层内部按 `base`、`engine`、`client`、`server` 和 `qmclient/<功能域>` 区分。`test.cpp`、`test.h` 是公共入口。`QmAnimDropdownTest.cpp` 已归入 `unit/qmclient/ui/`。

新增测试应通过生产接口观察输出或状态变化，在根 `CMakeLists.txt` 的对应目标显式注册。新增公共辅助代码放在 `support/`，使用 `<test/support/文件名.h>`；使用公共入口时包含 `<test/test.h>`。跨进程测试仍放在 `qmclient_scripts/integration/`。

运行 `python qmclient_scripts/test_inventory.py` 检查递归库存、未注册文件、注册但缺失的源码和重复测试名；`--json` 输出完整数据。数量表示测试宏声明，参数化与类型化实例不展开。CMake 声明统计包含条件分支和独立目标，不能当作本机实际执行数。`mixed` 单独统计，不把整个文件的行为声明算成静态合同。合同后缀只是文件职责声明，不能证明每项断言都符合合同边界。

quick/default/full gate 的“测试层级与注册库存”检查扫描当前完整仓库，混合声明、未注册文件、缺失源码或重复 ID 会导致失败；扫描不执行真实测试，也不能判断合同是否合理或 benchmark 测量是否有效。

目录移动应同时更新注册、辅助头文件引用、路径型 include guard 和使用旧路径的脚本，并构建受影响目标、核对实际测试发现。禁止只移动文件后依赖库存数量判断执行成功。

监控遗留未注册文件已完成逐功能核对并删除，有效行为迁入对应目录；库存工具继续报告未注册文件和缺失注册源码。JSON schema 为 7，汇总区分合同、混合、单元与集成文件，计数表示宏声明。

卡片行为按页面布局、表单状态、外观几何、放置排序、动画与交互进入 `unit/qmclient/settings/`；碰撞几何和武器行为进入 `unit/qmclient/client/`。对应资源标签与源码接线继续由 `contract/` 承载。混合文件声明已清零；源码合同债务仍独立保留并继续按观察点审查。

库存 schema 7 同时识别源码读取 helper 和直接 `TestSourcePath("src/…")` / 仓库根流式读取，避免只把 helper 调用去掉就漏计。聊天、IME、增强模式、HUD 与 UI tokens 已按行为/合同分离；HUD 行为继续按生命周期与场景拆文件。
